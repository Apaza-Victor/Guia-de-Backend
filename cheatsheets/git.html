Pull requests (GitHub)

  1. Abre una rama nueva desde main.
  2. Haz push y pulsa Compare & pull request.
  3. Escribe título y descripción con contexto, adjunta capturas o logs.
  4. Marca Draft si sigue en construcción.
  5. Revisa los checks (CI): deben pasar antes del merge.
  6. Fusiona: preferible Squash and merge para historial limpio.
  7. Borra la rama al final.

.gitignore

Deshacer: revert, reset y restore

Buenas prácticas

  • Commits pequeños, atómicos y con mensajes en español claros usando Conventional Commits.
  • Todo lo que llega a main pasa por PR revisada y con CI verde.
  • Nunca subas secretos: rota la clave si llego a pushear uno.
  • Ramas temáticas cortas con un único propósito.
  • Rebase para leer historial; merge para no reescribir lo compartido.
  • Actualiza main antes de empezar una rama y vuelve a sincronizar antes del PR.
