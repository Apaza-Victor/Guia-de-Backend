🔗 REST

Diseño de APIs REST: recursos, métodos, códigos de estado, versionado, paginación, filtros, autenticación e idempotencia. El estándar dominante en backend.

⚡ Cheatsheet APIs Cheatsheets

Recursos y URLs

  • Un recurso es una entidad: usuarios, posts, pedidos. Va en plural y en minúscula.
  • Usa sustantivos; nunca verbos en la URL (los verbos son los métodos HTTP).
  • Identificadores al final: /api/users/42.
  • Subrecursos para relaciones: /api/users/42/posts.
  • Jerarquía máxima de 2 niveles si es posible.

Métodos HTTP

MétodoPropósito¿Idempotente?Cuerpo?
GETLeer (solo lectura)SíNo
POSTCrear o acción complejaNoSí
PUTReemplazar por completoSíSí
PATCHActualizar parcialmenteNoSí
DELETEEliminarSíOpcional
HEADCabeceras sin bodySíNo
OPTIONSVer métodos permitidosSíNo

Idempotente: repetir la petición N veces produce el mismo efecto que una vez.

Buenas prácticas

  • Nombres de recursos en plural y kebab-case; JSON en snake_case.
  • Molde de respuesta fijo y errores con código propio además del HTTP.
  • Paginación y filtros desde el principio, aunque el listado sea pequeño.
  • Safe methods (GET) nunca modifican estado.
  • Versiona la API desde el día uno: /api/v1.
  • Tokens con exp corto + refresh rotado; rate limiting para todo lo público.
