🐳 Docker

Contenedores para empaquetar aplicaciones y sus dependencias. Imágenes, run, volúmenes, redes, Dockerfile y Compose.

⚡ Cheatsheet Herramientas Cheatsheets

Conceptos clave

  • Imagen: plantilla inmutable con el código y sus dependencias. Se comparte.
  • Contenedor: instancia en ejecución de una imagen. Efímero por naturaleza.
  • Volumen: datos que sobreviven al contenedor (BD, uploads).
  • Red: los contenedores se descubren por nombre dentro de una red propia.
  • Dockerfile: receta para construir una imagen.
  • Compose: define varios servicios (app + postgres + redis) con un docker-compose.yml.

Ejecutar contenedores: docker run

Imágenes: pull, build y push

Dockerfile esencial

El orden importa: capas con menos cambios van primero para aprovechar la caché de capas (npm ci antes de copiar el código).

Buenas prácticas

  • Usa imágenes oficiales y etiquetas concretas (nunca latest en producción).
  • Prefiere bases slim/alpine y build en multi-etapa para imágenes pequeñas.
  • No instales dependencias de desarrollo en la imagen final.
  • Secretos vía variables de entorno o secrets de Compose, nunca dentro de la imagen.
  • Un servicio por contenedor; procesos con PID 1 gestionado (node directo, no npm start si pide shell).
  • Define restart y límites de recursos en producción.
