🗺️ El mapa mental del backend

🗺️ Mapa de conceptos

Antes de aprender una tecnología, conviene situarla en el mapa. Este glosario expandido agrupa los conceptos del backend en seis bloques temáticos, con una definición corta y real de cada uno. Úsalo como referencia rápida mientras avanzas por los cursos: si un término aparece en una lección y no lo recuerdas, vuelve aquí.

6 bloques 70+ conceptos En español

🌐 HTTP y Web

El idioma con el que se comunican clientes y servidores. Todo el backend lo habla.

HTTP

Protocolo de transferencia de hipertexto: el lenguaje con el que clientes y servidores intercambian peticiones y respuestas por la web.

HTTPS

HTTP cifrado con TLS: garantiza confidencialidad, integridad y autenticación del servidor. Es el estándar obligatorio hoy.

Request

Petición del cliente al servidor: método, URL, cabeceras y, opcionalmente, un cuerpo con datos (por ejemplo en un POST).

Response

Respuesta del servidor al cliente: código de estado, cabeceras y, normalmente, los datos solicitados en el cuerpo.

Métodos HTTP

GET, POST, PUT, PATCH, DELETE y más: las acciones que el cliente pide ejecutar sobre un recurso del servidor.

Códigos de estado

Respuestas de tres dígitos: 2xx éxito, 3xx redirección, 4xx error del cliente y 5xx error del servidor.

Cabeceras (headers)

Metadatos de una petición o respuesta: Content-Type, Cache-Control, Authorization y cientos más que condicionan el comportamiento.

Cookies

Pequeños datos que el servidor guarda en el navegador para mantener estado y sesiones entre peticiones distintas.

Caché

Almacenamiento temporal de respuestas repetidas para evitar recalcular: reduce latencia y descarga al servidor.

REST

Estilo de arquitectura de APIs basado en recursos, verbos HTTP y representaciones como JSON. Stateless, es decir, sin estado guardado en el servidor.

GraphQL

Lenguaje de consulta de APIs: el cliente pide exactamente los campos que necesita a través de un único endpoint.

WebSocket

Conexión bidireccional y persistente entre cliente y servidor para comunicación en tiempo real: chats, juegos y streaming.

SSE

Server-Sent Events: el servidor empuja datos al navegador por una conexión HTTP abierta, usado en notificaciones y feeds.

🗄️ Datos

Dónde vive la información de tu aplicación y cómo la manipulas con seguridad y rendimiento.

Base de datos relacional

Almacena datos en tablas con filas y columnas, relacionadas entre sí mediante claves primarias y foráneas.

SQL

Lenguaje declarativo para consultar, insertar, modificar y eliminar datos en bases de datos relacionales.

NoSQL

Motores no relacionales: documentos, clave-valor, grafos o columnas, elegidos por escala o modelo de datos flexible.

Índice

Estructura auxiliar que acelera la búsqueda de filas: agiliza las consultas SELECT pero ralentiza las escrituras.

Transacción

Conjunto de operaciones que se aplican todas o ninguna (ACID): protege la integridad de los datos ante errores.

ORM

Capa que traduce entre objetos del lenguaje y tablas de la base de datos: evita escribir SQL a mano en el código.

Migración

Cambios versionados del esquema de la base de datos, aplicados de forma ordenada y repetible en todos los entornos.

Normalización

Proceso de diseño que elimina redundancias dividiendo tablas y estableciendo relaciones limpias entre datos.

Replicación

Copias de los datos en varios nodos para conseguir alta disponibilidad y distribuir la carga de lectura.

Sharding

Particionado horizontal de una tabla entre varios servidores para escalar escritura y almacenamiento.

🧩 Programación

Los conceptos del lenguaje que usa tu servidor para procesar peticiones.

Lenguaje de programación

Herramienta con la que escribes la lógica del servidor: Python, JavaScript, PHP, Java, Go, Rust y otros.

Paradigma

Estilo de programación: orientado a objetos, funcional, imperativo o declarativo. Condiciona cómo modelas tu código.

Programación asíncrona

Ejecutar operaciones de entrada y salida (red, disco, base de datos) sin bloquear el hilo: promesas, async/await, callbacks.

Event Loop

Bucle de eventos que reparte los callbacks pendientes cuando las operaciones asíncronas terminan. El corazón de Node.js.

Proceso

Programa en ejecución con su propia memoria, aislado del resto de procesos del sistema operativo.

Hilo (thread)

Unidad de ejecución dentro de un proceso: permite paralelizar trabajo compartiendo la memoria del proceso.

Concurrencia

Gestionar muchas tareas a la vez con hilos, procesos o asincronía, aprovechando al máximo la CPU disponible.

Stream

Flujo de datos procesado de forma incremental en trozos: ideal para archivos grandes y respuestas largas.

🏛️ Arquitectura

Las formas de organizar tu software para que sea mantenible, escalable y evolucione sin romperse.

Cliente-servidor

Modelo donde un cliente pide recursos y un servidor los provee. Es la base de casi todo el backend web.

Monolito

Aplicación única que contiene toda la lógica de negocio. Fácil de empezar y desplegar; escala con límites.

Microservicios

Dividir la aplicación en servicios pequeños e independientes que se comunican por la red. Mayor flexibilidad, más complejidad.

Arquitectura en capas

Separación por responsabilidades: presentación, aplicación, dominio e infraestructura. Cada capa habla solo con las vecinas.

MVC

Modelo-Vista-Controlador: separa los datos (modelo), la presentación (vista) y la lógica de entrada (controlador).

API

Interfaz pública con la que otros sistemas hablan con tu backend, con reglas y contrato bien definidos.

Reverse proxy

Servidor que recibe el tráfico y lo reenvía a los servicios internos: termina TLS, cachea y equilibra la carga.

Load balancer

Distribuye las peticiones entre varios servidores para repartir la carga y evitar que un fallo tire el servicio.

Colas de mensajes

Buzón entre servicios: desacopla al emisor del receptor, absorbe picos de trabajo y permite reintentos.

Arquitectura orientada a eventos

Los servicios reaccionan a eventos en lugar de llamarse directamente: sistemas desacoplados y muy escalables.

Serverless

Ejecutar funciones sin administrar servidores: la plataforma escala desde cero hasta miles de peticiones automáticamente.

🖥️ Infraestructura

El sistema operativo, la red y el despliegue: lo que ya no está en tu portátil

Linux

El sistema operativo más usado en servidores: gestión de procesos, permisos, servicios y scripts.

Terminal y shell

Interfaz de texto para ejecutar comandos y scripts en el servidor. Scripting con Bash o PowerShell.

Dirección IP

Dirección numérica que identifica una máquina en una red, en formato IPv4 o IPv6.

DNS

Servicio que traduce nombres de dominio a direcciones IP: convierte "midominio.com" en un número de servidor.

Puerto

Punto de entrada numerado de una máquina: 80 HTTP, 443 HTTPS, 22 SSH, 5432 PostgreSQL.

SSH

Protocolo de acceso remoto cifrado para administrar servidores de forma segura desde tu máquina.

Contenedor

Proceso aislado con su propio sistema de archivos, empaquetado con la aplicación y todo lo que necesita para ejecutarse.

Docker

La herramienta más usada para crear, distribuir y ejecutar contenedores de forma reproducible.

Kubernetes

Orquestador de contenedores: escala, despliega y repara automáticamente tus servicios en producción.

CI/CD

Integración y despliegue continuos: cada cambio se prueba y se publica de forma automática y repetible.

Cloud

Servidores y servicios administrados por terceros por internet: modelos IaaS, PaaS y SaaS.

VPS

Servidor virtual dedicado con acceso de administración por internet, estándar para desplegar proyectos propios.

CDN

Red de caché distribuida que sirve el contenido desde el nodo más cercano al usuario, reduciendo la latencia.

Monitorización

Registrar métricas, logs y alertas de producción para detectar fallos y degradación antes de que impacten a los usuarios.

🔐 Seguridad y autenticación

Proteger la aplicación y sus datos: quién entra, qué puede hacer y cómo defenderse de ataques comunes.

Autenticación

Verificar quién es el usuario: contraseñas, códigos de un solo uso, proveedores sociales o tokens.

Autorización

Verificar qué puede hacer el usuario ya autenticado: roles, permisos y políticas de acceso a los recursos.

Sesión

Estado de un usuario autenticado guardado en el servidor y referenciado por una cookie en el cliente.

JWT

Token firmado y autocontenido con los datos del usuario: se valida sin consultar la base de datos.

OAuth 2.0

Protocolo de delegación de acceso: una app obtiene tokens para actuar en nombre del usuario sin ver sus contraseñas.

Hash de contraseñas

Guardar contraseñas como hash salado con algoritmos como bcrypt o argon2, nunca en texto plano.

TLS

Capa de cifrado que protege el tráfico entre cliente y servidor: es la "S" de HTTPS.

Inyección SQL

Vulnerabilidad que ocurre al concatenar entrada del usuario en consultas SQL. Se previene con sentencias preparadas.

XSS

Cross-Site Scripting: inyección de scripts en páginas que ejecutan código malicioso en el navegador de otras personas.

CSRF

Ataque que fuerza al navegador de un usuario autenticado a ejecutar acciones no deseadas contra tu API.

CORS

Política del navegador que decide qué orígenes pueden llamar a tu API, especialmente con credenciales.

OWASP Top 10

El ranking de las diez vulnerabilidades web más críticas, revisado periódicamente por la comunidad OWASP.
