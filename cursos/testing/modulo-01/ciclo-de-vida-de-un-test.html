Ciclo de vida de un test

🔧 Intermedio 10 min Testing Backend Módulo 1 · Fundamentos

Las 4 fases de todo test

Todo buen test respira en cuatro tiempos que se escriben arriba y se leen abajo:

Arrange, Act, Assert en PHPUnit

Pista: si necesitas dejar de leer para enterarte dónde está el Assert, no es legible. La estructura se ve a simple vista.

Hooks del ciclo: setUp y tearDown

Los frameworks de testing ofrecen ganchos que corren antes y después de cada test (y de la clase entera).

  • setUp(): se ejecuta antes de cada test. Ideal para conexiones, objetos comunes y datos.
  • tearDown(): después de cada test. Limpia registros y suelta recursos.
  • setUpBeforeClass() / tearDownAfterClass(): una vez por clase (ej: crear el esquema de BD).
  • static function once(): un dato computado una vez y compartido.

El secreto: aislamiento entre tests

Los tests nunca deben depender del orden ni de residuos de otros tests. Si el test A crea un usuario y el B lo busca, alguien rompió el contrato. Cada test debe poder correr solo, varias veces, y pasar igual.

Cuando un test falla intermitentemente

A un test «flaky» hay que perseguirlo hasta el final:

  • ¿Usa hora actual, azar o concurrencia? → inyecta reloj/random en el Arrange.
  • ¿Depende de datos que otro test borró? → aislamiento roto.
  • ¿Depende de orden? → nunca confíes en el orden; cada test es independiente.
  • Regla: un test inestable vale menos que ninguno porque te enseña a desconfiar del verde.

Ejercicio

  1. Toma un test que ya tengas y anota sus 4 fases con comentarios.
  2. Si no tiene setUp/tearDown, refactorízalo.
  3. Ejecútalo 10 veces y luego inviértelo (corre el último primero) para verificar aislamiento.

Resumen

  • Todo test: Arrange → Act → Assert → Cleanup.
  • setUp/tearDown centralizan preparación y limpieza.
  • Los tests deben ser independientes, sin orden ni residuos.
  • Un test intermitente se corrige o se elimina; nunca se ignora.
