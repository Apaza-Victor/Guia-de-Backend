Tipos de pruebas

🔧 Intermedio 11 min Testing Backend Módulo 1 · Fundamentos

¿De qué hablamos cuando hablamos de tipos?

Hay dos ejes: granularidad (¿qué tan grande es la parte bajo prueba?) y objetivo (¿qué verifica?). Aquí veremos los 4 que definen casi todos los pipelines de backend.

Pruebas unitarias

Prueban una unidad en aislamiento: una clase, una función, una regla. Si la unidad depende de algo externo (BD, API, tiempo), se sustituye por un doble.

  • Rapidez: milisegundos por test.
  • Aislamiento: falla precisa, sin infra de por medio.
  • Uso: reglas de negocio, cálculos, validaciones, transformaciones.

Pruebas de integración

Contratan varias piezas reales entre sí: repositorio + base de datos, controlador + enrutador, cliente HTTP + servicio. Se pueden usar contenedores reales o en memoria.

Pruebas end-to-end (E2E)

Ejecutan el flujo completo como lo ve un usuario/cliente real: petición HTTP entra, pasa por toda la app, toca BD y responde. La velocidad baja y la fragilidad sube, por eso van al mínimo crítico.

Pruebas de regresión

No son un tipo distinto: son el objetivo de las anteriores. Una prueba de regresión es aquella que se escribió para un bug que ya pasó, garantizando que no vuelva a aparecer.

  • Se escribe después del fix, falla contra el código roto y pasa contra el corregido.
  • Regla de oro: a todo bug reportado le toca su test de regresión.

Otros tipos que verás

Ejercicio

  1. Elige una función de tu código (ej: cálculo de envío).
  2. Escribe 3 unit tests para ella.
  3. Anota: ¿cuál sería su test de integración? ¿y su E2E?

Resumen

  • Unit: una unidad aislada, rápida y precisa.
  • Integración: piezas reales conectadas (BD, HTTP).
  • E2E: flujo completo; pocos pero críticos.
  • Regresión: el objetivo; un bug = un test para siempre.
