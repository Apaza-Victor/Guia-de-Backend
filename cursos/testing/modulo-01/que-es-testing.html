¿Qué es el testing?

🔧 Intermedio 9 min Testing Backend Módulo 1 · Fundamentos

¿Qué es testear?

Testear es ejecutar tu código de forma automatizada para verificar un comportamiento esperado. Un test es un programa que llama a otro programa, compara el resultado con lo que se esperaba y dice: verde (pasa) o rojo (falla).

No es «nice to have»: en backend, una línea sin verificar puede cobrarte factura en producción a las 3 a.m. El test es parte del código.

Lo que te aporta un test bien escrito

  • Red de seguridad: puedes refactorizar sabiendo que si rompes algo, el test grita.
  • Contrato viviente: «qué se espera de esta función» queda escrito y ejecutable, no en un correo borrado.
  • Documentación que no miente: un test dice cómo usar tu código mejor que mil comentarios (los comentarios envejecen; el test, si lo ejecutas, no).
  • Confianza para desplegar: el pipeline corre todos y se detiene si algo cambió el comportamiento.

Un primer test con PHPUnit

Ese assertSame es la pregunta: «¿el resultado es exactamente 5.0?». Si alguien cambia la suma por una resta, el verde se apaga.

Mitos que hay que desmontar

  • «Los tests me quitan tiempo»: te lo quitan hoy y te lo regalan doble mañana en cada refactor.
  • «Testear es solo para proyectos grandes»: un SDK, una API y un job valen igual; el tamaño no decide la necesidad.
  • «No hay bugs en mi código»: los hay, y el test los encuentra en el sandbox antes que en producción.
  • «El test manual alcanza»: el manual prueba una vez; el automatizado, cada commit y cada despliegue.

Ejercicio

  1. Abre tu función más usada del último proyecto.
  2. Escribe 3 casos que deba cumplir (normal, mínimo, borde).
  3. Convierte cada caso en un assert (usa PHPUnit u otra herramienta).

Resumen

  • Un test verifica un comportamiento esperado de forma automática.
  • Te da red de seguridad, contrato y documentación viva.
  • El assert es la pregunta; el verde/rojo es la respuesta.
  • Los mitos («no me da tiempo», «no hay bugs») se desmontan probando.
