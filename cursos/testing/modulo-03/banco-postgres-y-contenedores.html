Postgres con contenedores

🔧 Intermedio 15 min Testing Backend Módulo 3 · Integración

Por qué Postgres real en tests

SQLite no habla exactamente el SQL de Postgres: los índices JSONB, el ON CONFLICT, las funciones y los tipos se comportan distinto. Los tests de integración con la misma BD que producción eliminan la clase más cara de bugs falsos.

docker-compose para la BD de tests

Env por entorno, no valores quemados

Patrón: una BD por suite, rollback por test

El schema.sql se genera a partir de tus migraciones. En el CI lo mismo: subimos migraciones y después los tests corren en transacciones.

CI: como una tubería por commit

Trampas con la BD real en CI

Ejercicio

  1. Crea docker-compose.test.yml con Postgres 16 en memoria.
  2. Escribe una clase base con rollback por test.
  3. Porta tu repositorio de usuarios a un test contra Postgres real.

Resumen

  • Postgres real elimina bugs falsos de SQLite.
  • docker compose + tmpfs = datos en memoria para tests.
  • Esquema una vez, transacción y rollback por test.
  • Env por entorno; nunca credenciales en el código.
