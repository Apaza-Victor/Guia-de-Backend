Testing HTTP y servicios externos

🔧 Intermedio 15 min Testing Backend Módulo 3 · Integración

El problema: la red no es reproducible

Un test que llama a la API real de Stripe o a la de un proveedor de precios es lento, frágil y caro (y a veces inyecta datos reales). Por eso hay tres estrategias de integración HTTP, en orden de fidelidad:

Stub real: MockWebServer y servidor embebido

Probar de verdad el cliente HTTP

Esto ejercita serialización, headers, status codes y parsing: todo lo que los mocks de la interfaz no tocan.

Timeouts, retries e idempotencia

¿Y si quiero probar el sandbox real?

  1. Mantenlo fuera de la suite que corre por commit (es lento).
  2. Marca con #[Group('lentos')] o un script aparte.
  3. Usa credenciales de test, nunca las de producción.
  4. Acepta que el test pueda fallar por caída del proveedor: es info, no blocker del commit diario.

Ejercicio

  1. Crea un stub local para un endpoint de tu proveedor favorito.
  2. Escribe un test que ejercite el cliente real contra el stub.
  3. Agrega un caso con 503 + reintento y verifica el retry.

Resumen

  • La red no es reproducible: usa stubs y mock handlers.
  • MockWebServer / servidor embebido = contrato fiel sin red.
  • Timeouts y retries se testean con callbacks.
  • El sandbox real queda fuera del ciclo rápido de commits.
