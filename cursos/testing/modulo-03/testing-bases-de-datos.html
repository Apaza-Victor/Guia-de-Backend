Testing de bases de datos

🔧 Intermedio 16 min Testing Backend Módulo 3 · Integración

¿Por qué probar la capa de datos?

El 80 % de los bugs reales en backend viven en el acuerdo entre el SQL y el dominio: una columna mal nombrada, un tipo distinto, una relación mal contada. Los mocks de repositorios no ven eso. La integración contra una BD (aunque sea embebida) sí.

Ejercicio

  1. Crea un repositorio ProductoRepositorio con SQLite en memoria.
  2. Tests: guardar+leer, no existe, listar por categoría.
  3. Provoca la unicidad del sku y verifica la excepción.

Resumen

  • SQLite en memoria: rápido; Postgres en contenedor: fiel.
  • Base limpia por test: recreate o rollback.
  • Prueba unicidad, nulos, relaciones y SQL de verdad.
  • Nunca BDs compartidas ni fechas del reloj del sistema.
