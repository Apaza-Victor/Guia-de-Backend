Supertest para tu API

🔧 Intermedio 14 min Testing Backend Módulo 4 · E2E

Un E2E útil empieza por HTTP

Supertest dispara peticiones HTTP reales contra tu aplicación sin abrir un puerto: lo usan Apps con Express, Koa, Fastify y demás. Verifica status, cuerpo, headers y cookies tal como llegaría a un cliente.

Instalar y primer test

Los verbos y estados HTTP que importan

  • 2xx: éxito. 201 = creado, 204 = sin cuerpo.
  • 4xx: error del cliente. 400/422 = validación.
  • 401: sin autenticar · 403: sin permiso · 404: no existe.
  • 429: rate limit · 5xx: bug de servidor.

Autenticación y cookies

No confundir con unit

  • Supertest con la app real es E2E fino: HTTP entra, todo el middleware corre, salen headers.
  • Si tu app usa una BD, este test la toca: prepara base limpia antes (rollback/truncate).
  • Para repetir 100 veces el mismo camino, mejor unit. Para proteger el flujo de verdad, Supertest.

Ejercicio

  1. Levanta tu API con Express (o tu framework PHP en un puerto).
  2. Prueba con Supertest: 200 de un GET, 404 de uno inexistente.
  3. Añade autenticación para que /api/perfil exija token.

Resumen

  • Supertest dispara HTTP real a la app sin abrir puertos.
  • Verifica status, body, headers y cookies.
  • Conoce los códigos: 201, 422, 401, 403, 429, 5xx.
  • Prepara base limpia: los E2E tocan la BD de verdad.
