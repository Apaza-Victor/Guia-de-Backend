Flujos completos de API

🔧 Intermedio 14 min Testing Backend Módulo 4 · E2E

El valor de encadenar

Los unit tests verifican piezas; el flujo completo verifica la coreografía: «registrarse → loguear → agregar al carrito → pagar». Un bug entre pasos (un token que no guarda, un stock que no descuenta) solo se ve encadenando.

Un flujo crítico de compra

Datos únicos por ejecución

Un email repetido rompería la unicidad al correr dos veces seguidas. La solución: sufijo con timestamp en cada creación.

Limpia al final, no asumas

Nunca dependas de los datos de otros tests. Si la suite es ordenada, la BD de test se trunca por suite y todo arranca igual.

¿Qué flujos merecen E2E?

  • Los que tocan dinero (pagar, reembolsar).
  • Los que tocan la cuenta del usuario (registro, login, olvido de clave).
  • Los que arrastran estado entre servicios (pedido → envío → notificación).
  • Los que un bug rompería toda la productividad del cliente.

Ejercicio

  1. Lista tus 5 flujos críticos de negocio.
  2. Elige 1 y escribe el flujo completo con Supertest.
  3. Añade emails únicos con timestamp y limpieza en afterAll.

Resumen

  • Los bugs viven entre pasos: encadena los críticos.
  • Datos únicos por ejecución: timestamp + random.
  • Limpia al final, no asumas orden ni residuos.
  • E2E solo para flujos que valen la pena.
