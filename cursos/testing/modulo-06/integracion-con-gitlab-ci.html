Diferencias con GitHub Actions

Las buenas prácticas de verificación (branch protection en GitHub, approval + merge check en GitLab) son iguales de importantes en ambos.

Ejercicio

  1. Crea el .gitlab-ci.yml con Unit + Integration + coverage.
  2. Activa el badge de cobertura en el README.
  3. Rompe un test y verifica cómo se ve el pipeline rojo.

Resumen

  • Stages + jobs: test es un stage, cada suite un job.
  • Servicios: postgres nombrado, DSN apuntando a "postgres".
  • Cache por composer.lock; artefactos en fallo.
  • Badge de cobertura con el regex correcto.
