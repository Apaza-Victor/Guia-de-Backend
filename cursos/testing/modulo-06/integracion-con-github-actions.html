Tests en GitHub Actions

🔧 Intermedio 14 min Testing Backend Módulo 6 · Métricas y CI/CD

De qué nos encargamos acá

El objetivo del pipeline: cada push y cada PR ejecuta la suite, levanta la BD de integración, mide cobertura y bloquea el merge si algo huele mal. Todo automático y sin fricción.

El workflow mínimo y real

Blocker el PR con verificaciones

Matriz de versiones (los rangos importan)

Caché y velocidad (sin trucos sucios)

Buenas prácticas de pipeline

  • Solo dependencias dev: composer install --no-dev --no-interaction en el build final; para testear, sí instalamos con dev.
  • Falla rápido: lexing, sintaxis y Unit primero; E2E al final.
  • Artefactos útiles: sube coverage y JUnit XML para el review.
  • Nunca credenciales en los secretos del repo para servicios de test.
  • Tiempo límite: no dejes correr E2E infinitos; capa el workflow.

Ejercicio

  1. Crea el workflow de arriba en tu repo (ajusta vías).
  2. Sube un PR que rompa un test y verifica el rojo.
  3. Arregla y confirma el verde antes del merge.

Resumen

  • Unit + Integration + clover en cada push/PR.
  • Postgres como service en el job, DSN por env.
  • Branch protection: nadie mergea sin green.
  • Matriz de versiones y caché de dependencias.
