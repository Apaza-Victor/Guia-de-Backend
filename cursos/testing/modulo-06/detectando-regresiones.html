Detectando regresiones

🔧 Intermedio 13 min Testing Backend Módulo 6 · Métricas y CI/CD

¿Qué es una regresión?

Regresión: un comportamiento que antes funcionaba y ahora no, sin que nadie lo haya pedido. Son los bugs más caros porque acontecen sobre una base que «funcionaba». La suites existen para cazarlas en el commit, no en producción.

Estrategias de caza en el PR

Diff-coverage: la malla fina

La cobertura total puede engañarte (el 92 % global no dice si tu línea nueva tiene test). El diff-coverage mide solo las líneas añadidas o modificadas del PR:

El diff-coverage cambia la conversación: de «¿cuánto cubrimos?» a «¿cubres lo que afirto cambiar?».

Umbrales totales en el pipeline

El clásico: refactor que rompió algo

Versiona tu E2E con tu app

  • Un E2E de la versión anterior sobre la app nueva es la peor combinación.
  • Regla: tests y código viven en el mismo repo y se despliegan juntos (o el contrato de versionado es tu ruina).
  • En microservicios: tests de contrato versionados con cada lado.

Ejercicio

  1. Rota el refactor de una función con tests y rompe algo a propósito: ¿cuántos tests te avisan?
  2. Calcula el diff-coverage de tu último PR a mano.
  3. Define tu umbral de regresión para el pipeline.

Resumen

  • Regresión = comportamiento que se rompe sin pedido.
  • Suite completa + diff-coverage + gates = red.
  • El test de regresión por bug lo hace permanente.
  • Tests y código viven y se despliegan juntos.
