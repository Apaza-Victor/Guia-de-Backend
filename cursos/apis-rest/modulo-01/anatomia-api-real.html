La anatomía de una API real

⚙️ Intermedio 8 min APIs REST Módulo 1 · Fundamentos

Una petición HTTP, desnuda

  • Método: GET — qué operación pedimos.
  • RUTA (objetivo): qué recurso (la URL sin dominio).
  • Versión del protocolo: HTTP/1.1 (o HTTP/2, HTTP/3).
  • Host: a qué servidor. Accept: qué formato aceptamos.
  • Authorization: quién pide. User-Agent: qué cliente.

La respuesta

  • Status line: código 200 + frase. El estado del mundo.
  • Content-Type: qué es el cuerpo. Content-Length: cuanto pesa.
  • Cache-Control / ETag: decisiones de caché (módulo 3).
  • Cuerpo: JSON. Puede no haber cuerpo (204, por ejemplo).

Verlo con cURL, no con imaginación

cURL es tu estetoscopio para cualquier API: con él ves exactamente qué se manda y qué se recibe.

Anatomía de un endpoint

Un endpoint = método + ruta (+ parámetros de ruta). El mismo recurso con verbos distintos es cuatro operaciones distintas.

  • Base URL: https://api.tienda.test/api/v1.
  • Parámetros de ruta: /productos/42 selecciona uno.
  • Query params: ?page=2&limit=10&sort=precio afinan la colección.
  • Consistencia total: mismo patrón en TODOS los recursos (módulo 3·5).

Una API real que puedes tocar

Ejemplos reales de Big Tech que muestran la anatomía hasta aquí:

  • GitHub REST API: GET https://api.github.com/repos/{owner}/{repo}.
  • Stripe API: https://api.stripe.com/v1/customers.
  • OpenWeather: https://api.openweathermap.org/data/2.5/weather?q=Madrid.

Ejercicio

  1. Con tu navegador visita un endpoint JSON público y observa la respuesta.
  2. Usa curl -i en la terminal contra una API de prueba del curso.
  3. Anota las partes de la petición y de la respuesta que aparecen.

Resumen

  • Petición: método + ruta + host + cabeceras (+ cuerpo).
  • Respuesta: status line + cabeceras + cuerpo (JSON).
  • Endpoint = método + ruta (+ params).
  • cURL muestra el tren completo: verifica siempre lo que sucede por el cable.
