¿Qué es una API y para qué sirve?

⚙️ Intermedio 8 min APIs REST Módulo 1 · Fundamentos

La definición

API (Application Programming Interface) es el contrato entre dos programas: un conjunto de reglas firmadas que dice «si me mandas esto, te devuelvo aquello». El que pide, el que sirve y las reglas del juego.

  • Define qué se puede pedir (endpoints, operaciones).
  • Define cómo hay que pedirlo (formato, método, cabeceras).
  • Define qué se devuelve (estructura, errores, códigos).

Sin API, cada cliente tendría que conocer los entresijos del servidor. Con API, el interior (bases de datos, servicios, reglas) queda protegido tras una puerta bien definida.

La analogía del restaurante

En un restaurante tú no entras a la cocina a cocinar. El camerero (la API) toma tu pedido con una carta (el contrato), lo lleva a la cocina (el sistema) y te devuelve el plato (la respuesta). Si quieres algo que no está en la carta… te lo niegan con buenos modos (un error). La cocina jamás está expuesta.

API no es solo «web»

  • Web APIs (HTTP): REST, GraphQL, SOAP… las que verás en este curso.
  • Library APIs: las funciones de una librería que tus procesos llaman en memoria.
  • OS APIs: el sistema operativo expone servicios (ficheros, red, timers).
  • Hardware APIs: el sistema operativo se comunica con drivers y dispositivos.

En backend, cuando se dice «la API» normalmente se habla de la web API expuesta por HTTP.

API, UI y SDK: no confundir

  • UI (User Interface): la capa visual para humanos (un botón, un formulario).
  • API: la capa de interacción para programas (una petición JSON).
  • SDK (Software Development Kit): paquete de librerías que envuelve una API para que programar contra ella sea cómodo (p. ej. AWS SDK).

Una página de login usa la UI del navegador; la app móvil que inicia sesión con 2 campos usa la API del servidor. Funcionan en paralelo sobre los mismos datos.

Para qué sirve en la práctica

  • Centraliza reglas de negocio que la app y la web comparten.
  • Permite que terceros integren con tus datos de forma controlada.
  • Te deja evolucionar el interior sin romper a los clientes.

Ejercicio

  1. Escribe una analogía propia de una API (puede ser el restaurante u otra).
  2. Enumera tres APIs web que tu app o página use a diario (pago, mapas, clima…).
  3. Explica con tus palabras por qué la cocina no debería estar expuesta.

Resumen

  • API = contrato entre dos programas: qué, cómo y qué responde.
  • Existen APIs de web, de librerías, de SO y de hardware.
  • UI es para humanos; API para programas; SDK es el kit que la envuelve.
  • Una API centraliza reglas y protege el interior del sistema.
