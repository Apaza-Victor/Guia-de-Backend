Clientes y consumidores de una API

⚙️ Intermedio 9 min APIs REST Módulo 1 · Fundamentos

¿Quiénes llaman a tu API?

Una API bien diseñada se adapta a quién la consume. Conocer a tus clientes define contratos, formatos y políticas. Los grandes tipos:

  • Apps móviles (iOS/Android): conexiones a veces lentas, pantallas pequeñas. Quieren respuestas compactas.
  • Navegadores (JavaScript): sufren CORS, comparten datos públicos, piden JSON ligero.
  • Otros servidores (backends, microservicios, cron jobs): máquinas que hablan entre sí, alto volumen, poca paciencia con errores blando.
  • Integraciones de terceros (pagos, CRM, ERP): necesitan documentación clara y claves de acceso.

Cliente vs consumidor

Cliente es quien hace la petición HTTP (un dispositivo, un proceso). Consumidor es la aplicación o sistema que usa la API para cumplir su objetivo. El navegador es el cliente; tu página web, el consumidor. No son lo mismo, aunque se confundan en la charla diaria: el navegador transporta, el consumidor decide.

Lo que cada cliente exige

Paginación, orden, campos mínimos: un móvil en 3G agradece que le devuelvas solo lo que la pantalla muestra. Un servidor que sincroniza sí quiere informes completos.

Diseñar para el peor cliente

  • Si tu única salida es móvil, mantén JSON magro y peticiones atómicas.
  • Si consumes en servidor, permite filtros potentes desde el query para no volcar tablas.
  • Si hay terceros, la documentación y la compatibilidad son el producto.
  • Siempre: versiona (módulo 3) y marqueta límites razonables.

Ver en acción

Ejercicio

  1. Inventa una API (tienda, hotel, música) y enumera 3 tipos de cliente.
  2. Anota qué pediría cada uno sobre los mismos datos.
  3. Decide un ejemplo de contrato distinto para móvil y para servidor.

Resumen

  • Cliente = quien transporta la petición; consumidor = quien la usa.
  • Móvil quiere magro; navegador, ligero y sin fricción CORS.
  • Servidores piden volumen y filtros; terceros, documentación.
  • Diseña pensando en el cliente más exigente.
