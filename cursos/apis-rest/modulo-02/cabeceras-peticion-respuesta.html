Cabeceras de petición y de respuesta

⚙️ Intermedio 10 min APIs REST Módulo 2 · HTTP

Metadatos del mensaje

Las cabeceras HTTP son pares clave: valor que viajan antes del cuerpo: describen el mensaje, al remitente, el idioma, la caché, la autorización… El cuerpo es el contenido; las cabeceras, su ficha técnica.

Cabeceras de petición importantes

  • Host: obligatorio, el servidor destino (gran soporte de múltiples APIs en un solo IP).
  • Accept / Accept-Language: qué formatos e idiomas toleras.
  • Authorization: credenciales (Bearer, Basic, API key).
  • Content-Type: formato del cuerpo cuando envías datos.
  • User-Agent: quién pregunta; útil para analítica y bloqueos.

Cabeceras de respuesta importantes

  • Location: URL del recurso creado (o del destino de una redirección).
  • Content-Type: formato real devuelto.
  • Cache-Control: instrucciones de caché para clientes y proxies.
  • X‑Request‑Id / X‑Correlation‑Id: correlación para diagnosticar.
  • Retry-After: cuántos segundos esperar antes de reintentar (429 y 503).

Nombres de cabeceras propias

  • Prefijos estándar: X-* desincentivado por IETF; hoy se anima RateLimit-Remaining, Idempotency-Key, Traceparent.
  • Las claves son case-insensitive: Content-Type = content-type.
  • No pongas datos sensibles en cabeceras: van encriptadas en HTTPS, pero evita guardarlas en logs.

Verlas en vivo

Ejercicio

  1. Ejecuta un curl -i y anota 5 cabeceras de respuesta.
  2. Explica qué comunica cada una que el cuerpo no dice.
  3. Diseña la cabecera de correlación que tu equipo usará en logs.

Resumen

  • Cabeceras = ficha técnica del mensaje; cuerpo = contenido.
  • Petición: Accept, Authorization, Content-Type, User-Agent.
  • Respuesta: Content-Type, Location, Cache-Control, X-Request-Id.
