Content-Type y Content-Disposition

⚙️ Intermedio 9 min APIs REST Módulo 2 · HTTP

Tipos MIME: el idioma del contenido

El Content-Type dice qué formato tiene el cuerpo: un tipo MIME tipo/subtipo. Los que una API REST toca a diario:

Content-Type en las dos direcciones

  • En la petición: les dices al servidor el formato del cuerpo que envías. Un POST JSON debe llevar Content-Type: application/json.
  • En la respuesta: le dices al cliente cómo parsear lo que recibe.

«Yo huelo el JSON»: no adivines

Un cliente nunca debe deducir el formato del cuerpo por su apariencia: debe leer Content-Type y parsear según el tipo. JSON vacío, JSON binario… feo en la práctica. Cabecera = contrato.

Content-Disposition: ¿pescador o cazador?

Controla cómo debe consumir el contenido: ¿mostrar en línea (inline) o forzar descarga (attachment)?

  • inline: el navegador intenta abrirlo en pantalla.
  • attachment; filename="...": descarga con ese nombre.
  • También se usa en multipart/form-data para nombrar cada parte (Content-Disposition: form-data; name="file").

Subidas de ficheros

Ejercicio

  1. Usa curl -i en una API y anota su Content-Type.
  2. Diseña el endpoint que descarga una factura PDF de tu tienda.
  3. Explica cuándo elegirías multipart/form-data frente a JSON puro.

Resumen

  • Content-Type = formato del cuerpo (MIME).
  • Content-Disposition = cómo consumirlo (inline o descarga).
  • Nunca adivines el formato: léelo de la cabecera.
