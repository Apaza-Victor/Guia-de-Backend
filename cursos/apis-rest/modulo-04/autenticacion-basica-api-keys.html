Autenticación básica y API keys

⚙️ Intermedio 11 min APIs REST Módulo 4 · Implementación

«¿Quién eres?» ANTES de «¿qué quieres?»

Autenticar = saber quién llama. Autorizar = saber qué puede. Las APIs REST modernas lo hacen con cabeceras estándar.

HTTP Basic: el abuelo directo

  • Enviado con HTTPS SIEMPRE (el base64 no es cifrado).
  • Simple, universal… pero cada petición repite credenciales e invita a guardarlas.
  • Usado aún por CI scripts, peticiones de monitoring y prototipos.
  • Con OAuth2, a veces se exige como flujo client credentials interno.

Bearer token: JWT y compañía

  • El servidor emite un token firmado; el cliente lo presenta en cada petición.
  • JWT: payload firmado (sub, exp, iat, claims). Stateless: el servidor no guarda sesión.
  • Riesgo: token robado = identidad robada hasta su expiración. Usa exp cortos y tiempo; considera OAuth2 flows para rostros públicos.

API keys: identidad de máquina

Para servicios ↔ servicios (clima, pagos, envíos): una clave secreta por cliente, con caducidad y rotación. Cén yak: el X-Api-Key sigue vivo en muchos productos, pero Authorization: Bearer es más limpio y uniforme.

¿Dónde guardarlas en el cliente?

  • Frontend JS: jamás — cualquier clave embebida es pública.
  • Backend: variables de entorno o gestores de secretos (AWS Secrets, Vault), nunca en repos ni logs.
  • móvil: guarda tokens en líbería segura; servidor detrás de proxy para las claves propias.
  • Truco API keys de terceros: provee las tuyas vía proxy propio, nunca del cliente final.

Respuestas típicas

  • Sin credenciales → 401 + WWW-Authenticate.
  • Credenciales inválidas → 401 también (no digas «existe este usuario»).
  • Válido pero sin permiso → 403.

Ejercicio

  1. Protege un endpoint con una key de práctica (en middleware).
  2. Prueba los tres caminos: sin key (401), con key (200), con key sin permiso (403).
  3. Cifra un secreto en tu repo usando tu gestor de variables y úsalo.

Resumen

  • Basic: simple, pero HTTPS o nada.
  • Bearer/JWT: stateless y ligero, con caducidad.
  • API keys: identidad de máquina, con rotación y secretos bien guardados.
