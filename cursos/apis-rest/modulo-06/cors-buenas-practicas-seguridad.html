CORS y buenas prácticas de seguridad

⚙️ Intermedio 12 min APIs REST Módulo 6 · Calidad y seguridad

CORS desmitificado

CORS (Cross-Origin Resource Sharing) es una política del navegador, no un cortafuegos de tu API: decide qué orígenes de páginas web pueden hacer peticiones a tu API. Un servidor backend (curl, Node, móvil) no lo sufre: solo el navegador lo impone.

Peticiones simples y preflight

  • Simple: GET/HEAD/POST con cabeceras limitadas — no hay preflight.
  • Compleja: otras cabeceras o métodos (Authorization, Content-Type json) disparan un OPTIONS previo (preflight).

Config correcta (nada de asterisco con credenciales)

Con credenciales (cookies), * está prohibido: repite el origen explícito.

Checklist de buenas prácticas de seguridad

  • HTTPS en todo: nunca una API autenticada en HTTP plano.
  • Valida y sanea la entrada en el servidor (lección M4).
  • No expongas secretos: las claves viven en variables de entorno.
  • Minimiza PII en respuestas y logs.
  • Limitadas respuestas: cabeceras que muestran versión de framework las evita el atacante no las necesita.
  • Rate limit del login (fuerza bruta).
  • Caps en el tamaño del body (limita el JSON a 1mb, p. ej.).
  • Revoca API keys viejas y rota las activas en calendario.

Cabeceras de «fortaleza» fáciles de coser

Ejercicio

  1. Configura CORS con tu lista exacta de orígenes.
  2. Prueba un preflight con OPTIONS desde el DevTools.
  3. Recorre la checklist de seguridad de tu API y corrige 3 cosas.

Resumen

  • CORS es del navegador, no del servidor.
  • No asterisco con credenciales; orígenes explícitos.
  • HTTPS, validación, secretos, PII magra: la lista es tuya.
