Monitoreo y métricas básicas

⚙️ Intermedio 11 min APIs REST Módulo 6 · Calidad y seguridad

Sin datos, tu API es una opinión

Monitorear = medir, registrar y alertar para saber cómo se siente tu API antes de que lo diga el cliente. Las «4 señales de oro» de Google SRE:

  • Latencia: cuánto tarda en responder.
  • Tráfico: cuántas peticiones llegan.
  • Errores: cuántas fallan (status 5xx y reglas propias).
  • Saturación: % de uso de CPU, memoria, conexiones, disco.

RED y USE: dos casas para las métricas del servicio

Instrumentar sin frameworks (express + prom-client)

Logs estructurados: la pareja del dashboard

Alertas: tu guardia de noche

  • Ratio de 5xx > 1% en 5 min.
  • p95 de latencia > 500ms sostenido.
  • CPU > 85% sostenido.
  • Uptime: health check caído.
  • Empieza con 3 alertas buenas, no con 40 ruidosas.

Ejercicio

  1. Expón /metrics y lanza petición desde tu terminal.
  2. Graba 3 métricas RED a mano en una hoja.
  3. Define 3 alertas con umbral que SIEMPRE quieras ver.

Resumen

  • Mide latencia, tráfico, errores y saturación.
  • RED para el servicio; USE para el recurso.
  • Métricas Prometheus + logs JSON con trace_id + alertas mínimas.
