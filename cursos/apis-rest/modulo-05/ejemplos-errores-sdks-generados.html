Ejemplos, errores y SDKs generados

⚙️ Intermedio 10 min APIs REST Módulo 5 · Documentación

Ejemplos: la pasta del spec

Un schema nos dice «la forma», un example dice «así se ve». Docúentalos: aceleran el Try it out y son la referencia del frontend.

Mocks: tu API antes de tu API

  • Prism (Stoplight): responde con ejemplos del spec sin servidor real.
  • Mockoon / WireMock: servidores ficticios para probar frontend y conectores primero.
  • El equipo frontend y el backend trabajan en paralelo contra el mismo contrato.

SDKs generados: adiós a la helessa

Tipos, endpoints, serializadores y errores salen del spec: cero mantenimiento a mano. Lenguajes: TS, Python, Java, Go, Kotlin, Swift…

Errores: documentar es anticiparse

  • Documenta todos los códigos de error que emites en cada operación.
  • Explica la causa, el trace_id a reclamar y qué reintentar.
  • Usa description en cada response: «401 si el token expiró», etc.
  • Un contrato que no documenta errores es un contrato a medio hacer.

El ciclo completo del spec

Ejercicio

  1. Añade examples a los 3 campos clave de tu spec.
  2. Arranca Prism con tu spec y hazle una llamada real.
  3. Genera un cliente TypeScript y úsalo en una página de prueba.

Resumen

  • Examples afinan el spec para humanos y mocks.
  • Mocks (Prism) y SDKs (OpenAPI Generator) salen del mismo contrato.
  • Errores documentados = clientes que saben reaccionar.
