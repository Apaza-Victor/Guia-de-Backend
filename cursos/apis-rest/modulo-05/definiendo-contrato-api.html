Definiendo el contrato de la API

⚙️ Intermedio 11 min APIs REST Módulo 5 · Documentación

Estructura de tu openapi.yaml

paths: las rutas y sus verbos

schemas: las piezas de representación

  • Reutiliza: define una vez, refiere con $ref mil veces.
  • Declara required: tu validación «de verdad» y tu spec deben bailar la misma danza.

Respuestas y errores documentados

Spec-first vs code-first

  • Spec-first: escribes YAML; el código se adapta. Perfecto para equipos frontend/backend/laterales.
  • Code-first: el código genera spec (anotaciones, decorators). Rápido pero puedes «olvidar» documentar.
  • La disciplina es más importante que la dirección: un spec desactualizado es basura.

Ejercicio

  1. Creación tu primer openapi.yaml con un path CRUD completo.
  2. Define los schemas Producto y ProductoInput con required.
  3. Documenta la respuesta de error 422 usando components.

Resumen

  • openapi + info + servers + paths + components.
  • Spec = contrato vivo entre máquinas y humanos.
  • $ref + required + schemas reutilizables + errores estándar.
