¿Qué es OpenAPI?

⚙️ Intermedio 10 min APIs REST Módulo 5 · Documentación

Una especificación, no una herramienta

OpenAPI (antes Swagger Spec) es el estándar de facto para describir APIs REST: un documento YAML o JSON que declara endpoints, métodos, parámetros, respuestas, schemas y seguridad. Nace de Swagger (2010) y hoy lo mantiene la OpenAPI Initiative.

  • Autodescriptiva: el documento es la API, leíble por humanos y por máquinas.
  • Contrato ejecutable: de él se generan clientes, mocks, validaciones y docs.
  • Define TodoMenos el negocio: forma y comportamiento del protocolo.

Del spec a tu día a día

Todo un ecosistema gira en torno al mismo documento: un solo cambio de spec se replica a clientes, mocks y docs.

Un documento mínimo

La familia que debes conocer

  • OpenAPI Spec (v3.x): el contrato.
  • Swagger: marca histórica y toolkit (UI, Editor, Codegen).
  • Json Schema: base de los schemas de OpenAPI (v3).
  • Plantearse: generar de la spec o código → spec (annotations en Node/Python/Java).

¿Por qué merece la pena?

  • Onboarding 10x: alguien nuevo «lee» tu API en minutos.
  • Contrato para equipos paralelos: el frontend escribe contra el spec, no contra el servidor.
  • Testing y compliance: valida tu respuesta contra el spec en CI.
  • SDKs y mocks sin escribir una línea.

Ejercicio

  1. Abre el spec de una API pública (p. ej. petstore.swagger.io) en tu editor.
  2. Identifica info, paths y components.
  3. Escribe en papel un spec mínimo de tu recurso favorito.

Resumen

  • OpenAPI = estándar para describir APIs REST en YAML/JSON.
  • Contrato ejecutable: clientes, mocks, docs y tests del mismo archivo.
  • info + paths + components: las tres columnas del spec.
