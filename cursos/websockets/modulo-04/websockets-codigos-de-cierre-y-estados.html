Códigos de cierre y estados

🔥 Avanzado 10 min WebSockets y Tiempo Real Módulo 4 · Protocolo WebSocket en profundidad

Introducción

Cerrar un socket no es simplemente cortar el cable. El protocolo define códigos de cierre que explican por qué acabó la conexión: cierre normal, el servidor se va, política violada o tamaño excesivo.

En un backend bien diseñado el cierre transmite información: el cliente decide si reintenta, muestra un mensaje o se rinde según el código recibido.

Definición

Los códigos de cierre son números del frame de close (opcode 0x8) que describen la razón de terminación de la conexión.

Por qué importa. El código estandariza la señal de muerte para que el cliente reaccione correctamente y evites reconexiones infinitas ante errores que no tienen cura.

Cuándo usarlo. Usa 1000 para cierres normales, 1001 cuando el servidor se reinicia, 1008 por violación de política y 1009 por exceso de tamaño.

Conceptos clave

  • El close frame viaja con un código de 16 bits y un motivo opcional.
  • 1000 es el cierre normal; 1001 indica que el servidor se va.
  • 1008 rechaza mensajes que violan la política de la aplicación.
  • 1009 marca mensajes demasiado grandes para el servidor.
  • El cliente debe leer el código antes de decidir si reconecta.

Ejemplo intermedio

Cuando un mensaje supera el límite acordado, el cierre con 1009 comunica la causa al cliente.

Ejemplo real

En producción cada código debe mapearse a una reacción del cliente: reintentar, avisar o rendirse.

  • Asocia 1001 a un reintento y 1008 a un aviso sin reintento.
  • Envía un motivo legible para que la interfaz pueda mostrarlo.
  • Reserva close() con código para cierres programados; deja terminate() solo para emergencias.

Los códigos 1000 a 2999 están definidos por el protocolo; usa solo 3000 a 3999 para necesidades propias.

Explicación

  • El frame de close inicia un handshake de cierre: ambas partes se saludan antes de destruir la conexión.
  • Un close con 1000 y motivo permite al cliente distinguir un corte limpio de una caída.
  • Si el servidor muere sin enviar el frame, el cliente ve una caída de red y el código queda como 1006.
  • terminate() salta el protocolo de cierre y destruye la conexión de forma abrupta.
  • Los códigos 1002 y 1003 describen errores de protocolo y datos no soportados, útiles para depurar clientes rotos.

Errores comunes

  • Usar 1000 para cierres que realmente son errores de política.
  • Reintentar sin leer el código provoca bucles de reconexión.
  • Abusar de terminate() y perder la causa del corte.

Buenas prácticas

  • Define constantes con nombres para los códigos que uses.
  • Registra el motivo de cada cierre para analizar patrones de caída.
  • En el cliente, distingue el cierre programado de la caída real.
  • Documenta tus códigos de cierre junto a la API del sistema.

Ejercicio

  1. Cierra un socket con 1008 y captura el código desde el cliente.
  2. Envía un mensaje de 2 KB con un límite de 1 KB y observa el cierre.
  3. Registra en el cliente la decisión de reintentar según el código.

Resumen

  • El cierre transporta un código y un motivo legible.
  • Cada código guía la respuesta del cliente: reintentar o rendirse.
  • terminate() rompe el protocolo; close() transmite intención.
