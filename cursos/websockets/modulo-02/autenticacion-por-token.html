Autenticación por token

🔥 Avanzado 10 min WebSockets y Tiempo Real Módulo 2 · WebSockets en Node.js

Por qué autenticar sockets

Un servidor WebSocket sin autenticación es una puerta abierta: cualquiera puede conectarse, suscribirse a canales privados, leer notificaciones ajenas o impersonar a otro usuario. El handshake ocurre por HTTP, así que puedes reutilizar la misma estrategia de autenticación que tu API REST: un token JWT.

La clave es entender cuándo validar: no en cada mensaje, sino una sola vez, en el instante del handshake. Si el token no es válido, rechazas el Upgrade y el cliente jamás llega al estado OPEN.

Extraer el token del handshake

En el evento connection del paquete ws tienes a mano el objeto request del handshake HTTP. De ahí puedes leer el token de dos sitios:

  • Una cabecera propia, p. ej. Authorization: Bearer <token> (más seguro, no viaja visible en la URL).
  • Un parámetro en la URL, p. ej. ws://api/chat?token=xyz (más cómodo para algunos clientes, pero el token queda en los logs del proxy).
const http = require('http');
const { WebSocketServer } = require('ws');

const server = http.createServer(...);
const wss = new WebSocketServer({ server });

wss.on('connection', (ws, req) => {
  const cabecera = req.headers['authorization'] || '';
  const token = cabecera.startsWith('Bearer ')
    ? cabecera.slice('Bearer '.length)
    : null;

  const url = new URL(req.url, 'http://localhost');
  const tokenEnUrl = url.searchParams.get('token');

  autenticar(token || tokenEnUrl, ws); // decidir si aceptar o cerrar
});

Validar el JWT en el servidor

Un JWT firmado garantiza que solo tu servidor pudo emitirlo. Para validarlo usas la clave que lo firmó (secreto HMAC o clave pública asimétrica) y compruebas además la expiración (exp). El paquete jsonwebtoken hace todo el trabajo:

const jwt = require('jsonwebtoken');

const SECRETO = process.env.JWT_SECRETO; // nunca en el código

function autenticar(token, ws) {
  try {
    const payload = jwt.verify(token, SECRETO, { algorithms: ['HS256'] });
    // Guardar el usuario autenticado sobre el socket para usarlo
    // en cada evento posterior.
    ws.usuario = { id: payload.sub, rol: payload.rol };
    ws.send(JSON.stringify({ tipo: 'autenticado', usuario: ws.usuario }));
    console.log('Conectado:', payload.sub);
  } catch (err) {
    // Token inválido o expirado: rechazar sin vueltas.
    ws.close(4001, 'Token inválido o expirado');
  }
}

Recuerda fijar la lista de algoritmos (algorithms: ['HS256']): aceptar algoritmos por defecto permite a un atacante firmar tokens con none y saltarse la firma.

El middleware de autenticación

Cuando el handshake pase por un proxy (nginx, load balancer) o tengas varios puntos de conexión, conviene centralizar la autenticación en un middleware: una función que se ejecuta para cada conexión entrante, decide si la acepta o la cierra, y deja el resultado a disposición del resto del código.

function crearMiddlewareAutenticacion(secreto) {
  return (ws, req, siguiente) => {
    const tokenExtraido = extraerTokenDe(req);

    if (!tokenExtraido) {
      ws.close(4001, 'Falta el token');
      return;
    }
    try {
      ws.usuario = jwt.verify(tokenExtraido, secreto);
      siguiente(); // continuar: registrar salas, enviar bienvenida, etc.
    } catch {
      ws.close(4001, 'Token inválido o expirado');
    }
  };
}

// Aplicarlo en cada `connection`:
const requerirToken = crearMiddlewareAutenticacion(process.env.JWT_SECRETO);

wss.on('connection', (ws, req) => {
  requerirToken(ws, req, () => {
    console.log('Usuario', ws.usuario.sub, 'autenticado');
    // aquí, negocio: unirse a sus salas, cargar su estado, etc.
  });
});

Enviar el token desde el cliente

En el navegador, la API WebSocket nativa no permite cabeceras personalizadas en el handshake. La solución práctica es pasar el token en la URL del socket. (Si usas Socket.IO, la opción auth permite enviarlo sin exponerlo en la URL).

// Cliente del navegador: el token viaja como query del handshake.
const token = localStorage.getItem('jwt');
const socket = new WebSocket(
  'wss://api.miservidor.com/chat?token=' + encodeURIComponent(token)
);

socket.onopen = () => console.log('Conectado y autenticado');
socket.onclose = (e) => {
  if (e.code === 4001) {
    // Token invalidado: pedir login de nuevo.
    cerrarSesion();
  }
};

Recomendación de seguridad: si el token puede viajar en la URL de un handshake, evita registrarlo en los logs (configura nginx para que no escriba la query y redirige logs sensibles). Siempre que puedas, prefiere cabeceras con clientes que las soporten, o la opción auth de Socket.IO.

Ejercicio

  1. Crea un par de tokens de prueba con jsonwebtoken: uno firmado correctamente y otro con un secreto distinto.
  2. Conecta un cliente a tu servidor enviando el token en la URL; verifica el mensaje autenticado.
  3. Prueba el token inválido y comprueba que el servidor cierra con el código 4001. Anota qué ve el cliente al cerrar sesión.

Resumen

  • Autentica en el handshake, una sola vez, no por mensaje.
  • El token se extrae de una cabecera Bearer o de la query de la URL.
  • Valida el JWT con firma y algoritmo fijos, y rechaza tokens inválidos con un código propio (4001).
  • Un middleware centraliza la decisión y deja ws.usuario disponible para el negocio.
  • En el navegador el token va en la URL; con Socket.IO usa auth.
