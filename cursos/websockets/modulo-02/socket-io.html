Socket.IO

🔥 Avanzado 10 min WebSockets y Tiempo Real Módulo 2 · WebSockets en Node.js

¿Qué es Socket.IO?

Socket.IO es una librería (servidor en Node + cliente en el navegador) que se apoya en WebSocket y le añade capas de valor: un mensaje de eventos con nombres y datos, salas y broadcast nativos, reconexión automática con backoff y una caída automática a long-polling cuando el WebSocket no puede atravesar un proxy o firewall.

No es WebSocket «con esteroides» para todo: añade overhead (salas, heartbeats propios, acuses) y limita el rendimiento puro respecto a ws. Para aplicaciones de chat y notificaciones es la opción más productiva; para streaming de máxima velocidad a millones de sockets, el protocolo puro gana.

ws vs Socket.IO frente a frente

  • Nivel de abstracción: ws expone el protocolo tal cual (mensajes de texto/binario). Socket.IO organiza eventos nombrados con payload estructurado.
  • Reconexión: en ws escribe tú la lógica; Socket.IO la trae por defecto con espera exponencial.
  • Salas: en ws las construyes con mapas; Socket.IO trae join/leave.
  • Transporte: Socket.IO intenta WebSocket y degrada a HTTP long-polling; ws solo WebSocket.
  • Rendimiento: ws es más ligero; el bit de estado y el framework extra de Socket.IO tienen coste.

Emitir y escuchar eventos

El modelo de Socket.IO es el pub/sub discreto: el servidor emite eventos con nombre y el cliente los escucha (y al revés). El primer parámetro siempre es el nombre del evento y el segundo los datos.

// Servidor (Node.js + Socket.IO)
const { Server } = require('socket.io');
const io = new Server(3000, { cors: { origin: '*' } });

io.on('connection', (socket) => {
  console.log('Cliente conectado:', socket.id);

  // Escuchar un evento enviado por el cliente.
  socket.on('mensaje', (payload) => {
    console.log(payload.de, '-', payload.texto);
    // Devolver respuesta (emit general) o acusar recibo (emit a uno).
    socket.emit('recibido', { ok: true, cuando: Date.now() });
  });

  // Avisar a todos menos al emisor.
  socket.broadcast.emit('usuario-conectado', { id: socket.id });
});

El cliente del navegador usa exactamente la misma API de eventos con la contrapartida socket.on(...) / socket.emit(...), lo que elimina la tediosa tarea de parsear y enrutar JSON a mano.

Rooms con Socket.IO

Las salas son ciudadanos de primera clase. El método join añade un socket a una sala, leave lo quita, y io.to(nombre).emit(...) envía a todos sus miembros. Todo el mantenimiento (borrar salas vacías, limpiar sockets muertos) está resuelto.

io.on('connection', (socket) => {
  socket.on('entrar-a-partida', ({ partidaId, nombre }) => {
    // Un socket puede estar en varias salas a la vez.
    socket.join('partida:' + partidaId);
    socket.data.nombre = nombre;

    // Avisar al resto de jugadores.
    io.to('partida:' + partidaId).emit('jugador-ue', {
      nombre,
      enPartida: io.sockets.adapter.rooms.get('partida:' + partidaId)?.size
    });
  });

  socket.on('cambiar-ficha', (dato) => {
    // Broadcast solo a la sala de la partida actual.
    io.to('partida:' + dato.partidaId).emit('tablero', dato);
  });
});

Reconexión y gestión de estado

Socket.IO reconecta solo: cuando pierde la conexión, espera un backoff exponencial (50 ms → 100 ms → 200 ms …) con un tope configurable y reintenta. El evento disconnect te permite saber que el cliente se fue, y reconnect/connect te dicen cuándo vuelve.

// Servidor: librar estado entre desconexión y reconexión.
io.on('connection', (socket) => {
  socket.on('disconnect', (razon) => {
    console.log(`${socket.id} se fue (${razon})`);
    io.emit('presencia', { online: io.engine.clientsCount });
  });

  socket.on('alerta', () => {
    // Bandera para controlar reintentos del cliente.
    socket.emit('reintenta', { maximo: 5, esperaInicialMs: 500 });
  });
});
// Cliente: la reconexión es automática.
const socket = io('https://api.miservidor.com', {
  reconnectionDelay: 500,
  reconnectionDelayMax: 4000,
  timeout: 10000
});

socket.on('connect', () => console.log('Conectado, id', socket.id));
socket.on('disconnect', (razon) => console.log('Cayó:', razon));
socket.on('viaje', (dato) => console.log('Estado del viaje:', dato.estado));

Ejercicio

  1. Instala socket.io y el cliente, y monta un servidor que emita un evento tick cada segundo con Date.now().
  2. Crea una sala «partida:1» y conecta dos clientes; verifica que cambiar una ficha solo llega a esa sala.
  3. Apaga el servidor con el cliente abierto y observa los intentos de reconexión en la consola; vuelve a encenderlo y comprueba que retoma la comunicación.

Resumen

  • Socket.IO es WebSocket + conveniencia: eventos nombrados, salas, reconexión automática y fallback a polling.
  • ws es el protocolo puro y más ligero; Socket.IO aporta abstracción y resiliencia a costa de overhead.
  • Emitir/escuchar eventos (emit/on) elimina el enrutamiento manual de JSON.
  • Rooms con join, leave y io.to(sala).emit.
  • La reconexión automática con backoff la gestiona la librería, no tú.
