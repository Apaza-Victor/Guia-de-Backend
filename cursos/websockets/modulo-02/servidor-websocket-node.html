Servidor WebSocket con Node

🔥 Avanzado 10 min WebSockets y Tiempo Real Módulo 2 · WebSockets en Node.js

Elegir la librería correcta

Node.js no trae WebSocket en el núcleo: hay que instalar una librería que implemente el protocolo sobre sus sockets TCP. Las dos opciones que debes conocer son:

  • ws: la implementación de referencia de JavaScript, ligera, mantenida por la comunidad de Node y usada como base por miles de proyectos. Ideal para la mayoría de los casos.
  • uWebSockets.js: implementados en C++ sobre libuv y el loop de eventos de uNetworking. Extremadamente rápidos y con menor uso de memoria, buenos para servidores con millones de conexiones.

En este curso trabajamos con ws por su simplicidad y porque la API que expone es la más parecida a la del navegador, lo que facilita el salto entre cliente y servidor.

# Crear un proyecto y instalar el paquete ws
mkdir servidor-chat
cd servidor-chat
npm init -y
npm install ws

# Alternativa de alto rendimiento si la necesitas:
# npm install uwebsockets.js

El servidor mínimo con ws

Con veinte líneas tienes un servidor que acepta conexiones, saluda a cada cliente y responde cualquier mensaje que reciba:

const { WebSocketServer } = require('ws');

const wss = new WebSocketServer({ port: 8080 });

wss.on('connection', (ws, req) => {
  console.log('Nuevo cliente conectado desde', req.socket.remoteAddress);

  // Saludar en cuanto se abre la conexión.
  ws.send(JSON.stringify({ tipo: 'bienvenida', texto: '¡Conectado!' }));

  // Contestar cada mensaje que llegue del cliente.
  ws.on('message', (datos) => {
    const payload = JSON.parse(datos.toString());
    console.log('Recibido:', payload.tipo);
    ws.send(JSON.stringify({ tipo: 'eco', de: payload }));
  });

  ws.on('close', () => console.log('Cliente desconectado'));
});

console.log('Servidor WebSocket escuchando en ws://localhost:8080');

Observa que connection se emite por cada cliente recién conectado (después del handshake), y que el objeto ws que recibes representa UNA conexión concreta: es tu unidad de comunicación con ese cliente.

Los eventos del servidor

La API de ws en el servidor replica la del navegador pero con nombres de eventos Node nativos:

  • connection — se dispara tras el handshake exitoso con un nuevo peer.
  • message — llegan datos del cliente; en ws vienen como Buffer o string según la opción binaryType.
  • error — problema con la conexión o el protocolo.
  • close — la conexión se cerró; aquí limpias estado de memoria (quitarlo de salas, marcar presencia, etc.).
wss.on('connection', (ws) => {
  // Convertir automáticamente los mensajes entrantes a texto.
  ws.binaryType = 'text';

  ws.on('message', (mensaje) => {
    // No asumas que es JSON: valida antes de parsear.
    try {
      const datos = JSON.parse(String(mensaje));
      manejarEvento(ws, datos);
    } catch {
      ws.send(JSON.stringify({ tipo: 'error', razon: 'JSON inválido' }));
    }
  });

  ws.on('error', (err) => console.error('Error del socket:', err.message));
  ws.on('close', () => limpiarEstadoDe(ws));
});

Compartir puerto con HTTP

En producción casi siempre tendrás HTTP (tu API REST) y WebSocket en el mismo puerto expuesto al exterior. Con ws puedes adjuntar el servidor de sockets a un servidor HTTP existente: cuando llega un handshake Upgrade, ws se encarga; el resto lo atiende Express o tu enrutador.

const http = require('http');
const { WebSocketServer } = require('ws');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('Hola desde HTTP. Los sockets viven en la misma puerta.');
});

const wss = new WebSocketServer({ server, path: '/ws' });

wss.on('connection', (ws) => {
  ws.send('Conectado por la ruta /ws del mismo puerto.');
});

server.listen(3000, () => console.log('HTTP + WebSocket en :3000'));

Al fijar path: '/ws' solo responderás handshakes a esa ruta; cualquier otra ruta queda para HTTP. Esto te permite servir la API, la página y los sockets desde un único proceso y facilita el despliegue tras nginx (lo verás en el módulo 3).

Probar el servidor sin navegador

Para depurar rápido usa wscat, el cliente de consola del mismo ecosistema de ws: te conectas, envías texto y ves lo que responde el servidor.

# Instalar y usar el cliente CLI de ws
npm install -g wscat

# Conectar con el servidor de la lección
wscat -c ws://localhost:8080
# > {"tipo":"saludo","nombre":"ana"}
# < {"tipo":"eco","de":{"tipo":"saludo","nombre":"ana"}}

Ejercicio

  1. Instala ws, crea el servidor mínimo de la lección y arranca con node server.js.
  2. Conecta con wscat y envíale un mensaje JSON; comprueba que el eco llega intacto.
  3. Modifica el servidor para que envíe un mensaje de «despedida» antes de cerrar; usa ws.close(1000) y observa el cierre limpio en el cliente.

Resumen

  • Node.js necesita una librería para WebSocket: ws es la referencia y uWebSockets.js la opción de máximo rendimiento.
  • Con WebSocketServer y dos eventos (connection y message) tienes un servidor funcional.
  • Cada objeto ws es una conexión individual que puedes enviar y escuchar.
  • Puedes montar HTTP y WebSocket sobre el mismo puerto adjuntando ws a un servidor HTTP.
  • wscat te permite probar sin escribir código de cliente.
