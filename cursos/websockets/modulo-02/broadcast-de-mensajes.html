Broadcast y salas

🔥 Avanzado 10 min WebSockets y Tiempo Real Módulo 2 · WebSockets en Node.js

Enviar a un cliente

Lo más básico es el envío a un cliente concreto: el mensaje va solo por el socket de ese peer. En la práctica necesitas un registro que relacione cada conexión con un identificador del usuario (el id de sesión o de usuario autenticado).

const { WebSocketServer } = require('ws');
const wss = new WebSocketServer({ port: 8080 });

// registro: 'usuario-42' -> ws de su conexión actual.
const clientes = new Map();

wss.on('connection', (ws, req) => {
  const usuarioId = obtenerUsuarioDelRequest(req); // por token, por ejemplo
  clientes.set(usuarioId, ws);
  console.log(`[+online] ${usuarioId} · conectados: ${clientes.size}`);

  ws.on('close', () => clientes.delete(usuarioId));
});

function enviarA(usuarioId, tipo, datos) {
  const ws = clientes.get(usuarioId);
  if (!ws || ws.readyState !== ws.OPEN) return false;
  ws.send(JSON.stringify({ tipo, datos }));
  return true;
}

// Uso: cuando un pedido cambia de estado, avisar solo a su dueño.
enviarA('usuario-42', 'estado-pedido', { id: 'PED-2041', estado: 'en-camino' });

Broadcast: a todos a la vez

El broadcast envía el mismo mensaje a todos los clientes conectados. Con ws se consigue recorriendo wss.clients: un set de todas las conexiones vivas. Debes filtrar siempre por el estado OPEN, porque el set puede contener sockets en pleno cierre.

function broadcast(wss, tipo, datos) {
  const marco = JSON.stringify({ tipo, datos });

  for (const cliente of wss.clients) {
    if (cliente.readyState === cliente.OPEN) {
      cliente.send(marco);
    }
  }
}

// Anuncio masivo: "el sistema vuelve en 5 minutos".
broadcast(wss, 'anuncio', { texto: 'Mantenimiento a las 03:00 UTC' });

Es el mecanismo perfecto para anuncios globales, contadores de conectados o un chat «de todo el mundo» sin salas.

Salas (rooms) con ws

Los chats reales no quieren transmitir todo a todos: quieren salas. Una sala es simplemente un grupo de conexiones asociadas a un nombre. Con ws no hay noción de sala integrada, así que construyes un mapa a mano: nombre de sala → Set de ws.

// Salas:  'sala:soporte' -> Set
const salas = new Map();

function unirseASala(ws, nombreSala) {
  if (!salas.has(nombreSala)) salas.set(nombreSala, new Set());
  salas.get(nombreSala).add(ws);
}

function salirDeSala(ws, nombreSala) {
  const miembros = salas.get(nombreSala);
  if (!miembros) return;
  miembros.delete(ws);
  if (miembros.size === 0) salas.delete(nombreSala);
}

function enviarASala(nombreSala, tipo, datos) {
  const miembros = salas.get(nombreSala);
  if (!miembros) return;
  const marco = JSON.stringify({ tipo, datos });
  for (const ws of miembros) {
    if (ws.readyState === ws.OPEN) ws.send(marco);
  }
}

// Unir a la sala "soporte" cuando llega el evento de suscripción.
wss.on('connection', (ws) => {
  ws.on('message', (datos) => {
    const { tipo, sala } = JSON.parse(String(datos));
    if (tipo === 'unirse') unirseASala(ws, sala);
    if (tipo === 'mensaje') enviarASala(sala, 'chat', { texto: leerTexto(datos) });
  });
});

Con poco código ya tienes la base de un chat por canales: cada cliente se une a la sala que le interesa y solo recibe los mensajes de esa sala.

Limpieza de salas al desconectar

Un error clásico es dejar sockets muertos dentro de los Sets de las salas: el cliente cayó, pero el Map sigue pensando que pertenece a la sala. La solución es limpiar en el evento close (y también en error, porque normalmente precede a un cierre).

function limpiarDeTodasLasSalas(ws) {
  for (const [nombre, miembros] of salas) {
    if (miembros.delete(ws) && miembros.size === 0) salas.delete(nombre);
  }
}

wss.on('connection', (ws) => {
  ws.on('close', () => limpiarDeTodasLasSalas(ws));
  ws.on('error', () => limpiarDeTodasLasSalas(ws));
});

Mantener las salas sincronizadas con las conexiones reales evita dos problemas: mensajes enviados a conexiones caídas que nadie lee, y fugas de memoria por Sets que crecen sin parar.

Salas en Socket.IO

Socket.IO incorpora salas nativas: un socket entra, sale y la librería gestiona el mapa y la limpieza por ti. La misma idea del módulo con menos código:

const { Server } = require('socket.io');
const io = new Server(3000);

io.on('connection', (socket) => {
  socket.on('unirse', (sala) => socket.join(sala));
  socket.on('salir', (sala) => socket.leave(sala));

  socket.on('mensaje-sala', (payload) => {
    // Emitir solo a los miembros de esa sala, reservando a quién lo envió.
    io.to(payload.sala).emit('chat', {
      sala: payload.sala,
      de: socket.id,
      texto: payload.texto
    });
  });
});

Ejercicio

  1. Con el servidor de la lección anterior, añade un broadcast que envíe «un usuario nuevo entró al chat» a todos los conectados.
  2. Crea dos salas («general» y «soporte») y verifica con dos clientes de wscat que un mensaje en «soporte» no llega a «general».
  3. Desconecta uno de los clientes y comprueba en el log que su socket desapareció de la sala (ausencia de fuga).

Resumen

  • El envío a un cliente usa su objeto WebSocket individual, con un registro usuario→socket.
  • El broadcast recorre wss.clients filtrando por estado OPEN.
  • Las salas son Mapas de nombre→Set de sockets; ws no las regala, las construyes tú.
  • Limpia los sockets en close y error para no llenar de muertos las salas.
  • Socket.IO trae salas nativas con join, leave y io.to(sala).emit.
