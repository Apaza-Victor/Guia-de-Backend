Cliente WebSocket en el navegador

🔥 Avanzado 8 min WebSockets y Tiempo Real Módulo 2 · WebSockets en Node.js

La API WebSocket del navegador

El navegador trae WebSocket de serie: no hace falta instalar nada. Con el constructor global new WebSocket(url, [protocolos]) inicia el handshake y a partir de ahí vives dentro de su ciclo de vida: onopen, onmessage, onerror y onclose.

  • send(datos) — envía texto, JSON string o binario (Blob/ArrayBuffer).
  • close(codigo, razon) — cierra la conexión de forma cortés.
  • binaryType — elige si los binarios llegan como Blob o ArrayBuffer.
  • readyState — el estado actual (0 a 3).
const socket = new WebSocket('wss://api.miservidor.com/sockets');

socket.onopen = () => {
  console.log('Conectado. Enviando datos…');
  socket.send(JSON.stringify({ tipo: 'iniciar-sesion', sala: 'general' }));
};

socket.onmessage = (evento) => {
  // evento.data es string (texto) o Blob/ArrayBuffer (binario).
  console.log('Recibido:', evento.data);
};

socket.onerror = (err) => console.warn('Error del socket', err);

socket.onclose = (evento) => console.log('Cerrado:', evento.code, evento.reason);

Enviar y analizar mensajes JSON

El protocolo transmite texto, no objetos. La disciplina diaria es: serializar al enviar (JSON.stringify) y parsear al recibir (JSON.parse), siempre protegiendo el parseo contra mensajes malformados, porque te puede escribir un cliente cualquiera.

function enviar(socket, tipo, datos) {
  const marco = JSON.stringify({ tipo, datos });
  if (socket.readyState === WebSocket.OPEN) socket.send(marco);
}

function recibir(evento) {
  try {
    const mensaje = JSON.parse(evento.data);
    rutearPorTipo(mensaje); // switch a mano por "tipo"
  } catch {
    console.warn('Mensaje que no era JSON:', evento.data);
  }
}

function rutearPorTipo(m) {
  switch (m.tipo) {
    case 'chat':
      pintarMensaje(m.datos);
      break;
    case 'presencia':
      pintarConectados(m.datos);
      break;
    case 'estado-pedido':
      actualizarPedido(m.datos);
      break;
    default:
      console.log('Tipo desconocido:', m.tipo);
  }
}

Este patrón de envelope ({tipo, datos}) es el mismo que verás detrás del modelo de eventos de Socket.IO y hace tu cliente fácil de ampliar: añadir un caso al switch y listo.

Reconexión manual con backoff

La API nativa no reconecta sola: cuando la conexión se cae, tienes que crearla otra vez. El esquema estándar es el backoff exponencial: espera corta al principio y esperas crecientes tras cada fallo, con un tope para no martillear al servidor.

let intento = 0;
const ESPERA_INICIAL_MS = 500;
const ESPERA_MAXIMA_MS = 15000;

function conectarConBackoff() {
  const socket = new WebSocket('wss://api.miservidor.com/sockets');

  socket.onopen = () => intento = 0; // salió bien, reiniciamos contador

  socket.onclose = (evento) => {
    if (!evento.wasClean) {
      const espera = Math.min(
        ESPERA_INICIAL_MS * Math.pow(2, intento),
        ESPERA_MAXIMA_MS
      );
      const jitter = espera * (0.5 + Math.random() * 0.5); // evitar avalanchas
      intento += 1;
      console.log(`Reconexión en ${Math.round(jitter)} ms (intento ${intento})`);
      setTimeout(conectarConBackoff, jitter);
    }
  };

  socket.onmessage = (evento) => recibir(evento);

  return socket;
}

const socket = conectarConBackoff();

El jitter (variación aleatoria) evita el «thundering herd»: si mil clientes caen a la vez y todos esperan 2 s exactos, vuelven a golpear juntos. Añadir un toque de aleatoriedad reparte los golpes.

Integrar con el estado de la app

Un cliente de calidad expone su estado para que la UI reaccione: botón deshabilitado mientras reconecta, cola de mensajes si hiciera falta, indicador de «en línea».

const estado = { conectado: false, reintentando: false };

const socket = new WebSocket('wss://api.miservidor.com/sockets');

socket.onopen = () => {
  estado.conectado = true;
  estado.reintentando = false;
  actualizarBarraDeEstado();
};

socket.onclose = () => {
  estado.conectado = false;
  estado.reintentando = true;
  actualizarBarraDeEstado();
  programarReconexion();
};

function actualizarBarraDeEstado() {
  document.querySelector('#indicador').textContent =
    estado.reintentando ? 'Reconectando…' : (estado.conectado ? 'En línea' : 'Sin conexión');
}

Ejercicio

  1. Sirve tu servidor de la lección «Servidor WebSocket con Node» y ábrelo desde una página local con new WebSocket('ws://localhost:8080').
  2. Envía un mensaje {tipo:'mensaje', texto:'hola'} y pinta el eco recibido dentro de un elemento <div>.
  3. Implementa la reconexión con backoff y verifícala apagando y encendiendo el servidor: registra los tiempos de espera en consola.

Resumen

  • El navegador ofrece WebSocket con new WebSocket(url) y cuatro eventos: open, message, error, close.
  • Envía con send y parsea event.data para leer mensajes.
  • Serializa JSON al salir y valida al entrar: nunca asumas que el otro lado manda JSON válido.
  • La reconexión manual se escribe con backoff exponencial + jitter.
  • El estado de la conexión debe reflejarse en la UI y reiniciar el contador al reconectar con éxito.
