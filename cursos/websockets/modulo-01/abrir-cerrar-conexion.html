Abrir y cerrar la conexión

🔥 Avanzado 7 min WebSockets y Tiempo Real Módulo 1 · Fundamentos de WebSocket

Los eventos open, error y close

La API WebSocket del navegador gira alrededor de cuatro eventos que describen toda la vida de la conexión: onopen, onmessage, onerror y onclose. Esta lección se centra en los tres puntos de transición: cuando se abre, cuando algo falla y cuando se cierra.

  • open: el handshake terminó bien y ya se puede enviar y recibir.
  • error: algo salió mal en el transporte o en el protocolo. Ojo: los errores suelen ir seguidos de un cierre.
  • close: la conexión terminó, con un código y una razón que explican por qué.
const socket = new WebSocket('wss://api.miservidor.com/sockets');

socket.onopen = () => {
  console.log('Sockets: listos para hablar.');
  socket.send(JSON.stringify({ tipo: 'hola', usuario: 'ana' }));
};

socket.onerror = (err) => {
  // El evento no trae la causa exacta; el cierre posterior sí suele
  // explicar mejor qué pasó (y el motivo en el navegador, en console).
  console.warn('Sockets: error en la conexión.', err.message);
};

socket.onclose = (evento) => {
  console.log('Socket cerrado. Código:', evento.code, 'Razón:', evento.reason);
  if (evento.code !== 1000) {
    programarReconexion();
  }
};

Códigos de cierre

El estándar define una lista de códigos numéricos que acompañan al frame de cierre. Conocer los principales te ahorra horas de depuración:

  • 1000 Normal Closure — cierre a propósito, sin errores.
  • 1001 Going Away — el servidor se reinicia o la página se va (el servidor se tomó un descanso).
  • 1002 Protocol Error — bytes que no seguían las reglas del RFC.
  • 1008 Policy Violation — el servidor rechazó el mensaje por política (por ejemplo, contenido no permitido).
  • 1009 Message Too Big — intento de enviar un mensaje mayor que el límite configurado.
  • 1011 Internal Error — el servidor falló internamente y no puede seguir.
  • 4000-4999 — reservados para usos de aplicación específicos.
{
  "code": 1011,
  "reason": "Error interno al procesar el mensaje",
  "socketId": "ws_9f2c1a",
  "reconnectable": true
}

Cerrar la conexión correctamente

Cerrar es tan importante como abrir. Un WebSocket mal cerrado deja recursos colgados en el servidor y conexiones a medio limpiar. La forma educada es enviar un frame de cierre con un código y una razón, esperar a que el otro lado lo confirme, y solo entonces liberar.

En el navegador usas socket.close(). En el servidor (Node.js) con el paquete ws, el cierre se hace con ws.close(codigo, razon) y se puede escuchar el evento close para limpiar la memoria.

// Cliente: cerrar con código y motivo.
function salirDelChat() {
  socket.close(1000, 'sesión finalizada por el usuario');
}

// Servidor (Node.js + ws): evitar que el cliente entre dos veces.
const { WebSocketServer } = require('ws');
const wss = new WebSocketServer({ port: 8080, clientTracking: true });

wss.on('connection', (ws, req) => {
  ws.send('Bienvenido. Serás avisado si la sala se cierra.');

  ws.on('close', (code, reason) => {
    console.log('Cliente desconectado. Código:', code, 'Razón:', reason.toString());
  });

  // Cerramos la sala cuando llega la orden de shutdown.
  if (procesoApagandoServidor) {
    ws.close(1001, 'Servidor entrando en mantenimiento');
  }
});

Escenarios de error comunes

En la práctica, la mayoría de cierres inesperados caen en pocas categorías:

  • Batería o pestaña dormida: el navegador pausa timers y el socket muere de silencio en servidores que exigen heartbeat.
  • Red inestable: se rompe el TCP por debajo y el cierre llega con código 1006, que significa «desconexión anómala» (no hubo frame de cierre).
  • Reinicio del servidor: el despliegue tira las conexiones; suele aparecer 1001 o 1006 y debe disparar reconexión con backoff.
  • Mensajes demasiado grandes: el peer corta con 1009, pide que ajustes el límite (p. ej. con el paquete ws se configura maxPayload).

Regla de oro: el evento onclose es el único sitio donde debes decidir si reconectar. Aceptando el code decides: códigos 1000 y 1001 suelen ser intencionales; 1006 y 1011 casi siempre merecen reintentar.

Ejercicio

  1. Abre la consola y crea un socket contra wss://echo.websocket.events; define onopen, onerror y onclose y registra el código en cada cierre.
  2. Llama a socket.close(4001, 'cerrado por el ejercicio') y comprueba qué código recibe el onclose.
  3. Escribe una decisión: ¿qué haría tu cliente si recibe un cierre con código 1006 por tercera vez en un minuto? Justifícala en dos frases.

Resumen

  • El ciclo de vida se controla con los eventos open, message, error y close.
  • Los errores suelen encadenarse con un cierre; el código de cierre explica la causa.
  • Códigos clave: 1000 normal, 1001 reinicio, 1008 política, 1009 excesivo, 1011 error interno, 1006 desconexión anómala.
  • Cerrar bien libera recursos del servidor; onclose decide si reconectar.
