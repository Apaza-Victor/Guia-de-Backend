Estados de la conexión

🔥 Avanzado 7 min WebSockets y Tiempo Real Módulo 1 · Fundamentos de WebSocket

Una máquina de estados en cuatro casillas

Un WebSocket nunca está «a medias»: siempre está exactamente en uno de los cuatro estados que define la especificación. La propiedad que los expone se llama readyState y lees su valor en cualquier instante, tanto desde el cliente del navegador como desde algunos clientes en Node.js (el paquete ws también la implementa).

ConstanteValorSignificado
CONNECTING0Aún no llega la respuesta 101; el handshake está en curso.
OPEN1Conexión activa; se puede enviar y recibir.
CLOSING2Se envió el cierre y se espera confirmación.
CLOSED3Conexión terminada; no se puede reutilizar.

Leyendo readyState

Saber en qué estado está tu socket es la diferencia entre un send() que funciona y otro que lanza «call on closed WebSocket». El patrón típico es comprobar antes de actuar:

function enviarSiEstaListo(socket, datos) {
  // 1 = OPEN. Cualquier otro estado no admite envíos.
  if (socket.readyState !== WebSocket.OPEN) {
    console.warn('Socket no abierto. Estado:', socket.readyState);
    return false;
  }
  socket.send(JSON.stringify(datos));
  return true;
}

const socket = new WebSocket('wss://api.miservidor.com/sockets');
console.log('Acaba de crearse. Estado:', socket.readyState); // 0 CONNECTING

socket.onopen = () => {
  console.log('Conectado. Estado:', socket.readyState); // 1 OPEN
  enviarSiEstaListo(socket, { tipo: 'ping', marcaTiempo: Date.now() });
};

El viaje completo: CONNECTING → OPEN → CLOSING → CLOSED

La máquina de estados describe un viaje que casi nunca salta casillas en el orden lógico:

  1. CONNECTING: el objeto WebSocket se crea, se abre el TCP y se negocia el handshake. En clientes abiertos está muy poco tiempo.
  2. OPEN: el estado productivo. Todos los mensajes viajan aquí. Si el servidor cierra, el cliente verá onclose y pasará directo a CLOSED.
  3. CLOSING: el cliente llamó a close() o recibió un frame de cierre, y está a la espera de la confirmación del otro lado.
  4. CLOSED: el frame de cierre se confirmó (o se superó el timeout, o murió el TCP). El socket es inservible: solo queda crear uno nuevo.

Detalle de implementación: si un socket se cierra por un error de red sin negociación, el navegador salta casi directamente de OPEN a CLOSED con código 1006 en onclose. No esperes ver CLOSING en ese caso: CLOSING describe un cierre cortés, no un corte en la red.

Reflejar el estado en la interfaz

Una buena práctica de producto es reflejar el estado de la conexión en la UI: «conectado», «reconectando…», «sin conexión». Para eso conviene una función auxiliar que traduzca el numérico a una etiqueta y a un estilo:

function etiquetaDeEstado(socket) {
  const estados = ['Conectando…', 'Conectado', 'Cerrando…', 'Desconectado'];
  return estados[socket.readyState] || 'Desconocido';
}

function actualizarEstadoEnPantalla(socket, indicador) {
  const etiqueta = etiquetaDeEstado(socket);
  indicador.textContent = etiqueta;
  indicador.dataset.estado = String(socket.readyState);
  console.log('Estado del socket:', etiqueta);
}

// Uso: llama a la función en cada transición.
socket.addEventListener('open', () => actualizarEstadoEnPantalla(socket, led));
socket.addEventListener('close', () => actualizarEstadoEnPantalla(socket, led));

Errores típicos de estado

  • «WebSocket is closed before the connection is established»: cerraste el socket mientras estaba CONNECTING.
  • «The WebSocket connection to «wss://...» failed»: el handshake fue rechazado (auth, origen o servidor caído) y el estado cayó a CLOSED.
  • Enviar desde fuera de OPEN: el send() lanza excepción; siempre guarda tus send detrás del check readyState === WebSocket.OPEN.

Ejercicio

  1. Crea un socket y usa un setInterval para imprimir socket.readyState cada 300 ms desde el momento de crear el objeto.
  2. Marca con un comentario qué número ves antes del onopen y qué número después.
  3. Escribe una función enviarConEstado que devuelva false sin lanzar excepción cuando el socket no esté en OPEN.

Resumen

  • WebSocket tiene cuatro estados: CONNECTING (0), OPEN (1), CLOSING (2) y CLOSED (3).
  • readyState lee el estado actual en cualquier momento.
  • Solo se puede send() cuando el estado es OPEN.
  • CLOSING es un cierre cortés; un corte de red salta a CLOSED con 1006.
  • Refleja el estado en la UI para que los usuarios entiendan si están conectados.
