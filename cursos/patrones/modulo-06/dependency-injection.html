Dependency Injection

🔥 Avanzado 10 min Patrones de Diseño Módulo 6 · Modernos

Introducción

La Dependency Injection es simple: una clase recibe sus dependencias por fuera en lugar de crearlas o buscarlas. No es magia de frameworks: es el DIP de SOLID llevado a la práctica. La única aplicación hace la «composición» en un solo lugar: el composition root.

Sin inyección: buscar y construir

Cada método reconstruye dependencias; imposible probar sin base de datos y SMTP reales.

Con inyección: recibir y usar

La clase pide interfaces, no concretos: depende de contratos.

El composition root: dónde se une todo

Los frameworks automatizan esto con un contenedor de DI: registras interface → concreto una vez y el contenedor inyecta en todo el árbol.

La recompensa: testear sin mundo real

Las claves para no fallar

  • Inyecta hacia interfaces: dependencias abstractas = sustituibles.
  • No uses el contenedor dentro del negocio: el «service locator» acopla de nuevo; solo el composition root consulta el contenedor.
  • No inyectes todo: primitivas y datos por parámetro, al momento.
  • No abuses del «inflado»: un constructor con 8 dependencias huele a clase con demasiadas responsabilidades.

Ejercicio

  1. Encuentra una clase que cree sus dependencias con new o `getInstance()`.
  2. Define las interfaces y mueve la creación al composition root.
  3. Escribe un test con fakes de las dependencias.

Resumen

  • DI: las dependencias se reciben, no se buscan.
  • Inyecta contratos (interfaces), no concretos.
  • La composición vive toda en el composition root.
  • Regalo directo: los tests usan fakes sin infraestructura.
