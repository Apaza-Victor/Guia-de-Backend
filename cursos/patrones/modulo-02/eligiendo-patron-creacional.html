Eligiendo el patrón creacional

🔥 Avanzado 9 min Patrones de Diseño Módulo 2 · Creacionales

Introducción

Singleton, Factory Method, Abstract Factory y Builder resuelven problemas distintos. Saber no aplicar un patrón es tan valioso como saber aplicarlo. Esta lección te da un árbol de decisión práctico para elegir el creacional correcto.

La tabla comparativa

Las 4 preguntas que importan

  1. ¿Cuántos productos intervienen? Más de uno → fábrica. Más de uno con coherencia → Abstract Factory.
  2. ¿La construcción necesita pasos? Sí, con invariantes por paso → Builder.
  3. ¿El estado es global y compartido? Sí y compartido con coherencia → Singleton, pero piensa dos veces si el contenedor de DI no lo basta.
  4. ¿Puedo construir con el constructor normal? Sí y es simple → no uses ningún patrón.

Ejemplos del backend real

  • Pagos por pasarela: Stripe / PayPal / MercadoPago → Factory Method (Interfaz Pasarela, una clase por proveedor).
  • Facturación por país: impuesto + formulario + formato por país → Abstract Factory.
  • Pedido complejo: items + envío + descuentos + estado → Builder.
  • Config global: si no hay contenedor de DI, Singleton es la salida pragmática; con contenedor, registra el servicio como singleton y listo.

La advertencia más importante

Si la simplicidad funciona, no escribas patrones. Un new Pago(...) directo es más legible que una fábrica con un solo caso. Los patrones creacionales existen para que el cambio futuro sea barato, no para lucir arquitectura. Empieza simple, cambia de patrón cuando el cambio duela.

Ejercicio

  1. Lista las creaciones de objetos de tu proyecto que dependan de condiciones.
  2. Clasifica cada una según la tabla (Singleton / FM / AF / Builder / ninguno).
  3. Elige UNA que hoy no tenga patrón y refactorízala.

Resumen

  • No patrón es una opción válida y muchas veces la mejor.
  • Un producto elegido por parámetro → Factory Method.
  • Familia con coherencia → Abstract Factory.
  • Construcción paso a paso con invariantes → Builder.
  • Una instancia global → Singleton, salvo que el contenedor de DI lo resuelva mejor.
