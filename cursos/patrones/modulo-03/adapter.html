Adapter

🔥 Avanzado 9 min Patrones de Diseño Módulo 3 · Estructurales

Introducción

El Adapter traduce la interfaz de un componente ajeno (SDK, biblioteca, API externa) a la que tu dominio realmente espera. Sin él, el SDK se filtra por todo el código; con él, el cambio de proveedor toca un único archivo.

El problema

Tu dominio habla un idioma: cargar(cuentaId): float. El SDK del banco habla otro: getBalanceByUserId(string): number. Si el negocio llama directo al SDK, quedas atrapado en sus nombres, tipos y versiones.

La solución: un puerto y un adaptador

El dominio pide SaldoProveedor; el mundo real le llega traducido.

El uso con inyección

Cuándo usarlo

  • Integras SDKs o librerías que no controlas (pagos, SMS, geolocalización, IA).
  • Quieres poder cambiar de proveedor sin reescribir el negocio.
  • Necesitas convertir formatos o tipos del mundo ajeno (string→float, snake→camel).

Es la misma idea de puertos y adaptadores del hexágono: esta lección es su versión en miniatura.

Ejercicio

  1. Elige una dependencia externa de tu proyecto (SDK de pago, API de mapas…).
  2. Define el puerto que tu dominio desearía tener.
  3. Escribe el adaptador que traduzca la llamada real al puerto.

Resumen

  • Adapter traduce la interfaz ajena a la tuya.
  • Privilegia puerto (interfaz) + adaptador (traducción).
  • Cambiar de proveedor toca un solo archivo.
  • En hexágono, este patrón vive en cada adaptador de puerto.
