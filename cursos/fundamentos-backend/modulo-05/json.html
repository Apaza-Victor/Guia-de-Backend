JSON

⚙️ Intermedio 10 min Fundamentos de Backend Módulo 5 · Formatos y Comunicación

¿Qué es JSON?

JSON (JavaScript Object Notation) es el formato de intercambio de datos más usado en APIs modernas. Nació de JavaScript pero es independiente del lenguaje: casi todos los backends lo generan y lo leen sin esfuerzo.

Un objeto JSON se encierra entre llaves, los pares van como "clave": valor y los valores pueden ser números, textos, booleanos, null, arrays u otros objetos.

Las reglas de sintaxis

  • Las claves siempre entre comillas dobles.
  • No admite comentarios ni comillas simples (al contrario que JavaScript).
  • Las comas separan pares y elementos; no debe haber coma final.
  • Los números no llevan comillas; true, false y null van en minúscula.

Por eso conviene usar un validador o construir JSON con la librería del lenguaje y nunca a mano, para evitar errores tontos de sintaxis.

JSON dentro de HTTP

El header Content-Type: application/json avisa al receptor de qué formato recibe, y el backend lo usa para decidir cómo parsear el body.

Por qué es el rey

LegibleFácil de leer y depurar en cualquier navegador o consola.
LigeroMenos verbose que XML; menor volumen en cada respuesta.
UniversalCualquier lenguaje tiene parser JSON integrado o de librería.
EstructuradoObjetos y arrays anidados sin límites complicados.

Ejercicio

  1. Escribe a mano un JSON que represente a una biblioteca con 2 libros (título, autor, páginas y disponible).
  2. Valida que no usas comas finales y que las claves llevan comillas dobles.
  3. En tu backend, crea un endpoint que devuelva Content-Type: application/json con ese listado.

Resumen

  • JSON es el formato estándar de intercambio de datos en APIs.
  • Sus reglas: claves con comillas dobles, sin comentarios y sin coma final.
  • Se transporta por HTTP con el header Content-Type: application/json.
  • Es legible, ligero, universal y estructurado.
