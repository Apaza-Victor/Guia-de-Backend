WebSockets

⚙️ Intermedio 10 min Fundamentos de Backend Módulo 5 · Formatos y Comunicación

¿Qué son los WebSockets?

WebSockets es un protocolo que abre una conexión bidireccional persistente entre cliente y servidor. A diferencia de HTTP (donde el servidor solo responde cuando el cliente pregunta), por un WebSocket ambos pueden enviar mensajes en cualquier momento.

El handshake y el protocolo

  • Empieza con un HTTP normal al Upgrade de websocket; si el servidor acepta, la conexión "mejora" a WebSocket (con esquema ws:// o wss://).
  • Después del upgrade, los mensajes viajan como frames de texto o binarios.
  • La conexión vive hasta que uno de los dos la cierra (crash, timeout o cierre explícito).
  • Al ser TCP, un proxy/load balancer debe configurarse para no cortar conexiones largas.

Cuándo convienen

PerfectoChat, notificaciones en vivo, colaboración (editores), juegos, streaming de eventos, precios de bolsa.
EvitarOperaciones puntuales request/response o datos que cambian poco: ahí HTTP sigue siendo más simple y escala mejor.

Para "lo que puede pasar en cualquier momento" hay que decidir por evento: usa WebSockets si necesitas baja latencia y envío servidor→cliente espontáneo.

Del lado del backend

Alternativas maduras: ws (Node), Socket.IO (experiencias en tiempo real), WebSockets de Django Channels, ASP.NET SignalR, o servicios gestionados en las nubes para escalar las conexiones.

Ejercicio

  1. Elige una app en tiempo real que conozcas (chat, dashboards, juegos) y describe qué datos fluye por el websocket.
  2. Abre la consola del navegador en esa web y encuentra dónde aparecen mensajes ws:// o wss:// en la pestaña Network.
  3. Propón qué datos deberías enviar SIEMPRE por HTTP en lugar de por websocket.

Resumen

  • WebSockets mantienen un canal bidireccional y persistente.
  • Comienzan con un upgrade HTTP y luego hablan por frames.
  • Ideales para chat, colaboración y eventos en vivo.
  • HTTP sigue siendo mejor para operaciones simples que escalan.
