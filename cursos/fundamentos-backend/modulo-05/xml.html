XML

⚙️ Intermedio 9 min Fundamentos de Backend Módulo 5 · Formatos y Comunicación

¿Qué es XML?

XML (eXtensible Markup Language) es un formato de datos con etiquetas de apertura y cierre, pensado para ser legible tanto por humanos como por máquinas. Fue el estándar dominante antes de JSON y sigue vivo en servicios SOAP, RSS, Sitemaps y configuraciones.

Sintaxis y reglas

  • Toda etiqueta debe cerrarse: <nombre>...</nombre> o autcerrarse <img/>.
  • Un documento tiene una sola raíz que engloba a todos los elementos.
  • Los atributos van en la etiqueta de apertura (id="42").
  • Es case-sensitive: <Nombre> y <nombre> son distintos.
  • El nombre de las etiquetas es extensible: tú defines la estructura.

XML vs JSON

XMLOrientado a documentos y esquemas (XSD). Verboso pero con validación fuerte, namespaces y herramientas maduras (SOAP/WS).
JSONOrientado a datos. Menos volumen, parsing nativo en JS y más natural para APIs REST modernas.

Regla práctica: para APIs nuevas, elige JSON. Usa XML cuando ya estás dentro de un ecosistema que lo exige (SOAP, bancos, integraciones legacy).

XML por HTTP

Cuando recibes XML nunca lo proceses con expresiones regulares: usa un parser XML del lenguaje para manejar bien codificación, entidades y anidamiento.

Ejercicio

  1. Convierte el JSON de la lección anterior a XML con la misma estructura.
  2. Valida que tu XML tiene una sola raíz y que todas las etiquetas cierran.
  3. Busca en tu lengua favorita cómo parsearlo de forma segura y documenta la función que usarías.

Resumen

  • XML usa etiquetas cerradas y una raíz única para estructurar datos.
  • Es verboso pero muy validable (XSD) y clave en SOAP.
  • JSON lo ha superado para APIs nuevas; XML persiste en integraciones legacy.
  • Siempre se procesa con parser XML, nunca con regex.
