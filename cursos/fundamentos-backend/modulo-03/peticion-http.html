Request HTTP

🌱 Principiante 8 min Fundamentos de Backend Módulo 3 · HTTP

Introducción

El request (petición) HTTP es el mensaje que el cliente envía al servidor pidiendo algo. Es la «carta» que escribes: con una intención (método), un destinatario (URL), unas condiciones (headers) y, a veces, un contenido (body).

Un backend pasa todo el día leyendo requests. Saber cómo están formados te permite interpretar cualquier error de tu API al instante.

Anatomía de una petición

HTTP
GET /usuarios/42?conDetalles=true HTTP/1.1
Host: api.midominio.com
Authorization: Bearer eyJhbGciOi...
Accept: application/json
  • Línea de petición: método GET + ruta /usuarios/42 + query ?conDetalles=true + versión HTTP.
  • Headers: Host, Authorization (token), Accept (formato aceptado).
  • Body: solo en métodos con datos (POST/PUT/PATCH). Separado de los headers por una línea en blanco.

Distinguir path (qué recurso: /usuarios/42) de query (filtros/opciones: ?conDetalles=true) es un clásico del backend que verás en lecciones próximas.

Ejemplo: las 4 peticiones del CRUD clásico

  • GET /usuarios → listar.
  • POST /usuarios → crear (body con los datos).
  • PUT /usuarios/42 → actualizar el 42.
  • DELETE /usuarios/42 → borrar el 42.

Código: enviar una petición completa

Ejercicio

  1. Escribe a mano una petición GET y una POST completas.
  2. Usa F12 → Red en el navegador, recarga una web y señala la línea de petición de una imagen.
  3. Explica la diferencia entre la ruta y la query de una petición.

Resumen

  • Un request tiene método, URL, headers y opcionalmente body.
  • GET no lleva body; POST/PUT/PATCH sí.
  • La ruta identifica el recurso; la query son opciones.
  • El backend lee requests y decide qué respuesta dar.
