Arquitectura en Capas

💻 Básico 9 min Fundamentos de Backend Módulo 4 · Arquitectura Web

¿Qué es la arquitectura en capas?

La arquitectura en capas organiza el código siguiendo una dirección clara: cada capa solo puede usar a las capas inferiores, nunca al revés. En la web la versión más extendida tiene tres niveles:

  • Presentación: la interfaz (frontend) y los controladores que reciben peticiones.
  • Lógica de negocio / servicios: las reglas del dominio: calcular precios, validar permisos, orquestar procesos.
  • Datos: los repositorios y modelos que hablan con la base de datos.

La clave no es el número de capas, sino el sentido único de la dependencia: el cambio de una capa no debe filtrarse a las demás si respetas sus interfaces.

Los tres niveles típicos

Las reglas de oro

  • Flujo descendente: la presentación usa los servicios, los servicios usan los repositorios.
  • Interfaces sobre detalles: la capa de negocio depende de contratos (interfaces), no de implementaciones concretas de base de datos.
  • No saltar niveles: el controlador no toca SQL directamente; pasa por la capa que toca.
  • Inversión de dependencias: si hace falta inyectar la capa de datos desde fuera para poder probar, se inyecta.

Ventajas y cuándo decide

VentajasCódigo predecible, separación de responsabilidades, testeo aislado por capa y sustitución de infraestructura sin tocar la lógica.
LímitePara dominios simples puede generar demasiada ceremonia; su verdadera fuerza aparece cuando la lógica crece.

Es la arquitectura por defecto de la mayoría de backends profesionales porque ofrece el mejor equilibrio entre orden y pragmatismo.

Ejercicio

  1. Elige una acción de tu API (por ejemplo, "crear pedido") y reparte sus pasos entre las 3 capas.
  2. Encuentra UN punto donde tu código actual salta una capa (por ejemplo, SQL dentro de un controlador) y propón cómo corregirlo.
  3. Explica por qué cambiar de MySQL a PostgreSQL no debería tocar la capa de negocio.

Resumen

  • Las capas presentación → negocio → datos organizan el backend.
  • La dependencia fluye en un solo sentido, hacia abajo.
  • Las interfaces permiten cambiar implementaciones sin romper la lógica.
  • Es la arquitectura de referencia para proyectos en crecimiento.
