Servidores

🌱 Principiante 9 min Fundamentos de Backend Módulo 2 · Internet y la Web

Introducción

En el Módulo 1 conociste al servidor como el que responde peticiones. Ahora vas más lejos: qué servidores existen y cómo se pone tu software «en producción». El backend, al fin y al cabo, se escribe para vivir en un servidor.

Un servidor es, en esencia, una computadora con una dirección fija y un software que recibe conexiones. Lo que cambia de un tipo a otro es qué software corre en cada uno.

Los servidores que encontrarás

  • Servidor web (Nginx, Apache): entrega HTML y archivos. Rápido y simple.
  • Servidor de aplicaciones (Node.js, Django, Spring): ejecuta tu lógica y construye las respuestas dinámicas.
  • Base de datos (MySQL, PostgreSQL, MongoDB, Redis): guarda y consulta los datos.
  • Servidor de correo: SMTP para enviar y recibir emails.
  • Servidor de archivos (NFS, S3): almacena fotos, videos y backups.

En producción suelen organizarse en capas: el proxy (Nginx) recibe primero y delega en la app; la app trabaja con la base de datos. Este esquema lo profundizarás en el Módulo 4.

Ejemplo: cómo «sube» tu app a un servidor

  1. Escribes la aplicación y la pruebas en tu máquina (localhost).
  2. Compras (o alquilas) una máquina en la nube — un VPS o un servidor dedicado.
  3. Instalas el lenguaje de tu backend (Node, Python…), tu servidor web (Nginx) y tu base de datos.
  4. Subes tu código (git clone o rsync) y lo pones a correr como un servicio.
  5. Configuras el dominio y el HTTPS (lo verás en la lección de hosting y dominios).
Dato clave: en un servidor Linux real, tu app se ejecuta con un gestor de procesos (systemd, PM2) para que vuelva a arrancar sola si se cae. Un buen backend es el que nadie tiene que «levantar» a mano.

Código: tu app como servicio en Linux

Este es el esqueleto de un servicio systemd para una app Node. Guardalo como /etc/systemd/system/miapp.service.

Con systemctl start miapp arranca; con systemctl enable miapp arranca al iniciar el sistema. Si la app lanza un error, Restart=always la relanza sola.

Ejercicio

  1. Clasifica en una tabla: servidor web, servidor de aplicaciones, base de datos y servidor de correo (con un ejemplo real de cada uno).
  2. Explica por qué un servidor mal administrado (sin reinicio automático) puede «estar caído» aunque el código sea perfecto.
  3. Investiga qué es un gestor de procesos como PM2 y escribe una frase que lo explique con tus palabras.

Resumen

  • Un servidor es una máquina con una IP fija corriendo software que responde peticiones.
  • Hay servidores web, de aplicaciones, de datos, de correo y de archivos.
  • Publicar software: máquina + dependencias + servicio + dominio.
  • Los servicios deben reiniciarse solos ante fallos.
