Response

🌱 Principiante 8 min Fundamentos de Backend Módulo 1 · Introducción

Introducción

Una response (respuesta) es el mensaje que el servidor devuelve al cliente después de procesar una petición. Es la mitad del diálogo que completa el ciclo: every good request deserves a clear answer.

Para un desarrollador Backend, la response es tu firma: es lo único que el cliente verá. Un buen backend siempre responde con claridad, con el estado correcto y con la información justa.

Qué contiene una response

  • Código de estado: un número de 3 cifras que resume el resultado. 200 OK, 404 no encontrado, 500 error interno.
  • Headers: metadatos de la respuesta: el tipo de contenido, las cookies a guardar, instrucciones de caché.
  • Body: el contenido real: HTML, JSON, imagen, etc.

Los códigos de estado son el idioma común entre todos los clientes del mundo: cualquier navegador sabe qué significa un 403 aunque la respuesta esté vacía.

Ejemplo: tres respuestas para tres situaciones

  1. Todo bien: 200 OK con los datos pedidos.
  2. Aviso: el recurso no existe → 404 con un body que explica el error.
  3. Error del servidor: una excepción inesperada → 500.

Detalle importante: un error de programación jamás debe mostrar al cliente los detalles internos (trazas, SQL, contraseñas). El body debe ser genérico y el log completo queda en el servidor.

Código: el servidor escribe la respuesta

En Node.js, la respuesta se construye sobre el objeto respuesta. Aquí respondes con estado, header de contenido y JSON.

Ejercicio

  1. Modifica el código para responder 404 cuando la URL no sea /api/datos. Prueba ambos caminos.
  2. Abre F12 → Red en una web y observa: ¿qué código de estado tiene cada response? Identifica un 200 y un posible 304 (usa caché).
  3. Responde por escrito: ¿por qué un 500 no debería incluir la traza del error en el body?

Resumen

  • Response = mensaje del servidor al cliente tras procesar la petición.
  • Se compone de código de estado, headers y body.
  • El código de estado es el idioma universal entre backend y cualquier cliente.
  • Los errores internos se registran en el servidor, nunca se envían al cliente.
