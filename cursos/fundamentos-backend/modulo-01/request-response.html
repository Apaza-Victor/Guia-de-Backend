Request y Response

🌱 Principiante 10 min Fundamentos de Backend Módulo 1 · Introducción

Introducción

Ya conoces las dos piezas por separado. Ahora toca verlas como un todo: el ciclo request-response. Es la «conversación» más repetida en Internet: millones de veces por segundo, un cliente pide y un servidor responde.

Comprender el ciclo completo es la diferencia entre «sé picar endpoints» y «entiendo cómo se comporta mi sistema». Cada una de las lecciones siguientes (HTTP, headers, status codes) profundiza en una parte de este ciclo.

El ciclo paso a paso

  1. El cliente prepara la petición: método, URL, headers y opcionalmente body.
  2. El cliente la envía a través de la red (aquí actúan IP, DNS, puertos).
  3. El servidor recibe y valida: método soportado, autorización, formato de datos.
  4. El servidor ejecuta la lógica: consulta la base de datos, calcula, guarda.
  5. El servidor construye la respuesta: código de estado + headers + body.
  6. El cliente procesa la respuesta y decide qué mostrar.
Hay una regla de oro: cada request debe producir exactamente UNA response. Nunca dos, nunca cero. Si algo falla, la respuesta será un error 5xx, pero siempre habrá una.

Ejemplo: comprar un café (con detalle)

  1. GET /cafes → el servidor devuelve el menú (200).
  2. POST /pedidos con body {"cafe":"capuchino","tamaño":"grande"} → el servidor crea el pedido y devuelve el número #42.
  3. POST /pedidos/42/pagar con los datos de pago → el servidor cobra y responde 200.
  4. Si pagas con tarjeta vencida → el servidor responde 402 Payment Required explicando el problema.

Observa cómo cada acción hizo viajar un par request+response. El frontend jamás tocó la pasarela de pagos: la seguridad vive en el backend.

Errores frecuentes

  • Omitir el código de estado: responder 200 aunque falle. Gasta kilobytes y confunde al cliente.
  • No cerrar la respuesta (res.end()): el cliente se queda esperando una response que nunca llega.
  • Enviar credenciales en la URL: quedan en logs y navegadores. Van en headers o body.
  • Devolver siempre el body completo: un cliente no necesita 40 campos si solo muestra 3.

Ejercicio

  1. Ejecuta el código y confirma el ciclo en la consola: solicitud → respuesta → log.
  2. Cambia la URL a /noexiste y observa el 404. Verás que el ciclo también se completa en los errores.
  3. Escribe en papel el ciclo completo de «buscar un producto y agregarlo al carrito»: ¿cuántas request→response se producen?

Resumen

  • Cada interacción es un ciclo: una request y exactamente una response.
  • El servidor valida, procesa y responde; nunca «se queda en silencio».
  • Los códigos de estado comunican el resultado del ciclo con claridad.
  • La seguridad y los datos sensibles se manejan en el backend.
