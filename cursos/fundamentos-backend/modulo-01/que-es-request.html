Request

🌱 Principiante 8 min Fundamentos de Backend Módulo 1 · Introducción

Introducción

Una request (petición) es el mensaje que el cliente envía al servidor para pedir algo. Es el «pedido» en el restaurante: tiene una dirección, dice qué quieres y a veces incluye detalles («sin cebolla»).

En el mundo web, cada request viaja por el protocolo HTTP. Aunque lo estudiarás en profundidad en el Módulo 3, aquí verás el concepto: una petición es la unidad de conversación entre cliente y servidor, y todo backend empieza por leer peticiones.

Qué contiene una request

  • Método: la acción deseada. GET pide, POST crea, PUT actualiza, DELETE elimina.
  • URL: a qué recurso va dirigida la petición (qué plato).
  • Headers: metadatos: idioma aceptado, tipo de contenido, cookies, token de sesión.
  • Body: la información que se envía (solo en algunos métodos). Así viajan los datos de un formulario.

Un error común de principiante: creer que toda la información debe ir en la URL. Los datos que no deben verse ni quedar registrados (contraseñas, contenido) viajan en el body; los criterios de búsqueda pueden ir en la URL.

Ejemplo: dos peticiones para una misma app

  1. GET /libros/populares → pide la lista de libros más leídos.
  2. POST /usuarios con body {"correo":"ana@mail.com","clave":"..."} → crea una cuenta.

La misma URL puede hacer cosas distintas según el método. Este truco es la base del diseño de las APIs REST, que verás en el Módulo 4.

Código: el cliente escribe la petición

Con fetch tú (como cliente) decides método, headers y body. Aquí construimos y enviamos la petición que crea un usuario.

Observa que nadie «escrbe» la request a mano: se construye con código. El backend solo recibe el resultado y debe interpretarlo correctamente.

Ejercicio

  1. Toma la app que más uses y describe: ¿qué petición envía al abrirse, y qué información crees que lleva en la URL y en los headers?
  2. En el código de ejemplo, añade "X-Requester": "curioso" a los headers y observa cómo el servidor podría leer ese dato.
  3. Explica la diferencia entre enviar un dato en la URL (query) y enviarlo en el body.

Resumen

  • Request = mensaje del cliente al servidor pidiendo algo.
  • Se compone de método, URL, headers y, opcionalmente, body.
  • El método dice la intención; la URL, el recurso; el body, los datos.
  • El frontend construye peticiones y el backend las lee.
