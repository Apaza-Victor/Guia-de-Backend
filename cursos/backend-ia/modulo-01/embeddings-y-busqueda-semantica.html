Embeddings y búsqueda semántica

🧠 Experto 10 min Backend para IA Módulo 1 · Fundamentos de IA

Introducción

Una búsqueda por palabras clave falla cuando el usuario escribe «cómo reembolso» y tu documento dice «devolución de dinero»: ninguna letra coincide, pero el significado es el mismo. Los embeddings resuelven eso: convierten cada texto en un vector posicionado según su significado, y buscar pasa de comparar letras a comparar distancias.

Esta técnica es la pieza que le da memoria a los modelos con tus propios documentos —el RAG—, así que dominarla aquí te deja listo para el módulo siguiente.

Generar un embedding desde el backend

Cada texto (un documento, una pregunta, una reseña) se envía al modelo de embeddings y se guarda el vector resultante junto con el texto original en tu base de datos.

from openai import OpenAI

client = OpenAI()

documentos = [
    "Política de devolución: se aceptan cambios dentro de 30 días.",
    "El envío a domicilio tarda entre 2 y 5 días hábiles.",
    "Puedes pagar con tarjeta, transferencia o PayPal."
]

respuesta = client.embeddings.create(
    model="text-embedding-3-small",
    input=documentos
)

for i, dato in enumerate(respuesta.data):
    print(f"Documento {i}: {len(dato.embedding)} dimensiones")
    # Documento 0: 1536 dimensiones

Una sola llamada acepta varios textos a la vez (batching), lo que reduce peticiones y coste. Guarda cada vector con un identificador y el texto de origen: así podrás devolver el fragmento original cuando una búsqueda coincida.

Similitud coseno

Para saber qué tan parecidos son dos textos, calculamos el coseno del ángulo entre sus vectores: cuanto más cerca de 1, más parecidos; cercano a 0, nada que ver. En Python se calcula con un producto punto y dos normas:

import math

def similitud_coseno(a, b):
    if len(a) != len(b):
        raise ValueError("Los vectores deben tener la misma dimensión")
    dot = sum(x * y for x, y in zip(a, b))
    norma_a = math.sqrt(sum(x * x for x in a))
    norma_b = math.sqrt(sum(y * y for y in b))
    if norma_a == 0 or norma_b == 0:
        return 0.0
    return dot / (norma_a * norma_b)

consulta = "¿Puedo devolver mi compra?"
# Vamos a suponer que estos son los embeddings reales del proveedor
vector_consulta = [0.91, -0.20, 0.15, 0.40]
vector_documento1 = [0.88, -0.18, 0.21, 0.35]  # política de devolución
vector_documento2 = [0.10, 0.84, -0.22, -0.11] # envío a domicilio

print(similitud_coseno(vector_consulta, vector_documento1))  # ~0.99
print(similitud_coseno(vector_consulta, vector_documento2))  # ~0.07

Con embeddings reales, la consulta «¿Puedo devolver mi compra?» se acercará mucho al documento de la política de devolución y casi nada al de envíos, aunque ninguna palabra coincida exactamente.

Un buscador semántico en memoria

Para pocos miles de documentos, un barrido lineal es suficiente para empezar y entender el patrón:

def buscar(consulta, indice, top_k=3):
    vector = client.embeddings.create(
        model="text-embedding-3-small",
        input=[consulta]
    ).data[0].embedding

    puntuados = [
        (similitud_coseno(vector, doc["embedding"]), doc["texto"])
        for doc in indice
    ]
    puntuados.sort(reverse=True)
    return puntuados[:top_k]

indice = [
    {"texto": "Política de devolución: cambios dentro de 30 días.", "embedding": emb[0]},
    {"texto": "Envío a domicilio: 2 a 5 días hábiles.", "embedding": emb[1]},
    {"texto": "Medios de pago: tarjeta, transferencia o PayPal.", "embedding": emb[2]},
]

for puntuacion, texto in buscar("¿Me devuelven el dinero si no me gusta?", indice):
    print(f"{puntuacion:.2f} → {texto}")

Este código es un RAG en miniatura sin que el modelo de chat intervenga: ya sabes qué fragmentos responderán a cada pregunta. Cuando el índice crezca, ese barrido lineal se reemplaza por una vector database con índices ANN (como pgvector, Qdrant o Weaviate), que hace lo mismo en milisegundos.

Sobre precisión y filtros

  • Sin filtros: la búsqueda semántica por sí sola puede recuperar textos del tema equivocado. Combínala con filtros de metadatos (categoría, fecha, idioma).
  • Normaliza: muchos embeddings ya vienen normalizados; verifica la unidad de medida de tu proveedor antes de comparar.
  • Hibrida: los mejores buscadores combinan keyword (BM25) con semántica, sobre todo con nombres propios o códigos como «pedido 1234».
  • Umbral mínimo: define un corte de similitud (por ejemplo 0.7) y devuelve «no encontré respuesta» en lugar de forzar contexto irrelevante.

Ejercicio

  1. Genera los embeddings de 5 documentos propios sobre tu proyecto (FAQs, fragmentos de documentación).
  2. Escribe una función buscar(consulta, top_k=2) con similitud coseno y pruébala con 3 preguntas que no compartan palabras con los documentos.
  3. Imprime las puntuaciones: identifica qué consultas recuperan el documento correcto y cuáles fallan, y anota en qué guardarías metadatos para filtrar mejor.

Resumen

  • Un embedding es un vector que representa el significado de un texto.
  • La similitud coseno compara ángulos entre vectores: es la medida estándar en búsqueda semántica.
  • Generas embeddings por API y guardas vector + texto original en tu base de datos.
  • Un barrido lineal alcanza para prototipar; las vector databases escalan la misma idea.
  • Filtra por metadatos, define umbrales y mezcla con búsqueda por palabras para mejores resultados.
