Prompts y completions

🧠 Experto 10 min Backend para IA Módulo 1 · Fundamentos de IA

Introducción

El prompt es la instrucción que envías al modelo y el completion es su respuesta. Para tu backend, el prompt no es un texto suelto: es una estructura de datos —un arreglo de mensajes con roles— que define qué debe hacer el modelo y con qué contexto.

Un prompt bien diseñado separa lo que siempre debe cumplirse (las reglas del sistema) de lo que cambia por usuario (su pregunta y su contexto). Esa separación es la primera «arquitectura» de tu feature con IA.

Los roles: system, user y assistant

  • System: instrucciones permanentes e implacables. Define la personalidad, las reglas y el formato de salida. No viene del usuario.
  • User: el mensaje de la persona, tal como llega a tu servidor. Puedes añadirle contexto añadido por ti.
  • Assistant: respuestas previas del modelo. Se incluyen para dar historial al modelo sin repetir texto.
{
  "model": "gpt-4o-mini",
  "messages": [
    {
      "role": "system",
      "content": "Eres un agente de soporte de una tienda online. Respónde solo con datos verificados, en máximo 2 frases y en español."
    },
    {
      "role": "user",
      "content": "Mi pedido 1234 no aparece en el seguimiento."
    },
    {
      "role": "assistant",
      "content": "Cuéntame el correo con el que compraste."
    },
    {
      "role": "user",
      "content": "ana@correo.com"
    }
  ]
}

El modelo «recuerda» lo que esté dentro de su ventana de contexto. Si en tu base de datos guardas el historial, cada turno nuevo lo reconstruyes como este arreglo: ese es el patrón de los chatbots.

Temperatura y límite de tokens

Dos parámetros gobiernan la calidad operativa de cada completion:

  • temperature (0–2): 0 es determinista y preciso, ideal para extraer datos o clasificar. Valores altos añaden variedad, útiles para copy creativo pero peligrosos para lógica.
  • max_tokens: corta la salida al llegar al límite. Respuestas truncadas se reconocen por finish_reason: "length" y deben detectarse, o tu app servirá texto a medias.
const res = await fetch('https://api.openai.com/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`
  },
  body: JSON.stringify({
    model: 'gpt-4o-mini',
    messages: [
      { role: 'system', content: 'Eres una API. Devuelve solo JSON.' },
      { role: 'user', content: 'Clasifica el sentimiento de: "Me encanta el nuevo diseño".' }
    ],
    temperature: 0,
    max_tokens: 150
  })
});

const data = await res.json();
const choice = data.choices[0];

if (choice.finish_reason === 'length') {
  console.warn('La respuesta se cortó por max_tokens');
}

console.log(choice.message.content);

Regla de oro para features de lógica: temperature: 0 y, si el resultado esperado es un dato, pedir JSON y validarlo tú mismo.

Pedir y validar JSON

Tu backend no debería parsear la respuesta de un LLM como si fuera un API confiable. La técnica robusta es triple: pedir JSON explícitamente, usar el modo JSON si el proveedor lo ofrece y validar en tu código con un esquema.

const prompt = `
Devuelve un objeto JSON con el siguiente esquema exacto:
{
  "sentimiento": "positivo" | "negativo" | "neutralo",
  "confianza": number entre 0 y 1,
  "resumen": string de máximo 15 palabras
}
Texto a analizar: ${usuarioInput}
`;

Al recibir la respuesta, el primer paso del servidor es intentar JSON.parse. Si falla, puedes pedirle al modelo que la corrija una vez; si sigue fallando, devuelve un error controlado en lugar de propagar basura.

Plantillas de prompt en el backend

Nunca escribas prompts concatenando texto a mano dentro de las rutas. Centralízalos en una capa de plantillas que recibe datos y devuelve mensajes:

const plantillas = {
  clasificarTicker(ticker, noticias) {
    return [
      { role: 'system', content: 'Clasifica el impacto del ticker en: alcista, bajista o neutral. Devuelve solo JSON.' },
      { role: 'user', content: `Ticker: ${ticker}\nNoticias:\n${noticias.join('\n')}` }
    ];
  },
  resumir(contenido) {
    return [
      { role: 'system', content: 'Eres un resumidor técnico en español, máximo 100 palabras.' },
      { role: 'user', content: contenido }
    ];
  }
};

const mensajes = plantillas.clasificarTicker('TSLA', noticiasDelDia);

Centralizar los prompts hace que las pruebas sean más fáciles (puedes ver todo el mensaje en un solo lugar), que la seguridad se audite (sabes dónde entra input del usuario sin sanitizar) y que cambiar de modelo no implique buscar cadenas por todo el código.

Ejercicio

  1. Crea dos plantillas de prompt: una que clasifique el sentimiento de una reseña y otra que extraiga el nombre, email y teléfono de un texto.
  2. Llama con temperature: 0 y max_tokens suficiente, y valida que la respuesta del modelo sea JSON parseable en tu servidor.
  3. Comprueba qué ocurre cuando fijas max_tokens muy bajo (por ejemplo, 10): observa el finish_reason y añade el manejo correspondiente.

Resumen

  • El prompt es un arreglo de mensajes con roles: system (reglas), user (input) y assistant (historial).
  • temperature: 0 da resultados deterministas; valores altos son para tareas creativas.
  • max_tokens limita la salida y deja finish_reason: "length" cuando se trunca.
  • Para integrar datos, pide JSON e incluye una validación en tu backend.
  • Centraliza los prompts en plantillas reutilizables: se prueban, auditan y migran mejor.
