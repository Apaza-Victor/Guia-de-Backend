¿Qué es la IA en el backend?

🧠 Experto 9 min Backend para IA Módulo 1 · Fundamentos de IA

Introducción

Cuando un usuario habla con un bot y este «entiende» o cuando un correo se clasifica automáticamente como spam, detrás hay un modelo: un programa que aprendió a reconocer patrones a partir de datos. Tu aplicación no «ejecuta magia»; tu servidor hace algo muy concreto: envía un texto a un modelo y recibe una predicción.

En este curso, la IA es un servicio consumible: un API que tu backend llama, igual que llamaría a una base de datos o a un proveedor de pagos. Entender eso desde el inicio te ahorrará meses de tratar el tema como algo «científico» cuando, en realidad, es un problema de ingeniería de integración.

El rol del backend frente a la IA

Prácticamente ningún producto de IA se consume desde el navegador llamando directamente al modelo. Ese trabajo vive en el servidor, y son tareas clásicas de backend:

  • Proteger las API keys: el secreto nunca debe viajar al cliente; se queda en variables de entorno del servidor.
  • Orquestar llamadas: componer el prompt con contexto de tu base de datos, llamar al modelo y guardar el resultado.
  • Cachear y controlar costes: respuestas repetidas no deberían pagar tokens dos veces.
  • Limitar y autenticar: decidir quién puede consumir cuánto de tu integración de IA.
  • Transmitir respuestas: enviar los tokens al cliente a medida que llegan (streaming).

Todo lo demás —elegir el modelo, medir latencia, guardar historial, hacer fallback cuando el modelo falla— también es backend.

ML, deep learning y LLMs

Conviene ordenar la terminología, porque se usa de forma intercambiable y no lo es:

  • Machine learning (ML): algoritmos que aprenden patrones de datos para predecir. Incluye regresión, árboles de decisión, clasificadores, etc.
  • Deep learning (DL): una rama del ML basada en redes neuronales con muchas capas, capaces de aprender características complejas.
  • LLM (Large Language Model): un modelo de deep learning entrenado con enormes cantidades de texto para predecir y generar lenguaje. GPT, Claude y Gemini son ejemplos.

En la práctica, tu backend rara vez entrena modelos: los consume entrenados por otros. Eso cambia completamente el enfoque: tu trabajo es integrar bien, no ajustar pesos.

Tu primera llamada a un modelo

La forma más común de consumir un LLM desde un servidor Node.js es la API de chat completions: envías un arreglo de mensajes y recibes la continuación de la conversación.

const OPENAI_URL = 'https://api.openai.com/v1/chat/completions';

async function responder(pregunta) {
  const res = await fetch(OPENAI_URL, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`
    },
    body: JSON.stringify({
      model: 'gpt-4o-mini',
      messages: [
        { role: 'system', content: 'Eres un asistente de soporte técnico.' },
        { role: 'user', content: pregunta }
      ],
      temperature: 0.3
    })
  });

  if (!res.ok) throw new Error(`La API respondió ${res.status}`);

  const data = await res.json();
  return data.choices[0].message.content;
}

Observa los tres elementos de toda llamada: el modelo, los mensajes (con su rol) y los parámetros como la temperatura. En las próximas lecciones profundizaremos en cada uno.

Lo mismo con el SDK de Python

Python es el lenguaje natural del ecosistema de IA, y los proveedores publican SDKs oficiales que te ahorran escribir fetch a mano.

from openai import OpenAI

client = OpenAI()  # lee OPENAI_API_KEY del entorno

respuesta = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "Traduce del español al inglés."},
        {"role": "user", "content": "El pedido llegó con una pieza rota."}
    ],
    temperature=0.2,
)

print(respuesta.choices[0].message.content)
# "The order arrived with a broken piece."

Elige Python si tu equipo ya vive en él (análisis de datos, ML) y Node.js si tu backend es JavaScript. El protocolo es el mismo y, como verás, ambas formas llegan al mismo endpoint.

La respuesta que devuelve el modelo

La API no devuelve solo el texto: devuelve metadatos que tu backend debe saber leer para medir costes y diagnosticar.

{
  "id": "chatcmpl-ABC123",
  "model": "gpt-4o-mini",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Claro, te explico el problema..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 34,
    "completion_tokens": 12,
    "total_tokens": 46
  }
}

Los campos usage son tu medidor de coste y finish_reason te dice si el modelo terminó (stop), se cortó por el límite (length) o quería llamar a una herramienta (tool_calls). Esos detalles gobiernan la robustez de todo lo que construirás después.

Ejercicio

  1. Crea un pequeño script Node.js (o Python) que llame a un modelo de chat con el mensaje: «Explica en una frase qué hace el backend frente a la IA».
  2. Guarda la API key en una variable de entorno y nunca la escribas en el código ni la envíes al navegador.
  3. Imprime por consola los campos model, content y usage.total_tokens de la respuesta.

Resumen

  • La IA se consume como un servicio: tu backend envía texto a un modelo y recibe una predicción.
  • Proteger keys, orquestar prompts, cachear y medir costes son tareas de backend.
  • ML es el término general; el deep learning es su subconjunto neuronal; los LLMs son modelos de lenguaje profundos.
  • Una llamada típica envía modelo + mensajes con roles + parámetros como la temperatura.
  • La respuesta trae el texto y también metadatos útiles: tokens usados y motivo de finalización.
