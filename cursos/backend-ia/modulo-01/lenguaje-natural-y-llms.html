Lenguaje natural y LLMs

🧠 Experto 10 min Backend para IA Módulo 1 · Fundamentos de IA

Introducción

Un modelo no «lee» texto como tú: transforma las palabras en números. Todo lo que un LLM entiende y genera pasa por dos conversiones: las palabras se parten en tokens (la unidad que el modelo procesa) y esos tokens se convierten en embeddings (vectores que representan significado).

Esta lección te da el vocabulario exacto para razonar sobre costes, límites y calidad de las respuestas. Sin ella, parámetros como max_tokens o el precio por token serán una caja negra.

Tokens: la moneda del lenguaje

Un token es un fragmento de texto: puede ser una palabra entera, una parte de ella, un signo de puntuación o incluso un carácter. Cada modelo tiene su propio tokenizador. En español, por ejemplo, la frase «Hola, ¿cómo estás?» se parte en algo parecido a ["Hola", ",", "¿", "cómo", " estás", "?"].

Los tokens importan por tres razones: el modelo tiene una ventana máxima de contexto (no caben más de N tokens por conversación), el coste se mide por tokens y el tiempo de generación crece con ellos. Con la librería tiktoken puedes medir exactamente cuántos tokens consumirás antes de llamar al modelo:

import tiktoken

encoding = tiktoken.encoding_for_model("gpt-4o")

texto = "El pedido número 1234 llegó con una pieza rota."
tokens = encoding.encode(texto)

print(len(tokens))       # 13
print(encoding.decode(tokens))
# 'El pedido número 1234 llegó con una pieza rota.'

Regla práctica para estimar: en español, un token ≈ 0.75 palabras en promedio. Úsalo solo como cifra mental; para presupuestar, mejor contar con la librería real del proveedor.

Embeddings: texto convertido en números

Para comparar significados, el modelo convierte cada token (o cada frase) en un vector: una lista de números de cientos de dimensiones. Textos con significado parecido quedan cerca en el espacio, y textos opuestos, lejos. «Gato» y «felino» apuntan casi en la misma dirección; «auto» apunta hacia otro lado.

Desde el backend se obtienen con una API específica de embeddings, distinta del chat:

const res = await fetch('https://api.openai.com/v1/embeddings', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`
  },
  body: JSON.stringify({
    model: 'text-embedding-3-small',
    input: ['El pedido llegó con una pieza rota']
  })
});

const data = await res.json();
const vector = data.data[0].embedding;
console.log('Dimensiones del vector:', vector.length); // 1536

El resultado es un arreglo de 1536 números (con text-embedding-3-small). Ese vector se guarda en una base de datos de vectores y es la base de la búsqueda semántica, como verás en la lección de embeddings.

Generación: predecir el siguiente token

Un LLM genera texto de forma autoregresiva: mira el contexto completo y predice el siguiente token más probable, lo añade al contexto, y repite. Esa repetición, token a token, es literalmente lo que ves llegar en streaming.

# Ejemplo conceptual: pedir al modelo que complete una frase
curl https://api.openai.com/v1/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -d '{
    "model": "gpt-4o-mini",
    "prompt": "La capital de Francia es",
    "max_tokens": 8,
    "temperature": 0
  }'

El parámetro max_tokens limita cuántos tokens puede producir la respuesta (el presupuesto de salida). Con temperature controlas la aleatoriedad: cercana a cero, la salida es casi determinista; más alta, más creativa pero menos reproducible. Ningún modelo está «pensando»: está lanzando una distribución de probabilidad.

Por qué importa para tu backend

  • Ventana de contexto: historiales muy largos o documentos enormes se cortan. Debes gestionar cuánto contexto envías.
  • Coste: el precio está ligado a los tokens de entrada y de salida. Responder 500 tokens cuesta más que recibir 100.
  • Latencia: cada token adicional de salida agrega milisegundos. Los modelos grandes producen muchos tokens por segundo.
  • Determinismo: para tareas técnicas conviene temperature baja y validar estructuras en lugar de confiar en el texto libre.

Dato útil: la palabra contada como 1 token en inglés puede ser 3 o 4 tokens en español por los caracteres acentuados y los signos. Tu estimación de coste debe considerar el idioma real de tus usuarios.

Ejercicio

  1. Usa tiktoken en Python para contar los tokens de un párrafo tuyo en español y compara con su número de palabras.
  2. Llama al endpoint de embeddings con dos frases parecidas (por ejemplo, «El gato duerme» y «El felino descansa») y guarda ambos vectores.
  3. Con temperature: 0 pide al modelo que complete la frase anterior dos veces y confirma que obtienes la misma respuesta: así compruebas el determinismo.

Resumen

  • Los LLMs procesan texto en tokens: fragmentos de palabras que definen contexto, coste y latencia.
  • Los embeddings convierten el texto en vectores numéricos que representan significado.
  • Generar texto es predecir el siguiente token de forma autoregresiva.
  • max_tokens limita la salida y temperature controla la aleatoriedad.
  • Gestionar contexto, idioma y presupuesto de tokens es responsabilidad del backend.
