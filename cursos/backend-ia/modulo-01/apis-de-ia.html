APIs de IA

🧠 Experto 9 min Backend para IA Módulo 1 · Fundamentos de IA

Introducción

Los modelos de IA se consumen vía HTTPS igual que cualquier API REST: un JSON de entrada, un JSON de salida y una clave de autenticación. Lo que cambia entre proveedores es el formato exacto, los nombres de los modelos y detalles como la estructura de mensajes.

Aquí comparamos los tres grandes que verás en producción — OpenAI, Anthropic (Claude) y Google (Gemini) — para que puedas integrar cualquiera de ellos y, sobre todo, migrar cuando cambien los precios o el rendimiento.

El formato común: chat completions

Los tres proveedores coinciden en la idea central: envías un arreglo de mensajes con role y content, y el modelo responde con el siguiente mensaje de la conversación. Esto no es casualidad: es la forma más flexible de construir diálogos con contexto.

La diferencia práctica está en detalles: OpenAI usa messages y un único Authorization: Bearer; Anthropic además exige el header anthropic-version; Gemini acepta el cuerpo mediante contents. Veamos cada llamada.

OpenAI: el estándar de facto

const res = await fetch('https://api.openai.com/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`
  },
  body: JSON.stringify({
    model: 'gpt-4o-mini',
    messages: [
      { role: 'system', content: 'Respondes en español, de forma breve.' },
      { role: 'user', content: '¿Qué es una API key y por qué no debe ir al navegador?' }
    ],
    temperature: 0.4,
    max_tokens: 200
  })
});

const data = await res.json();
console.log(data.choices[0].message.content);

Toda la identidad del cliente, incluida la key, viaja en el header Authorization. Nunca la pongas en la URL ni en el cuerpo: los logs y los proxies la capturarían.

Claude: Anthropic

const res = await fetch('https://api.anthropic.com/v1/messages', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'x-api-key': process.env.ANTHROPIC_API_KEY,
    'anthropic-version': '2023-06-01'
  },
  body: JSON.stringify({
    model: 'claude-3-5-sonnet-latest',
    max_tokens: 1024,
    system: 'Eres un asistente de soporte en español.',
    messages: [
      { role: 'user', content: 'Explica el error 429 en una frase.' }
    ]
  })
});

const data = await res.json();
console.log(data.content[0].text);

Nota las diferencias con OpenAI: la key viaja en x-api-key (no Bearer), se exige anthropic-version, el prompt del sistema es un campo separado system y la salida se lee en content[0].text.

Gemini: Google

curl "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=$GEMINI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "parts": [
          { "text": "Resume las claves para integrar IA en un backend en 3 puntos." }
        ]
      }
    ]
  }'

Gemini pone la key en la query string (por diseño de Google) y usa el objeto contents → parts → text en lugar de messages. Aunque cada proveedor difiere, siempre responden con JSON estructurado: puedes unificar las tres llamadas detrás de una misma interfaz en tu servicio.

Manejo de errores y rate limits

Las APIs de IA fallan igual que cualquier API externa: pueden devolver 401 (key inválida), 429 (límite de peticiones o de tokens por minuto) o 5xx (caída temporal del proveedor). Tu backend debe traducir esos errores a algo entendible y reintentar solo cuando tenga sentido.

async function llamarConReintento(mensajes, intentos = 3) {
  for (let i = 0; i < intentos; i++) {
    const res = await fetch(process.env.OPENAI_URL, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`
      },
      body: JSON.stringify({ model: 'gpt-4o-mini', messages: mensajes })
    });

    if (res.status === 429) {
      const retryAfter = Number(res.headers.get('retry-after')) || 2 ** i;
      await new Promise((r) => setTimeout(r, retryAfter * 1000));
      continue;
    }
    if (res.status >= 500 && i < intentos - 1) {
      await new Promise((r) => setTimeout(r, 1000 * 2 ** i));
      continue;
    }
    if (!res.ok) throw new Error(`Error ${res.status}: ${await res.text()}`);
    return res.json();
  }
  throw new Error('El proveedor no respondió tras los reintentos');
}

El header retry-after de un 429 te dice cuándo reintentar. No reintentes un 401 ni un 400: son errores permanentes y el reenvío solo duplicará la factura.

Ejercicio

  1. Integra la llamada de OpenAI y la de Claude en dos funciones del mismo módulo de Node.js.
  2. Añade un AbortController con timeout de 30 segundos a ambas llamadas para que una respuesta lenta no cuelgue tu servidor.
  3. Fuerza un error (por ejemplo, una key vacía) y verifica que tu función lo lanza como una excepción con un mensaje claro, sin exponer la key.

Resumen

  • Las APIs de IA son REST sobre HTTPS: JSON de entrada, JSON de salida y una key de autenticación.
  • OpenAI usa Authorization: Bearer y messages; Claude exige x-api-key y anthropic-version; Gemini usa contents/parts y key en la URL.
  • Unifica los tres proveedores detrás de una interfaz propia para poder cambiar de modelo sin reescribir tu código.
  • Reintenta solo ante 429 y 5xx, respetando retry-after; nunca ante errores de autenticación.
  • Usa timeouts en todas las llamadas: la IA debe degradarse, no congelar tu servicio.
