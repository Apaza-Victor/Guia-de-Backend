Clasificación de texto con IA

🧠 Experto 12 min Backend para IA Módulo 4 · Clasificación y modelos de datos

Introducción

Un buzón de soporte recibe cientos de mensajes al día y cada uno debe ir al equipo correcto. La clasificación de texto convierte ese problema de contenido libre en una decisión de rutas: una categoría, un equipo, una acción.

En el backend la clasificación se delega normalmente a un modelo de lenguaje: defines un conjunto cerrado de categorías y el modelo asigna la más probable. El resultado es estable, se puede validar y se guarda junto al mensaje original.

Definición

La clasificación de texto asigna un documento o mensaje de entrada a una de entre varias categorías predefinidas, utilizando un modelo de lenguaje que devuelve la etiqueta más probable.

Por qué importa. Automatiza enrutado, moderación, priorización y analítica sin escribir reglas infinitas, y el resultado alimenta tablas, colas y dashboards.

Cuándo usarlo. Usa clasificación cuando tienes un conjunto de categorías conocido y estable. No lo uses para categorías que cambian cada hora o que no conoces de antemano: ahí mejor extracción abierta.

Conceptos clave

  • Categorías cerradas: lista fija de etiquetas conocidas por el modelo.
  • Zero-shot: el modelo clasifica categorías nuevas sin entrenamiento previo.
  • Few-shot: incluyes ejemplos en el prompt para fijar el formato.
  • Umbral de confianza: por debajo de él se deriva a revisión humana.
  • Etiqueta normalizada: forzamos valores canónicos, no texto libre.

Ejemplo básico

Lo más simple que se puede hacer en producción: una única llamada que devuelve la categoría.

Ejemplo intermedio

Forzamos categorías válidas y añadimos ejemplos few-shot para que el modelo no invente etiquetas.

Ejemplo real

En producción la clasificación vive dentro de un servicio con caché, validación y derivación a humano.

  • Normaliza la salida a minúsculas y valida contra las categorías permitidas.
  • Usa una caché por hash del mensaje para no pagar dos veces lo mismo.
  • Deriva a un humano los casos ambiguos o con baja confianza.

Combina la caché con una cola para los casos derivar_humano y que un moderador los revise.

Explicación

  • El modelo no piensa: asigna probabilidades de secuencia guiadas por el prompt de sistema.
  • temperature=0 reduce la aleatoriedad y estabiliza la salida entre llamadas.
  • Validar contra el conjunto cerrado protege el esquema de tu base de datos.
  • La caché por hash del texto ahorra coste y latencia cuando el mismo mensaje se reenvía.
  • Medir precisión sobre un golden set te dice si el umbral de derivación es correcto.

Errores comunes

  • Aceptar la salida sin validar: el modelo puede devolver Facturacion en vez de facturacion.
  • No fijar temperature: la misma entrada devuelve categorías distintas en cada llamada.
  • No derivar a humano: los errores de clasificación se acumulan en silencio.

Buenas prácticas

  • Usa etiquetas en minúsculas y sin acentos en el prompt y traduce solo en la interfaz.
  • Registra siempre entrada, etiqueta y modelo para auditar decisiones.
  • Empieza con 3-5 categorías y añade más solo cuando se repitan de verdad.

Ejercicio

  1. Clasifica comentarios de una app en bug, feature y duda con el mismo patrón.
  2. Cambia el prompt para pedir la categoría en mayúsculas y normalízala con .lower().
  3. Añade una regla manual que fuerce spam cuando el mensaje contenga una URL.

Resumen

  • La clasificación con LLM convierte texto libre en una etiqueta de un conjunto cerrado.
  • Zero-shot y few-shot permiten clasificar sin entrenamiento propio.
  • Validación, caché y derivación humana hacen la clasificación apta para producción.
