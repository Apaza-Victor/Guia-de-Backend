RAG con contexto empresarial en producción

🧠 Experto 12 min Backend para IA Módulo 6 · RAG y búsqueda semántica

Introducción

RAG es el puente entre la información de tu empresa y la fluidez del modelo: primero recuperas los fragmentos relevantes de tu base vectorial y luego le pides al modelo que responda citando ese contexto.

La calidad del RAG depende de cada eslabón: qué fragmento recuperas, en qué orden, y cómo redacta el modelo con esos datos.

Definición

RAG (Retrieval Augmented Generation) recupera fragmentos relevantes de un corpus propio y los inserta en el prompt para que el modelo genere una respuesta fiel a esa información.

Por qué importa. Reduce alucinaciones, permite responder sobre datos actualizados y quita del modelo la presión de memorizar tu dominio.

Cuándo usarlo. Úsalo cuando debas responder sobre documentos propios o información cambiante. No lo uses para preguntas genéricas de conocimiento: ahí el modelo va sobrado.

Conceptos clave

  • Recuperación: la búsqueda semántica inicial sobre el corpus.
  • Reranking: reordenar el candidato por relevancia fina.
  • Prompt de sistema con las fuentes y sus citas.
  • Umbral de corte: solo responder si hay contexto suficiente.
  • Preguntas irrelevantes: el sistema debe decir que no sabe.

Ejemplo básico

El pipeline mínimo: embebemos la pregunta, buscamos y generamos con las fuentes.

Ejemplo intermedio

Pedimos al modelo que cite el fragmento usado para poder auditar la respuesta.

Ejemplo real

En producción un RAG bien diseñado reordena candidatos, corta por umbral y responde que no sabe cuando falta contexto.

  • Aplica reranking sobre los candidatos vectoriales.
  • Corta la respuesta con plantilla si lo recuperado es irrelevante.
  • Guarda pregunta, fuentes y respuesta para evaluar después.

Mide con un golden set de preguntas-referencia para comparar versiones del pipeline.

Explicación

  • La búsqueda semántica recupera candidatos; el reranking refina el orden final.
  • El umbral evita inventar sobre fragmentos marginales.
  • Citar fuentes hace auditable la respuesta y facilita la evaluación.
  • El modelo debe mandar al contexto: más contexto, menos alucinación.
  • Evaluar por preguntas reales con referencias es la única forma de mejorar.

Errores comunes

  • Poner contexto sin fuentes: el modelo 'cita' datos que no ha visto.
  • Saltarse el umbral y responder a lo que no hay.
  • Usar el RAG para preguntas cualquiera que el modelo ya domina.

Buenas prácticas

  • Empieza con preguntas de tus clientes reales como golden.
  • Registra cada turno: pregunta, fuentes, umbral y respuesta.
  • Actualiza el corpus cuando cambie la documentación.

Ejercicio

  1. Monta el pipeline mínimo con diez artículos y prueba tres preguntas.
  2. Añade reranking con un modelo pequeño y compara con orden original.
  3. Crea un golden set de diez preguntas y mide aciertos con y sin umbral.

Resumen

  • RAG combina recuperación semántica y generación con contexto.
  • Umbral, reranking y citas convierten el pipeline en auditable.
  • Un golden set de preguntas reales mide la mejora continua.
