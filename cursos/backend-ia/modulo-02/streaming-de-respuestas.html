Streaming de respuestas

🧠 Experto 10 min Backend para IA Módulo 2 · Features con IA

Introducción

Un LLM genera la respuesta token a token, y el usuario lo nota como espera. Un chat sin streaming muestra el texto completo de golpe después de 5–15 segundos de silencio; con streaming, las primeras palabras llegan en menos de un segundo y el texto «se escribe solo». La percepción de velocidad cambia por completo.

El mecanismo es sencillo: tu backend activa el streaming en el proveedor, recibe los tokens en vivo y los reenvía al navegador usando Server-Sent Events (SSE), un flujo HTTP unidireccional perfecto para esto.

Server-Sent Events: el transporte

SSE es texto plano sobre HTTP con el header Content-Type: text/event-stream. Cada evento se delimita con data: y una línea en blanco. El navegador lo consume nativamente con EventSource; no necesitas bibliotecas de WebSocket.

HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

data: {"token": "Hola", "done": false}

data: {"token": ", ¿en", "done": false}

data: {"token": "qué", "done": false}

data: {"done": true}

El último evento marca el fin (done: true) con el token de uso real para facturar y loguear. Esa pieza final es clave: con streaming no puedes conocer los tokens usados hasta que termina el flujo.

Consumir el stream del proveedor en Node

Primero activas stream: true en la llamada al proveedor y lees los chunks SSE que llegan, extrayendo el fragmento de texto de cada uno:

async function* generarStream(mensajes) {
  const res = await fetch('https://api.openai.com/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`
    },
    body: JSON.stringify({
      model: 'gpt-4o-mini',
      messages: mensajes,
      stream: true
    })
  });

  if (!res.ok || !res.body) throw new Error(`LLM ${res.status}`);

  for await (const chunk of res.body) {
    const linea = new TextDecoder().decode(chunk);
    for (const pieza of linea.split('\n')) {
      if (!pieza.startsWith('data:')) continue;
      const data = pieza.slice(5).trim();
      if (data === '[DONE]') return;
      const json = JSON.parse(data);
      const token = json.choices[0]?.delta?.content;
      if (token) yield token;
    }
  }
}

Observa el patrón: una función generadora que yield cada token a medida que llega. Es la forma más limpia de conectar el stream del proveedor con el stream de salida de tu API.

Reenviar como SSE en Express

Ahora el endpoint de tu API consume ese generador y escribe cada token en la respuesta, que el cliente lee como un EventSource:

app.post('/api/chat', async (req, res) => {
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');

  const mensajes = [/* historial + pregunta del usuario */];

  try {
    for await (const token of generarStream(mensajes)) {
      res.write(`data: ${JSON.stringify({ token })}\n\n`);
    }
    res.write(`data: ${JSON.stringify({ done: true })}\n\n`);
  } catch (err) {
    res.write(`data: ${JSON.stringify({ error: err.message })}\n\n`);
  } finally {
    res.end();
  }
});

Importante: configura proxies (nginx) con buffering desactivado y el timeout del servidor por encima de la duración esperada del stream. Si algo corta la conexión, el cliente simplemente reconecta con EventSource y pide de nuevo.

El cliente: EventSource en 10 líneas

const ev = new EventSource('/api/chat-stream'); // usa GET con tu contexto
const caja = document.getElementById('respuesta');

ev.onmessage = (evento) => {
  const datos = JSON.parse(evento.data);
  if (datos.done) {
    ev.close();
    return;
  }
  caja.textContent += datos.token;   // se va escribiendo en vivo
};

ev.onerror = () => {
  // el cliente reconecta solo; muestra "reconectando..." en la UI
};

EventSource se reconecta automáticamente cuando se corta la conexión. Eso transforma los fallos de red en «un pequeño tic» en vez de una experiencia rota.

Ejercicio

  1. Modifica tu cliente LlmClient para aceptar stream: true y devolver un generador de tokens.
  2. Crea un endpoint POST /api/chat (Node o Python) que reenvíe los tokens por SSE terminando con un evento done que incluya los tokens usados.
  3. Consume el stream desde el navegador con EventSource (o con la librería de tu framework de front) y verifica que el texto aparece progresivamente.

Resumen

  • El streaming reduce drásticamente la latencia percibida: el texto llega token a token.
  • SSE es el transporte ideal: texto plano sobre HTTP con Content-Type: text/event-stream.
  • En el proveedor se activa con stream: true; tu backend reenvía los tokens en el momento.
  • EventSource en el navegador se reconecta solo: los cortes se degradan bien.
  • El evento final debe traer los tokens usados para loguear y facturar.
