Agentes y herramientas

🧠 Experto 10 min Backend para IA Módulo 2 · Features con IA

Introducción

Un LLM por sí solo solo genera texto. Para que «haga cosas» —consultar tu base de datos, calcular un impuesto, verificar un pedido— necesitas el patrón de agente con herramientas: el modelo decide cuál de tus funciones llamar, tu backend la ejecuta y devuelve el resultado, y el modelo continúa con esa información.

Técnicamente se llama function calling: describes cada herramienta como un esquema, y el modelo responde no con texto sino con una petición estructurada de llamada.

Definir herramientas con function calling

Cada herramienta se describe con su nombre, una descripción clara (el modelo elige según ella) y el esquema JSON de sus parámetros:

{
  "model": "gpt-4o-mini",
  "messages": [
    { "role": "system", "content": "Eres el asistente de la tienda. Cuando necesites datos, usa las herramientas." },
    { "role": "user", "content": "¿Salió mi pedido 998? Y dime cuánto cuesta enviarlo mañana." }
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "consultar_pedido",
        "description": "Obtiene el estado y la fecha estimada de un pedido por su id.",
        "parameters": {
          "type": "object",
          "properties": {
            "pedido_id": { "type": "string", "description": "Identificador del pedido" }
          },
          "required": ["pedido_id"]
        }
      }
    },
    {
      "type": "function",
      "function": {
        "name": "calcular_envio",
        "description": "Calcula el coste y tiempo de envío para una dirección.",
        "parameters": {
          "type": "object",
          "properties": {
            "direccion": { "type": "string" }
          },
          "required": ["direccion"]
        }
      }
    }
  ]
}

Las descripciones son las que «enseñan» al modelo cuándo usar cada herramienta. Descripciones vagas producen llamadas equivocadas; sé específico sobre cuándo y para qué usar cada una.

El bucle del agente (tool loop)

El flujo se repite hasta que el modelo responde texto normal: si responde con una tool_call, ejecutas la función, le devuelves el resultado como mensaje de rol tool y vuelves a preguntarle.

async function ejecutarAgente(conversacion, herramientas, maxVueltas = 5) {
  const registro = { ejecuciones: 0 };

  while (registro.ejecuciones < maxVueltas) {
    const respuesta = await llm.completarConTools(conversacion, herramientas);
    const llamada = respuesta.choices[0];

    if (llamada.finish_reason !== 'tool_calls') {
      return llamada.message.content;            // el agente terminó en texto
    }

    for (const tool of llamada.message.tool_calls) {
      const nombre = tool.function.name;
      const args = JSON.parse(tool.function.arguments);
      const resultado = herramientas[nombre](args);   // EJECUTA tu código

      conversacion.push({
        role: 'tool',
        tool_call_id: tool.id,
        content: JSON.stringify(resultado)
      });
    }
    conversacion.push(llamada.message);
    registro.ejecuciones++;
  }

  throw new Error('El agente superó el límite de vueltas');
}

El límite de vueltas es obligatorio: sin él, un agente que no encuentra lo que busca puede llamar herramientas infinitamente y disparar tu factura. Trata este bucle como a un while sobre una API externa: siempre con tope y con timeout.

Seguridad: el agente solo pide, tú ejecutas

La regla de oro es que el modelo jamás ejecuta operaciones reales: solo propone llamadas estructuradas. Toda ejecución pasa por tu código, donde aplicas permisos, validación y autorización:

from typing import Callable

def herramienta_protegida(func: Callable, puede_ejecutar: Callable):
    """
    Envuelve una herramienta para exigir autorización y validación
    antes de tocar cualquier dato real.
    """
    def wrapper(args: dict):
        usuario = extraer_contexto(args)
        if not puede_ejecutar(usuario):
            return {"error": "sin_permisos"}
        if not validar_esquema(args):
            return {"error": "argumentos_invalidos"}
        return func(args)
    return wrapper

herramientas = {
    "cancelar_pedido": herramienta_protegida(
        cancelar_pedido,
        puede_ejecutar=lambda usuario: rol_de(usuario) == "admin"
    )
}

Modelo mental: el LLM es solo el que pregunta. Nunca confíes en que validará bien, nunca le des credenciales, y recuerda que «los tokens que trata de meter el usuario» son datos — no hacks.

Orquestación y límites

  • Herramientas de solo lectura primero: consultas y búsquedas son baratas y seguras; las mutaciones exigen confirmación.
  • Auditoría: loguea siempre qué herramienta pidió el agente, con qué argumentos y qué devolvió.
  • Máximo tiempo: combina el tope de vueltas con un timeout global del agente.
  • Streaming de pasos: envía al cliente los avisos «consultando pedido...» como eventos SSE.
  • Escala: una arquitectura de agente real se separa en orquestador (decide) y ejecutores (hacen). No mezcles todo en la ruta.

Ejercicio

  1. Define dos herramientas (por ejemplo, buscar_producto y calcular_total_con_impuesto) en formato JSON.
  2. Implementa el bucle del agente con un máximo de 4 vueltas y un mapa de herramientas reales.
  3. Pide al agente algo que requiera ambas herramientas en secuencia y verifica que encadena las llamadas correctamente.

Resumen

  • Un agente = LLM que elige herramientas + tu código que las ejecuta + bucle de vuelta al modelo.
  • Las herramientas se describen con nombre, descripción y esquema de parámetros (function calling).
  • El bucle termina cuando el modelo responde texto, y siempre lleva tope de vueltas y timeout.
  • El modelo solo propone llamadas; las operaciones las ejecuta y autoriza tu backend.
  • Audita cada llamada de herramienta y separa orquestación de ejecución a escala.
