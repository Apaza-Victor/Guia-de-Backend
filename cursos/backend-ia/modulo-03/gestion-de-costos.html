Gestión de costos

🧠 Experto 11 min Backend para IA Módulo 3 · Producción de IA

Introducción

La IA se paga por uso: cada token de entrada y de salida cuesta dinero, y cada llamada multiplica el gasto. Un chatbot sin control puede costar cientos de dólares el primer mes sin que nadie lo note. La gestión de costos no es contabilidad: es una disciplina de backend tan importante como la latencia.

Aquí verás el flujo completo: medir, cachear, limitar y alertar.

Estimar el coste de cada llamada

El coste unitario se calcula con los precios por token del proveedor y la cantidad exacta de tokens. La librería de tokenización del proveedor te da la medición real de tu prompt:

import tiktoken

PRECIO = {
    "gpt-4o-mini": {"entrada": 0.00015, "salida": 0.00060},  # USD por 1k tokens
}
MODELO = "gpt-4o-mini"

encoding = tiktoken.encoding_for_model(MODELO)

def costo_estimado(mensajes, max_salida_tokens):
    entrada = sum(len(encoding.encode(m["content"])) for m in mensajes)
    tarifas = PRECIO[MODELO]
    costo_entrada = entrada / 1000 * tarifas["entrada"]
    costo_salida = max_salida_tokens / 1000 * tarifas["salida"]
    return costo_entrada + costo_salida

mensajes = [
    {"role": "system", "content": "Eres un asistente de reservas."},
    {"role": "user", "content": "Busca un vuelo a Madrid para el viernes."},
]
print(f"Coste estimado por llamada: ${costo_estimado(mensajes, 500):.5f}")
# Coste estimado por llamada: $0.00054

Con el coste por llamada estimado puedes proyectar tu facturación: multiplica por el volumen esperado de usuarios y por sus conversaciones promedio. Esa cifra decide qué modelo usas (un mini cuesta centésimas de un flagship) y dónde conviene cachear.

Cachear respuestas repetidas

Muchas preguntas se repiten (FAQ, documentación, errores comunes). Cachear una completion idéntica es el arma de ahorro más rápida: la primera llamada paga tokens; las demás, cero. La clave del caché es el prompt completo, así el modelo no se re-ejecuta dos veces por el mismo input.

import { createClient } from 'redis';

const redis = createClient();
await redis.connect();

function claveDeCache(mensajes, modelo) {
  return `llm:${modelo}:${JSON.stringify(mensajes)}`;
}

async function responderConCache(mensajes, modelo) {
  const clave = claveDeCache(mensajes, modelo);
  const cacheado = await redis.get(clave);
  if (cacheado) return { contenido: cacheado, desdeCache: true };

  const contenido = await llm.completar(mensajes, { modelo });
  await redis.set(clave, contenido, { EX: 24 * 3600 }); // 24 horas
  return { contenido, desdeCache: false };
}

Combina el caché por prompt con un TTL corto cuando el dato de referencia cambia: la factura de una feature que pregunta siempre lo mismo puede desplomarse un 80%.

Límites por usuario y rate limiting

Un solo usuario agresivo o un script malicioso puede quemar tu presupuesto en horas. Los límites por usuario son un contrato de costos: tokens por minuto, llamadas por día, presupuesto mensual por cuenta.

const MAX_TOKENS_DIA_POR_USUARIO = 100_000;

async function presupuestarTokens(usuarioId, tokensGastados) {
  const actual = Number(await redis.get(`tokens-dia:${usuarioId}`)) || 0;
  const nuevoTotal = actual + tokensGastados;

  if (nuevoTotal > MAX_TOKENS_DIA_POR_USUARIO) {
    throw new Error('Llegaste al límite diario de uso del asistente.');
  }

  await redis.set(`tokens-dia:${usuarioId}`, nuevoTotal, { EX: 24 * 3600 });
}

// En cada llamada real: descuenta los tokens reales de la respuesta
const data = await llm.completar(mensajes, { modelo });
await presupuestarTokens(usuario.id, data.usage.total_tokens);

Usa los tokens reales de la respuesta (usage.total_tokens), no la estimación. Introduce aquí también los rate limits de HTTP clásicos: una llamada cada X segundos por usuario evita los bucles de retry del cliente.

Presupuesto y alertas

Define topes por entorno y día, y haz que tu backend avise cuando se acerca a ellos. Las alertas tempranas convierten una sorpresa de fin de mes en una decisión de esta tarde.

# Presupuesto diario en variables de entorno (dashboard de observabilidad)
export IA_PRESUPUESTO_DIARIO_USD=25
export IA_ALERTA_AL="80"           # % del presupuesto que dispara aviso
export IA_ALERTA_MAX="100"         # % que corta tráfico nuevo

# Un cron corre cada 5 min:
#   > Presupuesto diario (USD) tomado de ausage + log de tokens.
#   > Si gasto/alerta >= 80  -> aviso a Slack
#   > Si gasto/alerta >= 100 -> edge activa un circuit breaker de la llamada al LLM

El corte automático al 100% es un circuit breaker: una feature de IA debe degradarse (mensaje «dame tiempo») antes que arruinar la factura mensual. Combina la alerta con un tablero que muestre costo por feature y por usuario.

Ejercicio

  1. Calcula el coste estimado de 5 prompts de tu proyecto con costo_estimado y compara el total del día con un volumen hipotético de 1000 usuarios.
  2. Implementa un caché de respuestas en Redis con TTL y mide cuántas llamadas reales te ahorras con 10 preguntas repetidas.
  3. Añade el límite diario de tokens por usuario y escribe una alerta que se dispare a 80% del presupuesto diario.

Resumen

  • El coste se estima con tokens reales del prompt y precios por modelo, y se proyecta por volumen de uso.
  • El caché de completions elimina el pago de preguntas repetidas.
  • Los límites por usuario (tokens por día, llamadas por minuto) protegen tu presupuesto.
  • Alerta al 80% y corte automático al 100%: la IA debe degradar antes que endeudarte.
  • Los datos reales para medir siempre vienen de usage de la respuesta.
