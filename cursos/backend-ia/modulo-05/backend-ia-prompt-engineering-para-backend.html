Prompt engineering para tareas de backend

🧠 Experto 11 min Backend para IA Módulo 5 · IA generativa y LLMs

Introducción

El prompt es la interfaz más frágil de tu sistema: un cambio de redacción puede alterar el resultado sin que el compilador se queje. Por eso se gestiona como código, con versiones y tests.

En el backend los prompts se centralizan en plantillas, se rellenan con datos validados y se prueban contra casos conocidos antes de desplegar.

Definición

Prompt engineering es el diseño sistemático de las instrucciones que recibe un modelo para que la salida sea predecible y reutilizable.

Por qué importa. Un prompt bien diseñado reduce coste, alucinaciones y trabajo de postprocesado, y se puede versionar y probar.

Cuándo usarlo. Aplícalo siempre que el prompt se reutilice en producción. Para confirmaciones ad hoc, basta un prompt razonable y una revisión humana.

Conceptos clave

  • Sistema + usuario: reglas fijas y contexto variable separados.
  • Plantillas: placeholders rellenados con datos validados.
  • Few-shot: ejemplos canónicos para fijar el formato.
  • Restricciones negativas: que NO debe hacer el modelo.
  • Registros de prompt: versión usada por cada respuesta.

Ejemplo real

En un sistema real el prompt vive en versiones y cada respuesta guarda qué versión generó ese resultado.

  • Versiona los prompts en el repositorio junto al código.
  • Guarda el prompt renderizado en los logs para auditar decisiones.
  • Prueba el prompt con un golden set antes de desplegarlo.

Un prompt roto cuesta lo mismo en un fallo que un bug: tiene que pasar revisión y tests.

Explicación

  • Las instrucciones del sistema se respetan más que el prompt de usuario mezclado.
  • Los ejemplos few-shot anclan el formato mejor que las descripciones largas.
  • Las restricciones negativas reducen variaciones inesperadas en la salida.
  • Rellenar plantillas con datos validados evita inyección en el prompt.
  • Versionar prompts permite revertir a la versión que funcionaba.

Errores comunes

  • Interpolar datos sin escapar: cualquier texto del usuario entra a tu sistema.
  • Mezclar instrucciones y datos en un mismo bloque giant.
  • Cambiar prompts sin tests y sin golden set, a ciegas.

Buenas prácticas

  • Mantén el prompt más impersonal y corto que consiga el objetivo.
  • Empieza por la descripción del resultado esperado, no del proceso.
  • Añade un campo verificar que el modelo responda al formato.

Ejercicio

  1. Versiona tu prompt de clasificación y añade un log de la versión usada.
  2. Escribe un test con diez mensajes y sus etiquetas esperadas.
  3. Refactoriza el prompt para que deje de usar exactas alignm.

Resumen

  • El prompt se gestiona como código: plantillas, versiones y tests.
  • Separar sistema, contexto y ejemplos estabiliza la salida.
  • Guardar la versión de prompt en logs permite auditar y revertir.
