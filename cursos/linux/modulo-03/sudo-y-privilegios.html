sudo y privilegios

💻 Básico 9 min Linux y Terminal para Backend Módulo 3 · Usuarios, permisos y procesos

Introducción

Operar como root todo el tiempo convierte cualquier fallo de tipeo en una tragedia del sistema. Linux ofrece sudo: elevar privilegios con puntualidad y dejando rastro en los logs.

Con sudo, tu usuario pide permisos administrativos comandándose, y el sistema registra quién ejecutó qué.

Definición

sudo ejecuta un solo comando con privilegios de root previa verificación de contraseña. Es la herramienta estándar para administrar sin loguearse como root.

Por qué importa. Principio de mínimo privilegio: operas como usuario normal y elevas solo cuando un comando lo requiere, con auditoría.

Cuándo usarlo. Usa sudo para tareas de administración (instalar paquetes, editar config del sistema). Para trabajo normal, ni lo pienses.

Conceptos clave

  • sudo comando ejecuta ese comando como root.
  • sudo -u otrousuario comando ejecuta como otro usuario.
  • El archivo /etc/sudoers lista quién puede usar sudo.
  • Visudo es la forma segura de editar sudoers.
  • sudo -i abre una shell de root puntual y rastreable.

Ejemplo básico

Renovar paquetes y gestionar un servicio requieren elevación puntual.

Cada comando se ejecuta con privilegios de root y queda registrado en el log de sudo.

Ejemplo intermedio

Damos a un usuario la capacidad de reiniciar un servicio sin root completo.

Ejemplo real

El acceso de despliegue típico: tu usuario solo reinicia la app, no toca el resto del sistema.

  • Configura sudoers con comandos específicos, nunca ALL sin límite.
  • Revisa los logs de sudo (journalctl _COMM=sudo) periódicamente.
  • Deshabilita el login de root por SSH: entra con tu usuario y sudo.

Puedes desactivar la contraseña en sudoers con NOPASSWD para scripts de CI, siempre limitada a comandos concretos.

Explicación

  • sudo valida tu contraseña y consulta /etc/sudoers.
  • La lista de reglas define usuario, host, usuario destino y comandos.
  • Cada ejecución queda en el log con la marca de tiempo.
  • sudo -l muestra qué comandos puedes elevar.
  • Nunca entres con root por SSH: usa sudo puntual.

Errores comunes

  • Dejar a un usuario en sudoers con ALL: permisos de root completo.
  • Editar sudoers sin visudo y romper la sintaxis.
  • Usar sudo para comandos triviales y acostumbrar el password en scripts.

Buenas prácticas

  • Comienza con NOPASSWD y comandos concretos para automatizaciones.
  • Mantén el login root deshabilitado en sshd_config.
  • Audita los logs de sudo en cada revisión de seguridad.

Ejercicio

  1. Muestra qué puedes ejecutar con sudo -l.
  2. Añade una regla sudoers que permita reiniciar un servicio.
  3. Consulta los logs de sudo del último día.

Resumen

  • sudo eleva privilegios de forma puntual y registrada.
  • sudoers limita qué comandos puede elevar cada usuario.
  • Usuario normal + sudo puntual supera al login root de siempre.
