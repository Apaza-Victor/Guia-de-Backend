Gestión de usuarios y grupos

💻 Básico 10 min Linux y Terminal para Backend Módulo 3 · Usuarios, permisos y procesos

Introducción

Cada servicio, cada proceso del backend trabaja bajo una identidad: un usuario con su propio espacio y sus permisos. Crear personas y cuentas de servicio de forma ordenada es la base del control de acceso.

Linux separa usuario, grupo y contraseña en unos pocos archivos que los comandos useradd, usermod, groupadd y passwd administran por ti.

Definición

Un usuario tiene un nombre, un UID, un home y un shell. Un grupo agrupa usuarios para compartir permisos. useradd crea, usermod modifica, groupadd crea grupos y passwd fija la contraseña.

Por qué importa. La multitarea de Linux: un VPS con varios servicios necesita una identidad por servicio para que un compromiso de uno no arrastre al resto.

Cuándo usarlo. Crea un usuario por persona o por servicio (deploy, app, postgres). No uses root cuando un usuario dedicado puede bastar.

Conceptos clave

  • useradd -m -s /bin/bash usuario crea con home y shell.
  • passwd usuario fija o cambia la contraseña.
  • usermod -aG grupo usuario añade a un grupo suplementario.
  • groupadd y gpasswd gestionan los grupos.
  • Los ids viven en /etc/passwd, /etc/group y /etc/shadow.

Ejemplo básico

Creamos un usuario de despliegue con su home y contraseña.

Ejemplo intermedio

Añadir un usuario a un grupo y a sudo para concederle privilegios.

Ejemplo real

En un servidor real, cada servicio corre con su propio usuario: www-data para Nginx, postgres para la base de datos, deploy para tu aplicación.

  • Usa usuarios de servicio sin login y con home mínima.
  • Nunca des a los procesos más privilegios de los necesarios.
  • Revoca accesos eliminando usuarios o sacándolos de grupos.

Auth logs y el historial del shell te ayudan a auditar quién entró al servidor: revisa los logs con regularidad.

Explicación

  • Los usuarios se almacenan en /etc/passwd; las contraseñas hasheadas en /etc/shadow.
  • El UID 0 es root; el resto de usuarios tienen ids desde 1000.
  • Un grupo primario y varios suplementarios definen los permisos.
  • useradd -r crea usuarios de sistema sin login.
  • Para los servidores, menos cuentas interactivas significa menos superficie de ataque.

Errores comunes

  • Crear usuarios con contraseñas vacías o extremadamente débiles.
  • Usar root para todo, en vez de sudo puntual.
  • Olvidar -m y quedarte sin home para el usuario.

Buenas prácticas

  • Password-lock los usuarios de servicio: passwd -l.
  • Guarda las claves públicas SSH en ~/.ssh/authorized_keys.
  • Elimina usuarios inactivos en cuanto deje de necesitarlos.

Ejercicio

  1. Crea un usuario monitor con shell y un home.
  2. Añádelo a un grupo admins y compruébalo con getent.
  3. Crea un usuario de servicio sin login y verifica que no puede entrar.

Resumen

  • Un usuario por persona y por servicio mantiene el control de acceso.
  • Grupos y sudo distribuyen privilegios sin recurrir a root para todo.
  • Los archivos /etc/passwd y /etc/shadow guardan las identidades.
