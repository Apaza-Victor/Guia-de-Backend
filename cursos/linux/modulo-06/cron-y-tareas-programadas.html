cron: tareas programadas

💻 Básico 10 min Linux y Terminal para Backend Módulo 6 · Scripting y automatización

Introducción

El backup nocturno, la limpieza de logs del domingo, el check de salud de cada hora: tareas que nadie debe lanzar a mano. El cron las dispara solo.

Cronex dirige la tabla de tareas de tu usuario, y cada línea define minuto, hora, día, mes y el comando que se ejecuta.

Definición

cron ejecuta comandos según una tabla de tiempos: cinco campos de tiempo (minuto, hora, día de mes, mes, día de semana) más el comando, listados en crontab.

Por qué importa. La operación quieta del servidor está llena de rutinas. Programarlas en cron libera al equipo y garantiza que se ejecuten aunque nadie recuerde.

Cuándo usarlo. Usa cron para periodicidades simples (diarias, horarias). Para calendarios complejos o con arranques fallidos, considera systemd timers.

Conceptos clave

  • crontab -e edita la tabla de tu usuario.
  • crontab -l lista; crontab -r borra.
  • Los campos: minuto hora dia mes diaSemana.
  • * significa 'todos los valores'.
  • Los scripts de cron siempra redirigen salidas y errores.

Ejemplo real

Las tareas de cron usan environment mínimos: pon rutas absolutas y redirección de logs o el script fallará sin dejar rastro.

  • Rutas absolutas en los comandos (el PATH no es completo).
  • Redirige la salida si no quieres spam de correo.
  • Dale ejecución y prueba el script a mano primero.

Las variables de entorno de cron no incluyen tu .bashrc: si tu script depende de algo, definelo dentro del propio script o envía el PATH explícito.

Explicación

  • Los cinco campos de tiempo coordinan minuto, hora, día y mes.
  • La ruta del comando debe ser absoluta en crontab.
  • La salida se redirige para no depender del correo.
  • crontab -T valida la sintaxis sin aplicarla.
  • El check de logs verifica que cron está ejecutando.

Errores comunes

  • Comandos con PATH relativo y cron que 'no ejecuta'.
  • Sin redirección, la salida llega al correo y nadie la ve.
  • Editar /etc/crontab sin el campo de usuario.

Buenas prácticas

  • Prueba tu script a mano antes de montarlo en cron.
  • Logs por tarea: nunca adivines si cron corrió.
  • Empieza con horarios simples y ajusta.

Ejercicio

  1. Añade una tarea que haga ping cada hora y loguee.
  2. Programa tu backup con redirección a un log.
  3. Valida la sintaxis de tu crontab con crontab -T.

Resumen

  • cron ejecuta tareas según una tabla de tiempos.
  • Rutas absolutas y logs por tarea evitan el cron 'fantasma'.
  • Los scripts de operación se prueban antes de programar.
