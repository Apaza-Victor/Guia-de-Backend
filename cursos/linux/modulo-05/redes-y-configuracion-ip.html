Redes y configuración IP

💻 Básico 10 min Linux y Terminal para Backend Módulo 5 · Redes y servicios

Introducción

Un servidor sin red no es un servidor: cada petición HTTP llega por una interfaz con su IP. Cuando el servidor 'no responde', a menudo el problema está en la capa de red.

ip a muestra tus interfaces, ping mide la ruta y ss lista los puertos escuchando. Con ellas diagnosticas la conectividad puerto a puerto.

Definición

La red se organiza en interfaces (eth0, ens3) con direcciones IP, máscaras y una puerta de enlace. ip configura y consulta; ping comprueba alcance; ss repta puertos y conexiones.

Por qué importa. La conectividad es el primer sospechoso de cualquier incidente: desde la IP hasta el puerto del servicio, cada salto se diagnostica con estas herramientas.

Cuándo usarlo. Usa ip address para ver la IP, ping para probar alcance, ss -tlnp para saber qué puertos escuchan y qué proceso los sirve.

Conceptos clave

  • ip addr (ip a) muestra las interfaces y sus IPs.
  • ping host comprueba el alcance por ICMP.
  • ss -tlnp lista sockets TCP en escucha con su proceso.
  • La puerta de enlace (default) dirige el tráfico hacia fuera.
  • curl y nc prueban la capa de aplicación de un puerto.

Ejemplo real

Si la app no responde: ¿es la red o es el servicio? Se corta el problema en capas.

  • Primero ping al host, luego prueba el puerto.
  • ss te dice quién escucha: quizá el puerto está gratis.
  • El firewall (ufw/iptables) puede bloquear sin avisar.

Entre un 'no anda desde mi casa' y un 'anda en el servidor' siempre hay un firewall o una IP mal configurada. Cortá capa por capa.

Explicación

  • ip addr describe interfaces: IPv4, IPv6 y estado de la placa.
  • ping mide la latencia y el alcance por ICMP.
  • ss -tlnp junta puerto, estado y proceso.
  • nc es la prueba de puerto TCP 'a pelo'.
  • El diagnóstico en capas evita horas de devolución de culpas.

Errores comunes

  • Pingar IPs hacia fuera y sospechar de la red cuando el puerto ni escucha.
  • Olvidar el firewall (ufw) y no ver el puerto externamente.
  • Confundir IP privada y pública del provedor.

Buenas prácticas

  • Aprende ss antes que netstat: es el estándar moderno.
  • Probar con timeout y nc para no colgarte en un puerto cerrado.
  • El orden: red -> escucha -> firewall -> puerto.

Ejercicio

  1. Lista tus interfaces y su IP con ip addr.
  2. Comprueba puertos en escucha y quién los sirve.
  3. Averigua si el puerto 80/443 está protegido por firewall.

Resumen

  • ip, ping y ss diagnostican red, alcance y puertos.
  • El firewall es el filtro invisible entre tu servicio y la red.
  • Diagnosticar en capas resuelve 'no responde' en minutos.
