Contenerizar y desplegar el portafolio

🔥 Avanzado 12 min Proyectos Backend Módulo 4 · Del portafolio al proyecto real

Introducción

Un proyecto que solo existe en tu máquina es un boceto. El portafolio despega el día que tu API responde en una URL pública: alguien puede probarla, un reclutador puede abrirla y tú puedes dormir sabiendo que el despliegue también es parte de tu habilidad.

El camino estándar: Docker para empaquetar, una VPS pequeña para correr y un proxy inverso para entregar tráfico con HTTPS. Todo reproducible y versada.

Definición

Desplegar un proyecto es hacer que su código corra de forma estable y accesible fuera de tu máquina, idealmente reproducible con contenedores y un proceso simple de actualización.

Por qué importa. El despliegue demuestra las competencias de DevOps que hoy se piden en todos los roles de backend.

Cuándo usarlo. Despliega el primer proyecto en cuanto el CRUD base funcione; el despliegue temprano obliga a la calidad operativa desde el inicio.

Conceptos clave

  • La imagen Docker empaqueta código, dependencias y entorno.
  • El VPS da un hogar fijo a tus servicios.
  • El proxy inverso (Nginx) entrega desde el servidor hasta el cliente.
  • El HTTPS se obtiene con el certificado automático (Let's Encrypt).
  • Las variables de entorno separan secretos de código.

Ejemplo real

Un ingeniero acaba su API de tareas y la despliega en una VPS de 5 dólares con Docker Compose y Nginx. En el README escribe el despliegue: `docker compose up -d`, un certificado con Let's Encrypt y un CNAME al dominio. El entrevistador lo abre, crea una tarea y llama a un compañero: es la diferencia entre un repo y un producto.

  • Fija la imagen de la base en versiones concretas.
  • Expón el API solo al proxy inverso, no al mundo.
  • Deja tu script de despliegue en el README o en un Makefile.

Ejecuta el despliegue primero en un VPS de prueba; los errores suceden una vez y se aprenden.

Explicación

  • El contenedor reproduce el entorno en cualquier máquina.
  • El proxy inverso suma HTTPS, compresión y cabe en un solo puerto.
  • Las variables de entorno mantienen los secretos fuera del repositorio.
  • El despliegue reproducible permite volver a montar el proyecto desde cero.
  • El VPS educa en lo que luego verás en la nube sin cortinas.

Errores comunes

  • Subir secretos al repositorio y exponerlos en los logs.
  • Exponer la base de datos a Internet sin protección.
  • Correr el servicio como root y sin restart policy.

Buenas prácticas

  • Usa Docker Compose para el stack completo y Nginx como proxy.
  • Nunca pongas secretos en código: usa variables de entorno.
  • Automatiza el HTTPS con Let's Encrypt en cuanto tengas el dominio.
  • Escribe un Makefile con los comandos del despliegue.

Ejercicio

  1. Conteneriza tu API con un Dockerfile de dos etapas.
  2. Levanta el stack con Compose y accede solo vía Nginx.
  3. Despliega en un VPS con HTTPS y dominio propio.

Resumen

  • El despliegue en contenedores hace reproducible a tu proyecto.
  • El proxy inverso y HTTPS entregan el tráfico con seguridad.
  • Un proyecto desplegado vale más que diez repos en local.
