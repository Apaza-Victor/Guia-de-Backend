Conectando a PostgreSQL con pg

⚙️ Intermedio 11 min Node.js desde cero hasta avanzado Módulo 5 · Bases de datos con Node

Introducción

La mayoría de los backends terminan guardando su estado en una base de datos relacional. Con Node, el cliente estándar para PostgreSQL es pg.

pg ofrece dos modos: el Client para una conexión puntual y el Pool para reutilizar conexiones. Esta lección arranca con lo básico: conectar y ejecutar la primera consulta.

Definición

pg es el driver oficial de PostgreSQL para Node. Con new Client o new Pool y un objeto de configuración (host, port, database, user, password) ejecutas consultas mediante métodos que devuelven promesas.

Por qué importa. Persistir tus datos con un driver probado y promesas de serie te permite querying seguro y estructurado sin salir del ecosistema Node.

Cuándo usarlo. Usa Client para scripts puntuales y Pool para servidores en producción que reciben muchas peticiones por segundo.

Conceptos clave

  • npm install pg añade el driver al proyecto.
  • new Client() abre una conexión única para scripts.
  • client.query(sql, params) devuelve una promesa con rows.
  • Las credenciales viven en variables de entorno, no en el código.
  • El parámetro connectionString agrupa toda la configuración.

Ejemplo real

Cada petición HTTP pide datos: la conexión se abre una vez y el query se ejecuta con parámetros para no perderla ni exponerla.

  • Cierra el cliente en scripts; en un servidor reutiliza el Pool.
  • Nunca interpoles valores en el SQL: usa parámetros.
  • Saca las credenciales a variables de entorno.

Abrir y cerrar conexión por petición es caro. Este patrón es didáctico; en servidores reales usarás un Pool (siguiente lección).

Explicación

  • pg devuelve filas en el array rows de cada resultado.
  • Los parámetros $1, $2 evitan la inyección SQL.
  • El callback de errores en la promesa evita promesas sin catch.
  • client.end() libera la conexión en scripts cortos.
  • connectionString es el estándar de despliegues gestionados.

Errores comunes

  • Olvidar client.end() y dejar procesos colgados en scripts.
  • Hardcodear la contraseña en el archivo versionado.
  • Interpolar valores en el SQL (inyección a la vista).

Buenas prácticas

  • Usa connectionString y variables de entorno desde el inicio.
  • Parse loss ids con Number antes de query.
  • En un server, siempre Pool; ya verás por qué en la siguiente lección.

Ejercicio

  1. Conecta a una base local y muestra las tablas de tu esquema.
  2. Ejecuta una consulta parametrizada y observa rows.
  3. Mueve las credenciales a un archivo .env cargado en runtime.

Resumen

  • pg es el driver estándar de PostgreSQL para Node.
  • client.query devuelve promesas con filas en rows.
  • Las credenciales y la seguridad por parámetros mandan desde el día uno.
