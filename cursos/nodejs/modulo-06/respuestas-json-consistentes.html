Respuestas JSON consistentes

⚙️ Intermedio 9 min Node.js desde cero hasta avanzado Módulo 6 · APIs REST en Node

Introducción

El éxito y el error de tu API se leen igual: JSON con un formato estable. Cuando un error parece un éxito y un listado devuelve la mano a veces, el cliente sufre.

Una envoltura común (wrapper) define qué devolver siempre: datos, metadatos y errores con la misma estructura.

Definición

Una respuesta JSON consistente envuelve el contenido: { exito: true, datos: … } para líneas bien, y { exito: false, error: { codigo, mensaje } } para fallos, con el mismo Content-Type y códigos correctos.

Por qué importa. Un contrato de respuesta uniforme facilita el tipado del cliente, el manejo central de errores y la evolución de la API sin sorpresas.

Cuándo usarlo. Úsalo desde el primer endpoint. La consistencia se paga cara de corregir más tarde.

Conceptos clave

  • Envoltorio de datos: { exito: true, datos }.
  • Envoltorio de error: { exito: false, error: { codigo, mensaje } }.
  • El Content-Type: application/json se fija una vez.
  • Los códigos HTTP transportan el estado global.
  • Los listados añaden metadatos de paginación (total, página).

Ejemplo real

El formato común conviierte a las herramientas del cliente (axios, tipos) predecibles, y los errores de validación incluyen detalle con los campos.

  • Define el contrato en un README o en la spec OpenAPI.
  • Los errores 4xx detallan el campo; los 5xx ocultan internos.
  • Los códigos HTTP y la envoltura se complementan, no se contradicen.

Elige un esquema y adjúntalo a tu spec OpenAPI: el cliente copia y pega el tipo, y la API evoluciona con menos fricción.

Explicación

  • La envoltura unifica datos y errores en el mismo molde.
  • Los códigos HTTP y el cuerpo se complementan sin contradecirse.
  • Los metadatos (paginación) viajan dentro de datos, no aparte.
  • Los errores 4xx pueden detallar; los 5xx nunca filtran internos.
  • El formato se define una vez y se aplica del helper central.

Errores comunes

  • Mezclar formatos: a veces {data}, a veces el objeto pelado.
  • Devolver errores con stack o mensajes internos.
  • Ignorar los códigos HTTP y fingir éxitos en el cuerpo.

Buenas prácticas

  • Crea los helpers exito/error y úsalos en toda la API desde el día uno.
  • Documenta el envoltorio en OpenAPI como esquema común.
  • Mantén 404/422/500 con el mismo molde de error.

Ejercicio

  1. Crea los helpers exito/error en un módulo utils.
  2. Aplica el envoltorio a un listado con paginación.
  3. Asegura que un 404 use el mismo formato que un 422.

Resumen

  • La envoltura JSON unifica éxitos y errores en un formato estable.
  • Los metadatos de paginación viajan en datos.
  • El formato común se define una vez y se documenta.
