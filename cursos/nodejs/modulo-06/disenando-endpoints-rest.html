Diseñando endpoints REST

⚙️ Intermedio 10 min Node.js desde cero hasta avanzado Módulo 6 · APIs REST en Node

Introducción

Una API no se diseña en el teclado: se diseña con reglas. El estilo REST hace una API predecible cuando cada recurso responde a un patrón claro de recursos y verbos.

Las mejores APIs se leen como inglés: los recursos son sustantivos en plural y los verbos HTTP dicen qué hacer con ellos.

Definición

REST organiza la API por recursos (sustantivos en plural, /pedidos) y usa los verbos HTTP (GET, POST, PUT, PATCH, DELETE) para las operaciones: leer, crear, sustituir, actualizar o borrar.

Por qué importa. Un contrato coherente permite a cualquier cliente deducir el comportamiento sin documentación exhaustiva y facilita el mantenimiento del servidor.

Cuándo usarlo. Aplica este diseño a toda API HTTP nueva; las excepciones (acciones, RPC) se modelan como sub-recursos o con verbos propios y se documentan.

Conceptos clave

  • Recursos en plural: /pedidos, /clientes.
  • GET /recursos lista; GET /recursos/:id lee uno.
  • POST /crea; PUT /sustituye; PATCH /actualiza; DELETE /borra.
  • Las jerarquías: /pedidos/:id/lineas expresan pertenencia.
  • Los verbos de acción se evitan salvo casos justificados.

Ejemplo real

La jerarquía y la semántica bien empleadas hacen que un cliente sepa reaccionar sin leer el código de la API.

  • Nombra los recursos en plural y con foco en el dominio.
  • Usa 201 al crear, 204 al borrar, 404 si falta, 409 si hay conflicto.
  • Las acciones de negocio se modelan como sub-recursos (/pagar).

Si una acción no encaja en la semántica de recursos, pregúntate antes si estás modelando bien el dominio.

Explicación

  • Los sustantivos en plural describen colecciones de recursos.
  • Los verbos HTTP codifican la intención sin ambigüedad.
  • Las jerarquías expresan relaciones y no requieren query params extraños.
  • Los códigos de estado completan la semántica de cada respuesta.
  • La consistencia es más importante que la perfección teórica.

Errores comunes

  • Usar /obtenerPedidos o /listarPedidos: los verbos van en HTTP.
  • Mezclar plural/singular entre recursos del mismo dominio.
  • Devolver 200 en creaciones en vez de 201.

Buenas prácticas

  • Define la jerarquía pensando en cómo navegan los clientes.
  • Mantén una tabla de verbos y códigos visible en el repo.
  • Consistencia > opinión: elige un estilo y aplica.

Ejercicio

  1. Diseña el CRUD de un recurso nuevos (productos) con sus códigos.
  2. Modela una jerarquía pedido->lineas con sus endpoints.
  3. Revisa tu API y corrige verbos en URL o recursos en singular.

Resumen

  • REST usa recursos en plural y verbos HTTP para la intención.
  • Los códigos de estado completan la semántica de cada operación.
  • Las jerarquías de recursos expresan relaciones del dominio.
