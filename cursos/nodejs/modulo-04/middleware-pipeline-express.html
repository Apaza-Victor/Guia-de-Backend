El pipeline de middlewares

⚙️ Intermedio 11 min Node.js desde cero hasta avanzado Módulo 4 · Express avanzado

Introducción

Casi todo lo que hace una API Express ocurre dentro de funciones encadenadas: loguear, autenticar, parsear, responder. Cada una de esas funciones es un middleware.

El pipeline es una cebolla: la petición entra pasa capa por capa, y cada middleware decide si responde ya o llama a next() para continuar.

Definición

Un middleware es una función (req, res, next) que se registra con app.use y se ejecuta en orden para cada petición, pudiendo terminar la respuesta o delegar con next().

Por qué importa. Las preocupaciones transversales (logs, auth, CORS, parseo) se resuelven una vez por petición sin repetir código en cada ruta.

Cuándo usarlo. Usa middlewares para tareas en cada petición: logueo, compresión, autenticación, cabeceras. Las tareas específicas de una ruta quedan en su controlador.

Conceptos clave

  • app.use(middleware) registra una función que corre en cada petición.
  • next() continúa la cadena; sin next la petición queda colgada.
  • El orden importa: los middlewares se ejecutan en el orden registrado.
  • Un middleware responde o llama a next(), nunca ambas cosas.
  • app.use('/ruta', mw) limita el middleware a ese prefijo.

Ejemplo básico

Un middleware que loguea toda petición antes de llegar a la ruta.

GET / -> se imprime 'GET /' y responde {"ok":true}

Ejemplo intermedio

Middlewares que responden ellos mismos, como un gatekeeper de autenticación.

Ejemplo real

Un pipeline típico de producción: parseo, log, seguridad y rutas, cada pieza con un propósito y en el orden correcto.

  • Registra los middlewares globales antes de las rutas.
  • Pon el middleware específico justo en la ruta que lo necesita.
  • Responde con next(err) en errores para delegar al manejador central.

El middleware de error tiene CUATRO parámetros: su firma le dice a Express que es el manejador global de fallos.

Explicación

  • Cada petición recorre el pipeline en el orden en que registraste las capas.
  • next() sin argumentos continúa; next(err) salta directo al manejador de error.
  • Un middleware que no responde ni llama a next() cuelga la petición para siempre.
  • Las rutas son middlewares con verbo y ruta: Express las selecciona en la cola.
  • El orden correcto resuelve la mayoría de los bugs de middleware.

Errores comunes

  • Registrar rutas antes que los middlewares globales y no recibirlos.
  • Olvidar next() en un middleware: la petición se queda colgada.
  • Llamar a next() tras haber enviado la respuesta.

Buenas prácticas

  • Mantén cada middleware en una sola responsabilidad.
  • Usa app.use('/ruta', mw) para no enganchar middlewares a todo.
  • Pon el manejador de errores el último del pipeline.
  • Comprueba con curl -v que las cabeceras y el orden se cumplen.

Ejercicio

  1. Añade un middleware que mida y loguee la duración de cada petición.
  2. Protege la ruta /admin con un middleware que corte con 403 si no hay token.
  3. Reordena el pipeline y observa cómo cambia el comportamiento.

Resumen

  • Los middlewares encadenan el tratamiento de cada petición.
  • next() continúa, responder corta, next(err) salta a errores.
  • El orden de registro define el orden de ejecución.
