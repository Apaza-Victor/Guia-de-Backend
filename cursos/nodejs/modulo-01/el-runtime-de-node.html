El runtime de Node: V8 y APIs nativas

⚙️ Intermedio 10 min Node.js desde cero hasta avanzado Módulo 1 · Introducción a Node.js

¿Qué es un runtime?

Un runtime es el entorno que ejecuta tu código y le ofrece herramientas para interactuar con la máquina. El navegador es un runtime (con DOM, ventanas y eventos). Node.js es otro runtime: el mismo compilador de JavaScript, pero enfocado al servidor.

Suena simpático compararlo con un coche: el motor (V8) convierte el JavaScript en código de máquina, y el chasis y accesorios (libuv, módulos core) permiten circular: leer discos, escuchar red y lanzar procesos.

V8: el motor de Google

V8 es el motor que Google desarrolló para Chrome y que Node adoptó. Su función: traducir JavaScript a código nativo muy rápido (compilación JIT) y gestionar la memoria mediante su recolector de basura.

  • JIT: compila el código en caliente mientras se ejecuta, optimizando las rutas más usadas.
  • Gestión de memoria: el GC libera objetos que ya no se referencian, sin que tú lo hagas a mano.
  • Tipos: JavaScript no declara tipos, pero V8 los infiere y genera optimizaciones internas.

Puedes comprobarlo: un bucle de un millón de iteraciones en Node suele ejecutarse en milisegundos gracias a estas optimizaciones.

libuv: el sistema operativo en JavaScript

Node no se limita a V8. La biblioteca libuv (escrita en C) es la que conecta con el sistema operativo: gestiona el event loop, las operaciones de red asíncronas, el sistema de archivos, timers y un thread pool para tareas pesadas.

Gracias a libuv, cuando llamas a fs.readFile, Node no se queda esperando parado: le pide a libuv que lea el archivo en segundo plano y sigue ejecutando tu código. Cuando el archivo está listo, el resultado vuelve a la cola del event loop.

Las APIs nativas de Node

Sobre V8 y libuv, Node construye un conjunto de módulos core que cubren las necesidades clásicas de un servidor. Algunos de los más importantes:

  • fs: archivos y directorios.
  • http / https: servidores y clientes HTTP.
  • path: rutas y extensiones de archivos.
  • stream: lectura y escritura por flujos.
  • crypto: cifrado, hashes y generación segura de datos.
  • worker_threads: paralelismo real con varios hilos.

Ejercicio

  1. Ejecuta el bucle con console.time y anota cuántos milisegundos tarda tu máquina.
  2. Crea un archivo datos.txt, ejecuta el ejemplo de fs.readFile y observa el orden de las salidas en consola.
  3. Genera un UUID con crypto.randomUUID() y explícalo con palabras propias.
  4. Lista todas las APIs que recuerdes de este capítulo y para qué sirve cada una.

Resumen

  • Un runtime ejecuta tu código y le ofrece las herramientas del entorno.
  • V8 compila JavaScript a código nativo de forma optimizada.
  • libuv conecta Node con el sistema: event loop, red, archivos y timers.
  • Los módulos core (fs, http, crypto, stream…) son las APIs nativas de Node.
  • Las operaciones de E/S no bloquean: se piden en segundo plano y el resultado vuelve después.
