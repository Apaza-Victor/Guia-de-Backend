CommonJS y ES Modules

⚙️ Intermedio 10 min Node.js desde cero hasta avanzado Módulo 2 · Módulos y npm

¿Por qué existen dos sistemas de módulos?

Desde su nacimiento, Node usó CommonJS (require / module.exports): un estándar pensado para servidores. Años después, el estándar web ES Modules (import / export) se hizo omnipresente en el navegador, y Node terminó adoptándolo también.

Hoy puedes usar cualquiera de los dos. El proyecto moderno tiende a ES Modules, pero millones de paquetes siguen en CommonJS, así que conocer ambos es obligatorio en backend.

CommonJS: require y module.exports

Es el formato por defecto en .js dentro de Node. Carga los módulos de forma síncrona: el programa se detiene hasta que el archivo es leído y ejecutado.

Un detalle require es memorizado: si pides el mismo módulo dos veces, Node devuelve la misma copia (el archivo solo se ejecuta una vez). Eso da caché gratis, pero también estado compartido.

ES Modules: import y export

Es el estándar del lenguaje y del navegador. Sin embargo, hay una peculiaridad: para usar import en un archivo .js, Node necesita saber que tratas con ESM. Puedes indicarlo con la extensión .mjs o añadiendo "type": "module" en tu package.json.

En ESM las importaciones son estáticas: aparecen al principio del archivo y se resuelven antes de ejecutar nada. Esa restricción permite análisis y optimizaciones que CommonJS no ofrece.

Comparativa rápida

CaracterísticaCommonJSES Modules
Sintaxisrequire / module.exportsimport / export
CargaSíncronaEstática (al inicio)
Extensión.js (por defecto).mjs o "type": "module"
En navegadorNo (exclusivo de Node)Sí
Usado porPaquetes tradicionales de npmProyectos y paquetes modernos

Ninguno es "el malo". Regla práctica: si mantienes paquetes o herramientas antiguas, CommonJS; si creas algo nuevo, ES Modules.

Ejercicio

  1. Crea suma.js en CommonJS y úsalo desde app.js.
  2. Repite el mismo ejemplo en suma.mjs y app.mjs.
  3. Añade "type": "module" al package.json de un proyecto de prueba y confirma que require deja de funcionar.
  4. Responde: ¿en qué caso elegirías CommonJS deliberadamente?

Resumen

  • CommonJS usa require/module.exports; ES Modules usa import/export.
  • CommonJS carga en síncrono y memoriza los módulos cargados.
  • ES Modules es el estándar del lenguaje y del navegador.
  • Para ESM necesitas .mjs o "type": "module".
  • Proyectos nuevos abrazan ES Modules; heredarás CommonJS de muchas librerías.
