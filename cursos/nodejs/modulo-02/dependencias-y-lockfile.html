Dependencias y lockfile

⚙️ Intermedio 9 min Node.js desde cero hasta avanzado Módulo 2 · Módulos y npm

Los cuatro tipos de dependencias

El package.json separa las dependencias por finalidad, y cada categoría se instala o descarta según el contexto:

  • dependencies: lo que tu app necesita en producción (express, pg, bcrypt).
  • devDependencies: herramientas solo en desarrollo (nodemon, eslint, jest).
  • peerDependencies: paquetes que esperas que el consumidor aporte (plugins, por ejemplo).
  • optionalDependencies: funcionamiento opcional que no debe romper la instalación.

Al desplegar en producción se instala solo lo imprescindible con npm install --omit=dev (o NODE_ENV=production), lo que ahorra tiempo y espacio en el servidor.

node_modules y el árbol

Cuando instalas Express, npm también descarga las dependencias de Express (sus "hijos"). Todo termina en node_modules, que puede tener miles de archivos. Por eso node_modules nunca debe subirse a Git: cada quien lo regenera con npm install.

npm audit en particular es tu brújula de seguridad: revisa las dependencias contra la base de datos de vulnerabilidades y te sugiere actualizar o parchear.

package-lock.json: la memoria de las versiones exactas

El package.json dice "usa express 4.x". Pero x evoluciona: npm install hoy puede dejar una versión distinta que mañana. Para que todo el equipo (y la producción) instale exactamente lo mismo, npm genera package-lock.json, un mapa con las versiones exactas de todas las dependencias y sus subdependencias.

  • El lockfile se crea automáticamente al primer npm install.
  • Debe comprometerse al repositorio (es parte del contrato del equipo).
  • Cambia solo cuando alguien modifica dependencias; las diffs pequeñas son señal de instalaciones limpias.

El campo integrity es un hash (SRI) que garantiza que el archivo descargado no fue alterado.

Ejercicio

  1. Instala express en un proyecto y ejecuta npm ls --depth=1 para ver su árbol.
  2. Revisa el package-lock.json generado y localiza integrity de express.
  3. Ejecuta npm audit y anota el resumen de la salida.
  4. Explica por qué node_modules no debe entrar a Git, y el lockfile sí.

Resumen

  • dependencies, devDependencies, peerDependencies y optionalDependencies cubren cada caso.
  • Producción instala solo dependencies con --omit=dev.
  • El lockfile fija versiones exactas: se comparte, no se ignora.
  • node_modules no viaja en Git.
  • npm audit y npm outdated vigilan seguridad y frescura.
