Callbacks

⚙️ Intermedio 10 min Node.js desde cero hasta avanzado Módulo 3 · Asincronía avanzada

Qué es un callback

Un callback es una función que pasas a otra función para que se ejecute cuando termine. Es el mecanismo original de Node para la asincronía: "haz X y cuando termines, ejecuta esto".

El patrón error-first

Node estandarizó la firma de los callbacks: primer argumento, el error (si lo hay, o null); segundo, el resultado.

Este orden es un contrato: quien consuma tu API de callbacks sabe siempre qué espera. Ignorar el error es la fuente número uno de fallos silenciosos.

El callback hell

Cuando una operación depende de otra, los callbacks se anidan y el código avanza hacia la derecha formando la temida "pirámide de la perdición".

Identifica los tres males: legibilidad nula, errores repetidos a mano y casi imposible de probar. La comunidad respondió con promesas, primero con fs.promises y luego async/await.

Callbacks sin dolor

  • Nombra tus funciones: los callbacks anónimos esconden el stack en errores.
  • Chequea el error primero: sal siempre con return si hay error.
  • Achata: si necesitas tres niveles de anidamiento, es señal de que toca refactorizar a promesas.
  • Nunca ignores el argumento err: un (err) sin usar es un bug disfrazado.

Ejercicio

  1. Crea tu propia función de callback error-first que simule una consulta (usa setTimeout).
  2. Úsala consumiendo el resultado y gestionando el error con return.
  3. Copia el ejemplo del callback hell y anota sus tres problemas.
  4. Justifica con tus palabras por qué el error siempre va primero.

Resumen

  • Un callback es una función que se ejecuta cuando la operación termina.
  • El patrón error-first ordena err, result como argumentos.
  • El anidamiento excesivo genera callback hell: ilegible y frágil.
  • Nombra tus callbacks y gestiona siempre el error.
  • Las promesas (próxima lección) nacen para resolver esto.
