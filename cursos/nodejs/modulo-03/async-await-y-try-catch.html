async/await y try/catch

⚙️ Intermedio 10 min Node.js desde cero hasta avanzado Módulo 3 · Asincronía avanzada

La sintaxis que parece síncrona

async/await es azúcar sobre las promesas: declaras la función como async y usas await antes de una promesa para "pausarla" sin bloquear el hilo. El código queda liso y vertical, como si fuera síncrono.

Aviso importante: una función async siempre devuelve una promesa, aunque leas return "texto". Quien la llame deberá esperarla con await o encadenarla con then.

Errores con try/catch

El try/catch captura los rechazos de cualquier await dentro del bloque. Es la forma más legible de manejar errores que has visto hasta ahora.

Secuencial, y el error típico

Si usas varios await seguidos, se ejecutan en serie: cada uno espera al anterior. Si las operaciones no dependen entre sí, esperas inútiles se acumulan.

Regla práctica: usa await seriado solo cuando el segundo necesita datos del primero. Para el resto, Promise.all (próxima lección).

Los errores ocultos de async

  • Promesas sin manejar: una función async cuyo error no se captura lanza un rechazo no controlado (unhandledRejection). No lo dejes pasar.
  • setTimeout y try/catch: un error dentro de un callback asíncrono no cae en tu try; captúralo dentro del callback.
  • Top-level await: en ES Modules puedes usar await fuera de una función.

Ejercicio

  1. Convierte el ejemplo de copiarRegistro y añádele un tercer archivo en la cadena.
  2. Ejecuta el comparativo serie vs paralelo y anota los tiempos reales.
  3. Crea una función async con try/catch/finally y una operación que falle a propósito.
  4. Responde: ¿por qué una función async siempre devuelve una promesa?

Resumen

  • async/await lee como código síncrono y no bloquea el hilo.
  • try/catch centraliza los errores de los await.
  • finally ejecuta limpieza siempre.
  • Await seriado solo cuando hay dependencia real.
  • Nunca dejes un rechazo sin manejar.
