GitFlow y estrategias de flujo

💻 Básico 10 min Git y GitHub Módulo 2 · Ramas y merges

Las ramas son reglas de equipo

Una estrategia de ramas no es magia: es acuerdo. Qué rama es sagrada, quién fusiona, cuándo se libera. Sin reglas, cada quien hace su caos.

GitFlow clásico

GitHub Flow (el más usado hoy)

Trunk-based

¿Cuál elegir?

EquipoFlujo
1-5 personas, despliegue continuoGitHub Flow / trunk
Versiones planificadas, SO o apps empresarialesGitFlow
Releases con mantenimiento de ramas viejasGitFlow con hotfix

Reglas que siempre valen: main verde, PR revisados, ramas cortas, y eliminar ramas al fusionar.

Ejercicio

  1. Define el flujo de tu proyecto actual (si no hay, elige GitHub Flow).
  2. Escribe las 4 reglas de tu equipo en el README.
  3. Practica el ciclo completo feature → PR → main.

Resumen

  • Estrategia = acuerdo de equipo, no mandamiento.
  • GitFlow: develop + features + releases + hotfixes.
  • GitHub Flow: main + features que llegan por PR.
  • Trunk: integración corta al tronco con CI.
