Conflictos y cómo resolverlos

💻 Básico 10 min Git y GitHub Módulo 2 · Ramas y merges

Cuándo aparece un conflicto

Dos ramas modifican la misma línea de un archivo: Git no sabe cuál ganar y te lo marca. No es un error ni una catástrofe: es una pregunta que solo el humano responde.

El mensaje te dice dónde

Los marcadores del conflicto

  • <<<<<<< HEAD: tu versión actual.
  • =======: separador.
  • >>>>>>> feature/config: la versión entrante.

Resolver con criterio

Evitar conflictos (cuando se puede)

  • Ramas cortas: menos tiempo separadas, menos choques.
  • Re-fusiona main en tu feature a menudo.
  • Evita editar el mismo archivo en dos features a la vez.
  • Usa el merge/PR como lugar natural de resolución por pares.

Ejercicio

  1. Crea un conflicto a propósito y ábrelo con tu editor.
  2. Resuélvelo con la opción correcta y completa el merge.
  3. Practica git merge --abort antes de resolver.

Resumen

  • Conflicto = misma línea tocada por dos ramas.
  • Marcadores: HEAD, separador y rama entrante.
  • Elige, git add, git merge --continue.
  • --abort es tu red de seguridad.
