Ramas: por qué y para qué

💻 Básico 10 min Git y GitHub Módulo 2 · Ramas y merges

Una rama es un puntero

En Git, una rama no copia nada: es solo un puntero a un commit. Crear una rama cuesta cero, cambias de rama al instante y varios experimentos conviven sin molestarse. HEAD te dice en qué rama estás parado.

Dos ramas, dos realidades

Los tres usos típicos

  • Features: una rama por funcionalidad, se fusiona o muere.
  • Experimentos: romper sin miedo; si falla, la borras.
  • Hotfixes: parche urgente de producción aislado del resto.

Nombrar ramas con intención

Ejercicio

  1. Lista tus ramas con git branch y git branch -v.
  2. Crea feature/primera y haz un commit ahí.
  3. Regresa a main y confirma que no está tu cambio.

Resumen

  • Rama = puntero barato a un commit.
  • HEAD marca la rama activa.
  • Features, experimentos y hotfixes conviven.
  • Nombres claros: feature/, fix/, docs/, chore/.
