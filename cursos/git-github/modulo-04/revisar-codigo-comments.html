Revisar código y comentarios

💻 Básico 10 min Git y GitHub Módulo 4 · Colaboración y PR

La revisión se regala

Revisar código es generosidad con barra de tiempo: lees el trabajo de otra persona para que el código del equipo sea mejor. El tono importa tanto como el contenido.

Lista mental del revisor

El tono de un comentario

Las tres salidas

  • Approve: listo, adelante.
  • Request changes: hay algo que debe arreglarse antes de fusionar.
  • Comment: dudas y sugerencias que no bloquean.

Como autor: los comentarios no son ataques. Responde con cortesía, corrige lo sensato y discute lo que no conviendas a medias verdades.

Ejercicio

  1. Haz una review real: abre un PR ajeno y deja 2 comentarios.
  2. Pide review de tu propio PR con una lista de puntos concretos.
  3. Responde a una petición de cambios con una solución.

Resumen

  • Revisar = leer con intención y respeto.
  • Comentarios: el porqué y una alternativa.
  • Approve / request changes / comment.
  • Autor y revisor juegan al mismo equipo.
