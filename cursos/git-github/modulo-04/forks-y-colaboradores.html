Forks y colaboradores

💻 Básico 10 min Git y GitHub Módulo 4 · Colaboración y PR

Dos caminos para colaborar

En GitHub hay dos formas de tocar un proyecto: dentro del equipo (colaborador con push, o branch protected obligando PR) o desde fuera (fork del repo, sin permiso, vía pull request).

El flujo fork + PR

Proteger las ramas

Ejercicio

  1. Haz fork de una librería que uses en GitHub.
  2. Clónalo y añade el remoto upstream.
  3. Actualízalo con git merge --ff-only upstream/main.

Resumen

  • Fork: copia del repo para contribuir sin permiso.
  • Colaborador: acceso directo, a menudo con ramas protegidas.
  • Ramas protegidas = PR + aprobaciones + CI.
  • upstream es el repo original, origin el tuyo.
