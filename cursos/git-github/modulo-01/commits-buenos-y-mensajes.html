Commits buenos y mensajes

💻 Básico 10 min Git y GitHub Módulo 1 · Fundamentos de Git

El commit atómico

Un commit ideal contiene un solo cambio lógico y deja el proyecto en un estado funcional. "Todo lo que tocó hoy" no sirve: más tarde, cuando un bug aparece, no sabrás cuál de tus 40 cambios lo causó.

El commit es tu firma

El autor (quien escribió) y el committer (quien lo selló) salen de tu configuración global/local. Un buen hábito: commits pequeños y frecuentes, verificables con git blame cuando preguntes "quién tocó esta línea y por qué".

Ejercicio

  1. Reescribe 3 de tus últimos commits con mensajes Conventional Commits (puedes usar git commit --amend en el último).
  2. Visualiza git log --oneline --graph.
  3. Separa un commit "del día" en dos atómicos con git restore --staged.

Resumen

  • Un cambio por commit, siempre funcional.
  • Conventional Commits: tipo + alcance + importancia.
  • git log --oneline --graph lee la historia.
  • Commits pequeños = git blame útil.
