PDO: conexión y configuración

⚙️ Intermedio 10 min PHP desde cero hasta avanzado Módulo 5 · Base de datos con PDO

Introducción

Antes de consultar datos necesitas hablar con la base de datos de forma estable y segura. PDO (PHP Data Objects) es la extensión estándar que unifica el acceso a MySQL, PostgreSQL y SQLite con la misma API.

Una conexión bien configurada deja de ser un problema: define el DSN, el modo de errores y el juego de caracteres de una sola vez.

Definición

PDO es la capa de abstracción de acceso a bases de datos de PHP. Una conexión se crea con new PDO(dsn, usuario, contraseña, opciones): el DSN describe el driver, host, base de datos y charset.

Por qué importa. Consolidar la conexión en una sola configuración evita credenciales repetidas, errores tácitos y problemas de codificación con texto acentuado.

Cuándo usarlo. Úsalo siempre que tu aplicación necesite MySQL, PostgreSQL o SQLite. La misma interfaz funciona para los tres motores.

Conceptos clave

  • El DSN: mysql:host=...;dbname=...;charset=utf8mb4.
  • PDO::ERRMODE_EXCEPTION convierte errores SQL en excepciones.
  • ATTR_DEFAULT_FETCH_MODE define el formato de las filas por defecto.
  • Las conexiones persistentes (ATTR_PERSISTENT) amortizan el handshake.
  • Las credenciales vienen de variables de entorno, nunca del código fuente.

Ejemplo real

En un servicio real, la conexión se crea una vez (por ejemplo en el arranque de tu API) y se inyecta donde haga falta, nunca se cierra en cada petición.

  • Crea la conexión en un único punto y compártela por inyección.
  • Nunca pongas credenciales reales en un archivo versionado.
  • Usa utf8mb4 para que emojis y acentos se guarden sin pérdidas.

PDO lanza PDOException en errores de conexión. Captúrala en la frontera (bootstrap) para responder 500 con datos de diagnóstico internos.

Explicación

  • El DSN define el motor y los parámetros de conexión en una sola cadena.
  • ERRMODE_EXCEPTION evita que los errores SQL pasen desapercibidos.
  • FETCH_ASSOC devuelve filas como arrays asociativos, cómodas para JSON.
  • Las conexiones se cierran al finalizar el script; no es necesario llamar a close.
  • Una conexión por proceso, inyectada, es el patrón estándar en frameworks y APIs.

Errores comunes

  • Olvidar charset=utf8mb4 y mostrar '?' en lugar de acentos y emojis.
  • Poner credenciales en el código y filtrarlas en un commit público.
  • Dejar los errores en modo silencioso (PDO::ERRMODE_SILENT).

Buenas prácticas

  • Configura el DSN y opciones una sola vez en un único lugar.
  • Usa sockets Unix o localhost así evitas tráfico en la red.
  • Saca las credenciales a variables de entorno desde el primer día.

Ejercicio

  1. Cambia el charset de tu DSN a utf8mb4 y guarda un texto acentuado.
  2. Refactoriza tu conexión a un singleton con variables de entorno.
  3. Fuerza un error de conexión y captura la PDOException.

Resumen

  • PDO unifica el acceso a MySQL, PostgreSQL y SQLite con una sola API.
  • El DSN, ERRMODE_EXCEPTION y utf8mb4 configuran una conexión sana.
  • La conexión se crea una vez y se inyecta, nunca se replica por el código.
