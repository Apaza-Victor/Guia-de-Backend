Consultas preparadas con parámetros

⚙️ Intermedio 12 min PHP desde cero hasta avanzado Módulo 5 · Base de datos con PDO

Introducción

Interpolar valores del usuario directamente en el SQL es el atajo que más bases de datos ha tumbado. La inyección SQL sigue siendo una de las vulnerabilidades más explotadas del backend.

PDO trae la solución de serie: las consultas preparadas separan el SQL del dato y dejan que el motor las compile con parámetros.

Definición

Una consulta preparada envía al motor el SQL con marcadores (named :param o posicional ?) y luego ejecuta la consulta pasando los valores por separado. El motor trata los parámetros como datos, nunca como código SQL.

Por qué importa. Elimina de raíz la inyección SQL: ningún valor puede alterar la estructura del comando, y además la consulta se compila una vez y se reutiliza con distintos datos.

Cuándo usarlo. Usa preparadas siempre que el SQL contenga un valor que provenga del exterior: formularios, query params, cuerpos JSON o cualquier entrada no confiable.

Conceptos clave

  • prepare() prepara el SQL y devuelve un PDOStatement.
  • execute([...]) pasa valores con marcadores named (:id) o posicionales.
  • bindValue()/bindParam() vinculan valores o referencias antes de ejecutar.
  • Los marcadores nunca van entre comillas: PDO se encarga del escaping.
  • Una consulta preparada se prepara una vez y se ejecuta muchas veces.

Ejemplo real

Un repositorio de búsqueda que se prepara una vez y se ejecuta miles de veces por petición: esa es la receta de un servicio que toca la base de datos sin miedo.

  • Prepara una vez y reutiliza el statement para volúmenes grandes de datos.
  • Usa bindParam para reutilizar el statement con valores que cambian en cada iteración.
  • Nunca aceptes nombres de columna o tabla como parámetros: esa parte se valida/mapea aparte.

Los parámetros named y posicionales no se mezclan en una misma consulta. Un error de sintaxis en el SQL lanza PDOException a menos que ejecutes en modo silencioso.

Explicación

  • La preparación envía plan y tipos al motor; los valores viajan después como datos.
  • bindParam vincula por referencia: lo que cambies en la variable se usa al ejecutar.
  • bindValue copia el valor en el momento de llamar.
  • El escape se delega en el motor, evitando el clásico bug de comillas escapadas.
  • No uses comillas alrededor de los marcadores: el motor las maneja según el tipo.

Errores comunes

  • Concatenar $id directamente en el SQL: puerta abierta a la inyección.
  • Mezclar :named y ? en la misma consulta.
  • Pasar un parámetro usado dos veces con marcadores posicionales duplicados.

Buenas prácticas

  • Trata todo dato del usuario como no confiable: siempre por parámetro.
  • Usa nombres explícitos (:email, :pais) en consultas largas.
  • Mapea los nombres de columnas dinámicos a una lista blanca.

Ejercicio

  1. Reescribe una consulta con concatenación para usar parámetros named.
  2. Crea una función que busque por email usando una consulta preparada.
  3. Reutiliza un statement con bindParam para insertar tres registros.

Resumen

  • Las consultas preparadas separan el SQL del dato y ganan la batalla a la inyección.
  • execute() con arrays nombra los parámetros y PDO vuela.
  • Prepara una vez y reutiliza para ejecutar muchas variaciones de un dato.
