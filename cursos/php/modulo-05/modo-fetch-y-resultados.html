Modo fetch: asociativo, objeto y clase

⚙️ Intermedio 9 min PHP desde cero hasta avanzado Módulo 5 · Base de datos con PDO

Introducción

Una consulta devuelve filas, pero el backend las necesita como estructura: arrays para JSON, objetos para el dominio o instancias de una clase de modelo.

PDO resuelve esta decisión en el momento de leer: el mismo result set puede materializarse de varias formas según el modo de fetch.

Definición

El modo de fetch decide cómo se convierte cada fila de un resultado: FETCH_ASSOC a array asociativo, FETCH_OBJ a objeto genérico, FETCH_CLASS a instancias de una clase u FETCH_COLUMN a un único valor escalar.

Por qué importa. Definir el formato de salida en un solo punto simplifica el resto del código: la capa de servicio no tiene que transformar ni adivinar la forma de los datos.

Cuándo usarlo. Usa FETCH_ASSOC para consumir por índice, FETCH_CLASS para hidratar modelos de dominio y FETCH_COLUMN para listas de un solo campo.

Conceptos clave

  • PDO::FETCH_ASSOC devuelve cada fila como array asociativo.
  • PDO::FETCH_OBJ devuelve objetos estándar con propiedades públicas.
  • PDO::FETCH_CLASS instancia una clase y le asigna las propiedades por fila.
  • FETCH_CLASS requiere el nombre de la clase; constructor y propiedades se respetan.
  • fetchAll() devuelve todas las filas; fetch() devuelve una cada vez.

Ejemplo básico

Consultamos productos y los recuperamos como arrays asociativos listos para JSON.

Array
(
    [0] => Array
        (
            [id] => 1
            [nombre] => Teclado
        )
    ...
)

Ejemplo intermedio

Hidratar una clase de dominio con FETCH_CLASS mantiene tu modelo tipado y sin SQL pegado.

Ejemplo real

Una lista de ids o de emails se resuelve con FETCH_COLUMN en una sola línea, evitando transformaciones manuales en el servicio.

  • Establece un modo por defecto (FETCH_ASSOC) en la conexión.
  • Para hidratación de dominio, usa FETCH_CLASS con modelos sin lógica SQL.
  • Las consultas grandes: procesa con fetch() en bucle en lugar de fetchAll().

Si tu consulta devuelve muchas filas, iterar con fetch() en lugar de fetchAll() limita la memoria: el cursor se consume de a una fila.

Explicación

  • FETCH_ASSOC da arrays: la forma más directa para json_encode.
  • FETCH_OBJ produce objetos dinámicos útiles para estructuras efímeras.
  • FETCH_CLASS rellena propiedades declaradas, respetando su tipado.
  • Los modos por defecto se configuran en la conexión o por statement.
  • fetchAll(FETCH_COLUMN) devuelve una lista plana de un campo.

Errores comunes

  • Esperar objetos con FETCH_ASSOC y acceder con ->.
  • Usar FETCH_CLASS sobre clases sin propiedades públicas o con constructor que requiere args.
  • Cargar con fetchAll() tablas gigantes y agotar la memoria.

Buenas prácticas

  • Fija ATTR_DEFAULT_FETCH_MODE a FETCH_ASSOC en la conexión.
  • Usa fetch() con bucle para volúmenes grandes.
  • Mantén los modelos de dominio libres de lógica de base de datos.

Ejercicio

  1. Consulta una tabla y muéstrala como JSON usando FETCH_ASSOC.
  2. Hidrata una clase Usuario con FETCH_CLASS desde una fila.
  3. Extrae una lista de emails con FETCH_COLUMN en una línea.

Resumen

  • El modo de fetch decide la forma de cada fila: array, objeto o clase.
  • FETCH_ASSOC alimenta JSON; FETCH_CLASS hidrata el dominio.
  • fetch() iterativo controla la memoria en resultados grandes.
