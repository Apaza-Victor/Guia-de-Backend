Composer: autoload y PSR-4

⚙️ Intermedio 11 min PHP desde cero hasta avanzado Módulo 6 · APIs y servicios

Introducción

Gestionar dependencias a mano, descargando zip y pegando archivos, no escala. Composer es el gestor de paquetes de PHP: instala librerías, las versiona y resuelve sus dependencias.

Su autoload PSR-4 hace que tus propias clases se carguen solas siguiendo el namespace, sin require manuales.

Definición

Composer es el gestor de dependencias de PHP que instala paquetes desde Packagist y genera un autoloader (vendor/autoload.php). PSR-4 mapea namespaces a carpetas para cargar cada clase bajo demanda.

Por qué importa. Sin autoload, cada archivo que añades exige recargar manualmente require; con PSR-4 la estructura de carpetas reemplaza la gestión manual y el proyecto crece sin fricción.

Cuándo usarlo. Usa Composer en cualquier proyecto PHP que quiera crecer. PSR-4 debe ser el estándar de tu propia organización, junto a 'vendor/' ignorado por git.

Conceptos clave

  • composer init crea composer.json interactivamente.
  • La sección autoload.psr-4 mapea 'Tienda\\' a 'src/'.
  • vendor/autoload.php se incluye una vez en el front controller.
  • composer install instala desde composer.lock; composer update lo renueva.
  • --no-dev y --classmap-authoritative sirven para producción.

Ejemplo real

El despliegue en producción corre composer install --no-dev --optimize-autoloader para instalar solo lo necesario y generar un mapa de clases rápido.

  • Versiona composer.lock para reproducir las mismas versiones en todos.
  • Instala dependencias de producción con --no-dev.
  • Optimiza el autoloader con --optimize-autoloader o --classmap-authoritative.

composer.lock fija versiones exactas: es el archivo que garantiza que tu deploy se comporta como tu local.

Explicación

  • PSR-4 liga el namespace a la ruta de archivo: Tienda\Controladores → src/Controladores.
  • vendor/autoload.php se incluye una vez y registra todos los cargadores.
  • composer.lock congela las versiones instaladas para reproducirlas.
  • --classmap-authoritative desactiva la búsqueda dinámica y acelera en prod.
  • gitignore a vendor/ y reinstálalo en cada despliegue con composer install.

Errores comunes

  • Olvidar require vendor/autoload.php y recibir class not found.
  • Commitear vendor/ (o lo contrario: no reproducir las instalaciones).
  • Confundir composer update (renueva lock) con composer install (respeta lock).

Buenas prácticas

  • Organiza src/ por módulos: Controladores, Servicios, Repositorios.
  • Escribe dos puntos de fuga en PSR-4 si mezclas librerías antiguas.
  • Corre composer dump-autoload tras añadir carpetas o namespaces.

Ejercicio

  1. Inicializa composer.json y mueve una clase a src/ con PSR-4.
  2. Instala una librería (p.ej. vlucas/phpdotenv) y úsala en tu proyecto.
  3. Prepara un composer install --no-dev reproducible desde git clone y lock.

Resumen

  • Composer instala y versiona dependencias desde Packagist.
  • PSR-4 autoload carga cualquier clase según su namespace sin require manuales.
  • composer.lock + --no-dev garantizan deploys reproducibles y rápidos.
