Serializando JSON desde PHP

⚙️ Intermedio 10 min PHP desde cero hasta avanzado Módulo 6 · APIs y servicios

Introducción

El JSON es el idioma del backend moderno: como lo devuelvas, lo consumirán apps, frontends y terceros. PHP lo serializa en una llamada, pero el diablo está en los detalles de formato.

Dominar json_encode con sus flags y el patrón JsonSerializable te permite exponer exactamente los campos y la forma que cada cliente necesita.

Definición

json_encode() transforma arrays, objetos y escalares a una cadena JSON, con flags como JSON_UNESCAPED_UNICODE o JSON_THROW_ON_ERROR. La interfaz JsonSerializable deja definir qué se expone de cada objeto.

Por qué importa. Una API cuyo JSON se serializa mal (acentos escapados, errores silenciosos, campos internos filtrados) se convierte en bugs difíciles de rastrear en el cliente.

Cuándo usarlo. Usa json_encode en cada respuesta, JsonSerializable en los modelos de dominio que no quieras exponer tal cual, y JSON_THROW_ON_ERROR en el arranque.

Conceptos clave

  • JSON_UNESCAPED_UNICODE conserva los acentos legibles.
  • JSON_PRETTY_PRINT da formato legible en entornos de desarrollo.
  • JSON_THROW_ON_ERROR lanza JsonException ante datos no serializables.
  • json_decode($cadena, true) devuelve arrays asociativos.
  • JsonSerializable::jsonSerialize() decide qué campos del objeto se emiten.

Ejemplo real

Con JsonSerializable, el modelo de dominio decide qué campos expone y cuáles se quedan dentro (contraseñas, internos).

  • Nunca serialices el modelo completo con campos internos.
  • Mapea a la forma pública deseada dentro de jsonSerialize().
  • Usa JSON_THROW_ON_ERROR para no devolver JSON vacío por error.

json_encode de un objeto DateTime sin serializarlo devuelve false o un objeto raro; configura su formato o expón un DTO.

Explicación

  • Los flags controlan acentos, formateo y manejo de errores de json_encode.
  • JSON_THROW_ON_ERROR evita el JSON vacío silencioso.
  • JsonSerializable define la vista pública de cada objeto.
  • Los DTOs son la alternativa a exponer el dominio crudo.
  • Los null cuentan: decide si tus campos opcionales aparecen o no.

Errores comunes

  • Omitir JSON_UNESCAPED_UNICODE y devolver \u00f3 en lugar de ó.
  • Serializar recursos o closures: JSON_THROW_ON_ERROR lo destapa.
  • Exponer el hash de contraseña por serializar el modelo al completo.

Buenas prácticas

  • Habilita JSON_THROW_ON_ERROR y JSON_UNESCAPED_UNICODE en toda la API.
  • Siempre Document the schema público en un DTO o en jsonSerialize.
  • Usa JSON_PRETTY_PRINT solo en desarrollo: en producción pesa de más.

Ejercicio

  1. Serializa un array con acentos y prueba ambos flags.
  2. Define jsonSerialize en una clase Pedido que oculte el campo totalBruto.
  3. Captura un JsonException cuando serializas algo inválido.

Resumen

  • json_encode con flags controla el formato y el manejo de errores.
  • JsonSerializable expone la vista pública de tus modelos.
  • JSON_THROW_ON_ERROR convierte errores silenciosos en excepciones visibles.
