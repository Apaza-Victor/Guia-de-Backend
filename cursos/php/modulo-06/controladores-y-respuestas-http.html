Controladores y respuestas HTTP

⚙️ Intermedio 11 min PHP desde cero hasta avanzado Módulo 6 · APIs y servicios

Introducción

El controlador es la pieza que conecta la petición con el dominio: recibe datos validados, llama al servicio y decide la respuesta. Su contrato de salida (código + cuerpo) define la calidad de tu API.

Una respuesta coherente —201 al crear, 404 al faltar algo, formato JSON siempre— es lo que hace predecible a un backend.

Definición

Un controlador es una clase (o callable) que recibe la petición ya enrutada, delega en servicios y devuelve una respuesta HTTP: un código de estado, cabeceras y un cuerpo serializado.

Por qué importa. Centralizar la respuesta (código, cabeceras, cuerpo) hace la API consistente y fácil de consumir por cualquier cliente.

Cuándo usarlo. Usa un controlador por recurso o por grupo de acciones; mantén el verbo HTTP como la acción y el recurso como la clase.

Conceptos clave

  • El controlador no toca la base de datos: delega en un servicio o repositorio.
  • http_response_code() fija el código de estado de la respuesta.
  • header() define cabeceras como Content-Type y Cache-Control.
  • El cuerpo JSON se genera con json_encode.
  • La estructura del controlador: validar, invocar, responder.

Ejemplo básico

Un controlador mínimo que lista pedidos y responde con JSON y el código adecuado.

Ejemplo intermedio

Separamos la construcción de la respuesta con un pequeño helper para no repetir cabeceras.

Ejemplo real

Un controlador REST de verdad valida su entrada, llama al servicio inyectado y decide el código por el resultado, sin conocer el SQL.

  • Inyecta el servicio por el constructor: el controlador solo orquesta.
  • Elige el código por el resultado: 200 para listados, 201 al crear.
  • Responde siempre JSON, también en los errores.

El controlador no responde HTML ni redirige: un API solo necesita JSON y códigos. That separation keeps el backend consumible por apps y frontends.

Explicación

  • Validar, invocar y responder es el ciclo que mantiene el controlador corto.
  • Los códigos de estado transportan el resultado; el cuerpo lo complementa.
  • El controlador inyecta su servicio: testable y sin dependencias ocultas.
  • Respuestas siempre JSON, incluso en errores, simplifican al cliente.
  • Un helper de respuesta evita repetir header/echo/exit en cada método.

Errores comunes

  • Responder siempre 200 y ocultar los errores en el cuerpo.
  • Pegar consultas SQL en el controlador.
  • Olvidar el Content-Type y devolver JSON como texto plano.

Buenas prácticas

  • Elige el código por el resultado: crear=201, vacío válido=200, inválido=422.
  • Un método por acción de verbo mantiene las clases pequeñas.
  • Serializa al final con una función json() única para toda la API.

Ejercicio

  1. Añade un método detalle a un controlador con 404 controlado.
  2. Devuelve 201 al crear y 422 si falta un campo obligatorio.
  3. Refactoriza tus respuestas a un helper json(codigo, cuerpo).

Resumen

  • El controlador valida, invoca al servicio y decide la respuesta.
  • Los códigos y el JSON unificados hacen la API predecible.
  • La inyección de servicios mantiene el controlador testable y fino.
