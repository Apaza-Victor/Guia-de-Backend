Repository y acceso a datos

🔥 Avanzado 10 min Arquitectura de Software Módulo 3 · Patrones

Introducción

La base de datos es un detalle de implementación, no parte del negocio. El patrón Repository media entre el dominio y la persistencia: expone operaciones como si fueran de una colección en memoria (obtener, buscar, guardar) y esconde SQL, ORM y conexiones.

El beneficio grande: la lógica de negocio habla un idioma de colección y puede testearse sin base de datos real.

El contrato del repositorio

Un repositorio se declara como interfaz en el «borde interior» de tu arquitectura:

La interfaz usa términos del dominio (Pedido), no términos de base de datos. Su implementación concreta (Eloquent, Doctrine, PDO) vive en la infraestructura.

Implementación concreta

Observa cómo la entidad y el modelo se convierten en los dos extremos del repositorio: el dominio no sabe nada de Eloquent.

¿Cuándo vale la pena?

  • Cuando la persistencia es compleja: consultas de negocio no triviales que se repiten.
  • Cuando quieres tests rápidos: sustituir el repositorio por una implementación en memoria.
  • Cuando hay posibilidad de cambiar de BD o usar distintos storages (SQL, cache, API externa).

No lo fuerces en CRUD triviales: nadie necesita un repository para volcar una tabla simple si ya tienes un ORM con query builder.

Trampas típicas

  • Filtrar en el servicio: traer todo y filtrar en memoria; ese trabajo es del repositorio.
  • Repositorios con SQL visible: exponer métodos tipo query() devuelve el detalle afuera.
  • Anemic domain: repositorio que solo guarda DTOs sin aplicar reglas de negocio.

Ejercicio

  1. Crea una interfaz UsuarioRepository con 3 métodos y su implementación sobre tu ORM.
  2. Escribe una implementación en memoria (array) para usarla en tests.
  3. Reemplaza el acceso directo al modelo en tu controlador por el repositorio.

Resumen

  • El Repository media entre dominio y persistencia con una interfaz de colección.
  • La interfaz usa lenguaje de dominio; la implementación escribe SQL/ORM.
  • Permite tests con repositorios en memoria.
  • No se aplica a CRUD triviales: es una herramienta, no una obligación.
