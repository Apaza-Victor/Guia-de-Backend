Conectando la infraestructura

🔥 Avanzado 11 min Arquitectura de Software Módulo 5 · Clean Architecture

Introducción

El dominio y los casos de uso definen puertos; los adaptadores los implementan y se instalan a través del composition root. Esta es la pieza final que conecta el mundo del negocio con las herramientas reales sin filtrar detalles hacia adentro.

Implementar adaptadores

Cada puerto del dominio tiene al menos un adaptador en infraestructura. El adaptador traduce los términos del puerto al idioma del proveedor (SQL, API externa, sistema de correo):

La conversión doble es clave: del puerto al SQL y del SQL al puerto (Pedido::restaurar).

El composition root

El composition root es el punto de entrada de la aplicación (bootstrap, index.php, un provider). Es el único lugar donde se permite conocer todas las implementaciones concretas y armar el grafo:

El dominio ni se entera de PDO, ni de Stripe, ni del contenedor. El composition root es el «electricista» que enchufa todo.

No confundir adaptador con un «francotirador»

Un adaptador solo traduce. Si dentro del adaptador aparece lógica de negocio (descuentos, validaciones de reglas, transiciones de estado), el negocio se ha escapado de su capa. El adaptador debe ser tonto: mapea, delega y nada más.

Probar la conexión

Con el composition root separado de los adaptadores, los tests son baratos:

  • Dominio/casos de uso: fakes de repositorios en memoria (sin DB).
  • Adaptadores: tests de integración con la DB o con el proveedor real pero aislado.
  • Composition root: un «smoke test» que arma el grafo completo en cada PR.

Ejercicio

  1. Implementa un adaptador (Eloquent/PDO) para el puerto UsuarioRepository.
  2. Mueve el arranque de tus servicios a un único composition root.
  3. Escribe un smoke test que instancie el caso de uso con fakes.

Resumen

  • Los adaptadores traducen puertos del dominio a proveedores concretos (SQL, HTTP, mail).
  • El composition root es el único que conoce implementaciones y arma el grafo.
  • Los adaptadores no contienen lógica de negocio: solo traducen.
  • Esta separación hace el sistema extensible y fácil de testear.
