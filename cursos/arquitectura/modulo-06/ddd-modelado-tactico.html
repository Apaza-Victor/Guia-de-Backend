DDD: modelado táctico

🔥 Avanzado 12 min Arquitectura de Software Módulo 6 · Hexagonal y DDD

Introducción

El Domain-Driven Design de Eric Evans propone llevar el lenguaje del negocio al código. El modelado táctico es la caja de herramientas concreta: lenguaje ubicuo, entidades, value objects, agregados, servicios de dominio, eventos y factories. Aquí te muestro cada pieza con casos de un ecommerce.

El lenguaje ubicuo

Antes de escribir código: todos hablan el mismo idioma. Si el producto llama a algo «carrito» y el equipo lo llama «cesta», nunca van a coincidir el analista, el developer y el tester. El lenguaje ubicuo es ese glosario compartido que se vierte tal cual a las clases, tablas y atributos.

Ejemplo de entrada en el glosario: «Pedido confirmado» — evento que publica la aplicación cuando un pedido pasa de borrador a confirmado.

Las piezas tácticas

  • Entidad: tiene identidad continua (Pedido#42) y estado mutable guiado por reglas.
  • Value object: se define por sus atributos y es inmutable (Money(120.5, 'EUR')); dos iguales son «lo mismo».
  • Agregado: un grupo de entidades y valores con una raíz que garantiza consistencia. (La próxima lección lo desarrolla.)
  • Servicio de dominio: comportamiento que no es natural en una sola entidad (ej. AplicaDescuentoEnPromocion).
  • Evento de dominio: suceso del negocio con significado («PedidoCobrado», «StockAgotado») que otros contextos pueden escuchar.

Entidad con reglas, inmutable solo cuando debe

La transición de estado es su responsabilidad; nadie desde fuera puede dejar al pedido inválido.

¿DDD táctico para todo?

No. DDD brilla en negocios con reglas complejas (banca, logística, seguros). En una CRUD simple, entidades y agregados son un gasto innecesario. Regla práctica: si el equipo discute cómo calcular algo de negocio durante semanas, DDD paga; si solo llenan formularios, no lo fuerces.

Ejercicio

  1. Escribe una entrada de lenguaje ubicuo con el equipo para el flujo de compra.
  2. Modela una entidad arraigada (por ejemplo Curso) con sus reglas de estado.
  3. Añade un evento de dominio que tu aplicación escuche para notificar.

Resumen

  • DDD habla de modelo táctico: entidades, value objects, agregados, servicios y eventos.
  • El lenguaje ubicuo une negocio y código antes de escribir.
  • Las entidades vigilan sus reglas; los value objects son inmutables.
  • DDD táctico se aplica cuando el negocio tiene complejidad real.
