CDN y contenido estático

🔥 Avanzado 10 min System Design / Arquitectura de Sistemas Módulo 5 · Caching y datos a escala

Introducción

Un recurso estático (logo, JS, video) es el mismo byte que viaja miles de veces. La CDN (Content Delivery Network) lo copia en cientos de puntos de presencia (PoP) y el usuario descarga de la réplica más cercana.

La regla de oro detrás de toda CDN es la misma del caching: el contenido debe ser identificable por su versión. Si el byte no cambia de nombre cuando cambia de contenido, la CDN te servirá la versión vieja.

Definición

Una CDN es una red de servidores perimetrales (edge) que cachean réplicas de contenido estático y lo sirven desde el PoP más cercano al usuario, cortando latencia y tráfico al origen.

Por qué importa. Cada milisegundo de descarga cuenta y cada TB servido desde el origen cuesta. Con la CDN no solo ganas velocidad: proteges el origen porque el pico de lectura lo absorbe el borde.

Cuándo usarlo. Úsala para todo lo inmutable y público: JS/CSS/imágenes/video/APIs GET de lectura. No metas en ella datos privados por usuario sin firmar las URLs y cuidar la expiración.

Conceptos clave

  • Cache veronada: una URL = una versión; los hashes en el filename hacen que el contenido nuevo tenga URL nueva.
  • Cache-control y TTL del borde: max-age, immutable, y s-maxage si hay una red intermedia.
  • Invalidación por purga o por versionado: purgar es factible; versionar es lo robusto.
  • Signed URLs / tokens para contenido privado que la CDN sirve solo a quien autorizamos.
  • Los orígenes sanos también importan: la CDN rellena de tu origen y la caché solo ayuda si el cópia está bien hecha.

Ejemplo básico

Cabeceras que le dicen al borde (y al navegador) cuánto tiempo conservar cada fichero.

Ejemplo intermedio

Para contenido privado, la CDN debe poder exigir autorización: URLs firmadas con expiración.

Ejemplo real

Una plataforma de cursos geolocalizada: la misma lección en video se pedía 300k veces al día, el origen ardía en ancho de banda y los alumnos de Europa sufrían 900 ms de carga. Con la CDN se sirvió el video desde PoPs locales (latencia 120 ms) y el origen pasó de servir bytes a servir solo la primera copia de cada video nuevo.

  • Hash el nombre de cada build: app..js para que el versionado invalide solo.
  • Firma las URLs de cursos de pago y expira con la sesión.
  • Cachea también los GET de API de lecturas públicas (catálogo, precios) en el borde.
  • Mide la cobertura geográfica: la CDN gana según dónde están tus usuarios.

Versionar el nombre es la invalidación que nunca falla: lo viejo muere solo.

Explicación

  • El paralelismo de la CDN y el tiempo de llegada: el PoP más cercano elimina rondas de ida y vuelta largas.
  • La coherencia importa más en dinámico que en estático: por eso la CDN se reserva para lo inmutable y las APIs públicas con TTL corto.
  • El ahorro de coste llega de mover el tráfico del origen al borde: bytes que ya no cruzan tu infra.
  • Las URLs firmadas extienden la CDN al contenido protegido: el control está en quién sabe firmar.
  • El cold-start es el enemigo: un contenido popular recién publicado golpea el origen una vez por PoP; pre-cachear lo predecible evita la manada de bordes.

Errores comunes

  • Inmutabilidad prometida sin hash en el nombre: cambias el CSS y el usuario sigue viendo el viejo del cache.
  • Cache-Control inmutable en ficheros que no llevan versión y que cambian en cada deploy.
  • Firmar todo el contenido público por igual y complicar el borde sin necesidad.

Buenas prácticas

  • Versiona con hash los estáticos y decláralos immutable por un año.
  • Usa no-store para cualquier respuesta con datos privados por usuario.
  • Firma URLs solo en contenido protegido y rota el secreto.
  • Pre-cachea los hitos predecibles (lanzamientos) para que el borde no golpee el origen de golpe.

Ejercicio

  1. Diseña el scheme de nombres con hash para un build de una SPA.
  2. Configura cabeceras de caché para estático, API pública y API privada.
  3. Genera y verifica una URL firmada con expiración para un video.

Resumen

  • La CDN corta latencia y protege el origen moviendo bytes cerca del usuario.
  • Versionar el nombre es la invalidación robusta; la purga es la manual.
  • Contenido privado: URL firmada y expiración, no caché pública.
