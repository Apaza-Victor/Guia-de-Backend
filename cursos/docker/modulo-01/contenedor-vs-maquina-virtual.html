Contenedor vs máquina virtual

🔧 Intermedio 9 min Docker para Backend Módulo 1 · Fundamentos

La diferencia de fondo

Una máquina virtual ejecuta un sistema operativo completo (kernel incluido) sobre un hipervisor. Un contenedor ejecuta procesos que comparten el kernel del host con todos los demás contenedores.

Comparación rápida

Cuándo usar cada uno

  • Contenedor: tu API, BD, caché, colas, herramientas del pipeline. Ciclo de vida corto y reproducible.
  • VM: aislar por hardware, correr Windows/macOS/Linux en el mismo equipo, probar kernels distintos, límites de seguridad duros (multitenant hostil).
  • En la práctica: suelen complementarse: una VM aloja el Docker engine de un entorno.

Seguridad: el matiz que olvidan

Compartir kernel significa que una explotación del kernel compromete al host y a todos. Docker aísla procesos con namespaces y restringe recursos con cgroups, pero el kernel es único. Para cargas desconfiadas del host se usa una VM entre el host y los contenedores.

Ejercicio

  1. Haz una tabla de dos columnas con las ventajas de cada tecnología.
  2. Decide en qué contexto usarías una VM aunque exista Docker.
  3. Busca una imagen en Docker Hub y observa su tamaño (la próxima lección la usas).

Resumen

  • VM: SO completo sobre hipervisor (GB, minutos).
  • Contenedor: procesos que comparten el kernel (MB, segundos).
  • El aislamiento de contenedor no es seguridad absoluta.
  • Para multitenant hostil: VM + Docker dentro.
