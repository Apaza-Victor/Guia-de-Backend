¿Qué es un contenedor?

🔧 Intermedio 10 min Docker para Backend Módulo 1 · Fundamentos

El problema del empaquetado

Tu API funciona en tu laptop y revienta en el servidor. Versiones de Node distintas, librerías sistemas que faltan, variables de entorno que nadie documentó. Un contenedor es la respuesta: tu código más su runtime más las librerías del sistema empacados juntos, corriendo aislados del resto del host.

Definición simple

Contenedor = un proceso (o grupo de procesos) con su propio filesystem, red y limitaciones de recursos, ejecutando normalmente el kernel del host. Es reproducible: si corre en tu máquina, corre igual en producción.

Imagen vs contenedor

Analogía: la caja de mudanza

  • Imagen: una caja sellada con la app, el Node, las llaves y las instrucciones. Idéntica para todos.
  • Contenedor: la caja abierta en el nuevo piso, funcionando con sus cosas y guardando cambios que afectan SOLO a esa caja.
  • Registry: el almacén (Docker Hub) donde guardas y tomas cajas.

Qué resuelve en backend

  1. Paridad dev/prod: mismo runtime, mismo entorno.
  2. Aislamiento: dos apps con dependencias incompatibles coexisten.
  3. Empaquetado de servicios: BD, caché, colas y API se levantan con un comando.
  4. Escalado: aumentas instancias copiando el contenedor, no el servidor.

Ejercicio

  1. Escribe en una línea qué guardaría tu imagen si containerizaras tu último proyecto.
  2. Explica con tus palabras la diferencia entre imagen y contenedor.
  3. Di docker --version y verifica la instalación antes de la siguiente lección.

Resumen

  • El contenedor empaqueta código + runtime + librerías.
  • Corre aislado compartiendo el kernel del host.
  • La imagen es el plano inmutable; el contenedor, su ejecución.
  • Resuelve paridad, aislamiento y empacado de servicios.
