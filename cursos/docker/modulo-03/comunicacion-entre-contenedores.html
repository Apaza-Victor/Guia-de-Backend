Comunicación entre contenedores

🔧 Intermedio 10 min Docker para Backend Módulo 3 · Volúmenes y Redes

El truco del nombre en vez de IP

En una red bridge personalizada, Docker incluye su propio DNS: puedes llegar a un contenedor por su --name desde otro. Tu API habla con Postgres a través de postgres, no de una IP que cambia en cada arranque.

El flujo completo

Comprobar de verdad la conexión

Diagnóstico de "no me puedo conectar"

  1. ¿Misma red? docker inspect api | grep Network. Sin red compartida no hay nombre que valga.
  2. ¿Nombre correcto? El DNS usa el --name del SEGUNDO contenedor.
  3. ¿DB acepta conexiones? pg_hba/firewall puede bloquear desde la red interna.
  4. ¿El puerto interno es 5432? El -p solo afecta al host; dentro se usa el puerto del contenedor.

Ejercicio

  1. Levanta 2 contenedores en una red con nombre.
  2. Desde uno, curl al otro por SU nombre.
  3. Publica SOLO el de cara al usuario y verifica el resto cerrado.

Resumen

  • Bridge personalizado = DNS por nombre dentro de la red.
  • La BD no se publica; solo comparte red con quien debe.
  • Nunca IPs en tu config: los nombres ya hacen el trabajo.
  • Misma red → mismo nombre → conexión limpia.
