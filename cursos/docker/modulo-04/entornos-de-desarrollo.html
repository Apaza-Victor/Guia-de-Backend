Entornos de desarrollo

🔧 Intermedio 11 min Docker para Backend Módulo 4 · Docker Compose

El objetivo: "empieza ya a trabajar"

El mejor entorno de dev es el que se levanta con docker compose up -d y no rompe cuando lo clona otra persona. Tres pilares: hot-reload, datos de dev y mismo comportamiento que prod.

Compose para desarrollo

Este override se fusiona en tu máquina, no viaja a producción.

Datos listos para arrancar

La paridad con producción

  • Misma imagen base y misma red: los bugs de versión salen en dev.
  • Variables por entorno, no por máquina: .env.dev y .env.prod.
  • El runner "watch" es solo el host: producción lanza el CMD real.

Scripts para que nadie adivine

Ejercicio

  1. Crea un override de dev con bind mount y npm run dev.
  2. Agrega seed inicial a Postgres con init.
  3. Nombra los 3 comandos que ofrece tu Makefile.

Resumen

  • Dev = compose override + bind + npm run dev.
  • Los datos de arranque entran por init scripts.
  • Paridad: misma base, red y variables; solo cambia el CMD.
  • Scripts cortos (make up) bajan la curva del equipo.
