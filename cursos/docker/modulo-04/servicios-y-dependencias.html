Servicios y dependencias

🔧 Intermedio 10 min Docker para Backend Módulo 4 · Docker Compose

El arranque en orden

Un depends_on simple solo ordena el inicio: levanta la BD antes que la API. Pero tu API puede arrancar cuando Postgres aún está "arrancando". Para esperar de verdad se usa condition: service_healthy.

La forma correcta

healthcheck: el pulso del servicio

El estado vive en docker inspect y Compose puede usarlo como condición de arranque.

Otras dependencias útiles

  • restart: unless-stopped en la API para que intente reconectar.
  • depends_on: más de un servicio: lista de nombres.
  • Si tu app tiene retry lógico en la conexión, el restart basta; el healthcheck es para no dejar huérfanas las condiciones.

Fallo típico: connect ECONNREFUSED

Ejercicio

  1. Agrega un healthcheck a tu servicio postgres.
  2. Haz que api espere a service_healthy.
  3. Reinicia el stack y observa el arranque ordenado en los logs.

Resumen

  • depends_on ordena: solo service_healthy espera de verdad.
  • healthcheck = pulso del servicio para Compose.
  • restart + retry en la app cubren el resto.
  • DB lista ≠ conexión hecha: el cliente sigue intentando.
