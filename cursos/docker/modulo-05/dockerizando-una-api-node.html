Dockerizando una API Node

🔧 Intermedio 11 min Docker para Backend Módulo 5 · Docker en el Backend

El plan en tres etapas

El Dockerfile listo para copiar

Correrla como se corre en prod

Las 3 cosas que nadie copia

  • Listen en 0.0.0.0: app.listen(3000) no basta: si tu server escucha en loopback en el contenedor, no será visible. Usa HOST=0.0.0.0.
  • Graceful shutdown: captura SIGTERM para cerrar conexiones y drenar requests.
  • La imagen no lleva secretos: todo entra por variables al run.

Ejercicio

  1. Crear el Dockerfile del reto y build -t mi-api:1.0.
  2. Levantar y verificar healthy y el endpoint /health.
  3. Verifica que la imagen corre como UID no-root: exec id.

Resumen

  • deps → build → runtime: la API entra en 3 capas lógicas.
  • USER no-root, HEALTHCHECK y dist solo lo necesario.
  • Escuchar en 0.0.0.0 y atender SIGTERM: paridad real.
  • Secretos SIEMPRE por entorno, nunca en la imagen.
