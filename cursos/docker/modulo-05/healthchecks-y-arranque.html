Healthchecks y arranque

🔧 Intermedio 10 min Docker para Backend Módulo 5 · Docker en el Backend

Qué es un healthcheck

Un comando que Docker ejecuta cada interval para saber si el contenedor está vivo. Si falla retries veces seguidas, Docker lo reinicia (o el orquestador lo quita del balanceo). Tres respuestas: starting, healthy, unhealthy.

En el Dockerfile

O en Compose (más control)

Arranque en orden: depends_on

Asegurado el orden, tu up ya no necesita sleep 30 antes de migrar: docker compose up -d --wait espera a todos los healthchecks.

El truco del endpoint /health

Un /health que solo mira "proceso vivo" miente: valida que las dependencias que importan responden. Liveness ≠ readiness.

Ejercicio

  1. Agrega pg_isready como healthcheck de tu Postgres.
  2. Encadena api con condition: service_healthy.
  3. Sube con up -d --wait y confirma "Up (healthy)" en ps.

Resumen

  • Healthcheck del Dockerfile o de Compose: proceso o dependencias.
  • condition: service_healthy = orden real entre servicios.
  • Liveness dice "vivo", readiness dice "listo para tráfico".
  • /health que toca la BD gana al que solo hace PING.
