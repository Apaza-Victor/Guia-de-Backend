API Node con Postgres

🔧 Intermedio 11 min Docker para Backend Módulo 5 · Docker en el Backend

El compose de un backend real

Conectar bien (NO localhost)

Dentro de la red de Compose, cada servicio tiene su dominio: el PostgreSQL del ejemplo es postgres, y el Redis del próximo tema será redis. Nada de IPs fijas.

Esperar a la BD sin "sleep 30"

Probar el stack entero

¿Y las migraciones?

  • Entrada del DB init: para seed y esquemas iniciales, docker-entrypoint-initdb.d (solo corre la primera vez).
  • Migraciones de verdad: corre un job en Compose (command: npx prisma migrate deploy) que depende de la BD healthy y luego sale.
  • Nunca supongas que un cambio llegó por casualidad: decláralo en el job, no lo des por hecho.

Ejercicio

  1. Levanta el compose y verifica /health con la BD arriba.
  2. Entra a Postgres desde el host sin publicar su puerto: compose exec.
  3. Haz un down -v y confirma que se recrea limpio.

Resumen

  • La API conecta al servicio por su nombre: postgres, nunca localhost.
  • healthcheck + condition: service_healthy ordenan el arranque.
  • Los datos viven en el volumen pg_data.
  • Migraciones = job declarado en Compose, no magia.
