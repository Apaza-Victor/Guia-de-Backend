Redis como caché

🔧 Intermedio 10 min Docker para Backend Módulo 5 · Docker en el Backend

Redis como servicio de Compose

El patrón cache-aside

Invalidar sin misterio

  • TTL: la clave expira sola; tú solo eliges el tiempo.
  • Actualización: al modificar el dato, DEL clave antes de responder.
  • Si guardas "toda la API" con TTL largo, estarás sirviendo basura vieja. Cachea datos concretos, no el modelo entero.

Ver y vaciar desde el host

Ejercicio

  1. Suma el servicio redis a tu compose.
  2. Guarda una respuesta de tu /perfil con TTL 60 en cache-aside.
  3. Verifica con redis-cli TTL que expira sola.

Resumen

  • Redis = servicio con nombre redis y healthcheck.
  • Cache-aside: lees caché → si falla lees BD → guardas con TTL.
  • Invalidar = DEL en el flujo de escritura.
  • Todo verificable con exec redis-cli.
