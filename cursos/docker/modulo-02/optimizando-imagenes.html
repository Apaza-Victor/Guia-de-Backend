Optimizando imágenes

🔧 Intermedio 10 min Docker para Backend Módulo 2 · Imágenes y Dockerfile

Producción no es "que corra"

Una imagen de producción importa por tres razones: tamaño (descarga y disco), seguridad (superficie de ataque) y arranque (que sobreviva reinicios del host).

La checklist que aplica a casi todos

Métodos por lenguaje

Medir antes de "optimizar"

Lo que NO optimiza

  • Comprimir dentro de la imagen a costa de CPU en cada arranque.
  • Multi-stage sin separar deps dev: el runtime sigue gordo.
  • Sin .dockerignore: el "contexto" infla builds, no la imagen. (La imagen viene por COPY).

Ejercicio

  1. Compara tu imagen actual vs una con USER node + multi-stage.
  2. Agrega HEALTHCHECK al Dockerfile de la API.
  3. Ejecuta docker inspect del resultado y confirma el user y el healthcheck.

Resumen

  • Base alpine/slim + versiones fijas + USER no-root.
  • Multi-stage: el runtime solo lleva lo que corre.
  • Healthcheck para orquestador y restart policies.
  • Apaga cache del gestor de paquetes en el MISMO RUN.
