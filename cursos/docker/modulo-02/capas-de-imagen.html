Las capas de la imagen

🔧 Intermedio 10 min Docker para Backend Módulo 2 · Imágenes y Dockerfile

Cada instrucción, una capa

El engine ejecuta cada línea del Dockerfile y guarda el resultado como una capa. Las capas son inmutables y se reutilizan: si una no cambió, Docker la copia del cache y salta los pasos de esa capa.

El orden que acelera tus builds

Con este orden, editar un archivo de código NO reinstala dependencias: se aprovecha la capa de npm install.

Qué invalida el cache

  • Cambiar el contenido copiado por un COPY/ADD.
  • Cambiar un ARG que usa una instrucción.
  • Cambiar la imagen base (FROM).
  • Un RUN que descarga cosas sin fijar versión (npm con ^).

Ver y limpiar el cache

Ejercicio

  1. Tu Dockerfile: mueve COPY package*.json antes que el código.
  2. Reconstruye 2 veces seguidas y observa "CACHED".
  3. Cambia una línea de código y verifica que solo esa capa se re-ejecuta.

Resumen

  • Cada instrucción es una capa inmutable y cachéable.
  • Dependencias primero, código después: builds rápidos.
  • El cache se invalida si cambia lo que copia/usa esa capa.
  • --no-cache para builds reproducibles y limpios.
