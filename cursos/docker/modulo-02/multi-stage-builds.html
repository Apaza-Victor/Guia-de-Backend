Multi-stage builds

🔧 Intermedio 11 min Docker para Backend Módulo 2 · Imágenes y Dockerfile

El problema de una sola etapa

Si compilas e instalas deps en la misma imagen, te quedas con el compilador, las deps de desarrollo, los cache de apt/npm y decenas de MB inútiles en producción.

La idea: dos (o tres) etapa

Multi-stage para una API Node

Herramientas de la técnica

Cuándo usarlo

  • Node/Python/Go/Rust: separa build de runtime.
  • Compilación de assets (frontend servido por nginx).
  • Todo lo que necesite herramientas que la app final no necesita.

Ejercicio

  1. Convierte tu Dockerfile de una sola etapa a 3 etapas.
  2. Compara docker images antes y después del cambio.
  3. Corre la imagen final y verifica que la app funciona igual.

Resumen

  • Compila en una etapa, corre en la mínima.
  • COPY --from= pasa solo lo necesario.
  • Imagen final: sin compiladores, sin deps dev, sin cache.
  • --target te deja construir una etapa suelta.
