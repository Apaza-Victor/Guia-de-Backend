Rate limiting

🔥 Avanzado 11 min Seguridad en el Backend Módulo 5 · Seguridad de APIs

El abuso se limita, no se detecta

Rate limiting frena la tasa de peticiones por usuario, IP o recurso. Su presencia evita fuerza bruta en login, scraping, denegación de servicio y costes inesperados. Va en el gateway (Nginx, API Gateway, Cloudflare) o como middleware propio.

Patrones de límite

PatrónComportamiento
Ventana fijaX peticiones por minuto/hora, independiente del ritmo.
DeslizanteMax se desplaza con el tiempo (más suave).
Token bucketAñade tokens a ritmo constante; deja ráfagas.

Implementación con Redis

El óptimo real es usar INCR + EXPIRE en una misma llamada de Lua script, para evitar condiciones de carrera; la idea es la misma.

Rate limit en Nginx

Ejercicio

  1. Limita /api/login a 5 por minuto con tu capa preferida.
  2. Dispara con un loop y comprueba el 429 y Retry-After.
  3. Añade cabeceras X-Ratelimit en tus endpoints.

Resumen

  • Rate limit protege login, scraping y costes.
  • Ventana fija simple; token bucket para ráfagas.
  • Redis con INCR/EXPIRE escala a varios nodos.
  • El gateway lo aplica antes de tocar tu código.
