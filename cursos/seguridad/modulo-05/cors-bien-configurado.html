CORS bien configurado

🔥 Avanzado 11 min Seguridad en el Backend Módulo 5 · Seguridad de APIs

CORS no es firewall

CORS es el mecanismo del navegador que decide si un frontend en otro origen puede leer tus respuestas. No frena APIs, scripts ni herramientas de terminal, solo la lectura del navegador. Confundir eso lleva a configurarlo abierto, que anula su propósito.

Los tres pecados

  • Access-Control-Allow-Origin: * con credenciales (combina mal, y deja leer a todos).
  • Devolver el origen solicitante sin chequear nada (eco ciego).
  • Access-Control-Allow-Methods: * en vez de listar métodos.

Decisiones que importan

  • API pública sin credenciales: lista blanca igualmente, nunca * salvo assets.
  • Con cookies/tokens: Credentials y orígenes explícitos.
  • Frontend móvil/nativo no usa CORS: no lo uses como tu única defensa.

Ejercicio

  1. Configura CORS solo para tu dominio real con métodos exactos.
  2. Prueba desde otro origen y comprueba el bloqueo.
  3. Revisa que el error de CORS sea claro para el dev que se equivoque.

Resumen

  • CORS controla lectura del navegador, no el acceso al servidor.
  • Lista blanca + Vary: Origin + métodos explícitos.
  • Preflight OPTIONS responde 204 solo a orígenes permitidos.
  • Nunca * con credenciales ni eco ciego.
