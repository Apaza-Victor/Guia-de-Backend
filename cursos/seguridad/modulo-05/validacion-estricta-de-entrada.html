Validación estricta de entrada

🔥 Avanzado 11 min Seguridad en el Backend Módulo 5 · Seguridad de APIs

Nada que venga del cliente es de fiar

Cada campo que llega al backend es sospechoso: headers, query, body, cookies. La validación no es UX ni decoración: es la primera línea que evita datos corruptos, inyecciones y lógica rota. La regla: falla temprano, falla claro.

Estrategia por niveles

Validar el body JSON tal cual llega

Bibliotecas serias

  • Symfony Validator o Respect\Validation en PHP: reglas declarativas.
  • JSON Schema en tu contrato OpenAPI: la validación vive en el contrato.
  • Tipos en el lenguaje (strict_types=1) menos trampas de coerción.

Ejercicio

  1. Escribe validación estricta para el body de un endpoint.
  2. Prueba con tipos malos, strings gigantes y enumerados inválidos.
  3. Configura un JSON Schema y valida contra el contrato.

Resumen

  • Nada del cliente es confiable, ni headers.
  • Tipo + longitud + rango + enumerado + normalizado.
  • Fallar temprano con 422 y mensajes claros.
  • JSON Schema / OpenAPI mantienen el contrato sano.
