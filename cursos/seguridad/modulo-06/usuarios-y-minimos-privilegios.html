Usuarios y mínimos privilegios

🔥 Avanzado 11 min Seguridad en el Backend Módulo 6 · Hardening

El peor titular: "root"

Si tu app corre como root y alguien la rompe (una LFI, una shell en un upload), ya tiene el servidor entero. El mínimo privilegio dice: cada proceso usa la identidad mínima que necesita su tarea. Root solo para arrancar; después, los servicios con usuarios dedicados.

Crear el usuario de la app

systemd sin excesos

Los permisos se tejen en capas

  • chmod 640/750 por defecto; jamás 777.
  • Base de datos: usuario DB sin DROP global ni GRANT.
  • Llaves SSH de deploy específicas y con passphrase / agente.
  • El web server lee, el proceso escribe solo lo necesario.

Ejercicio

  1. Crea el usuario app_run sin login.
  2. Mueve tu app a su dueno y quita permisos de mundo.
  3. Define una unidad systemd con las protecciones de arriba.

Resumen

  • Root jamás corre aplicaciones.
  • Usuario del sistema por servicio: sin shell, sin home.
  • systemd: NoNewPrivileges, ProtectSystem, read-only.
  • Permisos 750/640, secreto para SSH y DB.
