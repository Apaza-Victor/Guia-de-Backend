NoSQL Injection en MongoDB

🔥 Avanzado 10 min Seguridad en el Backend Módulo 2 · Inyecciones

La misma enfermedad, otro idioma

En NoSQL no hay SQL que concatenar, pero si pasas un objeto JSON del cliente a una consulta, los operadores de Mongo ($ne, $gt, $where) entran como si fueran tus intenciones. El límite entre dato y lógica vuelve a difuminarse.

Login vulnerable por JSON

Otros trucos

  • {"$gte": ""} para evitar comparar valores.
  • {"$where": "this.rol=='admin'"} ejecuta JS dentro del motor.
  • Campos extra del JSON: enviar "rol": "admin" en un registro.
  • Arrays: "id": {"$in": [...]} para forzar rangos.

La defensa

Regla: define el esquema de lo que aceptas (campos y tipos) y construye tú el documento de consulta.

Ejercicio

  1. Crea un login Mongo y prueba el payload $ne.
  2. Fuerza tipos con (string) y verifica que el ataque muere.
  3. Escribe una lista de campos que tu API no debe aceptar jamás.

Resumen

  • NoSQL se inyecta por operadores en el JSON.
  • $ne, $gte y $where son los trucos típicos.
  • Construye el filtro tú, nunca copies el body.
  • Tipado estricto y campos permitidos.
