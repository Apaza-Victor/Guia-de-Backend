¿Qué es SQL Injection?

🔥 Avanzado 10 min Seguridad en el Backend Módulo 2 · Inyecciones

Código donde deberían ir datos

La inyección SQL ocurre cuando el input del usuario se mete en una consulta como si fuera código en vez de dato. Tu aplicación interpreta y ejecuta lo que el atacante escribió. No hay magia: es concatenar cadenas sin separar instrucción de parámetro.

La consulta vulnerable

Resultado: OR 1=1 hace la condición siempre verdadera y el -- comenta el resto. El atacante puede listar usuarios, robar credenciales o, con más jugadas, borrar tablas.

Impacto real

  • Lectura: extraer toda la tabla usuarios (UNION SELECT).
  • Escritura: insertar un admin o modificar precios.
  • BOF: dopar con sqlmap o ; DROP TABLE.
  • Shell: en BD con funciones externas, ejecutar comandos del sistema.

Dónde se cuela

No solo en el login: en cualquier lugar donde se construye SQL con strings — búsquedas, filtros, ids, orden. El antivirus de la neta: nunca concatenes; usa parámetros (siguiente lección). Y recuerda: mysql_real_escape_string y el «escaping» de antaño no son la solución completa en PHP moderno.

Ejercicio

  1. Busca en tu código toda concatenación en queries (grep de $db->query).
  2. Prueba el payload ' OR 1=1 -- en una app local.
  3. Escribe los ítems de impacto que aplicarías a tu proyecto.

Resumen

  • SQLi = mezclar input con código SQL.
  • Concatenación es la causa raíz.
  • Impacto: leer, escribir, borrar y hasta ejecutar.
  • La solución estándar: prepared statements.
