Sanitización y escaping

🔥 Avanzado 11 min Seguridad en el Backend Módulo 3 · XSS y CSRF

Sanitizar no es escapar

  • Sanitizar: al entrar, favor de quitar lo que no queremos (etiquetas) o reducir a un formato seguro (números, slugs). Sirve para campos con formato libre mínimo.
  • Escapar: al salir, transformar caracteres para que no se interpreten como etiqueta en ese contexto (HTML, atributo, JS).

El gran fallo: sanitizar solo en la entrada y creer que ya está. El dato se guarda limpio, pero la salida sigue necesitando su escape. Y al revés: escapar cada salida sin haber validado la entrada abre la puerta a otros huecos.

Escapar para HTML

Los contextos que traicionan

Reglas de oro

  • Contexto es todo: el escape para HTML no sirve dentro de un <script> próprio.
  • Nunca construyas HTML con innerHTML a partir de datos.
  • Para HTML enriquecido: siempre HTMLPurifier o similar, nunca strip_tags solo.
  • El escape vive en la vista; la validación en el borde; la BD guarda puro.

Ejercicio

  1. Repasa una vista y escapa todas las salidas de datos.
  2. Prueba <b onmouseover="alert(1)"> en tu HTML sin escapar.
  3. Permite solo URLs http(s) en un campo y rechaza javascript:.

Resumen

  • Sanitizar = entrada; escapar = salida.
  • htmlspecialchars para HTML; listas blancas de URL.
  • HTML enriquecido exige HTMLPurifier.
  • El contexto decide qué escape usar.
