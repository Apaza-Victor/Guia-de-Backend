Security headers y CSP

🔥 Avanzado 10 min Seguridad en el Backend Módulo 3 · XSS y CSRF

El navegador como aliado

Varias cabeceras HTTP hacen el trabajo sucio por el servidor. Aunque el código tenga un fallo, el navegador puede negarse a ejecutar scripts o a cargar la página en un iframe. La más poderosa es CSP.

Content-Security-Policy

CSP define de dónde se pueden cargar scripts, estilos, imágenes y frames. Si un atacante inyecta <script>, el navegador lo bloquea si su origen no está en la política. Configuración típica de salida:

El resto del set

Desplegar CSP sin romper

  • Empieza en modo informe: Content-Security-Policy-Report-Only.
  • Revisa los reportes, añade orígenes legítimos, luego aplica.
  • El frame-ancestors y base-uri son poco costosos y muy útiles.
  • Prueba con securityheaders.com para puntuar tu respuesta.

Ejercicio

  1. Añade el set de headers en tu framework (middleware o bootstrap).
  2. Intenta inyectar un script inline con CSP activa.
  3. Comprueba tu dominio local en securityheaders.com.

Resumen

  • CSP decide qué se ejecuta y de dónde viene.
  • Sin unsafe-inline, el XSS inline cae.
  • X-Frame-Options y frame-ancestors frenan el clickjacking.
  • Referrer-Policy, HSTS y nosniff completan el corset.
