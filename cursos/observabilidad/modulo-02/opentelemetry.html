OpenTelemetry

🚀 Avanzado 10 min Observabilidad Backend Módulo 2 · Herramientas

Qué es OpenTelemetry

OpenTelemetry (OTel) es el estándar abierto para instrumentar aplicaciones y generar telemetría (trazas, métricas y logs) sin atarte a un proveedor. Instrumentas una vez con la API de OTel y decides después hacia dónde exportar: Jaeger, Prometheus, Grafana Cloud, Datadog, New Relic...

Sus piezas:

API
interfaces estables para crear spans, métricas y contextos. El código de negocio solo conoce la API.
SDK
implementación concreta: configura el procesador de spans, el muestreo y los exporters.
Exporter
envía la telemetría a un destino (OTLP, Jaeger, Zipkin, Prometheus).
Collector
proceso intermedio que recibe de múltiples servicios, transforma, filtra, bufferiza y reenvía.
Semconv
convenciones de nombres de atributos para que todos los equipos hablen igual.

El Collector

El Collector evita que cada servicio serialice y haga retries por su cuenta: todos envían por OTLP al Collector, y este hace el trabajo sucio (memoria, batch, filtrado, redacción de secretos, failover entre backends):

Los servicios solo configuran OTEL_EXPORTER_OTLP_ENDPOINT=http://collector:4317. Cambiar de backend deja de ser un cambio de instrumentación: el Collector reexporta a donde quieras.

Cuando la instrumentación automática intercepta la llamada HTTP de checkout a inventario, inyecta este header y, en inventario, el SDK crea el span hijo con parentSpanId = 00f067aa0ba902b7. La misma mecánica aplica a colas (headers de mensaje) y a gRPC (metadata).

Buenas prácticas

  • Configura OTEL_SERVICE_NAME en cada servicio: es el campo que agrupa todo.
  • Muestreo en el SDK (por la petición raíz), no en cada lobby de process: samplea la entrada y los hijos siguen.
  • Usa semconv para atributos (http.request.method, db.system): no inventes nombres propios del equipo.
  • Exporta también métricas por OTLP al Collector; así Prometheus scrapea una sola puerta.

Ejercicio

  1. Arranca el SDK de OTel en tu API con auto-instrumentación y guarda un span por request.
  2. Añade un span manual alrededor de una operación de negocio (envío de email, cobro, importación).
  3. Despliega el Collector en local con docker-compose y exporta OTLP hacia Jaeger.

Resumen

  • OTel separa API (estable) del SDK y los exporters (configurables).
  • La auto-instrumentación cubre la mayoría: HTTP, BD, colas, gRPC.
  • El Collector redirige la telemetría a cualquier backend sin tocar el código.
  • El contexto W3C (traceparent) conecta trazas entre servicios.
