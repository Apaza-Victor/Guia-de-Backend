Quorum y recuperación

🚀 Avanzado 10 min Sistemas Distribuidos Módulo 2 · Replicación y consistencia

Introducción

En un sistema sin líder (leaderless), nadie sabe cuál es la copia «verdadera». Para decidir, el cliente no habla con un solo nodo: habla con varios y exige un mínimo de confirmaciones. Ese mínimo es el quórum, y con la fórmula adecuada consigues consistencia fuerte sin un liderazgo central.

La regla W + R > N

Con N réplicas por clave:

  • W = número mínimo de nodos que deben confirmar una escritura.
  • R = número mínimo de nodos que deben confirmar una lectura.

Si W + R > N, cualquier lectura quórum lee al menos de un nodo que tenga la última escritura. Es la base para tener lecturas siempre frescas, pero a costa de latencia: cada operación espera a varios nodos.

Ejemplo: con N=3, si usas W=2 y R=2 (2+2>3), toleras la caída de un nodo y sigues leyendo datos consistentes. Si optimizas velocidad con W=1 y R=1 (1+1 no >3), ganas rendimiento pero puedes leer datos viejos.

Modelo de quórum en código

Representemos el flujo de una lectura quórum. El cliente pide la clave a varias réplicas y elige la versión más nueva entre las que llegan a tiempo:

import asyncio

def leer_quorum(replicas, clave, r, timeout_ms=500):
    pendientes = [pedir(replica, clave) for replica in replicas]
    respuestas = esperar_esas_pendientes(pendientes, timeout_ms)

    if len(respuestas) < r:
        raise Error("no se alcanzó el quórum de lectura")

    # Elegir la versión con el número mayor (asumiendo versiones)
    return max(respuestas, key=lambda v: v.version)

Cuando el quórum no se alcanza —por ejemplo, tras una partición—, el sistema decide entre fallar la operación (política CP) o servir igualmente (política AP).

Recuperación: read repair

¿Qué pasa cuando una réplica se quedó desactualizada pero el cliente sí tenía el valor correcto? La técnica del read repair aprovecha la lectura con quórum para sanear: al detectar versiones divergentes, el nodo que tiene el valor más nuevo se lo envía a los atrasados.

{
  "operacion": "lectura_quorum",
  "replicas_consultadas": ["nodo-a", "nodo-b", "nodo-c"],
  "versiones_recibidas": {
    "nodo-a": { "version": 9, "valor": "Activo" },
    "nodo-b": { "version": 7, "valor": "Pendiente" },
    "nodo-c": { "version": 9, "valor": "Activo" }
  },
  "decision": "devolver version 9",
  "read_repair": { "nodo-b": "reenviar version 9 para sanear" }
}

Así, sin un proceso central, el propio tráfico de lectura va curando a las réplicas rezagadas.

Hinted handoff

Cuando un nodo está caído durante una escritura, otro nodo sano acepta el dato «en préstamo» y lo deja anotado (hint). Cuando el nodo caído vuelve, el que guardó el hint se lo entrega. Así la escritura «no se pierde» aunque el destino estuviera apagado.

  • Aumenta disponibilidad de escritura (no necesitas los N acuses, solo W de nodos sanos).
  • Requiere que el nodo que hizo de «casillero» sobreviva hasta la devolución.
# Configuración de Cassandra (Docker) que fija N, W y R por defecto:
# - keyspace con factor de replicación N=3 (clase SimpleStrategy)
# - consistency por operación: WRITE=LOCAL_QUORUM, READ=LOCAL_QUORUM

storage:
  cluster_name: 'AppCluster'
  num_tokens: 256
  hints_directory: /var/lib/cassandra/hints
  hinted_handoff_enabled: true
  max_hint_window: 3h

Sistemas grandes sin líder ni quórum

Algunas bases (epílogo) mezclan líder y quórum. Las lightweight transactions de Cassandra usan Paxos internamente para operaciones «comparar-y-marcar» (por ejemplo, crear una clave única). Para eso ya entramos en el territorio del consenso, que verás en una lección próxima.

Ejercicio

  1. Con N=5, calcula combinaciones de W y R que mantengan consistencia fuerte y otras que no. ¿Cuál tolera más nodos caídos?
  2. Simula un read repair por escrito: 3 réplicas, una con versión vieja; describe qué devuelves al cliente y qué se reenvía.
  3. Responde: si dos nodos guardan un hint para el mismo nodo caído, ¿qué puede salir mal y cómo lo evitas?

Resumen

  • El quórum define cuántos nodos deben confirmar una operación (W escritura, R lectura).
  • W + R > N garantiza lecturas con la última escritura, tolerando algunos nodos caídos.
  • Read repair sanea réplicas atrasadas aprovechando las lecturas quórum.
  • Hinted handoff guarda la escritura temporalmente y la entrega cuando el nodo vuelve.
