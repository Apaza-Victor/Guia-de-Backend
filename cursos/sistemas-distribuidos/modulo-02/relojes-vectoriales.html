Relojes vectoriales y versiones

🚀 Avanzado 9 min Sistemas Distribuidos Módulo 2 · Replicación y consistencia

Introducción

Los relojes físicos no sirven para ordenar eventos en un sistema distribuido: cada nodo lee su propio reloj, que se desvía. Para saber «¿este evento ocurrió antes que aquel?» sin depender del tiempo, usamos relojes lógicos: contadores que se intercambian entre nodos.

Reloj de Lamport

El reloj de Lamport es un contador entero con dos reglas:

  1. Cada nodo incrementa su contador en 1 antes de cada evento.
  2. Al enviar un mensaje, se incluye el contador; al recibirlo, el receptor toma máx(contador_local, contador_recibido) + 1.
class RelojLamport:
    def __init__(self, nodo):
        self.nodo = nodo
        self.valor = 0

    def evento(self):
        self.valor += 1

    def enviar(self):
        self.valor += 1
        return self.valor  # se adjunta al mensaje

    def recibir(self, valor_recibido):
        self.valor = max(self.valor, valor_recibido) + 1

# Orden causal viaja en los mensajes: lo que "pasó antes" queda registrado

Los relojes de Lamport dan un orden parcial: si un mensaje viajó, sabemos quién fue primero; eventos de nodos distintos sin comunicación quedan «concurrentes» (no comparables).

Relojes vectoriales

Para detectar exactamente qué pares de eventos son concurrentes, usamos un reloj por nodo: el vectorial. Cada nodo mantiene un vector con un contador por nodo del sistema.

// Reloj vectorial: Map(nodo -> contador) por proceso
function incrementar(clk, nodo) {
  const nuevo = new Map(clk);
  nuevo.set(nodo, (nuevo.get(nodo) || 0) + 1);
  return nuevo;
}

function comparar(a, b) {
  // Devuelve "igual", "despues" (a domina a b), "antes" o "concurrente"
  let dominaA = false, dominaB = false;
  const nodos = new Set([...a.keys(), ...b.keys()]);
  for (const nodo of nodos) {
    const ca = a.get(nodo) || 0;
    const cb = b.get(nodo) || 0;
    if (ca > cb) dominaA = true;
    if (ca < cb) dominaB = true;
  }
  if (dominaA && dominaB) return "concurrente";
  if (dominaA) return "despues";
  if (dominaB) return "antes";
  return "igual";
}

Al recibir una actualización, el nodo fusiona el reloj del remitente tomando el máximo por entrada. Así, cualquier versión «sabe» qué otras versiones ya conoce.

Importante: los relojes vectoriales no te dicen cuál valor es el correcto; te dicen si hay conflicto. La resolución de conflictos es otra decisión: last-writer-wins, fusión o unificación de valores.

Versionado de objetos

En bases sin líder, cada valor replicado se guarda junto con un contexto de versiones. Si al leer obtienes dos versiones concurrentes, el sistema devuelve ambas y la aplicación (o el usuario) las resuelve. Así lo modela DynamoDB/Cassandra internamente:

{
  "clave": "carrito:usuario-42",
  "versiones": [
    { "valor": "añadir:camiseta-M",   "reloj": { "nodo-a": 3, "nodo-b": 0 } },
    { "valor": "añadir:gorra-negra",  "reloj": { "nodo-a": 0, "nodo-b": 2 } }
  ],
  "estado": "conflicto",
  "siguiente_paso": "el cliente fusiona ambas listas"
}

Las dos versiones son concurrentes (ninguna domina a la otra) y por eso el sistema conserva ambas en vez de descartar una. Tras la fusión, se escribe con un reloj que las domina a las dos.

Resolver conflictos

  • Last-writer-wins (LWW): el reloj con el timestamp mayor gana. Simple y pierde datos: una edición antigua puede pisotear una nueva.
  • Merge de valores: combinar estructuras de datos convergentes (CRDT, contadores, conjuntos). Correcto para casos específicos.
  • Conflicto visible: devolver ambas versiones y pedir decisión al usuario o a la aplicación. Lo más seguro para datos importantes.

En el mundo real, Cassandra usa LWW por defecto y permite «resolver en la aplicación» con operaciones CAS. La elección depende de cuánto duele perder una actualización.

La regla clave

El orden causal vale solo si seguimos el «tiempo de los mensajes»: si a pasa a b (a sucede-before b) y ambos modifican la misma clave, siempre podremos decir cuál deriva de cuál. Cuando dos nodos modifican sin cruzarse mensajes, hay un conflicto genuino. Esa distinción —derivado vs conflicto— es exactamente lo que resuelven los relojes vectoriales.

Ejercicio

  1. Simula con lápiz y papel un reloj de Lamport: nodo A envía a B, luego B envía a C. Escribe los contadores de cada evento.
  2. Con el código comparar() de esta lección, di qué relación tienen: (a-b:3 , b:1) vs (a-b:2, b:2).
  3. Para un carrito de la compra, diseña la fusión de dos versiones concurrentes y qué reloj asocias a la versión resultante.

Resumen

  • Los relojes lógicos ordenan eventos sin depender de relojes físicos.
  • Lamport da un orden parcial; los relojes vectoriales detectan concurrencia exacta.
  • Las versiones concurrentes se guardan juntas, nunca se descartan a ciegas.
  • La resolución es decisión de negocio: LWW, merge o conflicto visible.
