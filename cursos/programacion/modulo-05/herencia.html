Herencia

12 min Intermedio PHP Programación Orientada a Objetos

Introducción

Dos clases que comparten comportamiento terminan duplicando código. La herencia permite que una clase hija herede atributos y métodos de una clase padre y solo añada o modifique lo que le diferencia.

Definición

Con class Hija extends Padre la clase hija obtiene todo lo public y protected del padre (lo private no se hereda pero existe dentro), puede sobrescribir métodos con la misma firma, llamar a la versión padre con parent::metodo() y acceder a $this como si fuera suyo. Una clase puede tener muchas hijas, pero una hija solo un padre.

Conceptos clave

  • extends establece la relación padre-hijo.
  • Lo heredado: métodos public/protected (los private no pasan a la hija).
  • Sobrescritura: redefine el método con la misma firma.
  • parent::metodo() delega en la versión del padre.
  • Herencia única: una clase solo puede extender a una.

Ejemplo básico

Una clase base y una hija que hereda y amplía:

PHPherencia.php
class Personaje {
    public function __construct(
        protected string $nombre,
        protected int $vida = 100
    ) {}

    public function saludar(): string {
        return "Soy $this->nombre";
    }

    protected function restarVida(int $danio): void {
        $this->vida = max(0, $this->vida - $danio);
    }
}

class Guerrero extends Personaje {
    public function atacar(): string {
        $this->restarVida(10);
        return "$this->nombre golpea con espada (vida: $this->vida)";
    }
}

$g = new Guerrero("Zelda");
echo $g->saludar() . "\n";
echo $g->atacar();

Ejemplo intermedio

Sobrescritura con delegación al padre:

PHPsobrescritura.php
class Animal {
    public function hablar(): string {
        return "…";
    }
}

class Perro extends Animal {
    public function hablar(): string {
        return parent::hablar() . " ¡Guau!";
    }
}

echo (new Perro())->hablar();   // … ¡Guau!

Ejemplo real

Jerarquía de notificaciones reutilizando el envío base:

PHPnotificaciones.php
class Notificacion {
    public function __construct(protected string $destino) {}

    public function enviar(): string {
        return "Enviando notificación a $this->destino";
    }
}

class Email extends Notificacion {
    public function enviar(): string {
        return parent::enviar() . " vía SMTP";
    }
}

echo (new Email("ada@example.com"))->enviar();

Código completo

Código completo: medios de pago con lógica común y regla específica en cada uno:

PHPpagos.php
<?php

declare(strict_types=1);

class Pago {
    protected const COMISION = 0.0;

    public function comision(float $monto): float {
        return round($monto * self::COMISION, 2);
    }

    public function procesar(float $monto): string {
        return sprintf(
            "Pagando %.2f € (comisión %.2f €)",
            $monto,
            $this->comision($monto)
        );
    }
}

class PagoTarjeta extends Pago {
    protected const COMISION = 0.015;
}

class PagoPayPal extends Pago {
    protected const COMISION = 0.05;
}

echo (new PagoTarjeta())->procesar(100) . "\n";
echo (new PagoPayPal())->procesar(100);

Explicación

En herencia.php el Guerrero hereda saludar() y el estado $nombre/$vida, y añade su atacar() sin reescribir nada del padre. En la sobrescritura, la hija llama a parent::hablar() para no perder el comportamiento base: la herencia reutiliza y transforma.

La jerarquía de notificaciones muestra la reutilización real: el envío vive en la clase base y cada hija lo especializa. En los pagos, la comisión es una constante protected que cada hija redefine y $this->comision() usa la versión de la instancia (polimorfismo, que llega en la siguiente lección).

Errores comunes

  • Heredar solo por "reutilizar métodos" sin relación real: mejor composición.
  • Sobrescribir cambiando la firma (PHP 8 exige compatibilidad en muchos casos).
  • Olvidar parent:: y perder funcionalidad del padre al sobrescribir.
  • Jerarquías de más de 2-3 niveles: difíciles de razonar.

Buenas prácticas

  • Herencia horizontal superficial (clases hijas similares), no vertical profunda.
  • Delega en parent:: cuando la hija solo añade un paso.
  • Si solo necesitas compartir métodos sin estado, considera interfaces o traits.

Ejercicio

Roles con base común

Dificultad: Media
  1. Crea class Empleado con $nombre y salario().
  2. Crea Desarrollador extends Empleado que sobrescriba salario() sumando un bono y llame a parent::salario().
  3. Instancia ambos y muestra sus salarios.

Resumen

  • extends: hereda estado y comportamiento del padre.
  • Sobrescritura + parent:: reutilizan y especializan.
  • Herencia única y poco profunda: relación real de "es un".
