Encapsulamiento: public, private y protected

12 min Intermedio PHP Programación Orientada a Objetos

Introducción

Si todos los atributos son públicos, cualquier parte del código puede romper el objeto. El encapsulamiento protege el estado interno y expone solo la superficie necesaria, la base de API estables y clases difíciles de romper.

Definición

El encapsulamiento combina dos ideas: agrupar estado y comportamiento, y ocultar los detalles internos. En PHP se controla con tres modificadores: public (visible fuera), private (solo dentro de la clase) y protected (dentro y en subclases). Accedes a lo privado mediante métodos públicos: getters y setters.

Conceptos clave

  • private: nadie fuera de la clase puede tocarlo.
  • protected: visible para la clase y sus hijas (veremos herencia).
  • public: la superficie pública (la API de la clase).
  • Los métodos privados son "tubería interna" reutilizable por métodos públicos.
  • Regla práctica: atributos privados, método público mínimo.

Ejemplo básico

Atributos privados con getters y setters:

PHPprivado.php
class Tarjeta {
    public function __construct(
        private string $titular,
        private string $numero,
        private float $saldo = 0.0
    ) {}

    public function getTitular(): string {
        return $this->titular;
    }

    public function setSaldo(float $nuevo): void {
        if ($nuevo > 10000) {
            throw new RuntimeException("Requiere verificación");
        }
        $this->saldo = $nuevo;
    }
}

$t = new Tarjeta("Ada", "4111....");
echo $t->getTitular();   // Ada
// $t->saldo = 99999;    // Fatal error: private

Ejemplo intermedio

Métodos privados que esconden detalles de implementación:

PHPmetodo-privado.php
class PagoBancario {
    public function __construct(private string $cvv) {}

    public function cobrar(float $monto): bool {
        if ($this->validarCvv()) {
            echo "Cobrando $monto…\n";
            return true;
        }
        return false;
    }

    private function validarCvv(): bool {
        return preg_match('/^\d{3,4}$/', $this->cvv) === 1;
    }
}

$p = new PagoBancario("123");
echo $p->cobrar(99.9) ? "OK" : "CVV inválido";

Ejemplo real

Encapsular contadores y límites internos:

PHPsesion.php
class Sesion {
    private int $pasos = 0;
    private const MAXIMO = 3;

    public function registrar(): int {
        if ($this->pasos >= self::MAXIMO) {
            throw new RuntimeException("Límite de pasos superado");
        }
        return ++$this->pasos;
    }

    public function completada(): bool {
        return $this->pasos === self::MAXIMO;
    }
}

$s = new Sesion();
$s->registrar();
$s->registrar();
echo $s->completada() ? "Pendiente" : "Completada: " . $s->registrar();

Código completo

Código completo: una cuenta bancaria con operaciones validadas y saldo protegido:

PHPcuenta-encerrada.php
<?php

declare(strict_types=1);

class Cuenta {
    private float $saldo = 0.0;

    public function __construct(private string $titular) {}

    public function depositar(float $monto): void {
        if ($monto <= 0) {
            throw new InvalidArgumentException("El monto debe ser positivo");
        }
        $this->saldo += $monto;
    }

    public function retirar(float $monto): bool {
        if ($monto <= 0 || $monto > $this->saldo) {
            return false;
        }
        $this->saldo -= $monto;
        return true;
    }

    public function getSaldo(): float {
        return $this->saldo;
    }
}

$c = new Cuenta("Ada");
$c->depositar(100);
echo $c->retirar(40) ? "Retiro OK\n" : "Retiro fallido\n";
echo "Saldo: " . $c->getSaldo();

Explicación

Los atributos private impiden el acceso directo: $obj->saldo fuera de la clase es un error fatal, así que el único camino es el método. Eso permite que los setters validen (no aceptar saldos sin verificar) y que un método privado (como validarCvv()) quede oculto de la superficie pública.

La sesión encapsula su contador: nadie externo puede resetearlo o sobrescribirlo. Y la cuenta bancaria es el caso de negocio perfecto: retirar() decide con reglas de negocio y el saldo nunca puede quedar negativo. El estado interno vive aislado: solo las operaciones públicas lo tocan.

Errores comunes

  • Hacer todo public "porque es más rápido": pierdes las garantías.
  • Exponer setters que cualquiera pueda usar sin reglas de negocio.
  • Confundir private con protected antes de tener herencia.
  • Devolver referencias a datos internos mutables (arrays) y que el llamador los modifique.

Buenas prácticas

  • Atributos privados por defecto; sube a protected solo si la herencia lo necesita.
  • Getter mínimo para leer, método de acción para modificar.
  • Evita getters que devuelven colecciones internas: devuelve copias o array_* ya resueltos.

Ejercicio

Caja registradora segura

Dificultad: Media
  1. Crea class Caja con private float $total = 0.
  2. Método agregar(float $v) que rechace negativos.
  3. Método getTotal(): float y comprueba que fuera de la clase no puedas asignar $total.

Resumen

  • private oculta, protected comparte con hijas, public expone.
  • Regla: atributos privados + superficie pública de métodos.
  • Esos gets/sets validan y mantienen el objeto coherente.
