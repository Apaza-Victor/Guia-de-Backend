Polimorfismo, abstracción e interfaces

14 min Avanzado PHP Programación Orientada a Objetos

Introducción

Llega la joya del diseño orientado a objetos: poder escribir código que funciona con muchas clases distintas sin conocer su tipo concreto. Eso es polimorfismo, y se logra con interfaces y clases abstractas.

Definición

Una interfaz declara métodos que las clases deben implementar (contrato sin código): interface Repositorio { public function guardar(array $d): void; }. Una clase abstracta separa implementación concreta y casos base: puede tener métodos implementados y métodos abstractos que las hijas deben completar. Polimorfismo = tratar objetos distintos por su interfaz común, de modo que $factory->crear(...) responda según la instancia real.

Conceptos clave

  • Interfaz: qué métodos hay (contrato); la clase dirá cómo.
  • implements conecta clase e interfaz; extends con abstracta.
  • Clase abstracta: no se instancia; obliga a implementar sus métodos abstract.
  • abstract en el método = "píntalo tú, hija".
  • Polimorfismo: una variable tipada como interfaz acepta cualquier implementación.

Ejemplo básico

Una interfaz que dos clases implementan de forma distinta:

PHPinterfaz.php
interface Repositorio {
    public function guardar(array $datos): bool;
}

class RepositorioArchivo implements Repositorio {
    public function guardar(array $datos): bool {
        file_put_contents("datos.json", json_encode($datos));
        return true;
    }
}

class RepositorioMemoria implements Repositorio {
    public function guardar(array $datos): bool {
        echo "Guardado en memoria (simulación): " . json_encode($datos) . "\n";
        return true;
    }
}

function persistir(Repositorio $r): void {
    $r->guardar(["clave" => "valor"]);
}

persistir(new RepositorioArchivo());
persistir(new RepositorioMemoria());

Ejemplo intermedio

Clase abstracta con API base y único método a completar:

PHPabstracta.php
abstract class Servicio {
    abstract protected function preparar(): string;

    public function ejecutar(): string {
        return $this->preparar() . " — ejecutado";
    }
}

class ServicioEmail extends Servicio {
    protected function preparar(): string {
        return "Creando conexión SMTP";
    }
}

echo (new ServicioEmail())->ejecutar();

Ejemplo real

El polimorfismo en acción: un validador que no conoce el detalle:

PHPpolimorfismo.php
interface Validable {
    public function esValido(): bool;
}

class Pedido implements Validable {
    public function __construct(private float $total) {}
    public function esValido(): bool { return $this->total > 0; }
}

class Usuario implements Validable {
    public function __construct(private string $email) {}
    public function esValido(): bool { return str_contains($this->email, "@"); }
}

function procesar(Validable $objeto): string {
    return $objeto->esValido() ? "Válido — paso al siguiente flujo" : "Inválido — rechazo";
}

echo procesar(new Pedido(45.5)) . "\n";
echo procesar(new Usuario("sin-arroba"));

Código completo

Código completo: notificadores intercambiables en una única función de negocio:

PHPnotificadores.php
<?php

declare(strict_types=1);

interface Notificador {
    public function enviar(string $mensaje): string;
}

class CorreoNotificador implements Notificador {
    public function enviar(string $mensaje): string {
        return "Email: $mensaje";
    }
}

class SMSNotificador implements Notificador {
    public function enviar(string $mensaje): string {
        return "SMS: " . substr($mensaje, 0, 160);
    }
}

class SistemaInformes {
    public function __construct(private Notificador $notificador) {}

    public function reportar(string $texto): string {
        $entregado = $this->notificador->enviar($texto);
        return "Informe enviado — $entregado";
    }
}

$s = new SistemaInformes(new CorreoNotificador());
echo $s->reportar("Ventas del día arriba un 20%") . "\n";

$s2 = new SistemaInformes(new SMSNotificador());
echo $s2->reportar("Alerta: servidor al 90% de CPU");

Explicación

La interfaz Repositorio declara guardar(); cada clase implementa la mecánica. Como la función persistir() espera la interfaz, puede recibir cualquier implementación: eso es polimorfismo por abstracción.

La clase abstracta aporta el "esqueleto": ejecutar() ya está listo y solo el método abstracto preparar() depende de la hija. Y el validador demuestra el poder real: una sola función procesa pedidos, usuarios o cualquier cosa Validable sin conocer su clase.

Errores comunes

  • Implementar una interfaz y olvidar algún método: error fatal de sintaxis.
  • Las clases abstractas no se instancian: intentar new Abstracta() falla.
  • Tipar con la clase concreta cuando podrías tipar con la interfaz.
  • Crear jerarquías solo para rellenar interfaces que no aportan contrato.

Buenas prácticas

  • Programa contra interfaces, no contra implementaciones concretas.
  • Interfaces pequeñas (1-3 métodos) y con nombre de sustantivo capaz.
  • Usa clases abstractas cuando compartas implementación real entre hijas.

Ejercicio

Almacenamiento intercambiable

Dificultad: Difícil
  1. Define la interfaz Almacenamiento con guardar(string $clave, string $valor): void.
  2. Implementa EnvMemoria (print_r) y EnvArchivo (file_put_contents).
  3. Escribe una función parametrizada por la interfaz que guarde y confirme; llámalo con ambas implementaciones.

Resumen

  • Interfaces = contratos; clases abstractas = esqueleto con responsabilidades.
  • Polimorfismo: código que trabaja con la interfaz, no con la clase.
  • Inyección de dependencias en el constructor lo hace real: __construct(private Notificador $n).
