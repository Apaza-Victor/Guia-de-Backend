Ámbito (scope) de las variables

10 min Intermedio PHP Funciones

Introducción

¿Por qué una variable no se ve desde cualquier parte? Porque cada variable nace en un ámbito (scope) y muere al salir de él. Entender el scope evita el 80 % de los bugs de variables y te enseña a compartir estado cuando toca.

Definición

El ámbito es la zona del script donde una variable existe y es visible. En PHP: las variables creadas dentro de una función son locales (muertas al terminar), las del nivel superior del archivo son globales (accesibles en el script) y las marcadas static conservan su valor entre llamadas a la función. Una función no ve las variables globales sin declararlas dentro con global.

Conceptos clave

  • Variables locales: existen solo dentro de la función.
  • Variables globales: visibles en el script, no automáticamente dentro de funciones.
  • global $x; importa una variable global al interior de la función.
  • static $n = 0; conserva el valor entre llamadas.
  • Una función no ve las variables del ámbito desde el que se llama: pásale los datos como argumentos.

Ejemplo básico

Dos variables con el mismo nombre en ámbitos distintos no se pisan:

PHPscopes.php
$saludo = "global";

function decir(): void {
    $saludo = "local";
    echo $saludo . "\n";   // local
}

decir();
echo $saludo . "\n";       // global (no se tocó)

Ejemplo intermedio

Con global la función puede leer y escribir la variable exterior:

PHPglobal.php
$contador = 0;

function registrarVisita(): void {
    global $contador;
    $contador++;
}

registrarVisita();
registrarVisita();
echo $contador;   // 2

Ejemplo real

static conserva el valor entre llamadas sin exponer nada fuera:

PHPstatic.php
function siguienteId(): int {
    static $ultimo = 0;
    $ultimo++;
    return $ultimo;
}

echo siguienteId() . " ";   // 1
echo siguienteId() . " ";   // 2
echo siguienteId();         // 3

Código completo

Código completo: contador de peticiones con estado estático, sin tocar globales:

PHPcontador-peticiones.php
<?php

declare(strict_types=1);

function contadorPeticiones(string $clave): int {
    static $conteo = [];
    if (!isset($conteo[$clave])) {
        $conteo[$clave] = 0;
    }
    $conteo[$clave]++;
    return $conteo[$clave];
}

echo "Login: " . contadorPeticiones("LOGIN") . "\n";
echo "Login: " . contadorPeticiones("LOGIN") . "\n";
echo "API:   " . contadorPeticiones("API") . "\n";

Explicación

En scopes.php las dos $saludo viven en mundos separados: se llaman igual pero nada las conecta. Esto es una protección: una función no puede romper variables ajenas por accidente.

global abre esa puerta, pero crea dependencias ocultas: quien lee la función no sabe qué toca. static es más fino: el estado vive dentro de la función y sobrevive entre llamadas, ideal para secuenciadores como el de IDs. En el contador real usamos un array estático con claves para llevar varios contadores a la vez.

Errores comunes

  • Creer que la función ve las variables del script: sin global nace una local vacía.
  • Abusar de global: acoplar la función a su entorno la hace inreutilizable.
  • Reinicializar una variable static en cada llamada con = en vez de usar el valor guardado.
  • Confundir global con static: uno importa de fuera, el otro conserva dentro.

Buenas prácticas

  • Pasa datos por parámetros y devuelve resultados; evita global.
  • Usa static solo para estado interno persistente sencillo.
  • Si necesitas estado compartido complejo, una clase (módulo 5) es mejor estructura.

Ejercicio

Ticket numerado

Dificultad: Media
  1. Crea una función nuevaTicket(): int con una static $num que incremente y devuelva.
  2. Llámalas 3 veces y muestra los números (deben ser 1, 2, 3).
  3. Añade una variable global $taquilla = "Central" y una función con global que imprima "Taquilla: $taquilla — Ticket N".

Resumen

  • Cada ámbito protege sus variables: local, global y estático.
  • global importa variables exteriores; úsalo con cuidado.
  • static conserva el valor entre llamadas.
