DRY y KISS

8 min Intermedio PHP Código profesional

Introducción

Dos reglas del sentido común técnico: DRY (Don't Repeat Yourself, no te repitas) y KISS (Keep It Simple, Stupid, mantenlo simple). Suena fácil, pero suelen violarse en producción: copiar y pegar para "ahorrar tiempo" y overengineering "por si acaso".

Definición

DRY defiende que cada conocimiento del sistema tenga una única representación, no duplicada. Si la misma regla (un IVA, una validación) vive en dos sitios, cualquier cambio deben hacerse en dos. KISS pide la solución más simple que funcione hoy: sin patrones de más, sin abstracciones especulativas. Combinadas: "extrae lo que se repite, simplifica lo que no hace falta complicar".

Conceptos clave

  • DRY detecta duplicación de reglas (no de texto trivial).
  • Extrae a función/clase cuando la misma lógica aparece 2+ veces.
  • KISS: empieza sin abstraer; añade complejidad solo cuando la necesidad es real.
  • "YAGNI" — You Aren't Gonna Need It: no construyas para un futuro imaginario.
  • Código simple = pocos movimientos para contar qué hace.

Ejemplo básico

Violación de DRY: la misma regla del IVA copiada dos veces:

PHPdry-mal.php
// productoServicio.php
function precioMil(float $p): float { return $p * 1.21; }

// checkout.php
function totalConIva(float $p): float { return $p * 1.21; }
// El día que el IVA cambie a 1.20… caza bugs de rebote
PHPdry-bien.php
// impuestos.php
const IVA = 0.21;
function conIva(float $base): float { return $base * (1 + IVA); }

// ambos sitios usan la MISMA función
echo conIva(100);

Ejemplo intermedio

KISS frente a overengineering:

PHPkiss.php
// SOBREDISEÑO: una fábrica de sumas…
interface Sumador { public function sumar(int $a, int $b): int; }
class SumadorSimple implements Sumador {
    public function sumar(int $a, int $b): int { return $a + $b; }
}

// KISS: 5 líneas bastan
function suma(int $a, int $b): int {
    return $a + $b;
}
echo suma(2, 3);

Ejemplo real

DRY bien aplicado: normalización de texto reutilizada en los formularios:

PHPdry-entrada.php
function normalizarEntrada(string $valor): string {
    return trim(mb_strtolower($valor));
}

// siguiendo el camino feliz en tres flujos distintos
$usuario = normalizarEntrada($inputUsuario);
$email   = normalizarEntrada($inputEmail);
$ciudad  = normalizarEntrada($inputCiudad);
// un solo cambio aquí se propaga a los tres

Código completo

Código completo: utilidad central que varios archivos reutilizan (DRY) con la implementación más directa (KISS):

PHPdry-real.php
<?php

declare(strict_types=1);

// lib/tiempo.php
function hms(int $segundos): string {
    $h = intdiv($segundos, 3600);
    $m = intdiv($segundos % 3600, 60);
    $s = $segundos % 60;
    return sprintf("%02d:%02d:%02d", $h, $m, $s);
}

// streaming.php
require_once __DIR__ . "/lib/tiempo.php";
echo "Duración total: " . hms(7325) . "\n";

// informe.php
require_once __DIR__ . "/lib/tiempo.php";
echo "Tiempo de actividad: " . hms(86400);

Explicación

En el ejemplo DRY, la regla del IVA duplicada se rompe en cuanto cambia la tasa; centralizada en conIva() + constante, el cambio se hace en un solo punto. KISS muestra cómo una interfaz para sumar dos números es "impresionante y absurda": para ese problema, $a + $b es la solución simple y correcta.

La normalización reutilizada demuestra DRY en datos: tres flujos comparten una única regla de limpieza, y el caso real unifica una utilidad (hms()) que dos informes distintos consumen. La regla de oro: si lo duplico, lo extraigo; si no lo necesito aún, no lo diseño.

Errores comunes

  • Copiar-pegar bloques enteros "por urgencia" (DRY se paga al cambiar).
  • Abstraer de más: un patrón por cada par de líneas es un anti-patrón.
  • Implementar YAGNI: cachés, colas y frameworks de eventos que nadie pidió.
  • Premature optimization y premature abstraction suelen ir juntos.

Buenas prácticas

  • Extrae tras notar la segunda repetición, no antes (regla de tres).
  • Simplifica el diseño hasta que añadir una función nueva sea más barato sin él.
  • Código claro y aburrido > código ingenioso e ilegible.

Ejercicio

Factura sin duplicados

Dificultad: Media
  1. Escribe dos veces la fórmula $base * 1.16 en archivos distintos (mala DRY).
  2. Refactoriza a una función precioFinal(float $base): float en un módulo propio.
  3. Usa esa función desde ambos sitios y comprueba que un solo cambio los arregla.

Resumen

  • DRY: una sola fuente de verdad para cada regla.
  • KISS/YAGNI: solución mínima que funcione hoy.
  • Extracto cuando se repite, simplifico cuando se complica.
