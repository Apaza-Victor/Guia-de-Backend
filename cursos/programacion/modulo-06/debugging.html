Debugging y herramientas

12 min Intermedio PHP Código profesional

Introducción

Los bugs no desaparecen, se encuentran. La diferencia entre un buen y un mal programador está en el método: leer el error, aislar la causa, corregir y verificar. Este sistema se llama debugging, y las herramientas (Xdebug, logs, trazas) lo hacen rápido.

Definición

Depurar es encontrar la diferencia entre lo que el programa hace y lo que debería. El flujo: reproducir el fallo, leer el mensaje (y su línea), observar el estado en ese punto (con var_dump(), logs o el depurador de Xdebug), formular hipótesis y corregir. Las trazas (stack traces) muestran la ruta de llamadas que llevó al error.

Conceptos clave

  • Mensaje de error = pista principal: lee la línea antes de tocar nada.
  • var_dump() / print_r() para inspeccionar valores ahí mismo.
  • Los logs (error_log()) registran lo que ocurre sin pantalla.
  • Xdebug + tu editor: breakpoints y pasos sin echo a ciegas.
  • Bisect: comenta / aísla la mitad del código para reducir la zona del bug.

Ejemplo básico

Inspección básica con var_dump():

PHPinspeccion.php
$total = 0;
var_dump($total);          // int(0)

$total += "10";
var_dump($total);          // int(10) — ¡entró "10" como texto!

// Hipótesis: la entrada era string.
$entrada = "10";
if ($total + $entrada != 20) {   // problema clásico de tipos
    echo "Bug detectado: " . gettype($entrada);
}

Ejemplo intermedio

Leer la traza: el error te dice dónde, tú debes decir por qué:

PHPtraza.php
// Supongamos este error:
// Fatal error: Uncaught TypeError: dividir(): Argument #1 ($a) must be
// of type int, string given in test.php on line 12

function dividir(int $a, int $b): float {
    return $a / $b;
}

// $a llega como "24" (string) desde formulario:
dividir("24", 3);   // TypeError por tipos estrictos

Ejemplo real

Logs en lugar de perdigones: registra contexto y fecha:

PHPlogs.php
function procesarOrden(array $orden): void {
    error_log("[" . date("Y-m-d H:i:s") . "] Orden " . $orden["id"] . " recibida");
    if (!isset($orden["productos"])) {
        error_log("Orden " . $orden["id"] . " SIN productos — auditoría asegura");
        return;
    }
    // … continuar con la lógica
}

procesarOrden(["id" => 42]);

Código completo

Código completo: mini-depurador de un rango de precios con verificación por pasos:

PHPdepurando.php
<?php

declare(strict_types=1);

function rangoPrecios(array $productos): array {
    if (count($productos) === 0) {
        return ["min" => 0.0, "max" => 0.0];
    }

    $precios = array_map(fn($p) => $p["precio"], $productos);
    error_log("Precios: " . json_encode($precios));

    $min = min($precios);
    $max = max($precios);
    error_log("Rango calculado: $min .. $max");

    return ["min" => $min, "max" => $max];
}

$oferta = ["min" => 15.0, "max" => 99.9];
$alto   = ["min" => 120.0, "max" => 250.0];

var_dump(rangoPrecios([
    ["precio" => 25.5],
    ["precio" => 8.75],
    ["precio" => 43.2],
]));

Explicación

La inspección con var_dump() muestra tipo y valor, clave para cazar bugs de tipos (el caballo de batalla del backend). La traza te dice el archivo y la línea, pero el por qué lo descubres tú siguiendo los datos hacia atrás.

Los logs con marca de tiempo y contexto (id de orden) convierten un fallo misterioso en un rastro recuperable; los revisarás cuando otra persona reporte el bug. Por último, el depurador por pasos: cada operación se registra, así que cuando un cálculo dé un resultado raro, la línea equivocada salta a la vista.

Errores comunes

  • Cambiar código al azar sin hipótesis: "si cambio x y reza…".
  • Ignorar el mensaje y la línea del error.
  • Dejar var_dump() y logs de depuración en producción.
  • Depurar una copia diferente de la que se rompe (versiones o entornos distintos).

Buenas prácticas

  • Sigue el flujo: reproducir → leer → aislar → corregir → verificar.
  • Haz bisect sobre el rango de código sospechoso.
  • Aprende Xdebug: los breakpoints aceleran todo diez veces.

Ejercicio

Caza el bug

Dificultad: Media

Este código muestra "Total: 10125" en vez de 125. Encuentra el bug con var_dump():

PHPbug.php
function conIva(float $base): float { return $base * 1.21; }
echo "Total: " . conIva("100");

Pista: mira qué recibe la función y qué devuelve gettype().

Resumen

  • Método: reproducir → leer → aislar → corregir → verificar.
  • var_dump(), logs y trazas son tus ojos en cada punto.
  • Xdebug reemplaza el "echo a ciegas" por depuración real.
