Manejo de errores y excepciones

12 min Intermedio PHP Código profesional

Introducción

Un script que muere al primer error no vale para un servidor que atiende miles de peticiones. El manejo de errores decide qué pasa cuando algo falla: si suena la alarma, si se registra, si se degrada con elegancia o si responde al usuario con un código correcto.

Definición

PHP distingue errores (avisos, advertencias y fatales del motor) y excepciones (Exception y sus hijas), que se lanzan con throw y se capturan con try { ... } catch (MiTipo $e) { ... }. La prioridad del catch importa: va de lo más específico a lo genérico. El bloque finally siempre se ejecuta (cierre de conexiones, por ejemplo). PHP 8 mejora los errores preexistentes y exige tipado.

Conceptos clave

  • throw new Excepcion(...) lanza; try/catch captura.
  • Excepciones específicas primero: catch (InvalidArgumentException $e).
  • finally se ejecuta siempre, haya o no error.
  • getMessage() y getCode() extraen contexto del error.
  • Nada capturado = error fatal = petición caída.

Ejemplo básico

El mínimo que todo backend usa:

PHPtry-catch.php
function dividir(float $a, float $b): float {
    if ($b === 0.0) {
        throw new DivisionByZeroError("No se puede dividir entre cero");
    }
    return $a / $b;
}

try {
    echo dividir(10, 0);
} catch (DivisionByZeroError $e) {
    echo "Error: " . $e->getMessage();
}

Ejemplo intermedio

Máscaras-las específicas según el tipo de fallo:

PHPmulti-excepcion.php
function guardarUsuario(array $datos): void {
    if ($datos["edad"] < 0) {
        throw new InvalidArgumentException("La edad no puede ser negativa");
    }
    if ($datos["edad"] > 120) {
        throw new RangeException("Edad fuera de rango");
    }
    // … persiste en BD
}

try {
    guardarUsuario(["edad" => -3]);
} catch (InvalidArgumentException $e) {
    echo "Datos inválidos: " . $e->getMessage();
} catch (RangeException $e) {
    echo "Rango: " . $e->getMessage();
} finally {
    echo " (registro de intento completado)";
}

Ejemplo real

Excepciones propias para que el dominio hable:

PHPexcepcion-propia.php
class PagoRechazado extends RuntimeException {}

function cobrar(string $tarjeta, float $monto): string {
    if (strlen($tarjeta) !== 16) {
        throw new PagoRechazado("Número de tarjeta incompleto");
    }
    return "Pago de $monto procesado";
}

try {
    echo cobrar("4242", 99.9);
} catch (PagoRechazado $e) {
    echo "El cliente no pudo pagar: " . $e->getMessage() . " — devolvemos la vista de error";
}

Código completo

Código completo: una API segura que responde con códigos y conserva la trazabilidad:

PHPapi-errores.php
<?php

declare(strict_types=1);

class ApiError extends RuntimeException {}

function procesarPeticion(string $cuerpo): string {
    $datos = json_decode($cuerpo, true);

    if (json_last_error() !== JSON_ERROR_NONE) {
        throw new ApiError("JSON malformado", 400);
    }
    if (!isset($datos["email"])) {
        throw new ApiError("Falta el campo email", 422);
    }
    // … lógica de negocio
    return "ok";
}

function responder(string $cuerpo): void {
    try {
        $resultado = procesarPeticion($cuerpo);
        echo "200 OK: " . $resultado . "\n";
    } catch (ApiError $e) {
        http_response_code($e->getCode());
        echo $e->getCode() . " " . $e->getMessage() . "\n";
        error_log("[API] Código {$e->getCode()}: {$e->getMessage()}");
    } catch (Exception $e) {
        http_response_code(500);
        echo "500 Error interno\n";
        error_log("[API] No controlado: " . $e->getMessage());
    }
}

responder('{"email":"ada@x.com"}');   // 200
responder('{"email":"sin arroba"}');  // 200 (validación real la haría otro)

Explicación

El try/catch rodea solo el tramo arriesgado y el error se convierte en un flujo controlado en vez de un fatl. Con varias excepciones, el backend puede responder distinto según el tipo de fallo — datos inválidos, rango, red— y finally garantiza la limpieza.

Las excepciones propias (PagoRechazado, ApiError) hacen que el mensaje hable el idioma del negocio y lleven códigos HTTP (getCode()). La API final muestra el patrón estelar: errores esperados → respuesta 4xx con traza en log; errores inesperados → 500 genérico sin filtrar detalles al cliente.

Errores comunes

  • Swallowing errors: catch (Exception $e) { } vacío que esconde todo.
  • Capturar la excepción genérica antes de la específica (nunca se alcanza la segunda).
  • Exponer $e->getMessage() al cliente: revela estructura interna.
  • Olvidar finally: conexiones y locks que nunca se cierran.

Buenas prácticas

  • Lanza temprano y específico; captura tarde y con contexto.
  • Registra siempre (error_log) y responde mensajes seguros.
  • Una sola responsabilidad por excepción capturada.

Ejercicio

Matrícula a prueba de fallos

Dificultad: Media
  1. Crea matricular(string $email, int $edad): void que lance InvalidArgumentException si el email no tiene "@".
  2. Envuelve la llamada en try/catch y muestra un mensaje amistoso.
  3. Añade un finally que registre en el log la intención de matrícula.

Resumen

  • try/catch doma lo inesperado; finally hace la limpieza.
  • Excepciones específicas y propias para un dominio expresivo.
  • Log interno + respuesta segura al cliente.
