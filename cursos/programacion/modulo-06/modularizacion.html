Modularización

12 min Intermedio PHP Código profesional

Introducción

Un archivo de 2000 líneas acaba siendo imposible de mantener. La modularización divide el programa en archivos pequeños y con responsabilidad clara, para leer, probar y reutilizar cada pieza por separado. Es el mismo principio que aplicarás en controladores, servicios y repositorios.

Definición

En PHP se incluyen archivos con include, require, include_once y require_once. La diferencia: require detiene el script si falta el archivo (include sigue); el _once evita cargar dos veces el mismo archivo. Cada módulo expone funciones, clases o datos y define sus propias dependencias.

Conceptos clave

  • require para piezas imprescindibles; include para opcionales.
  • Prefiere require_once para clases y utilidades.
  • Un archivo = una responsabilidad (config, lógica, entidades…).
  • Rutas relativas con __DIR__ para no depender del directorio actual.
  • Composer y PSR-4 automatizan la carga de clases en proyectos grandes.

Ejemplo básico

Dos archivos: una librería y un script que la usa:

PHPutilidades.php
// utilidades.php
function precioConIva(float $base, float $tasa = 0.21): float {
    return round($base * (1 + $tasa), 2);
}

function moneda(float $valor): string {
    return number_format($valor, 2, ",", ".") . " €";
}
PHPindex.php
// index.php
require_once __DIR__ . "/utilidades.php";

echo moneda(precioConIva(99.9));

Ejemplo intermedio

Separar la configuración del resto del código:

PHPconfiguracion.php
// configuracion.php
const BD_HOST   = "localhost";
const BD_NOMBRE = "tienda";
const APP_NOMBRE = "Mi Api";
PHPconexion.php
// conexion.php
require_once __DIR__ . "/configuracion.php";

function conectar(): string {
    return "mysqli://" . BD_HOST . "/" . BD_NOMBRE;
}

echo APP_NOMBRE . ": " . conectar();

Ejemplo real

Organización de un proyecto coherente con cargas independientes:

PHPestructura.php
// backend/
// ├── configuracion.php   (¡constantes!)
// ├── modelos/Producto.php
// ├── servicios/Precios.php
// └── index.php

// modelos/Producto.php
class Producto {
    public function __construct(public string $nombre, public float $precio) {}
}

// servicios/Precios.php
require_once __DIR__ . "/../modelos/Producto.php";

function aplicarIva(Producto $p, float $tasa): float {
    return $p->precio * (1 + $tasa);
}

Código completo

Código completo: minimedidor de velocidad organizado en módulos:

PHPproyecto.php
<?php

declare(strict_types=1);

// lib/matematicas.php
function promedio(array $nums): float {
    return array_sum($nums) / count($nums);
}

// lib/matematicas.php (continuación)
function mayor(array $nums): float {
    return max($nums);
}

// test.php
require_once __DIR__ . "/lib/matematicas.php";

$mediciones = [120, 118, 122, 119, 121];
printf("Promedio: %.2f Mbps\n", promedio($mediciones));
printf("Máximo: %.2f Mbps\n", mayor($mediciones));

Explicación

require_once carga utilidades una sola vez y su ausencia detiene el programa, exactamente lo que quieres con código imprescindible. Usar __DIR__ al construir la ruta evita el gran clásico: scripts que se rompen al cambiar de directorio.

En la estructura por carpetas (modelos/, servicios/) ves el patrón que luego usarás con frameworks: cada pieza se carga solo cuando se necesita. Finalmente, el medidor de velocidad separa la librería (lib/) del uso (test.php), de modo que puedes importar la lógica desde cualquier sitio.

Errores comunes

  • Usar include con clases imprescindibles: si el archivo falla, todo sigue roto.
  • Rutas relativas frágiles ("../" encadenados) en vez de __DIR__.
  • Cargar el mismo archivo varias veces y duplicar constantes o clases.
  • Meter toda la lógica en un único index.php monstruoso.

Buenas prácticas

  • Una responsabilidad por archivo; nombres descriptivos del contenido.
  • Configuración centralizada y validada al arranque.
  • En proyectos reales, usa Composer y autoloading (PSR-4) en vez de require/once a mano.

Ejercicio

Módulo de conversión

Dificultad: Fácil
  1. Crea conversiones.php con kmAMillas(float) y celsiusAFahrenheit(float).
  2. Crea main.php que las require_once __DIR__ y muestre dos conversiones.
  3. Verifica que cargar dos veces no rompe.

Resumen

  • Divide en módulos con responsabilidad única.
  • require_once + __DIR__ = cargas robustas.
  • En producción: Composer/PSR-4 sobre los includes manuales.
