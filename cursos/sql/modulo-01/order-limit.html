Ordenando y limitando resultados

⚙️ Intermedio 8 min SQL Módulo 1 · Fundamentos de SQL

Introducción

Sin ORDER BY, una base puede devolver las filas en cualquier orden. Y devolver 50 millones de filas a la vez es un desperdicio: LIMIT recorta el resultado. Estas dos cláusulas construyen los «top» y la paginación de cualquier API.

ORDER BY

LIMIT y OFFSET

PostgreSQL acepta LIMIT/OFFSET; SQL Server usa ORDER BY ... OFFSET ... FETCH. La idea es universal, la sintaxis cambia.

El caso «top N»

Consejos y límites

  • El ORDER BY sobre millones de filas sin índice es costoso (lo verás en optimización).
  • OFFSET muy grande se vuelve lento: para deep pagination se usan claves (keyset pagination).
  • Los resultados sin ORDER BY son impredecibles: si importa el orden, decláralo siempre.
  • LIMIT sin OFFSET es la forma más común de «traer poco de una consulta gigante».

Ejercicio

  1. Lista los productos ordenados por precio descendente.
  2. Extrae el top 2 con menor stock.
  3. Simula la página 3 de una lista paginada de 10 en 10 con LIMIT/OFFSET.

Resumen

  • ORDER BY ordena por una o varias columnas.
  • LIMIT recorta el resultado; OFFSET salta filas.
  • Top N = ORDER BY + LIMIT.
  • La deep pagination con OFFSET tiene límites prácticos.
