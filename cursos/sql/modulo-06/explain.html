Leer planes con EXPLAIN

⚔️ Avanzado 11 min SQL Módulo 6 · Optimización

Introducción

EXPLAIN muestra el plan de ejecución sin ejecutar la consulta. Es el estetoscopio del optimizador: dice cómo piensa leer las tablas, en qué orden y con qué estrategia.

Dónde y cómo

No borra la consulta: construye el plan. En MySQL, EXPLAIN ANALYZE además la ejecuta y mide filas y tiempo real.

Las columnas que importan

  • type: el método de acceso. De mejor a peor: const → eq_ref → ref → range → index → ALL (scaneo completo).
  • possible_keys: qué índices existen para la consulta.
  • key: el índice finalmente usado (NULL = ninguno).
  • rows: estimación de filas que se leerán.
  • Extra: maravillas y avisos (Using index = solo índice; Using filesort = ordena en memoria/disco; Using temporary = tabla temporal).

Comparación práctica

Qué buscar cuando algo es lento

  • type = ALL repetido en varias tablas: busca índice o reescribe.
  • key = NULL con possible_keys lleno: el optimizador estimó que no compensaba.
  • Using filesort con tablas grandes: revisa el ORDER BY.
  • Using temporary en agregaciones: ojo con GROUP BY.
  • Filas estimadas vs reales muy dispares: estadísticas viejas → ANALYZE TABLE.

Ejercicio

  1. Corre EXPLAIN sobre un SELECT simple por PK y por una columna sin índice.
  2. Añade el índice y compara type, key y rows.
  3. Fíjate en un Extra con Using filesort y mueve el ORDER BY.

Resumen

  • EXPLAIN = plan sin ejecutar; ANALYZE añade medición real.
  • type, key y rows revelan el método de acceso.
  • ALL y key NULL disparan los radares de rendimiento.
  • Extra avisa de filesort, temporales e índice puro.
