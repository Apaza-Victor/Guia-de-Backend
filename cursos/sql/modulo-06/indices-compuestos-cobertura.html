Índices compuestos y de cobertura

⚔️ Avanzado 11 min SQL Módulo 6 · Optimización

Introducción

Un índice sobre varias columnas es un compuesto. Ordenado por la primera columna, luego la segunda, etc. El orden lo es todo: define qué consultas se benefician y cuáles lo ignoran.

Índices compuestos

Regla del prefijo izquierdo

Un compuesto (a, b, c) sirve para consultas por: a; a+b; a+b+c. No sirve para b solas ni para b+c. La columna más «discriminante» (lo que más reduce) va primero; las de orden, agrupación y cobertura van detrás.

Índice de cobertura

Cuando el SELECT solo pide columnas del propio índice, el motor responde sin tocar la tabla: Extra: Using index. Es la consulta más barata posible:

Perfecto para contadores y datos «delgados» en renglones de read-heavy dashboards.

Jugar a dos bandas

No multipliques índices por obsesión: cada uno cuesta disco y escrituras. Estrategia realista:

  • Empieza por los WHERE y JOINs más calientes (mira EXPLAIN).
  • Añade compuestos sobre los pares más consultados.
  • Suma las columnas del SELECT para lograr cobertura si el reporte lo exige.
  • Borra con EXPLAIN los que nunca aparecen en key.

Ejercicio

  1. Crea un compuesto (estado, fecha) y prueba las tres variantes del prefijo.
  2. Añade cobertura y comprueba el Extra: Using index.
  3. Propón la columna primera para un WHERE muy selectivo de tu esquema.

Resumen

  • Compuesto = orden de columnas que marca el prefijo izquierdo.
  • La mejor columna «discriminante» va primero.
  • Cobertura = consulta resuelta solo con el índice (Using index).
  • Cada índice extra paga: diseñalos por EXPLAIN, no por intuición.
