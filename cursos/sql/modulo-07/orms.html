ORMs en el backend

⚔️ Avanzado 12 min SQL Módulo 7 · SQL en el backend

Introducción

Un ORM (Object-Relational Mapping) modela tus tablas como objetos y traduce tus llamadas a SQL. Tienes Sequelize, TypeORM, Prisma (Node), SQLAlchemy (Python), Django ORM, ActiveRecord (Ruby), Hibernate (Java)… Todos resuelven lo mismo: que no repitas el mapeo a mano.

Modelar y consultar

Las virtudes

  • Seguridad: query builders/parametrizaciones vienen de serie (adiós inyección accidental).
  • Velocidad de desarrollo: CRUD básico en pocas líneas.
  • Portabilidad: cambias de motor y tu código apenas cambia.
  • Validaciones y eventos: reglas de negocio cerca de los datos.

El lado oscuro

Los ORMs esconden SQL: N+1, selects de columnas inútiles y joins inesperados. Si no conoces lo que hay debajo, tu "simple" llamada hace 200 consultas.

¿Cuándo quieres SQL puro?

  • Reportes y agregaciones complejas (una consulta «de monstruo»).
  • Patrones de alto rendimiento: ventanas, CTEs, UPDATE en bloque.
  • Middle donde el ORM brilla menos: facturación, analítica.

La tendencia madura: híbrido. ORM para CRUD y migraciones; SQL crudo (con parámetros) para lo pesado. Prisma incluso permite «queryRaw» para eso.

El principio que salva

Nunca dejes que el ORM decida por ti cuando el rendimiento importa. Antes de entregar: mira el SQL que genera (log de consultas o EXPLAIN) y pregunta «¿cuántos round-trips?».

Ejercicio

  1. Crea un modelo Cliente→Pedido en el ORM de tu stack.
  2. Activa el log de queries y ejecuta el CRUD: ¿cuántos SELECTs salen?
  3. Reescribe un reporte pesado en SQL crudo con parámetros.

Resumen

  • ORM mapea tablas a objetos y genera SQL.
  • Gana seguridad, velocidad y portabilidad en CRUD.
  • N+1, selects gordos y joins ocultos: su riesgo.
  • Híbrido (ORM + SQL crudo) es la práctica madura.
