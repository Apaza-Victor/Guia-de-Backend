Buenas prácticas SQL en backend

⚔️ Avanzado 11 min SQL Módulo 7 · SQL en el backend

Introducción

Módulo de cierre: el decálogo que convierte «SQL que funciona» en «SQL que un equipo puede mantener a las 3 a.m.». Ordenado de seguridad a crecimiento.

El decálogo

  1. Parametriza todo. Ningún valor de usuario viaja dentro de la cadena SQL (véase consultas preparadas).
  2. Campos explícitos. Nada de SELECT * en producción: listas columnas, aprovecha cobertura y evita fugas.
  3. Paginación siempre. LIMIT/OFFSET o cursor en listas; los endpoints sin tope derriban la base.
  4. Filtra en la base, no en la app. No bajes 10 000 filas para filtrar en memoria.
  5. Índices con EXPLAIN. Crea, mide, borra lo que no se usa (módulo 6).
  6. Transacciones para escrituras multi-paso. Todo o nada cuando tocas dos tablas (ACID).
  7. Conexiones con pool y timeout. Comprobar la conexión por operación es pecado; reutiliza el pool.
  8. Límites y timeouts. Define timeouts para no colgar el servidor con una bestia.
  9. Migraciones versionadas. El DDL se codea y se revisa; nunca se corre a mano en producción.
  10. Logs y métricas. Consultas lentas, tiempo de respuesta y errores visibles al equipo.

El patrón de cada endpoint

La revisión de código

En cada PR que toque datos, pregúntate:

  • ¿Existe la migración (no DDL suelto) y es reversible?
  • ¿Hay un plan para volver atrás si rompe?
  • ¿El EXPLAIN del nuevo SELECT tiene índices o va a explorar?
  • ¿El conteo de consultas por request es razonable (ni N+1)?

Cuando crezca

  • Cachea respuestas calientes (Redis) antes de parchear con índices raros.
  • Separa lecturas y escrituras (replicas) cuando el tráfico lo pida.
  • Particiona las tablas gigantes; archiva los datos viejos.
  • Aplica tooling de online schema change para ALTER sin cortes.

Ejercicio

  1. Audita un endpoint propio contra el decálogo: ¿cuáles cumples?
  2. Reescribe un SELECT * y añade paginación con tope.
  3. Supervisa su EXPLAIN y su número de queries por request.

Resumen

  • Parametrizar, campos explícitos y paginar: los tres blindajes.
  • Filtra en SQL, indexa con plan y transacciona lo multi-paso.
  • El DDL viaja versionado; la app usa pools con timeouts.
  • Revisa cada cambio de datos como un revisor.
