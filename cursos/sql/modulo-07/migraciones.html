Migraciones de esquema

⚔️ Avanzado 11 min SQL Módulo 7 · SQL en el backend

El problema

Producción no es como tu máquina: ya tiene datos y no se puede «borrar y volver a crear». El esquema evoluciona en pasos versionados: esa es la migración. Se crea una, se codea, se revisa, y después se aplica arriba y abajo del stack sin adiós.

La unidad: up y down

La migración up avanza el esquema; la down lo revierte. El nombre de archivo lleva fecha/orden para saber quién va antes.

Herramientas

  • Node: Knex con su CLI, Sequelize-CLI, Prisma Migrate, TypeORM migrations.
  • Python: Alembic (sobre SQLAlchemy), Django migrations.
  • Otros: Rails migrations, migrate/Liquibase para Java/Net.

Buenas prácticas de migración

  • Una migración = un cambio atómico y reversible.
  • Prueba la down en desarrollo antes de aplicarla arriba.
  • Cada migración nueva se codea y se aplica en orden (el historial nunca se edita).
  • Solo se agrega, no se corrije una ya aplicada: se crea otra.
  • Las migraciones viven en el repo, como el código.

Migraciones que duelen

Ojo: en tablas enormes, ALTER que reescribe filas produce bloqueo. Divide en pasos (add column → backfill → constraint) o usa herramientas online (pt-online-schema-change).

Ejercicio

  1. Crea una migración up/down y aplícala y revierte.
  2. Añade una columna con DEFAULT a una tabla con datos.
  3. Escribe la migración «anti-blank» para una columna NOT NULL.

Resumen

  • La migración versiona el DDL como si fuera código.
  • up avanza; down revierte; el historial es inmutable.
  • Emplea herramientas de tu stack (Knex, Alembic, Prisma…).
  • Las tablas grandes piden pasos cuidadosos.
