INNER JOIN

⚙️ Intermedio 11 min SQL Módulo 3 · JOINs

Introducción

El INNER JOIN devuelve solo las filas donde ambas tablas tienen pareja. Si un cliente no tiene pedidos, no aparece; si un pedido apunta a un cliente que ya no existe (no debería pasar con integridad referencial), tampoco. Es la intersección.

Sintaxis moderna

Cuando las columnas se llaman igual (cliente_id en las dos tablas) puedes usar USING(cliente_id), pero la forma con ON es de largo la más explícita y flexible.

El JOIN implícito (la vieja escuela)

El WHERE con «coma» sigue funcionando: la base lo reedita como INNER JOIN.

Escribe siempre INNER JOIN ... ON: el código deja claro qué es condición de unión y qué es filtro.

El error de las filas duplicadas

Imagina un cliente con 3 pedidos y otro con 2. El INNER JOIN devuelve 5 filas: el nombre del cliente se repite en cada una. No es un bug, es cómo funciona la combinación:

Ejercicio

  1. Une clientes y pedidos y devuelve solo los pagados.
  2. Escribe el mismo INNER JOIN en estilo moderno y en estilo antiguo.
  3. Predice cuántas filas devuelve un JOIN con 3 clientes (2, 1 y 0 pedidos) antes de ejecutarlo.

Resumen

  • INNER JOIN = solo parejas que existen en ambas tablas.
  • Obligatorio el ON con la condición de igualdad de claves.
  • Los alias hacen la consulta legible.
  • Las filas del lado «uno» se repiten por cada «muchos».
