Errores tipados y estados

🔥 Avanzado 11 min GraphQL Módulo 5 · Mutaciones y suscripciones

Introducción

GraphQL devuelve los errores en una lista junto a los datos, no como cuerpo de respuesta: el cliente puede obtener datos parciales y errores a la vez. Aprovechar esa arquitectura exige asignar un código estable a cada fallo.

Los errores planos de texto son difíciles de manejar en el cliente; los errores tipados con extensiones permiten ramificar la lógica sin parsear mensajes.

Definición

Un error tipado es un GraphQLError con una extensión estándar (código y campos extra) que el cliente puede interpretar de forma determinista.

Por qué importa. Con códigos estables el cliente sabe si reintentar, redirigir a login o mostrar un mensaje, sin depender de cadenas localizadas.

Cuándo usarlo. Usa códigos para errores de autenticación, autorización, no encontrado y validación; deja el mensaje para humanos y las extensiones para máquinas.

Conceptos clave

  • errors[] acompaña a data en toda respuesta GraphQL.
  • extensions.code difiere acciones del negocio y de la validación.
  • GraphQLError de Apollo Server lanza errores con forma y stack.
  • Un error de negocio no debe tumbar por completo la respuesta.
  • El cliente byee rama según code: NOT_FOUND, UNAUTHENTICATED, VALIDATION.

Ejemplo real

Un cliente real captura los errores de una mutación y define el flujo con un switch por código.

  • Trata UNAUTHENTICATED como señal de refresco de sesión.
  • Distinguir VALIDATION de FORBIDDEN para no chocar con el formulario.
  • Muestra el mensaje al usuario solo cuando aporta valor.

Apollo Client expone graphQLErrors con extensions para que no tengas que parsear nada.

Explicación

  • Los errores viajan en la ruta de respuesta, separados de los datos: eso permite respuestas parciales.
  • extensions es el campo reservado para metadatos: códigos, campos y trazas.
  • El código NOT_FOUND permite al cliente 'ocultar' un recurso borrado sin parsear.
  • La validación se beneficia de devolver la lista de campos con error.
  • Un mensaje bien redactado para humanos y un código estable para la lógica.

Errores comunes

  • Devolver errores como texto plano sin código.
  • Asustar con errores crudos (stack) al cliente.
  • Tratar todos los errores igual sin distinguir códigos.

Buenas prácticas

  • Define un catálogo de códigos en un fichero del schema.
  • Añade el campo afectado en la extensión para formularios.
  • Localiza los mensajes en el cliente, no en el servidor.
  • Registra los errores en el servidor con su código.

Ejercicio

  1. Lanza un NOT_FOUND al actualizar un id inexistente.
  2. Añade a tu helper el código VALIDATION con campos.
  3. Escribe un switch en el cliente para three códigos.

Resumen

  • Los errores GraphQL viajan con los datos y con extensions.
  • El código estable hace el flujo del cliente determinista.
  • Mensaje para humanos, extensiones para máquinas.
