Tipos y Schema

🔥 Avanzado 9 min GraphQL Módulo 1 · Fundamentos de GraphQL

Introducción

Todo en GraphQL gira alrededor del schema: la definición completa de todos los tipos, campos y operaciones que la API entiende. Escrito en SDL (Schema Definition Language), es el contrato entre cliente y servidor, y además es la fuente de verdad para la validación y la documentación automática.

Entender bien los tipos del schema es entender GraphQL: cada campo tiene un tipo, y ese tipo determina qué puedes consultar y qué no. Empecemos por los elementos más básicos.

Tipos escalares

Los escalares son los ladrillos atómicos: representan un valor simple que no se puede descomponer en campos. GraphQL define cinco integrados:

  • Int — números enteros
  • Float — números decimales
  • String — texto UTF-8
  • Boolean — verdadero o falso
  • ID — identificador único serializado como string

Un tipo objeto agrupa escalares. Observa cómo se declara un usuario:

type Usuario {
  id: ID!
  nombre: String!
  email: String!
  edad: Int
  altura: Float
  activo: Boolean!
}

Tipos objeto y listas

Un tipo objeto define un conjunto de campos con nombre y describe entidades como usuario, post o pedido. Los campos pueden ser escalares, otros objetos o listas de cualquiera de ellos:

type Post {
  id: ID!
  titulo: String!
  contenido: String
  autor: Usuario!
  vistas: Int!
}

type Usuario {
  id: ID!
  nombre: String!
  posts: [Post!]!
}

La anidación es lo que hace potente a GraphQL: autor es un objeto completo y posts una lista de posts. El cliente podrá recorrer estas relaciones en una sola consulta porque el schema lo permite explícitamente.

El operador de no-null: !

El signo de exclamación declara que un campo no puede ser nulo: es obligatorio. Es crucial para la API porque permite garantizar contratos fuertes:

  • String — puede ser null o un string.
  • String! — siempre devuelve un string; nunca null.
  • [Post] — lista que puede ser null, cuyos elementos pueden ser null.
  • [Post!]! — lista siempre presente y sin elementos nulos dentro.

La doble exclamación de la lista ([Post!]!) es un idioma común: garantiza que siempre habrá una lista y que cada post dentro tendrá valor. El cliente puede confiar en ello sin comprobaciones defensivas.

Definir el schema completo

El schema se compone de los tipos de datos más los tipos raíz: por convención Query (lecturas), Mutation (escrituras) y opcionalmente Subscription (eventos). Todo lo demás son datos que esos raíces devuelven:

type Query {
  usuario(id: ID!): Usuario
  posts: [Post!]!
  post(id: ID!): Post
}

type Mutation {
  crearPost(titulo: String!, contenido: String!): Post!
}

type Usuario {
  id: ID!
  nombre: String!
  email: String!
  posts: [Post!]!
}

type Post {
  id: ID!
  titulo: String!
  contenido: String
  autor: Usuario!
  vistas: Int!
}

Fíjate en que Query y Mutation son tipos como cualquier otro: tienen campos con tipos y argumentos. Si un campo no está en el schema, no existe en la API, y una consulta que lo pida fallará en la validación.

Enums y escalares personalizados

Un enum limita un campo a un conjunto cerrado de valores, ideal para estados y roles:

enum Rol {
  ADMIN
  EDITOR
  LECTOR
}

type Usuario {
  id: ID!
  rol: Rol!
}

Cuando los cinco escalares no bastan —fechas, horas, monedas, claves de color— se puede definir un escalar personalizado:

scalar Fecha

type Evento {
  id: ID!
  nombre: String!
  comienzaEn: Fecha!
}

Un scalar personalizado exige implementar su serialización y deserialización en el servidor (cómo se convierte de/a JSON), algo que verás en la práctica en el módulo 2. También existen los input types, tipos especiales para agrupar argumentos, que se estudian en la lección de mutations.

Ejercicio

  1. Elige una entidad de tu dominio (producto, pedido, curso…) y escribe su tipo objeto en SDL.
  2. Añade una relación: un campo que apunte a otro tipo y una lista de ese tipo con no-null en ambos niveles.
  3. Define un enum para el estado de esa entidad (por ejemplo: PENDIENTE, PAGADO, ENVIADO).
  4. Completa un type Query con dos campos: uno que devuelva una entidad por ID y otro que devuelva todas.

Resumen

  • El schema en SDL es el contrato tipado entre cliente y servidor.
  • Hay cinco escalares integrados: Int, Float, String, Boolean e ID, más los personalizados.
  • Los tipos objeto agrupan campos y permiten anidar relaciones y listas.
  • El ! marca campos no-null; [T!]! garantiza listas sin nulos.
  • Query, Mutation y Subscription son los tipos raíz del schema.
