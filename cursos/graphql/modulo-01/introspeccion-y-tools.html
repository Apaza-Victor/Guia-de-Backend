Introspección y herramientas

🔥 Avanzado 8 min GraphQL Módulo 1 · Fundamentos de GraphQL

Introducción

Una de las superventas de GraphQL es que la API se documenta sola. Cada schema expone campos de introspección: consultas especiales que devuelven la descripción completa de tipos, campos, argumentos y directivas. Cualquier cliente puede "preguntarle a la API qué sabe hacer".

Gracias a eso, las herramientas —GraphiQL, Apollo Explorer, Playground, Altair— generan documentación, autocompletado y pruebas visuales sin que el equipo mantenga una documentación aparte.

Introspección: __schema

La palabra __schema lista todos los tipos del schema con su tipo de kind (OBJECT, SCALAR, ENUM, INPUT_OBJECT…):

query {
  __schema {
    types {
      name
      kind
    }
    queryType {
      name
    }
    mutationType {
      name
    }
  }
}

En la respuesta verás tus tipos de dominio y además los tipos del sistema (Query, Mutation, String, ID…). Es el mismo mecanismo interno que usan GraphiQL y Apollo Explorer para dibujar su panel de "Docs".

Introspección: __type

Con __type(name) se inspecciona un tipo concreto, sus campos y la firma de cada uno — argumentos, tipo de retorno y si es obligatorio:

query {
  __type(name: "Usuario") {
    name
    fields {
      name
      type {
        name
        kind
        ofType {
          name
        }
      }
    }
  }
}

Observa que el tipo puede anidarse con ofType porque el sistema de tipos es envolvente: [Post!]! se representa como LIST de NON_NULL de OBJECT Post. La introspección respeta esa estructura, lo que permite a las herramientas renderizar la firma exacta.

GraphiQL y las herramientas

Hay tres familias principales de herramientas para probar y explorar una API GraphQL:

  • GraphiQL — el IDE integrado en el navegador que monta la mayoría de servidores (express-graphql, Apollo). Ofrece autocompletado, pestaña Docs y ejecución con variables.
  • Apollo Explorer (Studio) — heredero de GraphQL Playground, con historial, colecciones y métricas de operaciones para equipos.
  • Altair y clientes HTTP — Altair es un cliente GraphQL de escritorio; también puedes probar desde Postman, Insomnia o curl enviando la query como JSON.

La diferencia clave con API REST se nota al instante: escribes el campo, la herramienta te sugiere sus subcampos y argumentos válidos. No tienes que memorizar nada — el schema lo sabe todo.

Probar con curl

Incluso sin herramientas, cualquier operación viaja por HTTP POST a un único endpoint. Así se consulta el tipo raíz de una API:

curl -X POST http://localhost:4000/graphql \
  -H "Content-Type: application/json" \
  -d '{"query": "{ __schema { queryType { name } } }"}'
{
  "data": {
    "__schema": {
      "queryType": {
        "name": "Query"
      }
    }
  }
}

Self-documenting en el trabajo diario

La introspección no es solo una curiosidad: es la base de la experiencia de desarrollo y de los generadores de código. Con ella puedes:

  • Generar tipos TypeScript a partir del schema (codegen) sin escribir un solo tipo a mano.
  • Validar las queries de tus clientes en tiempo de compilación contra el schema.
  • Auditar qué tipos expuestos son públicos y cuáles deberían quedar internos.

Una advertencia de seguridad: si la API se expone públicamente, la introspección suele desactivarse en producción (verás cómo en seguridad y limitación) para que un atacante no "mapee" todo el schema. En desarrollo es una bendición.

Ejercicio

  1. Monta (o usa) una API GraphQL local y abre GraphiQL en el navegador.
  2. Consulta __schema y cuenta cuántos tipos de dominio hay frente a los del sistema.
  3. Consulta __type(name: "Query") y lista los nombres de sus campos y argumentos.
  4. Usa la pestaña Docs para navegar un tipo hasta un escalar y explica en una frase cómo se relaciona con la introspección.

Resumen

  • El schema expone introspección mediante __schema y __type.
  • La introspección describe tipos, campos, argumentos y la estructura envolvente de tipos y no-null.
  • GraphiQL, Apollo Explorer y Altair usan esa información para documentar y autocompletar.
  • Toda operación viaja por un único endpoint, como POST con curl o Postman.
  • En producción pública conviene deshabilitar la introspección por seguridad.
