Persisted queries y CDN

🔥 Avanzado 10 min GraphQL Módulo 7 · GraphQL en producción

Introducción

Permitir cualquier query libre abre el API a la imaginación y al abuso; las persisted queries restringen el catálogo: el servidor conoce una whitelist de queries registradas por hash y rechaza lo demás.

Además, que cada query tenga un identificador estable permite servirlas desde el CDN y evita rondar un parser en el navegador.

Definición

Una persisted query es una query registrada en el servidor con un hash; el cliente referencia el hash y el servidor resuelve la query almacenada.

Por qué importa. Restringe el coste (solo lo aprobado), simplifica la caché y reduce el payload de red al mínimo.

Cuándo usarlo. Úsala en clientes de producción donde controlas qué queries se emiten; evita fricciones con queries dinámicas no registradas.

Conceptos clave

  • El hash SHA-256 identifica la query de forma estable.
  • El servidor mantiene la lista de queries permitidas.
  • El cliente envia solo el hash en el GET.
  • Las queries dinámicas se pueden enviar como fallback.
  • El CDN cachea por hash y variables: win-win.

Ejemplo intermedio

El cliente envía el hash y el server resuelve; si no existe, fallback con la query.

Ejemplo real

En producción la whitelist se mantiene en repositorio y el CDN cachea por hash variables.

  • Registra cada query nueva en la whitelist del cliente.
  • Usa los hashes como claves de caché del CDN.
  • Difunde el cambio de whitelist sin romper a los clientes en vuelo.

Apollo Client soporta persisted queries de forma nativa con AutomaticPersistedQueries.

Explicación

  • Permitir query libre abre coste ilimitado y queries raras.
  • El hash estable y la lista permiten evaluar el coste antes de ejecutar.
  • El CDN servirá cada hash+variables desde el borde.
  • Las query dinámicas pueden hacer fallback a texto, pero pierdes caché.
  • La whitelist vive en el repositorio: revisión clara y auditada.

Errores comunes

  • Queries dinámicas rotas por la whitelist sin registro previo.
  • Enviar el hash con variables que no casan con la query.
  • Olvidar desplegar la whitelist al lanzar una nueva función.

Buenas prácticas

  • Empieza con Automatic Persisted Queries y registra solo lo crítico.
  • Versa la whitelist junto al cliente.
  • Mide el ratio de hits en el CDN.
  • Registra las queries no encontradas para completar la lista.

Ejercicio

  1. Registra una query y llama con su hash.
  2. Prueba el fallback con una hash inexistente.
  3. Configura Automatique Persisted Queries en Apollo Client.

Resumen

  • Las persisted queries limitan el coste a un catálogo.
  • El hash estable habilita la caché de CDN.
  • La whitelist se gestiona en repositorio y se despliega con el cliente.
