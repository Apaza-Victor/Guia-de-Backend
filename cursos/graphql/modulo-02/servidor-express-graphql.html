Express + GraphQL

🔥 Avanzado 10 min GraphQL Módulo 2 · Implementación con Node.js

Introducción

Si tu aplicación ya vive sobre Express, montar GraphQL en un endpoint aparte te permite convivir REST y GraphQL en el mismo servicio: guardas el middleware de auth, el log de peticiones y las rutas existentes, y añades un único app.use('/graphql', ...).

La librería clásica de Douglas Wilson, express-graphql, expone el graphqlHTTP middleware; la moderna graphql-http es su sucesora y monta el createHandler. Veremos el patrón con la primera y la alternativa de la segunda.

Instalación

Además de Express y GraphQL, instala el adaptador. En proyectos nuevos se recomienda graphql-http; para seguir el patrón histórico usa express-graphql:

npm install express graphql express-graphql
npm install --save-dev nodemon

Montar el middleware

La integración más directa: cualquier petición a /graphql la resuelve el middleware, que además sirve graphiql: true para explorar la API en el navegador:

import express from "express";
import { graphqlHTTP } from "express-graphql";
import { schema } from "./schema.js";

const app = express();

app.use(
  "/graphql",
  graphqlHTTP({
    schema,
    graphiql: true,
  }),
);

app.listen(4000, () => console.log("API en http://localhost:4000/graphql"));

El middleware acepta una función en vez de un objeto para que cada request tenga su propio contexto:

const handler = graphqlHTTP((req, res, params) => ({
  schema,
  graphiql: true,
  context: {
    db: pool,
    usuario: req.usuario ?? null,
  },
}));

app.use("/graphql", handler);

El context por request

El context es el puente entre el mundo HTTP y los resolvers. Aquí se inyecta el pool de base de datos y la identidad del usuario autenticado, para que los resolvers solo accedan a context:

import jwt from "jsonwebtoken";

const handler = graphqlHTTP((req, res, params) => {
  const token = req.headers.authorization?.replace("Bearer ", "");
  let usuario = null;
  if (token) {
    try {
      usuario = jwt.verify(token, process.env.JWT_SECRET);
    } catch {
      usuario = null;
    }
  }
  return {
    schema,
    context: { db: pool, usuario },
  };
});

Así, un resolver puede exigir sesión sin volver a parsear headers ni tocar la base para cada campo.

Conectar la base de datos

Con el pool en el context, los resolvers se vuelven delgados: reciben args y consultan:

const resolvers = {
  Query: {
    productos: async (parent, args, context) => {
      const { rows } = await context.db.query(
        "SELECT * FROM productos ORDER BY nombre",
      );
      return rows;
    },
    producto: async (parent, args, context) => {
      const { rows } = await context.db.query(
        "SELECT * FROM productos WHERE id = $1",
        [args.id],
      );
      return rows[0] ?? null;
    },
  },
};

Como Express ya parsea el cuerpo, las operaciones llegan en el payload JSON estándar { query, variables } y el middleware lo desenvuelve por ti.

La alternativa gráfica: graphql-http

Si prefieres el adaptador moderno, el patrón cambia poco: mismo schema, misma idea de middleware:

import { createHandler } from "graphql-http/lib/use/express";

app.use(
  "/graphql",
  createHandler({
    schema,
    context: (req) => ({ db: pool, usuario: req.usuario ?? null }),
  }),
);

La diferencia práctica está en el mantenimiento: express-graphql quedó en modo de soporte y graphql-http recibe las novedades de la especificación. Para proyectos nuevos, empieza por ella.

Ejercicio

  1. Integra /graphql en una app Express que ya tenga una ruta GET / respondiendo HTML.
  2. Inyecta el pool de PostgreSQL (o un mock con query) en el context mediante la función de graphqlHTTP.
  3. Escribe un resolver productos que lea de context.db.
  4. Corrobora que graphiql: true sirve el IDE en el endpoint y prueba una consulta real.

Resumen

  • express-graphql (y su sucesor graphql-http) montan GraphQL como middleware Express.
  • GraphQL y REST pueden convivir en la misma aplicación.
  • El context por request inyecta la base de datos y al usuario autenticado.
  • Los resolvers consumen context.db y args sin tocar HTTP.
