Apollo Server básico

🔥 Avanzado 10 min GraphQL Módulo 2 · Implementación con Node.js

Introducción

Apollo Server es la implementación de GraphQL para Node.js más usada. Se encarga de recibir las operaciones HTTP, validarlas contra el schema, ejecutar los resolvers y formatear la respuesta — tú solo defines typeDefs (el schema en SDL) y resolvers (la lógica de cada campo).

Es el punto de partida perfecto: en menos de treinta líneas tienes una API completa, con GraphiQL integrado y lista para probar.

Instalación

Crea un proyecto Node e instala Apollo Server junto con la librería central de GraphQL:

npm init -y
npm install @apollo/server graphql
npm install --save-dev nodemon

Con nodemon podrás recargar el servidor automáticamente en cada cambio mientras desarrollas. Si usas TypeScript, instala además typescript, ts-node y @types/node.

Definir el esquema con typeDefs

Los typeDefs son el schema en SDL: un template literal con la definición de tipos, la query raíz y (más adelante) mutations y subscriptions:

type Libro {
  id: ID!
  titulo: String!
  autor: String!
}

type Query {
  libros: [Libro!]!
  libro(id: ID!): Libro
}

Todo lo que no esté aquí no existirá en la API. El schema es la frontera de lo expresable y la fuente de la validación automática.

Resolvers en memoria

Los resolvers traducen el schema en datos. Empezar con un arreglo en memoria es perfecto para interiorizar el flujo antes de conectar una base de datos:

const libros = [
  { id: "1", titulo: "Cien años de soledad", autor: "Gabriel García Márquez" },
  { id: "2", titulo: "El principito", autor: "Antoine de Saint-Exupéry" },
];

const resolvers = {
  Query: {
    libros: () => libros,
    libro: (parent, args) => libros.find((libro) => libro.id === args.id) ?? null,
  },
};

Obsérvalo: libros no necesita argumentos y devuelve todo; libro filtra por el id que llega en args. Como Libro no tiene campos calculados, el resolver del tipo es implícito: GraphQL copia los campos tal cual.

Configurar el servidor

Apollo Server v4 separa el núcleo del transporte HTTP; startStandaloneServer monta el servidor HTTP por nosotros:

import { ApolloServer } from "@apollo/server";
import { startStandaloneServer } from "@apollo/server/standalone";

const server = new ApolloServer({ typeDefs, resolvers });

const { url } = await startStandaloneServer(server, {
  listen: { port: 4000 },
});

console.log(`API GraphQL lista en ${url}`);

Con esto ya tienes un endpoint /graphql con introspección y únicamente las operaciones definidas. El uso de standalone es la vía rápida; en la siguiente lección integrarás GraphQL dentro de una app Express existente.

Probar la API

Arranca con node index.js y abre http://localhost:4000/graphql para entrar a GraphiQL, o prueba con curl:

npm run dev
query {
  libro(id: "1") {
    titulo
    autor
  }
}

Si preguntaras por un campo inexistente o con mal tipo, el servidor lo rechazaría antes de tocar un resolver. Esa garantía de validación previa es una de las grandes diferencias frente a un endpoint REST.

Ejercicio

  1. Instala Apollo Server y crea el esquema Libro con Query.libros y Query.libro(id).
  2. Añade al tipo Libro un campo año: Int y rellénalo en los datos de memoria.
  3. Escribe un resolver Query.libro que devuelva null si el id no existe.
  4. Arranca el servidor y verifica en GraphiQL que una consulta con un campo inválido devuelve un error en errors.

Resumen

  • Apollo Server une typeDefs (schema SDL) y resolvers (lógica de campos).
  • startStandaloneServer levanta un endpoint /graphql sin configuración extra.
  • La validación contra el schema ocurre antes de ejecutar resolvers.
  • Con datos en memoria es rápido demostrar el ciclo completo query → resolver → respuesta.
