Configuración y secretos

🧠 Experto 11 min Microservicios Módulo 7 · Microservicios en producción

Introducción

Una URL de base de datos que cambia, una API key de pago, el entorno staging contra producción. Cada servicio corre con millares de detalles de configuración que no deben estar en el código.

La configuración se va a variables de entorno y se centraliza; los secretos, cifrados y rotables. Así un despliegue cambia solo datos, no código.

Definición

La gestión de configuración separa los ajustes del servicio de su código: variables de entorno por entorno, config centralizada y secretos en gestores cifrados.

Por qué importa. Poder cambiar una URL o una credential sin redeployar es lo que hace operable un sistema de muchos servicios.

Cuándo usarlo. Usa variables de entorno siempre; añade config centralizada y gestor de secretos cuando tienes muchos servicios y equipos.

Conceptos clave

  • 12-factor: configuración en el entorno, nunca en el código.
  • Variables de entorno: por entorno y por servicio.
  • Config centralizada: etcconsul o Vault para distribuir ajustes.
  • Gestor de secretos: almacén cifrado con auditoría y rotación.
  • Rotación: cambiar una clave sin interrumpir el servicio.

Ejemplo básico

Leer configuración sin valores mágicos en el código.

El servicio arranca solo con las variables correctas del entorno.

Ejemplo intermedio

Ejemplo real

La URL de la BD cambia al migrar. El equipo edita el config mapa en Vault, los servicios reciben el nuevo valor al reiniciar y la rotación de la API key del proveedor se completa en minutos sin tocar imágenes.

  • Solo variables de entorno en el despliegue, sin excepciones.
  • Los secretos rotan: programala y comprueba que no rompe.
  • Audita quién leyó cada secreto: si pasa algo, sabes el quién.

Un secreto que no se rota es una deuda de seguridad que un día se paga con intereses.

Explicación

  • Sin configuración en el código, un mismo artefacto vuela a cualquier entorno.
  • La config centralizada evita editores de entornos uno a uno.
  • Los gestores de secretos cifran, auditan y rotan credenciales.
  • Falla rápido: si un secreto falta, arrancar debe fallar con mensaje claro.
  • La rotación automática, aunque duela al principio, reduce el riesgo.

Errores comunes

  • Configuración y secretos en el código o en el repo.
  • Variables de entorno sin validar: un typo se descubre en producción.
  • Secretos estáticos que nadie rota jamás.

Buenas prácticas

  • Valida la configuración al arrancar y falla temprano.
  • Nombra las variables con un prefijo común por servicio.
  • Centraliza la config cuando superes de diez servicios.
  • Renueva secretos con un programa y alerta si una clave es vieja.

Ejercicio

  1. Sacar todas las URL y claves de tu código a variables de entorno.
  2. Crea un gesto de validación de config al arrancar.
  3. Programa la rotación de una API key y verifica que no rompe.

Resumen

  • La configuración vive en el entorno y se centraliza con escala.
  • Los secretos se cifran, auditan y rotan en gestores dedicados.
  • Falla rápido: un servicio no arranca a medias con ajustes inválidos.
