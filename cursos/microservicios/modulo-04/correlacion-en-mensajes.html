Correlación y trazabilidad de mensajes

🧠 Experto 12 min Microservicios Módulo 4 · Comunicación entre servicios

Introducción

Cuando falla un pedido el equipo mira un log: ¿pero cuál de los cincuenta servicios lo falló? Sin un identificador común, seguir el rastro es abrir cincuenta logs y resignarse.

El id de correlación es ese hilo invisible que une todos los pasajes de una misma operación a través de servicios, colas y bases de datos.

Definición

El id de correlación es un identificador único que viaja en cada petición o mensaje y se registra en todos los logs para rastrear una operación completa.

Por qué importa. En arquitecturas distribuidas el diagnóstico depende de reconstruir el recorrido de una petición: sin correlación no hay forma de encadenar los eventos.

Cuándo usarlo. Usa correlación en cada entrada de API, cada consumo de mensaje y cada salto hacia otro servicio.

Conceptos clave

  • X-Request-Id: cabecera estándar por la que viaja el id de correlación.
  • Propagación: pasar el id de un servicio al siguiente, intacto.
  • Id neuvro: generar uno en la puerta de entrada si el cliente no lo trae.
  • Logs enriquecidos: cada línea incluye el id para filtrar por operación.
  • Trace: la vista de todos los pasos de una petición correlacionada.

Ejemplo básico

Middleware Express que genera y registra el id en cada petición.

X-Request-Id: 0f2c1a... en la respuesta y en todos los logs de la petición.

Ejemplo intermedio

Propagar el id al llamar a otro servicio con la cabecera intacta.

Ejemplo real

Una petición de pago cruza pedidos, pagos y notificaciones. Cuando falla la notificación, el equipo busca el X-Request-Id en el agregador de logs y ve la cadena completa.

  • Genera el id en el primer punto de entrada y propágalo siempre.
  • Incluye el id en mensajes de cola y eventos publicados.
  • Filtra todos los logs de una operación por su id en una traza.

Herramientas de tracing (Jaeger, Zipkin) construyen la vista completa usando exactamente estos ids.

Explicación

  • El id se genera en la frontera y se propaga sin reconstruirse nunca.
  • Cada salto HTTP, cola o base de datos debe recibir el id.
  • En logs estructurados el campo id permite consultas instantáneas por operación.
  • El id de correlación es el puente entre logs, métricas y trazas.
  • Solo correlacionando se puede responder "qué pasó con mi pedido 7812".

Errores comunes

  • Generar un id nuevo en cada servicio y perder el hilo de la operación.
  • No incluir el id en los mensajes de cola.
  • Logs sin campo de correlación: imposibles de consultar por operación.

Buenas prácticas

  • Usa un middleware o decorador para inyectar la correlación en todo el servicio.
  • Propaga también en redeliveries para mantener el mismo trace.
  • Normaliza el nombre del campo: x-request-id para todos.
  • Agrega timestamps en UTC para ordenar las piezas de la traza.

Ejercicio

  1. Añade el middleware X-Request-Id a tu API en Node.
  2. Propaga el id al llamar a dos servicios encadenados.
  3. Filtra una traza completa en tus logs con un solo id.

Resumen

  • El id de correlación une todos los pasos de una operación distribuida.
  • Viaja en cabeceras y mensajes y se registra en cada log.
  • Sin correlación, diagnosticar un sistema distribuido es casi adivinar.
