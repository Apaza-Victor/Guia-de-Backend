API Gateway

🔥 Avanzado 10 min Microservicios Módulo 2 · Comunicación

Introducción

Con varios microservicios, cada uno con su propia API, el cliente tendría que conocer todas las URLs, respetar contratos distintos y repetir autenticación en cada llamada. El API Gateway resuelve esto: es el único punto de entrada hacia el sistema; recibe la petición, la valida, la enruta al servicio correcto y devuelve la respuesta.

Responsabilidades típicas

  • Enrutamiento: mapea una URL pública hacia el servicio interno correspondiente.
  • Autenticación y autorización centralizada: valida JWT una sola vez en la puerta.
  • Rate limiting: protege los servicios internos del uso abusivo.
  • Agregación (composición): combina en una sola respuesta datos de varios servicios.
  • Traducción de contratos: oculta el modelo interno y expone un contrato público estable.
  • CORS, logging y tracing unificados.

Autenticación centralizada

Validar el token en el gateway simplifica a los servicios: todos asumen que una petición que llega ya está autenticada y solo deben validar permisos. El gateway propaga la identidad (por ejemplo, el id de usuario) en un header interno.

El patrón BFF

Cuando distintos clientes (web, móvil, TV) necesitan datos distintos, se usa un Backend for Frontend (BFF): un gateway específico por tipo de cliente. El BFF móvil puede devolver payloads ligeros; el web, versiones más ricas. La idea clave: el cliente no decide cómo componer el sistema, el BFF sí.

El riesgo: single point of failure

El gateway es un punto que toca todo el tráfico. Si cae, todo cae. Los mitigantes:

  • Replica el gateway (múltiples instancias detrás de un load balancer).
  • Mantenlo delgado: la lógica de negocio vive en los servicios.
  • Timeouts cortos hacia los servicios para no bloquear la puerta.
  • Monitoreo de latencia y tasas de error del propio gateway.

Ejercicio

  1. Define 6 rutas públicas de un e-commerce y qué servicio interno atiende cada una.
  2. Diseña un endpoint agregado que combine pedido + envío + factura con llamadas en paralelo.
  3. Compara un solo gateway global con BFF por cliente y decide cuál usarías aquí.

Resumen

  • El API Gateway es el punto de entrada único hacia los microservicios.
  • Centraliza autenticación, rate limiting, logging y enrutamiento.
  • Agrega respuestas de varios servicios, preferiblemente en paralelo.
  • El patrón BFF especializa el gateway por tipo de cliente.
  • Debe ser delgado, replicado y con timeouts para no convertirse en punto único de fallo.
