Sesiones y almacenamiento

⚙️ Intermedio 9 min Autenticación y Autorización Módulo 3 · Sesiones

El estado vive en el servidor

En una sesión del lado servidor el cliente solo conoce un identificador opaco: un número sin significado. Todo lo demás (quién es el usuario, sus permisos, su carrito) vive en el servidor bajo ese id. Robar el id presta la sesión, pero no revela datos. La clave es que el servidor valida contra su almacén en cada petición.

Dónde almacenar

  • Archivos (por defecto): sencillo para un servidor; no escala con varias máquinas.
  • Base de datos: compartida entre servidores; cada petición es un SELECT/UPSERT.
  • Redis: en memoria, con expiración nativa y lecturas rápidas; ideal a escala.

Sesiones PHP nativas

El identificador se genera con entropía criptográfica y la cookie asociada solo transporta ese valor. PHP se encarga de la persistencia y de la limpieza periódica.

Modelo para guardar en base de datos

Ejercicio

  1. Arranca sesiones PHP nativas en un script y observa la cookie creada.
  2. Inspecciona dónde se guardan los archivos de sesión en tu sistema.
  3. Explica con tus palabras por qué el id de sesión debe ser «opaco».

Resumen

  • La sesión de servidor guarda el estado; la cookie solo el id.
  • Archivos para desarrollo, BD/Redis para producción con varios servidores.
  • La cookie se configura antes de session_start().
  • El id debe ser aleatorio, impredecible y opaco.
