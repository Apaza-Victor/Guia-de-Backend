Access tokens y expiración

⚙️ Intermedio 9 min Autenticación y Autorización Módulo 4 · JWT

El access token

El access token es el token que el cliente envía en cada petición para probar que puede acceder (Authorization: Bearer). Como la validación es stateless, el token debe llevar su propia fecha de caducidad: es un bullet corto. Duración típica: 15-60 minutos. Corto significa menos ventana de abuso si se filtra.

Emisión del token

Middleware de validación

Incluye siempre las comprobaciones de exp, nbf, iss y aud; si tu librería no lo hace, hazlas tú.

El trade-off stateless

Al ser stateless, un token robado sigue siendo válido hasta su exp: no puedes «desautenticar» a un usuario revocando del mismo modo que con sesiones en servidor. De ahí la doble táctica: access corto + refresh revocable. También existe la lista negra de jiTs (jti) para casos puntuales de revocación inmediata.

Ejercicio

  1. Emite un token de 15 minutos con todos los claims estándar.
  2. Monta el middleware y prueba: token ausente, inválido y expirado.
  3. Decide una duración para un dashboard administrativo y justifica.

Resumen

  • Access token por header Bearer, vida de minutos.
  • Claims: sub, iat, nbf, exp, iss, aud.
  • Middleware único que valida firma y fechas.
  • Corto = menos daño si se filtra; la revocación la hace el refresh.
