Almacenamiento seguro en el cliente

⚙️ Intermedio 9 min Autenticación y Autorización Módulo 4 · JWT

El problema de fondo

Si emites un access token, el cliente debe guardarlo en algún sitio. Las dos opciones clásicas son localStorage y cookies, y ninguna es perfecta: el riesgo real viene de XSS (código ajeno que corre en tu página y roba lo que sea legible por JavaScript).

localStorage: pionero y peligroso

Simple: el JavaScript guarda y manda Authorization: Bearer. El problema es que todo el JS del sitio (incluido un script inyectado por XSS) puede leerlo. Un solo hueco de XSS y el atacante exfiltra el token con una fetch. Muy extendido, lógico para prototipos, pero arriesgado en producción.

Cookies HttpOnly

Las cookies marcadas HttpOnly y SameSite no las lee JavaScript: el navegador las envía solas. Así un XSS ya no puede robar el token. A cambio, pierdes el control del header Authorization y entran en juego otros riesgos (CSRF), que se mitigan comprobando Origin o con tokens CSRF.

Regla __Host-: cookie prefix que garantiza HTTPS, sin Domain y path /.

La estrategia moderna: BFF

En SPAs serias se usa un Backend for Frontend (BFF): la SPA nunca ve tokens; el BFF guarda la sesión en cookie HttpOnly y el JS solo consume una API protegida del propio BFF. Es la opción recomendada para apps token-based con frontend.

Reglas prácticas

  • Habilita HTTPS en local-host y producción; sin HTTPS, secure no tiene sentido.
  • Nunca metas el refresh token en localStorage.
  • Sanitiza la salida y usa CSP para reducir la superficie de XSS.
  • Si usas localStorage, acepta que el token es robable con un XSS.

Ejercicio

  1. Crea la cookie con el prefijo __Host- y verifica sus atributos en DevTools.
  2. Intenta leerla con document.cookie y anota el resultado.
  3. Dibuja el flujo con BFF: SPA → BFF → API, y dónde vive cada cookie.

Resumen

  • localStorage = simple, pero roba el token un XSS.
  • Cookies HttpOnly SameSite = mejor, con cuidado al CSRF.
  • BFF: la SPA no manipula tokens.
  • Siempre HTTPS y mínimo privilegio para los tokens.
