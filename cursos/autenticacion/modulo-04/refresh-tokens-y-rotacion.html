Refresh tokens y rotación

⚙️ Intermedio 11 min Autenticación y Autorización Módulo 4 · JWT

Por qué un refresh token

Un access token corto fuerza al cliente a autenticarse de nuevo cada 15 minutos, mala experiencia. El refresh token es una credencial de larga duración (días/semanas), revocable, que solo se usa para pedir nuevos access tokens. Contraste clave: el access es stateless; el refresh se guarda en una tabla con su estado.

Modelo en BD

El refresh suele ser opaco (un aleatorio binario), no un JWT: no necesita claims, solo referencia a la fila.

Rotación y detección de reuso

Flujo completo

  1. Login → devolver access_token + refresh_token.
  2. El cliente guarda el refresh en el servidor de confianza (no en JS).
  3. Access caduca → POST /oauth/token con el refresh → renovación.
  4. Refresh usado → revocado y reemplazado (rotación).
  5. Reuso detectado → revoca la familia completa (posible robo).

Ejercicio

  1. Implementa el endpoint de renovación con rotación.
  2. Envía un refresh ya usado y verifica que se revoca la familia.
  3. Decide la vida del refresh para una app móvil y una web.

Resumen

  • Refresh: largo, opaco, revocable y con rotación.
  • Tabla con familia_id para agrupar rotaciones.
  • Cada uso revoca el anterior y emite uno nuevo.
  • Reutilización = señal de robo → revocar la familia.
