Hashing vs encriptación

⚙️ Intermedio 11 min Autenticación y Autorización Módulo 1 · Fundamentos

Dos herramientas, dos objetivos

El cifrado (encriptación) transforma un mensaje con una clave de forma reversible: quien tiene la clave recupera el texto original. Es útil para protectar datos que un día necesitarás volver a leer (un correo, una tarjeta).

El hashing es una función de una sola vía: produce una huella de tamaño fijo y no tiene camino de vuelta. La misma entrada siempre produce la misma salida, pero con la salida no se reconstruye la entrada. Por eso es la herramienta correcta para contraseñas: nadie, ni siquiera tu backend, debe poder «des-cifrar» la contraseña.

¿Por qué hashear contraseñas?

  • Si se filtra la base de datos, las contraseñas cifradas se descifran si el atacante consigue la clave (y la clave suele estar en el mismo servidor).
  • Un hash de contraseña con sal (bcrypt, argon2) es costoso de invertir: cada intento de fuerza bruta es lento.
  • Tu sistema no necesita conocer la contraseña original: solo necesita verificar si el valor enviado produce el mismo hash.

Además, un hash de contraseña debe ser lento y llevar sal única por usuario. Los hashes rápidos de verificación (MD5, SHA-256) son inadecuados: se prueban a miles de millones por segundo.

bcrypt en PHP

PHP trae password_hash() y password_verify(), que usan bcrypt por defecto y gestionan la sal automáticamente.

Nota: password_hash() de bcrypt truncar implícitamente contraseñas muy largas (72 bytes); para más de 72 bytes usa PASSWORD_ARGON2ID si tu PHP lo soporta.

Cuándo sí cifrar

El cifrado se usa cuando necesitas recuperar el dato original, por ejemplo tokens de API que el servicio debe poder leer, o datos personales cifrados en reposo con claves gestionadas por separado. La regla práctica:

  • Contraseñas → hash (bcrypt/argon2 con sal).
  • Datos que deben volver a leerse → cifrado (AES, con clave protegida).

Ejercicio

  1. Genera el hash de tres contraseñas iguales y observa que los hashes son distintos por la sal.
  2. Verifica con password_verify una correcta y una incorrecta.
  3. Explica por escrito: «si un atacante roba mi clave de cifrado, ¿qué protege aún las contraseñas si las guardé con bcrypt?».

Resumen

  • Cifrar es reversible; hashear no lo es.
  • Las contraseñas se hashean con algoritmos lentos y con sal (bcrypt/argon2).
  • password_hash / password_verify encapsulan la práctica correcta.
  • El cifrado queda para datos que necesiten leerse de nuevo.
