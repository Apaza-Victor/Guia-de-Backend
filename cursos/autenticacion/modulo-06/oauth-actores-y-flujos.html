OAuth: actores y flujos

⚙️ Intermedio 10 min Autenticación y Autorización Módulo 6 · OAuth 2.0 y OIDC

Qué es OAuth 2.0

OAuth 2.0 es el estándar para delegar autorización: permite a una app acceder a recursos del usuario en otro servicio sin conocer su contraseña. Es el motor de «inicia sesión con Google/GitHub» y de permisos tipo «esta app puede leer tu calendario».

Los cuatro actores

  • Resource Owner: el usuario final que posee los datos.
  • Client: tu aplicación que quiere acceder.
  • Authorization Server: autentica al dueño y emite tokens.
  • Resource Server: sirve los datos y valida el access token (a veces es el mismo auth server).

Los flujos principales

FlujoCuándoRiesgo
Authorization Code + PKCESPAs, apps móviles y websBajo (recomendado)
Client CredentialsComunicación máquina a máquinaBajo
ImplicitHeredado; token en la URLAlto (evitar)
Resource Owner PasswordHeredado; la app ve la contraseñaAlto (evitar)

URLs que expone un proveedor

Cada proveedor publica estas URLs en su discovery document (/.well-known/openid-configuration).

Ejercicio

  1. Identifica los 4 actores en «login con GitHub desde tu app».
  2. Consulta el discovery document de un proveedor que uses.
  3. Justifica por qué el flujo implicit está en desuso.

Resumen

  • OAuth delega autorización sin compartir credenciales.
  • Cuatro actores: owner, client, auth server, resource server.
  • Authorization Code + PKCE es el flujo moderno para apps.
  • Discovery document centraliza las URLs del proveedor.
