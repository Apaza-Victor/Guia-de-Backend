Authorization code flow

⚙️ Intermedio 12 min Autenticación y Autorización Módulo 6 · OAuth 2.0 y OIDC

La idea del código

El authorization code flow evita exponer el token en el navegador: el cliente redirige al usuario, el proveedor autentica y consiente, y devuelve un código de un solo uso. Ese código se intercambia del lado del servidor (canal de confianza) por el access token. PKCE añade una prueba criptográfica que impide que un código robado sirva en otra app.

Verificaciones imprescindibles

  • state: coincide con el guardado (anti-CSRF en el flujo).
  • code_verifier: debe refirmar el challenge esperado.
  • Códigos de un solo uso: guardar los usados y rechazar repetición.
  • redirect_uri registrada exacta en el proveedor.

Ejercicio

  1. Implementa el flujo contra un proveedor de pruebas local.
  2. Roba el código por tu cuenta: intercambialo y observa que PKCE lo bloquea sin verifier.
  3. Cambia state y confirma que se rechaza.

Resumen

  • El código viaja por el navegador; el token solo en HTTPS servidor-a-servidor.
  • PKCE (S256) prueba que quien canjea es quien inició el flujo.
  • state previene el CRLF y la reinyección de flujo.
  • Código de un solo uso + redirect_uri exacta.
