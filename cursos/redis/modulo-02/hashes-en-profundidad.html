Hashes en profundidad

🔥 Avanzado 10 min Redis para Backend Módulo 2 · Estructuras

Objetos sin re-serializar

Guardar un JSON en un string obliga a serializar/deserializar completo hasta para tocar un campo. El hash trata cada campo como un sub-valor: actualizas solo lo que cambia, de forma atómica, sin travesía de JSON.

Comandos esenciales

Hashes desde Python

Caso real: el carrito de compra

  • Cada producto es un campo; sumar cantidades es HINCRBY.
  • El TTL elimina carritos abandonados sin jobs de limpieza.

Límites y sabiduría práctica

  • Un hash con pocos campos se comprime internamente (listpack): escribe poco, lee rápido.
  • Campos con valores cortos es el dulce de los hashes; si necesitas rangos numéricos, mejor sorted set.
  • No guardes un hash con miles de campos por objeto: la primera lectura completa será pesada (HGETALL).

Regla de oro: usa hashes cuando el objeto tiene campos conocidos y actualizaciones parciales frecuentes. Si solo lees deliberadamente todo el objeto, un string JSON está bien.

Ejercicio

  1. Crea en Python un perfil con 4 campos y actualiza uno con hincrby.
  2. Implementa el carrito con TTL de la lección.
  3. Compara el tamaño de memoria de un hash vs un JSON string equivalente.

Resumen

  • Los hashes modelan objetos con actualización parcial y atómica.
  • HINCRBY evita ventanas de carrera en contadores de campos.
  • El TTL limpia carritos y sesiones sin trabajos extra.
  • Elige hash si los campos son pocos y las lecturas parciales, frecuentes.
