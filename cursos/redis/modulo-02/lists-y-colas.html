Lists y colas

🔥 Avanzado 11 min Redis para Backend Módulo 2 · Estructuras

Una lista doblemente enlazada en RAM

Una list de Redis es una secuencia ordenada con empuje y extracción O(1) en ambos extremos. Modela dos mundos: feeds (los últimos N) y colas (trabajo FIFO).

Comandos esenciales

Cola segura: el patrón BRPOP + lista de reintentos

Importante: una list sola no da acuse de recibo: si el worker muere entre BRPOP y el procesado, el trabajo se pierde. Para envío garantizado usa un broker (el curso de Mensajería) o la lista de "procesando" reintentable.

Feed de actividad con paginación

Cuando una list no alcanza

  • Leer por índice al medio: O(N); una list no es un array.
  • Buscar un elemento: no hay índice: recorre masa.
  • Colas con retraso programado: mejor sorted set con timestamp.

Ejercicio

  1. Crea una cola con RPUSH y consúmela con BRPOP.
  2. Implementa el feed con LTRIM y paginación.
  3. Explica qué se pierde si el worker muere tras el BRPOP.

Resumen

  • Lists: O(1) en ambos extremos: feeds y colas FIFO.
  • BRPOP consume sin gastar CPU.
  • Sin acuse de recibo: trabaja en una cola sin confirmación puede perderse.
  • Para casos de reintento/retraso, la herramienta es el sorted set.
