Tipos de datos

🔥 Avanzado 13 min Redis para Backend Módulo 1 · Introducción

Elegir la estructura correcta

Cada problema Backend tiene su tipo de dato en Redis. El acierto no es memorizar comandos: es saber cuál usar y por qué.

Strings (el todoterreno)

Uso típico: caché de fragmentos, contadores, tokens, sesiones simples. Es la única pieza que admite operaciones numéricas atómicas.

Hashes (objetos)

Uso típico: modelar un objeto con varios campos: perfil, carrito, sesión con metadata. Evita reenviar el JSON entero para tocar un campo.

Lists (colas y feed)

Cola segura: para consumo seguro usa BRPOP (bloqueante), inmediato con el patrón de delivery-timeout si el worker puede fallar.

Sets (pertenencia y dedupe)

Sorted sets (rankings con peso)

Uso típico: rankings, colas priorizadas por fecha/score, rate limiting por ventana de tiempo.

Ejercicio

  1. Modela un perfil de usuario con HASH y actualízalo con HINCRBY.
  2. Arma un feed con LPUSH y léelo con LRANGE.
  3. Crea un ranking con ZADD y muéstralo con ZREVRANGE.

Resumen

  • String para caché/contadores; Hash para objetos; List para feeds y colas.
  • Set para pertenencia y dedupe; Sorted set para rankings y colas priorizadas.
  • La atómicidad (INCR, HINCRBY, ZINCRBY) evita lecturas-en-escritura.
  • Elige por el patrón de acceso, no por la comodidad del serializado.
