¿Qué es Redis?

🔥 Avanzado 9 min Redis para Backend Módulo 1 · Introducción

Un almacén que vive en RAM

Redis (REmote DIctionary Server) es un almacén de datos clave-valor en memoria. Mientras una base SQL escribe en disco, Redis guarda todo en RAM: por eso responde en microsegundos, miles de veces más rápido que consultar un disco. No reemplaza a tu base principal: la acelera.

Qué lo hace diferente

  • En memoria: velocidad extrema; el pago es que los datos viven donde cabe la RAM.
  • Tipos de datos ricos: no solo strings: hay hashes, listas, conjuntos, etc.
  • Operaciones atómicas: comandos que se ejecutan sin interrupciones (clave para contadores y locks).
  • TTL / expiración: las claves pueden borrarse solas, ideal para caché y tokens.
  • Single-threaded: un solo hilo ejecuta comandos: si un comando tarda, todos esperan.

El modelo de datos: clave → valor

Las claves suelen tener un prefijo de namespace (session:, cache:) que ayuda a organizar y a operar en masa.

Usos estrella en el Backend

  • Caché de consultas y páginas (pattern cache-aside).
  • Sesiones de usuario compartidas entre instancias.
  • Rate limiting (cuotas por IP/usuario).
  • Colas ligeras y pub/sub para eventos.
  • Contadores y rankings (sorted sets).

No es tu base de canon

Los datos de Redis son volátiles si no hay persistencia configurada, y vivir en RAM la encarece. La regla práctica: la base de verdad vive en SQL/NoSQL; Redis es su acelero para lo frecuente. En el módulo 3 verás exactamente dónde trazar esa línea.

Ejercicio

  1. Anota tres piezas de tu última API que tendrían sentido en Redis y por qué.
  2. Explica por qué un comando lento en single-threaded afecta a todos los clientes.
  3. ¿Qué pasaría si Redis se pone en producción sin persistencia y se reinicia?

Resumen

  • Redis es un clave-valor en memoria con latencias de microsegundos.
  • Tipos ricos, atómicidad y TTL lo hacen versátil.
  • Es single-threaded: los comandos caros bloquean a todos.
  • Su trabajo es acelerar; la verdad de los datos vive en tu base principal.
