Almacenamiento en la nube

⚙️ Intermedio 11 min Integraciones y Servicios Externos Módulo 2 · Integraciones prácticas

Introducción

Guardar archivos en el disco de tu propio servidor se rompe en cuanto escala: espacio finito, backups manuales, y mal repartido si despliegas varias instancias. El almacenamiento en la nube (S3 y equivalentes) resuelve eso con objetos duraderos y baratos, pero obliga a decidir quién sube el archivo, quién lo lee y durante cuánto tiempo. La respuesta moderna no pasa por tus instancias: pasa por signed URLs.

Buckets y objetos

  • Un bucket es un contenedor con una región, políticas de acceso y ciclo de vida (pasar a archivo frío y luego borrar).
  • Un objeto es un archivo identificado por una clave: usuarios/42/avatar.webp o facturas/2026/09/factura.pdf.
  • La clave es tu «sistema de archivos»: organizar dominio/id/tipo simplifica las políticas de acceso por prefijo.
  • Los buckets suelen ser privados por defecto; el acceso público se abre de forma controlada.

Subida directa con presigned PUT

El peor patrón es que el archivo pase por tu servidor: consumes memoria, ancho de banda y CPU, y tu API se bloquea durante la subida. Con un presigned PUT, tu backend genera (en segundos) una URL con permisos temporales y el navegador sube directo al bucket:

import boto3
from botocore.config import Config

s3 = boto3.client("s3", region_name="us-east-1",
                  config=Config(signature_version="s3v4"))

def url_subida_directa(usuario_id: str, nombre: str, content_type: str) -> str:
    clave = f"usuarios/{usuario_id}/{nombre}"
    return s3.generate_presigned_url(
        "put_object",
        Params={
            "Bucket": "mi-empresa-upl", "Key": clave,
            "ContentType": content_type,
        },
        ExpiresIn=600,   # 10 minutos para empezar a subir
    )

El navegador recibe la URL firmada, hace un PUT directo y tu backend solo registra la clave en la base de datos. El archivo nunca pasa por tu servidor.

Lectura con presigned GET

Lo mismo para descargar contenido privado: la URL de lectura se genera al vuelo y expira. Perfecto para facturas, adjuntos y archivos restringidos por rol:

import { S3Client, GetObjectCommand } from '@aws-sdk/client-s3';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';

const s3 = new S3Client({ region: process.env.AWS_REGION });

export async function urlLectura(clave) {
  return getSignedUrl(s3, new GetObjectCommand({
    Bucket: process.env.AWS_BUCKET,
    Key: clave
  }), { expiresIn: 900 }); // 15 minutos de acceso
}

Verifica el permiso del usuario antes de firmar la URL. La firma solo autoriza el acceso temporal a la llave, pero no decide si ese usuario tiene derecho a leer.

Servir por CDN

Si ese avatar se va a ver miles de veces, pagar una petición original al bucket cada vez es desperdicio. Un CDN (CloudFront, Fastly) cachea el objeto en nodos de borde y lo sirve cerca del usuario, con cabeceras de cache:

{
  "objeto": "usuarios/42/avatar.webp",
  "estrategia": "CDN + origen privado",
  "origen": { "tipo": "s3", "acceso": "OAC (Origin Access Control)" },
  "cache_control": { "max_age_s": 604800, "immutable": true },
  "invalidez_bajo_demanda": "solo versiones con hash en el nombre"
}

La técnica recomendada: nombres con hash de contenido (avatar-v42.webp). Así el CDN cachea para siempre y «invalidar» solo es crear un objeto nuevo. Las URLs públicas salen del CDN, nunca del bucket.

Regla práctica: sube directo con presigned PUT, sirve con presigned GET o CDN, y nunca guardes los archivos dentro de un request HTTP de tu API.

Seguridad básica del bucket

  • Bloquea el acceso público del bucket (Block Public Access) y entrega solo vía CDN/signed URL.
  • Usa IAM roles en las instancias en vez de claves estáticas de AWS.
  • Valida lado servidor: tipo (image/webp, application/pdf) y tamaño máximo antes de firmar la subida.
  • Configura un ciclo de vida: mover a Glacier archivos viejos y borrar temporales.

Ejercicio

  1. Genera un presigned PUT en Python (iniciamos sesión con credenciales de prueba) y súbete un archivo con curl.
  2. Implementa el presigned GET y comprueba que la URL expira cuando corresponde.
  3. Diseña el esquema de claves para tu producto: fotos de usuarios, facturas y exportaciones temporales.

Resumen

  • Los buckets guardan objetos privados identificados por una clave.
  • Los presigned PUT permiten que el navegador suba directo sin pasar por tu servidor.
  • Los presigned GET dan acceso temporal a contenido privado.
  • Un CDN con nombres con hash sirve el contenido de forma barata y rápida.
  • Siempre valida tipo y tamaño, y verifica permisos antes de firmar.
