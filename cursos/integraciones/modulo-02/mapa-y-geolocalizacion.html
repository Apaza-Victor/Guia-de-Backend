Mapas y geolocalización

⚙️ Intermedio 10 min Integraciones y Servicios Externos Módulo 2 · Integraciones prácticas

Introducción

Todo lo que tiene que ver con «dónde» se resume en dos operaciones: traducir una dirección a coordenadas (geocoding) y traducir coordenadas a una dirección (reverse geocoding). Google Maps Platform, Mapbox y alternativas libres exponen estas APIs por HTTP, con esquemas de cobro por petición, límites por minuto y la eterna pregunta: ¿esto lo llamo desde el servidor o desde el cliente?

Geocoding desde el backend

Tu backend geocodifica cuando necesita coordenadas para calcular distancias: ¿a cuánto llega el repartidor? ¿qué tiendas están en un radio? El patrón es idéntico al de cualquier API externa: clave, timeout y parseo de la respuesta:

import httpx

GOOGLE_API_KEY = os.environ["GOOGLE_MAPS_API_KEY"]

def geocodificar(direccion: str) -> dict | None:
    resp = httpx.get(
        "https://maps.googleapis.com/maps/api/geocode/json",
        params={"address": direccion, "key": GOOGLE_API_KEY},
        timeout=5.0,
    )
    resp.raise_for_status()
    resultado = resp.json()
    if resultado["status"] != "OK":
        return None
    ubicacion = resultado["results"][0]["geometry"]["location"]
    return {"lat": ubicacion["lat"], "lng": ubicacion["lng"]}

La dirección es entrada de usuario y a menudo contiene tildes y espacios; deja que la URL se codifique con los params del cliente, no concatene direcciones a mano.

Estructura de la respuesta

El servicio devuelve varios candidatos ordenados por exactitud. Nunca asumas que el primero es correcto; al menos revisa status y el formatted_address antes de confiar:

{
  "status": "OK",
  "results": [
    {
      "formatted_address": "Av. Siempre Viva 742, Ciudad de México",
      "geometry": {
        "location": { "lat": 19.4326, "lng": -99.1332 },
        "location_type": "ROOFTOP"
      },
      "place_id": "ChIJdeTu..."
    }
  ]
}

Costes, cuotas y buenas prácticas

  • Cada petición cuesta: geocodificar a la hora punta multiplica tu factura. Hazlo una sola vez y guarda las coordenadas junto al registro.
  • Cachea por dirección normalizada: «Av. Siempre Viva 742» y «av siempre viva 742» deberían dar la misma coordenada.
  • Respeta Rate Limit por minuto: ante OVER_QUERY_LIMIT espera unos segundos y reintenta.
  • Guarda el place_id: es el identificador estable del lugar y sirve para consultas posteriores (detalles, fotos).

El precio del geocoding por request hace que la cola para procesar en lotes sea casi obligatoria: datos de miles de direcciones se procesan de a poco, sin disparar la factura.

Servidor vs cliente

La regla es simple: la clave nunca viaja al navegador. Si el mapa interactivo necesita geocodificar o buscar lugares, el backend debe intermediar:

// El frontend pide a NUESTRA API; la clave de Google queda en el servidor
const resp = await fetch('/api/lugares?q=' + encodeURIComponent(texto));
const lugares = await resp.json();
// -> [{placeId, nombre, lat, lng}]

Además de proteger la clave, tu API puede aplicar tus propias reglas: límites por usuario, caché de autocompletados frecuentes y filtrado de resultados. Para renderizar el mapa, se usa una key del lado cliente restringida por dominios y con cuotas pequeñas, separada de la del backend.

Regla práctica: la lógica de ubicación vive en el backend. El cliente solo le pide a tu API; ninguna clave de proveedor debe vivir en tu JavaScript público.

Cálculo de distancias y rutas

Con las coordenadas guardadas, el backend puede calcular distancias sin llamar a ningún proveedor para lo simple (fórmula del haversine en línea recta) y solo pedir Distance Matrix o Directions cuando necesita distancia real por carretera o tiempos ETA con tráfico:

curl "https://maps.googleapis.com/maps/api/distancematrix/json?origins=19.4326,-99.1332&destinations=20.6668,-103.3518&mode=driving&key=$GOOGLE_MAPS_API_KEY"

Ejercicio

  1. Geocodifica tres direcciones de tu ciudad y guarda las coordenadas en tu base.
  2. Implementa una caché local que evite geocodificar dos veces la misma dirección normalizada.
  3. Crea un endpoint propio /api/lugares que consuma la API de Places con la clave solo del lado servidor.

Resumen

  • Geocoding traduce direcciones a coordenadas; reverse geocoding lo invierte.
  • Cada petición cuesta: cachea y geocodifica en lotes fuera del horario pico.
  • La clave del proveedor vive en el backend; el cliente solo consume tu API.
  • Guarda place_id y coordenadas junto al registro para no repetir llamadas.
