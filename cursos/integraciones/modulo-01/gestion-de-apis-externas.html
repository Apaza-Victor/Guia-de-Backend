Gestión de APIs externas

⚙️ Intermedio 8 min Integraciones y Servicios Externos Módulo 1 · Fundamentos

Introducción

Usar una API externa sin leer sus reglas es conducir sin señal de tránsito. Cada proveedor impone rate limits (cuántas peticiones por ventana), cuotas (cuántas peticiones por mes, muchas veces con cobro extra), contratos con versiones y un vocabulario de errores propio. Gestionar bien esa API significa conocer esas reglas, anticiparlas en el código y monitorizarlas en producción.

Rate limits y headers

La mayoría de las APIs comunican el estado de tu límite en los headers de la respuesta. Leyéndolos puedes decidir antes de que el proveedor te bloquee:

curl -sI https://api.github.com/repos/github/rest-api-description \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  | grep -i -E "ratelimit|x-ratelimit"

La respuesta típica incluye X-RateLimit-Limit (máximo por hora), X-RateLimit-Remaining (cuántas quedan) y X-RateLimit-Reset (segundos hasta que se renueve la ventana). Integrarlos en tu cliente te permite reducir la tasa proactivamente:

def leer_encabezados_limite(resp) -> dict:
    return {
        "limite": int(resp.headers.get("X-RateLimit-Limit", 0)),
        "restantes": int(resp.headers.get("X-RateLimit-Remaining", 0)),
        "reinicia_en_s": int(resp.headers.get("X-RateLimit-Reset", 0)) - int(time.time()),
    }

def hay_cuota(resp) -> bool:
    datos = leer_encabezados_limite(resp)
    return datos["limite"] > 0 and datos["restantes"] > 0 and datos["reinicia_en_s"] > 0

Errores que debes distinguir

No todos los errores del proveedor son iguales. Aprender a distinguirlos evita reintentos inútiles y bloqueos innecesarios:

  • 400/422 — tu request está mal: corregir el código, no reintentar.
  • 401/403 — credenciales o permisos: revisar secretos y scopes.
  • 429 — rate limit alcanzado: esperar respetando Retry-After.
  • 500/502/503 — problema del proveedor: reintentar con backoff.
{
  "error": "rate_limit_exceeded",
  "status": 429,
  "retry_after_s": 47,
  "sugerencia": "espera 47 segundos o baja la tasa antes de reintentar",
  "reintentar": true
}

Cuotas y costes

Además del límite por ventana existe la cuota mensual, que suele estar ligada a tu plan y tiene impacto económico. Estrategias para no quedarte sin crédito: cachear respuestas repetidas, procesar en lotes, alertar cuando el consumo supere un porcentaje y degradar el servicio (por ejemplo, geocodificar solo cuando es estrictamente necesario).

Regla práctica: trata cada llamada a una API de terceros como un coste. Si puedes cachear, ahorras dinero cada vez que el resultado no cambia.

Contratos y versionado

Las APIs evolucionan. Los proveedores serios versionan (/v1/, /v2/) y mantienen periodos de deprecación. Tu defensa es doble: anclar la versión que testeas y tratar a la API como un contrato que puede cambiar aunque no lo anuncie:

  • Lee el changelog antes de cada actualización de cliente o SDK.
  • Mantén tus tests de integración contra el sandbox del proveedor en CI periódico.
  • Registra en código qué campos consumes, para detectar campos eliminados de golpe.
// Ancla la versión de la API y documenta los campos usados
const CONFIG = {
  baseUrl: 'https://api.proveedor.com/v2',
  endpoints: {
    crearPedido: { metodo: 'POST', ruta: '/orders' },
    estadoPedido: { metodo: 'GET', ruta: '/orders/:id', camposUsados: ['status', 'trackingUrl'] }
  }
};

Ejercicio

  1. Haz una petición a una API pública que use rate limits (por ejemplo, GitHub) y registra los headers de límite que devuelve.
  2. Escribe una función que, ante un 429, lea Retry-After y espere ese tiempo antes de reintentar.
  3. Inventa el contrato JSON de una API tuya y decide qué campos deprecarías manteniendo compatibilidad con /v1.

Resumen

  • Los rate limits se comunican por headers: límpialos en tu cliente y actúa proactivamente.
  • 400 no se reintenta; 429 se espera; 5xx se reintenta con backoff.
  • Las cuotas tienen coste: cachea y procesa en lotes.
  • El contrato de una API externa puede cambiar sin previo aviso; ancla versiones y testea en sandbox.
