SDKs y clientes HTTP

⚙️ Intermedio 9 min Integraciones y Servicios Externos Módulo 1 · Fundamentos

Introducción

Consumir una API externa se puede hacer de dos formas: usar el SDK oficial que mantiene el proveedor o hablar con la API directamente mediante un cliente HTTP (fetch, axios, requests). Ambas son válidas, pero elegir sin contexto conduce a problemas: el SDK te ahorra tiempo al principio y te puede costar caro después, y el cliente plano te da control total pero te obliga a escribir la firma, el retry y el contrato a mano.

El SDK oficial

El SDK oficial trae tipos, autenticación, reintentos e incluso manejo de webhooks ya resueltos. Es una elección razonable cuando el proveedor es maduro y su SDK está bien mantenido:

  • Ventajas: menos código tuyo, respuestas tipadas, helpers de verificación de firmas, actualizaciones al ritmo del proveedor.
  • Desventajas: versiones que rompen contratos, dependencias pesadas en tu stack, comportamientos ocultos (retries por defecto) y APIs que no siempre encajan con tu estilo.

Sea cual sea la opción, la regla no cambia: el SDK vive dentro de tu adaptador, nunca diseminado por el código de negocio.

import Stripe from 'stripe';
const stripe = new Stripe(process.env.STRIPE_SECRET_KEY);

// El SDK se queda confinado en el adaptador de pagos
export async function crearSesionDePago(pedido) {
  return stripe.checkout.sessions.create({
    line_items: [{ price: pedido.precioId, quantity: 1 }],
    mode: 'payment',
    success_url: 'https://mi-tienda.com/ok',
    cancel_url: 'https://mi-tienda.com/cancel'
  });
}

El cliente HTTP plano

Cuando el SDK no existe, está desactualizado o es más complejo que la API, un cliente HTTP simple es tu mejor amigo. Con él controlas timeouts, headers y body exactos:

import httpx
from typing import Dict

class ApiGeocodificacion:
    BASE = "https://maps.example.com/v1"

    def __init__(self, api_key: str):
        self._cliente = httpx.Client(
            base_url=self.BASE,
            timeout=httpx.Timeout(connect=3.0, read=5.0),
        )
        self._api_key = api_key

    def geocodificar(self, direccion: str) -> Dict[str, float]:
        resp = self._cliente.get("/geocode", params={
            "address": direccion,
            "key": self._api_key,
        })
        resp.raise_for_status()
        dato = resp.json()["results"][0]
        return {"lat": dato["lat"], "lng": dato["lng"]}

Fíjate en el timeout explícito: un cliente sin timeout convierte una caída del proveedor en un request colgado que agota los hilos de tu servidor.

Envolver al tercero

Ambos caminos desembocan en lo mismo: una capa propia que los demás módulos consumen. El resto de tu aplicación nunca debería importar ni a Stripe ni a axios directamente. Eso convierte el futuro cambio de proveedor en un cambio de una sola clase:

{
  "adaptador": "CorreoProveedorA",
  "interfaz_interna": {
    "enviar_transaccional": "CorreoAdapter.enviar()",
    "consultar_entrega": "CorreoAdapter.estado()"
  },
  "clientes_permitidos": [
    "server/src/integraciones/correo/*",
    "server/src/adaptadores/*"
  ],
  "prohibido_en": "controladores, servicios de dominio"
}

Regla práctica: antes de instalar un SDK nuevo, pregúntate «¿esto me ahorra lógica que de verdad importa o solo tengo un nuevo amigo con release schedule?». La respuesta decide entre SDK y cliente plano.

Dependencias bajo control

El SDK de un tercero es software de otro equipo dentro de tu artefacto. Puede romperte en cada npm update. Estrategias de contención:

  • Fija la versión exacta en tu manifiesto y actualízala deliberadamente, con test y changelog leídos.
  • Verifica en CI que el contrato esperado sigue respondiendo (tests de integración contra sandbox).
  • Mantén el adaptador delgado: toda la lógica sensible sigue en tu código, no dentro del SDK.
# Congela la versión del SDK del proveedor en tu package.json
npm install --save-exact stripe@17.2.1 @sendgrid/mail@8.1.4

Ejercicio

  1. Elige un proveedor que uses (o uno ficticio) y decide: ¿SDK o cliente plano? Argumenta en una frase.
  2. Escribe un adaptador en Python o JavaScript con timeout y un solo método público.
  3. Simula el cambio de proveedor: reescribe solo la implementación interna del adaptador y verifica que la interfaz no cambió.

Resumen

  • El SDK oficial ahorra tiempo; el cliente plano da control total.
  • Ambos deben quedar confinados dentro del adaptador de integración.
  • Siempre define timeouts explícitos para no colgar tu servidor.
  • Fija versiones de SDKs y actualiza con tests que midan el contrato.
