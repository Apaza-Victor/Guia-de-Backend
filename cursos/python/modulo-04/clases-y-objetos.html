Clases y objetos

⚙️ Intermedio 11 min Python para Backend Módulo 4 · Programación orientada a objetos

Introducción

Los objetos agrupan datos y el comportamiento que actúa sobre ellos. En backend, las clases modelan el dominio: Usuario, Pedido, Token, Servicio.

Conocer clases te permite escribir código organizado, reutilizable y testeable.

Definición

Una clase es una plantilla; un objeto es una instancia concreta creada a partir de ella, con su propio estado.

Por qué importa. Modelar el dominio en clases hace que la lógica de negocio viva junto a sus datos y sea fácil de probar y extender.

Cuándo usarlo. Usa clases para entidades con estado (usuarios, pedidos) y para agrupar operaciones relacionadas de un servicio.

Conceptos clave

  • class Nombre: define la plantilla.
  • El método __init__ configura el estado inicial de cada objeto.
  • self referencia la instancia actual dentro de los métodos.
  • Los atributos son datos; los métodos son funciones del objeto.
  • Se instancia con NombreClase(*args): cada objeto tiene identidad propia.

Ejemplo real

Entidad de dominio con un método to_dict para exponerla en una API JSON.

  • El modelo contiene su propia validación.
  • to_dict controla qué se expone (por ejemplo, sin contraseñas).
  • El código de la API queda simple: recoger datos e invocar el objeto.

Este mapeo de objeto a dict es el paso previo a Pydantic y FastAPI, que verás en el módulo 7.

Explicación

  • __init__ no crea el objeto: lo inicializa. El objeto nace cuando llamas a la clase.
  • self es obligatorio y siempre va primero; agrupa el estado de la instancia.
  • Los atributos y métodos se acceden con el punto.
  • Varias instancias comparten el código de la clase pero no su estado.

Errores comunes

  • TypeError de __init__() faltando argumentos cuando olvidas los requeridos.
  • NameError si usas un atributo sin declararlo en __init__.
  • Olvidar self en un método provoca TypeError por argumentos descolocados.

Buenas prácticas

  • Declara todos los atributos en __init__ para que el estado sea predecible.
  • Escribe los métodos como frases de acción: confirmar_pedido, cancelar.
  • Mantén las clases pequeñas y con una sola responsabilidad.
  • Usa to_dict para controlar la serialización y no filtrar campos.

Ejercicio

  1. Crea una clase Producto con nombre, precio y stock, y un método rebajar(precio).
  2. Agrega a Usuario un método es_activo que valide su estado.
  3. Escribe to_dict para un Cliente con el email ofuscado.

Resumen

  • Las clases agrupan datos y comportamiento del dominio.
  • __init__ inicializa el estado y self enlaza la instancia.
  • to_dict facilita la serialización hacia APIs.
