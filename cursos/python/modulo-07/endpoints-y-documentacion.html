Endpoints CRUD y documentación automática

🔥 Avanzado 13 min Python para Backend Módulo 7 · APIs con FastAPI

Introducción

Reúne todo lo aprendido: modela con Pydantic, expón rutas con FastAPI y construye un CRUD (Crear, Leer, Actualizar, Borrar) completo.

Como bonus, FastAPI documenta cada endpoint automáticamente en OpenAPI.

Definición

Un CRUD expone operaciones sobre un recurso: POST crea, GET lee (lista o detalle), PUT actualiza y DELETE borra; en FastAPI cada una es una ruta con status codes y response_model.

Por qué importa. Es la base de casi toda API de backend: los recursos del dominio (usuarios, pedidos) se manejan con este patrón estándar.

Cuándo usarlo. Usa este patrón para tu primer API real con almacenamiento en memoria; luego sustituye la lista por una base de datos.

Conceptos clave

  • response_model fija el esquema de salida tipado.
  • status_code=201 para creación, 204 para borrado.
  • HTTPException con status y detail controla los errores.
  • Los path params int:id señalan el recurso concreto.
  • FastAPI genera y sirve la documentación OpenAPI en /docs.

Abre /docs: Swagger UI te deja crear, listar y borrar pedidos sin escribir una línea de curl. Esa documentación nació del tipado.

Explicación

  • response_model describe la respuesta y la valida contra el esquema.
  • status_code por ruta informa al cliente del estado esperado.
  • HTTPException mantiene los errores en JSON válido.
  • global contador hace mutable el id incremental.
  • Al cambiar la lista por una base de datos, los endpoints apenas cambian: mismo contrato.

Errores comunes

  • 404 controlados vs 500 crudos: usa HTTPException y no KeyError.
  • Olvidar el status_code=201 y responder 200 en creaciones.
  • Un response_model que no calza con lo devuelto genera errores de validación.

Buenas prácticas

  • Agrupa tus RUTAS en routers (APIRouter) cuando el proyecto crezca.
  • Usa modelos de salida separados para no exponer campos internos.
  • Prueba los 4 verbos desde /docs antes de escribir tests con pytest.
  • En producción sustituye pedidos {} por la base de datos; las rutas se mantienen.

Ejercicio

  1. Agrega un campo estado a Pedido y un endpoint para marcarlo entregado.
  2. Crea un endpoint /pedidos/{id}/total que devuelva el total con iva.
  3. Añade un GET /pedidos/estadisticas con totales y conteo.

Resumen

  • Un CRUD estándar usa POST, GET, PUT y DELETE sobre un recurso.
  • HTTPException y status_code producen respuestas correctas.
  • response_model y /docs documentan y prueban la API sin esfuerzo.
