Pydantic y modelos de datos

🔥 Avanzado 11 min Python para Backend Módulo 7 · APIs con FastAPI

Introducción

La parte que hace brillar a FastAPI es Pydantic: defines modelos con clases y anotaciones, y obtienes validación, coerción y serialización automáticas.

Un modelo Pydantic se parece a una dataclass con superpoderes de validación.

Definición

Pydantic valida datos usando modelos (subclases de BaseModel) con campos tipados: el framework los aplica a peticiones y respuestas automáticamente.

Por qué importa. Elimina decenas de if manuales: declaras el contrato y el framework responde 422 ante datos inválidos por ti.

Cuándo usarlo. Usa modelos para el body de peticiones, parámetros complejos, esquemas de respuesta y configuración de la app.

Conceptos clave

  • class Usuario(BaseModel) define el modelo.
  • Los campos se anotan: nombre: str, activo: bool.
  • Valores por defecto: rol: str = "usuario".
  • Field permite restricciones: min_length, gt, regex.
  • model_dump() serializa; el JSON de salida se genera solo.

Ejemplo real

Conectar el modelo a un endpoint: FastAPI valida el body y responde 422 ante errores.

  • Pydantic valida y convierte tipos automáticamente.
  • El 422 incluye el motivo exacto de cada campo.
  • La API declara el contrato en el schema OpenAPI.

Envía un body sin email y verás un 422 detallado en /docs: es la validación de Pydantic en acción.

Explicación

  • Las instancias validadas se convierten al tipo anotado (por ejemplo, "30" a 30).
  • Field permite min_length, gt, ge, lt, le y pattern.
  • Enviar campos de más o incompletos dispara un 422 automático.
  • El modelo define a la vez el schema de entrada, la documentación y la validación.
  • Con model_dump() vuelves a dict para devolver JSON.

Errores comunes

  • NameError si la clase se define sin importar BaseModel.
  • 422 al enviar campos que faltan o que no están anotados.
  • Olvidar que los campos SIN default son obligatorios.

Buenas prácticas

  • Separa modelos de entrada y salida, no mezcles campos internos.
  • Usa Field con restricciones y mensajes claros.
  • Explota los defaults para campos opcionales y evita Optional innecesarios.
  • Valida también la configuración de tu app con modelos Pydantic.

Ejercicio

  1. Crea un modelo Pedido con id, total y estado usando Field.
  2. Añade validación de email con pattern a UsuarioEntrada.
  3. Expón el modelo en un endpoint POST y comprueba los 422 en /docs.

Resumen

  • Pydantic valida datos con modelos y tipos puros.
  • Field añade restricciones detalladas.
  • FastAPI usa el modelo para validar, documentar y serializar.
