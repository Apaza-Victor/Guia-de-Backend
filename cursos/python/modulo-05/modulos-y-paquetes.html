Módulos y paquetes

⚙️ Intermedio 9 min Python para Backend Módulo 5 · Módulos, archivos y excepciones

Introducción

Un backend de verdad se organiza en muchos archivos: modelos, utilidades, configuración, rutas. Los módulos y paquetes hacen que el código viaje de archivo en archivo.

En Python, un módulo es cualquier archivo .py y un paquete es una carpeta con __init__.py.

Definición

Un módulo agrupa funciones, clases y constantes reutilizables; un paquete es una carpeta con __init__.py que agrupa módulos relacionados bajo un espacio de nombres.

Por qué importa. Dividir el código en módulos permite testear de forma aislada, reutilizar y mantener proyectos de cientos de archivos ordenados.

Cuándo usarlo. Usa módulos desde el primer helper; arma paquetes cuando el proyecto crece: utils, config, models.

Conceptos clave

  • import modulo o from modulo import funcion.
  • El bloque if __name__ == "__main__": evita ejecutar al importar.
  • Alias: import modulo as m.
  • Una carpeta con __init__.py es un paquete importable.
  • Los imports relativos (from .modulo import x) funcionan dentro del paquete.

Ejemplo real

Estructura típica de un pequeño backend por capas, con config y versionado.

  • Separa responsabilidades en archivos: config, utils, modelos, rutas.
  • Los imports explícitos revelan las dependencias.
  • El guard __main__ permite probar cada archivo por separado.

Los frameworks reales (FastAPI) usan paquetes de carpetas: routers, schemas, models. La misma mecánica que acabas de ver.

Explicación

  • Importar ejecuta el módulo una sola vez y lo guarda en sys.modules.
  • El guard __name__ evita efectos colaterales al importar.
  • Los paquetes sin __init__.py (namespace) existen, pero añadirlo es explícito.
  • Los imports relativos de un paquete evitan rutas frágiles.

Errores comunes

  • ModuleNotFoundError cuando la ruta o el nombre no coinciden.
  • Import circular (a importa b y b importa a) deja funciones sin definir.
  • Ejecutar código de arranque al importar por olvidar el guard __main__.

Buenas prácticas

  • Prefiere imports explícitos: from utilidades import normalizar_email.
  • Evita los imports circulares moviendo el punto de cruce a un tercer módulo.
  • Nombra módulos y paquetes en minúsculas (PEP 8).
  • Guarda secretos en variables de entorno, no en módulos de código.

Ejercicio

  1. Divide tu ejercicio de funciones en utilidades.py y app.py.
  2. Crea un paquete con __init__.py y dos módulos, luego impórtalos.
  3. Ejecuta un módulo directamente y también vía import, observando __name__.

Resumen

  • Un módulo es un archivo .py; un paquete una carpeta con __init__.py.
  • El guard __name__ == "__main__" separa import de ejecución.
  • Un backend por capas se apoya en paquetes organizados.
