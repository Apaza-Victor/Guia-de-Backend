Trabajar con JSON y serialización

⚙️ Intermedio 10 min Python para Backend Módulo 5 · Módulos, archivos y excepciones

Introducción

El JSON es el formato de intercambio estándar de las APIs: tu backend lo recibe en las peticiones y lo devuelve en las respuestas.

El módulo json convierte tus estructuras Python (dicts, listas) en texto JSON y viceversa con dos líneas.

Definición

Serializar es convertir una estructura Python en una cadena JSON (json.dumps); deserializar es lo opuesto (json.loads). La salida se guarda en archivos con dump y load.

Por qué importa. Sin serialización no hay intercambio de datos entre servicios: tu API solo entiende texto (JSON) y tu código piensa en dicts y clases.

Cuándo usarlo. Usa json para responder peticiones, leer archivos de config, guardar cachés y comunicarte con otras APIs.

Conceptos clave

  • json.dumps(python) convierte a cadena JSON.
  • json.loads(cadena) convierte a estructura Python.
  • json.dump y json.load escriben y leen directamente archivos.
  • ensure_ascii=False conserva los acentos en la salida.
  • indent=2 formatea el JSON para humanos.

Ejemplo básico

Convertir un dict de usuario a JSON y volver a Python.

{"nombre": "Ana", "roles": ["admin"], "activo": true}
<class 'str'>
['admin']
<class 'dict'>

Ejemplo intermedio

Guardar la configuración de la aplicación en un archivo JSON y cargarla al arrancar.

Ejemplo real

Construir la respuesta de una API: dict a JSON, y recibir JSON a dict en la petición.

  • Envías los datos de la respuesta serializados con dumps.
  • Recibes el body de la petición con loads.
  • Maneja JSON inválido con try/except para responder 400.

En FastAPI no llamas a json a mano: Pydantic valida y serializa por ti. Dominar json aquí te da la intuición de lo que ocurre debajo.

Explicación

  • dumps vs dump: uno a cadena, otro a archivo; loads vs load igual.
  • Los booleanos True y False se convierten a true y false; None a null.
  • Los dicts se serializan respetando su orden de inserción.
  • Objetos no serializables (datetime, clases) lanzan TypeError sin hook.
  • ensure_ascii=False emite acentos reales en lugar de secuencias \uXXXX.

Errores comunes

  • json.JSONDecodeError cuando el texto recibido no es JSON válido.
  • TypeError al serializar un objeto arbitrario sin default.
  • Cargar un JSON esperando un dict y recibir una lista.

Buenas prácticas

  • Envuelve loads en try/except siempre que el dato venga de fuera.
  • Usa indent=2 solo en desarrollo; en producción mantén la salida compacta.
  • Fija ensure_ascii=False para texto legible.
  • Para tipos complejos define default=str o usa modelos (Pydantic).

Ejercicio

  1. Serializa una lista de 3 pedidos a JSON con indent=2.
  2. Carga un archivo config.json y corrige un dato sin romper el resto.
  3. Crea un helper leer_json(ruta) que devuelva None si el archivo está corrupto.

Resumen

  • json.dumps y loads convierten entre Python y texto JSON.
  • dump y load trabajan directo con archivos.
  • Valida y maneja JSONDecodeError cuando el dato viene de fuera.
