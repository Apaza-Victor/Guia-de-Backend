Excepciones y try/except

⚙️ Intermedio 10 min Python para Backend Módulo 5 · Módulos, archivos y excepciones

Introducción

El backend vive rodeado de fallos: una base de datos caída, un parseo roto, un timeout, una entrada inesperada. Las excepciones son el mecanismo de Python para manejarlos.

Con try/except decides qué hacer ante cada error, en lugar de estrellarte.

Definición

Una excepción interrumpe el flujo normal; try/except la captura para manejarla, finally limpia siempre y raise la dispara manualmente.

Por qué importa. Un error no gestionado tumba el servicio o responde 500; manejado, tu API responde 400 o reintenta con criterio.

Cuándo usarlo. Usa try/except en puntos de entrada (parsing, I/O, llamadas HTTP) y raise para validar reglas de negocio.

Conceptos clave

  • try/except captura errores concretos: except ValueError, except KeyError.
  • else se ejecuta solo si no hubo excepción.
  • finally se ejecuta siempre (cerrar conexiones).
  • raise lanza una excepción propia o re-lanza la capturada.
  • La jerarquía: BaseException, luego Exception, luego los errores concretos.

  • Las excepciones llevan mensajes claros al cliente.
  • raise en validaciones del dominio mantiene el código legible.
  • Registra el error antes de devolver 500 en servicios de producción.

FastAPI valida este tipo de invariantes con Pydantic; pero el patrón try/except con raise te lo da escrito en arquitecturas custom.

Explicación

  • Captura las excepciones específicas que sabes manejar; no solo except Exception.
  • else no corre si entró en except, lo que hace el flujo explícito.
  • finally corre SIEMPRE, perfecto para cerrar recursos o limpiar.
  • raise sin argumentos dentro de except re-lanza la excepción original.
  • Una jerarquía ordenada evita que except demasiado generales atrapen todo.

Errores comunes

  • Capturar BaseException (incluye KeyboardInterrupt) y tragar señales.
  • Un except silencioso (except: pass) que oculta bugs críticos.
  • Levantar excepciones genéricas Exception sin contexto.

Buenas prácticas

  • Sé específico con el tipo de excepción que capturas.
  • Registra el error (logging) antes de mostrarlo al cliente.
  • Nunca devuelvas stack traces; limita el mensaje.
  • Define excepciones propias heredando de Exception para tu dominio.

Ejercicio

  1. Protege procesar_datos() ante TypeError y KeyError con mensajes claros.
  2. Crea una excepción personalizada PedidoInvalido y lánzala en una validación.
  3. Escribe un bloque con else y finally que cuente los procesos exitosos.

Resumen

  • try/except maneja fallos puntuales sin tumbar el servicio.
  • else y finally afinan la ejecución y la limpieza.
  • raise convierte validaciones en excepciones comunicables.
