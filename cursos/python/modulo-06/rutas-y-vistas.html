Rutas, vistas y peticiones HTTP

🔥 Avanzado 11 min Python para Backend Módulo 6 · Web con Flask

Introducción

Una API no son solo URLs fijas: recibe parámetros, distingue GET de POST y lee el cuerpo de la petición.

En Flask, request te da todo lo que el cliente te manda.

Definición

request es el objeto que envuelve la petición actual: métodos (GET, POST...), query params, JSON del body y cabeceras. Las rutas dinámicas se escriben con .

Por qué importa. El backend vive de las peticiones que recibe; sin request no hay entrada de datos, ni parámetros, ni bodies que procesar.

Cuándo usarlo. Usa rutas dinámicas para recursos con id (/usuarios/) y request para leer JSON y query params de cada petición.

Conceptos clave

  • @app.route("/usuarios/") captura un entero de la URL.
  • methods=["GET", "POST"] limita los verbos aceptados en la ruta.
  • request.get_json() lee el cuerpo JSON de la petición.
  • request.args guarda los parámetros de consulta (?pagina=1).
  • request.method dice con qué verbo llegó la petición.

Una ruta dinámica que responde según el identificador recibido.

Ejemplo intermedio

Aceptar GET y POST en la misma ruta para listar y crear usuarios.

Ejemplo real

Probar las rutas con curl: listar y crear, incluyendo un query param de paginación.

  • curl -X POST envía el verbo correcto.
  • -H establece el tipo de contenido esperado.
  • -d manda el JSON del cuerpo.

request.get_json() devuelve None si el body no es JSON; abre siempre con fallback {} y valida después.

Explicación

  • Los convertidores validan el tipo en la URL; /usuarios/abc da 404 directo.
  • request.args es un MultiDict: si un query param puede faltar, usa .get() con default.
  • jsonify fuerza el Content-Type correcto y permite códigos de estado.
  • Por defecto una ruta solo acepta GET hasta que declares methods.
  • Los handlers pueden devolver (cuerpo, status).

Errores comunes

  • Unsupported MediaType 415 al enviar JSON sin el Content-Type correcto.
  • request.get_json() con body vacío devuelve None y revienta tu código.
  • 404 porque la ruta esté mal escrita o el convertidor no haga match.

Buenas prácticas

  • Valida que los datos estén presentes con .get() antes de usarlos.
  • Devuelve códigos explícitos: 201 en creación, 404 en no encontrado.
  • Agrupa rutas por recurso con GET y POST en la misma URL.
  • Usa jsonify en vez de construir strings JSON a mano.

Ejercicio

  1. Crea /saludo?nombre=X que responda Hola X.
  2. Añade POST /usuarios que valide el email requerido y responda 400 si falta.
  3. Implementa /pedidos/ que devuelva 404 si el pedido no existe.

Resumen

  • Las rutas dinámicas capturan parámetros de la URL.
  • methods controla los verbos HTTP por ruta.
  • request.get_json() y request.args leen la petición entrante.
