Condicionales: if, elif y else

💻 Básico 9 min Python para Backend Módulo 2 · Control de flujo y funciones

Introducción

Las APIs y servicios reciben datos que cambian según la petición. Tu código necesita decidir qué hacer frente a cada caso: ¿el usuario tiene permisos? ¿el campo viene vacío? ¿el status es 200 o 404? Eso se resuelve con condicionales.

En Python las condiciones se escriben con if, elif y else, y el bloque de código que se ejecuta se marca por indentación.

Definición

Un condicional evalúa una expresión booleana y ejecuta un bloque de código solo si el resultado es verdadero. elif encadena condiciones alternativas y else captura el caso restante.

Por qué importa. Todo backend toma decisiones: autorización, validaciones, enrutado lógico y control de errores. Sin condicionales el código se ejecutaría siempre en línea recta.

Cuándo usarlo. Usa si verificas una condición de entrada, un estado de usuario, el valor de una variable de configuración o el código de respuesta de otra API.

Conceptos clave

  • if evalúa una condición y ejecuta el bloque si es True.
  • elif permite probar condiciones adicionales cuando la anterior falla.
  • else ejecuta el bloque final si ninguna condición se cumplió.
  • La indentación (4 espacios) delimita el bloque de cada rama.
  • Operadores: ==, !=, <, >, <=, >= y los lógicos and, or, not.

Ejemplo real

En un backend real sueles decidir qué respuesta devolver. Este patrón de clasificación es común en clientes HTTP y validadores de peticiones.

  • Devuelve pronto: evalúa primero los casos más urgentes.
  • Evita condiciones gigantes; refactoriza a funciones claras.
  • Usa constantes nombradas para que códigos como 404 sean legibles.

En FastAPI o Express usarás este tipo de lógica en middlewares y validadores antes de tocar la base de datos.

Explicación

  • La condición de un if siempre se reduce a un booleano: variables como 0, "" y None se consideran falsas.
  • elif ahorra anidar if dentro de else, dejando el código plano y legible.
  • Evalúa arriba los casos más probables o los más baratos de comprobar.
  • Un dict o match puede sustituir cadenas largas de elif cuando comparas un mismo valor.
  • La indentación inconsistente rompe el programa con IndentationError.

Errores comunes

  • SyntaxError: expected ':' cuando olvidas los dos puntos al final de la condición.
  • IndentationError al mezclar espacios y tabulaciones.
  • Confundir = (asignación) con == (comparación).

Buenas prácticas

  • Escribe condiciones legibles: 200 <= status < 300 en lugar de status >= 200 and status < 300.
  • Evita else innecesarios con guard clauses (return anticipado).
  • Usa constantes con nombre para códigos mágicos: HTTP_OK = 200.
  • Comprueba primero None o vacío para no reventar al acceder a atributos.

Ejercicio

  1. Escribe una función nivel_acceso(rol) que devuelva el nivel según admin, editor o visitante.
  2. Clasifica las edades de un diccionario de usuarios en mayor o menor usando condicionales.
  3. Agrega el caso de estado 3xx a clasificar_respuesta.

Resumen

  • if/elif/else deciden qué bloque se ejecuta según una condición booleana.
  • Los operadores de comparación y lógicos componen condiciones poderosas.
  • Las guard clauses y las constantes nombradas hacen el código de backend más claro.
