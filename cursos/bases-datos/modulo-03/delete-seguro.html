Borrado seguro con DELETE

🌱 Principiante 10 min Bases de Datos Módulo 3 · SQL básico

Introducción

Borrar es la única operación de SQL que no se puede deshacer una vez confirmada. Un DELETE sin WHERE vacía la tabla; un DROP TABLE se lleva la estructura y los datos. Esta lección te enseña a borrar con el mismo cuidado que un cirujano.

Sintaxis y uso correcto

La regla es la misma que con UPDATE: verifica el WHERE con un SELECT previo. Si el SELECT devuelve lo que esperas, el DELETE borrará exactamente eso.

Las claves foráneas te frenan (para bien)

Intentar borrar un cliente que tiene pedidos fallará si existe una clave foránea sin regla de borrado. Eso es una protección, no un error:

Usa ON DELETE CASCADE para datos desechables (detalles de un borrador) y RESTRICT/SET NULL cuando romper la referencia sería un problema de negocio.

Borrado lógico (soft delete)

En sistemas reales, los datos casi nunca se borran de verdad: se marcan. El «borrado lógico» agrega una columna de estado y oculta los datos en las consultas:

Ventajas: los datos siguen existiendo para auditoría o facturación, y nada se pierde para siempre. Coste: hay que acordarse de filtrar por eliminado = FALSE en cada consulta.

Protocolo anti-catástrofes

  • Ejecuta BEGIN; antes de borrar en masa y revísale con un SELECT.
  • ROLLBACK; si algo no cuadra; COMMIT; solo cuando estés seguro (verás los detalles en el módulo 5).
  • Haz un respaldo de la tabla antes de cambios masivos.
  • Usa borrado lógico por defecto en entidades con historial.
  • Prefiere TRUNCATE solo con datos temporales que sobreviven sin problema.

Ejercicio

  1. Escribe el SELECT de verificación antes de borrar «clientes inactivos de antes de 2023» y luego el DELETE.
  2. Agrega un borrado lógico eliminado a una tabla de posts y ajusta el listado.
  3. Explica la diferencia entre RESTRICT y CASCADE en un ON DELETE.

Resumen

  • DELETE ... WHERE borra filas concretas; sin WHERE lo borra todo.
  • Verifica siempre el filtro con un SELECT antes de borrar.
  • Las claves foráneas protegen las referencias al borrar.
  • El borrado lógico (soft delete) es la práctica estándar en producción.
  • Transacciones y respaldos convierten un borrado en un riesgo controlado.
