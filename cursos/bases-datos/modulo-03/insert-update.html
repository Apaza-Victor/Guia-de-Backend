Insertando y modificando datos

🌱 Principiante 10 min Bases de Datos Módulo 3 · SQL básico

Introducción

Las operaciones de escritura son las que más riesgo traen: un UPDATE sin condición puede pisarte toda una tabla. En esta lección dominarás INSERT y UPDATE con sus buenas prácticas para que nada se rompa.

INSERT: dar de alta datos

El INSERT añade registros. Puedes indicar las columnas o no; lo correcto es declararlas siempre para que el código no dependa del orden de las columnas:

Dejamos fuera id y los campos con DEFAULT, que el motor completa solo. Recuerda: las claves primarias AUTO_INCREMENT no se insertan a mano.

UPDATE: modificar registros

La regla de oro: un UPDATE sin WHERE afecta a todas las filas. Antes de ejecutar, pregunta siempre: «¿este WHERE identifica solo lo que quiero tocar?».

Consejo pro: escribe primero el SELECT con el mismo WHERE para ver cuántas filas devolverá, y recién entonces conviértelo en UPDATE.

Errores típicos

  • Olvidar el WHERE: se modifica todo. De nada sirve arrepentirse después.
  • Violar UNIQUE: insertar un email repetido lanza un error; el motor te protege.
  • Violar FK: referenciar un cliente que no existe: el motor lo rechaza.
  • Usar tipos incorrectos: guardar fechas como texto crea problemas de orden y búsqueda.

Protecciones en producción

Si usas MySQL/PostgreSQL a mano, acompaña tus cambios críticos con:

  • Transacciones (BEGIN … COMMIT/ROLLBACK) — las verás en el módulo 5.
  • Respaldos puntuales antes de cambios masivos (módulo 6).
  • Un entorno de pruebas donde verificar el SQL primero.
  • Herramientas como --safe-updates en el cliente MySQL, que exigen WHERE o LIMIT en UPDATE/DELETE.

Ejercicio

  1. Inserta 3 clientes nuevos y después actualiza el email de uno solo usando su id.
  2. Escribe un UPDATE que suba un 10% el precio de los productos con stock en 0.
  3. Explica por escrito qué le pasa a la tabla si ejecutas UPDATE productos SET precio = 0; sin WHERE.

Resumen

  • INSERT da de alta registros; declarar columnas es buena práctica.
  • UPDATE ... SET ... WHERE modifica filas específicas.
  • Un UPDATE sin WHERE toca toda la tabla: siempre verifica con SELECT antes.
  • Las restricciones del esquema protegen de errores de escritura.
  • Transacciones, back-ups y entornos de prueba blindan los cambios en producción.
