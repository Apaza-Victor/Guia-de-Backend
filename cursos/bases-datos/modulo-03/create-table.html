Creando tablas con CREATE TABLE

🌱 Principiante 9 min Bases de Datos Módulo 3 · SQL básico

Introducción

El comando CREATE TABLE es donde el modelo de datos se materializa: aquí declaras columnas, tipos y reglas. Lo que definas ahora limitará los datos durante toda la vida del sistema, por eso vale la pena ser cuidadoso.

Sintaxis básica

Partes del comando:

  • id INT PRIMARY KEY AUTO_INCREMENT: clave primaria numérica que se genera sola.
  • VARCHAR(120): texto de hasta 120 caracteres.
  • TEXT: texto largo sin límite rígido.
  • DECIMAL(10,2): número con 8 enteros y 2 decimales (adecuado para dinero).
  • NOT NULL: obliga a que la columna siempre tenga valor.
  • DEFAULT: valor usado cuando no se envía uno.

Restricciones que protegen los datos

  • PRIMARY KEY: única, no nula y de referencia para otras tablas.
  • UNIQUE: impide valores repetidos en la columna (ideal para emails).
  • NOT NULL: el valor es obligatorio.
  • DEFAULT: valor automático; los timestamps suelen usar CURRENT_TIMESTAMP.
  • CHECK: valida un rango (no en MySQL clásico; sí en PostgreSQL).
  • FOREIGN KEY: enlaza con otra tabla y garantiza integridad referencial.

Gestionar tablas existentes

  • DROP TABLE IF EXISTS productos;: la elimina por completo (¡con todos sus datos!).
  • TRUNCATE TABLE productos;: borra las filas y reinicia los autoincrementales.
  • ALTER TABLE productos ADD COLUMN talla VARCHAR(10);: añade columnas sin perder datos.

En el mundo real casi nunca te dedicas a «tirar» tablas: se evoluciona el esquema, tema que retomarás en el curso de SQL con las migraciones.

Ejercicio

  1. Crea la tabla usuarios con id, nombre, email único, fecha_nacimiento no nula y un campo booleano verificado con valor por defecto.
  2. Añade una columna bio TEXT con ALTER TABLE.
  3. Escribe la restricción CHECK que impida edades negativas en una columna edad INT.

Resumen

  • CREATE TABLE define columnas, tipos y restricciones.
  • Elegir el tipo correcto evita errores de datos.
  • Las restricciones (PRIMARY KEY, UNIQUE, NOT NULL, CHECK) protegen la integridad.
  • La clave foránea conecta tablas y asegura las referencias.
  • ALTER TABLE evoluciona esquemas sin perder la información.
