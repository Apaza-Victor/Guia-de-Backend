¿Qué es una base de datos?

🌱 Principiante 8 min Bases de Datos Módulo 1 · Fundamentos

Introducción

Piensa en un aeropuerto. Todos los vuelos, pasajeros, puertas de embarque y horarios están registrados en algún lugar. Si esa información viviera solo en la mente de una persona, el aeropuerto se paralizaría en cuanto esa persona pidiera un día libre. En las aplicaciones ocurre igual: cada «me gusta», cada pedido, cada mensaje necesita guardarse en un lugar donde se pueda leer, actualizar y eliminar de forma ordenada y segura. Ese lugar es una base de datos.

Una base de datos es una colección organizada de información relacionada, almacenada de forma persistente (no se pierde al apagar el servidor) y diseñada para ser consultada de manera eficiente por muchos usuarios a la vez.

El problema que resuelve

Sin una base de datos, guardarías los datos en archivos de texto o en memoria dentro del proceso del servidor. Eso funcionaría hasta que:

  • El servidor se reinicie y pierda todo lo que estaba en memoria.
  • Dos usuarios escriban el mismo archivo a la vez y se pisen los cambios.
  • Necesites buscar el pedido número 4.000.000 entre miles de archivos.
  • Quieras responder en milisegundos con datos que relacionan usuarios y pedidos.

Una base de datos resuelve estos cuatro problemas: persistencia, concurrencia, búsqueda rápida y relaciones.

Base de datos vs hoja de cálculo

La forma más fácil de imaginar una base de datos relacional es pensar en una hoja de cálculo con varias pestañas. Cada pestaña es una tabla, cada fila es un registro y cada columna es un campo. Por ejemplo, la pestaña clientes:

La diferencia clave frente a Excel: una base de datos controla la estructura y las reglas. No puedes poner un texto donde debía haber una fecha, no puedes repetir dos veces la misma identificación, y miles de personas pueden trabajar sobre los mismos datos al mismo tiempo sin romper nada.

¿Un solo tipo de base de datos?

Existen dos grandes familias:

  • Relacionales (SQL): organizan los datos en tablas conectadas entre sí por claves. Ejemplos: MySQL, PostgreSQL, SQLite. Son el estándar cuando los datos tienen relaciones claras, como clientes, pedidos y productos.
  • NoSQL: guardan los datos en documentos, pares clave-valor o grafos, pensados para flexibilidad o escala masiva. Ejemplos: MongoDB, Redis, Cassandra. Los verás en el módulo 7.

La gran mayoría de aplicaciones backend del mundo usan bases relacionales, por eso el curso empieza por ellas.

Ejercicio

  1. Elige una aplicación que uses a diario (banco, red social, delivery) y escribe 3 ejemplos de datos que tenga que guardar en una base de datos.
  2. Para uno de esos ejemplos, arma en papel una tabla con 5 filas y 4 columnas tal y como se vería guardada.
  3. Responde: ¿qué pasaría con tu carrito de compras si la tienda guardara sus datos solo en la memoria del servidor y este se reiniciara?

Resumen

  • Una base de datos es una colección organizada y persistente de información relacionada.
  • Resuelve persistencia, concurrencia, búsqueda rápida y relaciones entre datos.
  • En una base relacional, los datos se organizan en tablas, registros y columnas.
  • Las familias principales son SQL (relacional) y NoSQL.
  • Es la memoria de largo plazo de cualquier aplicación.
