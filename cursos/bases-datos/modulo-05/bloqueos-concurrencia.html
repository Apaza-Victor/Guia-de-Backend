Bloqueos y concurrencia

🌱 Principiante 11 min Bases de Datos Módulo 5 · Transacciones y concurrencia

Introducción

Cuando miles de usuarios hacen peticiones a la vez, decenas de transacciones corren en paralelo. Sin control, leen y escriben los mismos datos y se pisan. Los bloqueos (locks) son el mecanismo que ordena esa pelea por los datos.

Tipos de bloqueo

  • Compartido (S-lock): para leer. Varias transacciones pueden leer la misma fila a la vez.
  • Exclusivo (X-lock): para escribir. Solo una transacción puede tocar la fila; las demás esperan.

Un SELECT ... FOR UPDATE toma un bloqueo exclusivo «proactivo»: reservas la fila antes de modificarla, evitando que otra la cambie entre tu lectura y tu escritura.

La carrera crítica

El FOR UPDATE hace que la segunda transacción espere hasta que la primera confirme o deshaga. Problema resuelto: sin overbooking.

El deadlock (abrazo mortal)

Dos transacciones se bloquean mutuamente: A espera algo que bloqueó B, y B espera algo que bloqueó A. Ninguna puede avanzar → el motor detecta el ciclo, deshace una de ellas y la otra continúa:

Regla práctica para reducirlos: acceder a los recursos siempre en el mismo orden (primero la fila menor, luego la mayor).

Consejos para el backend

  • Mantén transacciones cortas: menos bloqueo, más concurrencia.
  • No hagas peticiones HTTP ni esperas dentro de una transacción.
  • Controla errores 1213 (deadlock): reintenta la operación.
  • Usa FOR UPDATE solo donde de verdad hay carrera (stock, saldos).

Ejercicio

  1. Simula con dos sesiones el problema del stock compartido y su solución con FOR UPDATE.
  2. Provoca un deadlock con dos sesiones y observa el error y el rollback del motor.
  3. Investiga qué es el bloqueo a nivel de tabla vs a nivel de fila en tu motor de BD.

Resumen

  • Locks compartidos para lecturas; exclusivos para escrituras.
  • SELECT ... FOR UPDATE reserva una fila ante carreras críticas.
  • Los deadlocks se resuelven deshaciendo una transacción.
  • Ordenar el acceso a recursos evita el abrazo mortal.
  • Transacciones cortas = mayor concurrencia.
