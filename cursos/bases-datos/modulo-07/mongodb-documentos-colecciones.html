MongoDB: documentos y colecciones

🌱 Principiante 11 min Bases de Datos Módulo 7 · NoSQL

Introducción

MongoDB guarda datos como documentos BSON (JSON binario) dentro de colecciones. En vez de filas con columnas fijas, cada documento es un objeto completo, y en vez de esquema rígido, cada documento puede tener su propia forma.

La unidad: el documento

El _id lo genera MongoDB automáticamente y es el identificador único del documento. Los arrays y los objetos anidados son tipos nativos: el mundo real cabe dentro de un documento.

Colecciones, el equivalente a «tablas»

Beneficios para el backend

  • Sin migraciones de esquema: agregas un campo al objeto de tu API y listo.
  • Modelado por uso: decides si anidar (embeder) o referenciar según cómo leas los datos.
  • Idioma común: JSON es el idioma de las APIs; el documento llega casi «listo para enviar».

Cuidados con la flexibilidad

  • Sin restricciones, los datos mal formados entran sin avisar: hay que validarlos en la API.
  • No hay JOIN: los datos se diseñan «para la consulta» y a veces se duplican (denormalización consciente).
  • Documentos desmesurados (campos que crecen sin límite) degradan el rendimiento.

Ejercicio

  1. Diseña el documento «producto» de una tienda online: incluye precio, variantes y stock.
  2. Compara ese documento con el mismo modelo en tablas relacionales (¿cuántas tablas serían?).
  3. Anota un caso donde embederías y otro donde referenciarías.

Resumen

  • MongoDB guarda documentos BSON en colecciones.
  • _id identifica cada documento de forma única.
  • El esquema es flexible: cada documento puede diferir.
  • Embedding vs referencia reemplaza al JOIN relacional.
  • La validación pasa a la aplicación.
