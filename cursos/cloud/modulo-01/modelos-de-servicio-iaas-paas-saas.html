Modelos de servicio: IaaS, PaaS, SaaS

🔥 Avanzado 12 min Cloud para Backend Módulo 1 · Fundamentos

La pregunta: ¿quién gestiona qué?

En la nube hay una escala: desde "te doy las máquinas y tú te encargas del resto" (IaaS) hasta "te doy la aplicación lista" (SaaS). La decisión es cuánta responsabilidad operativa delegas al proveedor a cambio de control.

IaaS: infraestructura como servicio

El proveedor entrega recursos básicos: VMs, almacenamiento, redes, firewalls. Todo lo demás (sistema operativo, runtime, dependencias, tu código) es tuyo.

  • Control total: configuras el kernel, el SO, los puertos, todo.
  • Responsabilidad total: patchear, asegurar, escalar y mantener es tu trabajo.
  • Ejemplos: AWS EC2, Google Compute Engine, Azure Virtual Machines. Un VPS es IaaS.

Ideal cuando necesitas raíz, software específico o cumplimiento personalizado. La contrapartida: horas de operación en cada máquina.

PaaS: plataforma como servicio

El proveedor añade la plataforma: SO parcheado, runtime (Python/Node/Java), escalado, load balancing. Tú subes tu código o imagen y listo.

  • Olvídate del sistema: nada de parches de seguridad ni configurar Nginx.
  • Escalado automático incluido en muchos casos.
  • Ejemplos: AWS Elastic Beanstalk / App Runner, Google Cloud Run, Azure App Service; IaaS gestionado como RDS también es PaaS.

La via más común para APIs de producción: despliegas tu contenedor y la plataforma lo sirve y escala.

SaaS: software como servicio

El cape es la aplicación completa, lista para usar por internet. No despliegas nada; pagas por usarla.

  • Cero desarrollo: el producto ya está terminado y gestionado.
  • Ejemplos: Gmail, Google Drive, Slack, Notion, y servicios internos como Sentry o Supabase (para un usuario final) funcionan como SaaS.

Un backendista consume SaaS todo el tiempo: monitoreo, CRM, correo, analytics. No lo despliegas, lo integras.

Comparativa de responsabilidad

La regla de oro: usa la capa más gestionada que cubra tu necesidad. Para una API, PaaS suele ser el equilibrio justo entre control y ahorro.

Ejercicio

  1. Clasifica estos servicios: Gmail, la VM de tu API, RDS, Google Drive, Cloud Run, tu propio laptop.
  2. ¿Quién patchea el SO en cada modelo? ¿Y quién responde el soporte de tu app?
  3. Elige el modelo para desplegar una API de pagos con requisitos de auditoría. Justifica.

Resumen

  • IaaS = máquinas crudas; tú gestionas hasta el SO.
  • PaaS = plataforma lista; subes tu código y olvidas el sistema.
  • SaaS = aplicación terminada que solo usas.
  • Elige la capa más gestionada que aún te dé el control que necesitas.
