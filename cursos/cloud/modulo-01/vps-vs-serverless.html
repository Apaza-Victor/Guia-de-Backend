VPS vs Serverless

🔥 Avanzado 12 min Cloud para Backend Módulo 1 · Fundamentos

Dos mentalidades para servir código

Hay dos formas extremas de ejecutar tu Backend. El VPS (o VM): una máquina virtual siempre encendida que pagas por mes. El serverless: funciones que el proveedor ejecuta a demanda, cobrándote por milisegundos reales de uso. La elección cambia tu arquitectura entera.

El caso del VPS

  • Control total: SO, runtime, daemons, memoria, hilos: todo tuyo.
  • Coste predecible: pagas algo fijo, suba o baje el tráfico.
  • Conexiones persistentes: ideal para WebSockets, tareas largas, colas.
  • Trabajo: configurar, patchear, escalar y monitorizar es tuyo.

Cuando el tráfico es estable o la carga es continua, el VPS suele salir más barato y es más simple de razonar.

El caso serverless

  • Escalado automático: de 0 a miles de ejecuciones sin tocar nada.
  • Pago por uso real: nada de pagar una VM ociosa a las 3 AM.
  • Cero servidores que mantener: el proveedor patchea y dimensiona por ti.
  • Cold starts: la primera petición tras un periodo de inactividad puede tardar 100 ms-2 s (las funciones "arrancan" al ser llamadas).

Pago ejemplo: 1M invocaciones × 200 ms de Lambda ≈ pocas decenas de USD al mes, mientras una VM costaría algo fijo aunque no la uses.

Matriz de decisión

La realidad: se mezclan

Las arquitecturas modernas no eligen una sola: el APY crítico en VPS o contenedores, las funciones de evento en serverless (thumbnails, webhooks, limpieza). Incluso serverless puede correr contenedores (Cloud Run, App Runner) cuando una función no alcanza.

Ejercicio

  1. Clasifica estas cargas: API de chat con WebSockets, redimensionado de imágenes por evento, e-commerce con picos de campaña, job nocturno de 40 min.
  2. Calcula cuál pagarías ocioso la mitad del tiempo: una VM de $12 o funciones por uso.
  3. Describe un sistema que use ambos a la vez y por qué.

Resumen

  • VPS: control total y coste fijo; serverless: cero operación y pago por uso.
  • El cold start es el precio de la escala a 0.
  • Tráfico continuo → VM/contenedor; picos o eventos → serverless.
  • Las arquitecturas reales mezclan ambos según cada pieza.
