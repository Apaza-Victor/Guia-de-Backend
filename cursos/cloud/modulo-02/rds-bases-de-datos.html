RDS: bases de datos gestionadas

🔥 Avanzado 11 min Cloud para Backend Módulo 2 · AWS

Postgres o MySQL sin el dolor del servidor

Instalar, parchear, hacer backups y restaurar una base es trabajo clásico de operaciones. RDS lo hace por ti: eliges el motor (PostgreSQL, MySQL, MariaDB, SQL Server, Oracle), el tamaño, y AWS gestiona el sistema operativo, el almacenamiento y las copias. Es el PaaS para datos de AWS.

Crear la instancia

Seguridad de serie: --no-publicly-accessible hace que la base solo se vea desde la VPC (ideal: tu API la alcanza por IP interna, y el público nunca).

El security group de la DB solo admite conexiones desde el security group de tu API: nadie de internet puede tocar Postgres.

Backups, réplicas y alta disponibilidad

  • Backups automáticos diarios (el retention del comando) + restauración a un punto en el tiempo.
  • Multi-AZ: una réplica sincrónica en otra zona; si la principal falla, conmutación automática.
  • Read replicas: réplicas asíncronas para leer (el tráfico de solo lectura) y descargar la principal.

¿Y si tu proyecto es pequeño?

RDS tiene un mínimo de costo (~$15-30/mes). Para aprendizaje, tests o MVPs low-cost hay opciones serverless (Aurora Serverless, por uso) o gestionar Postgres en la propia EC2. Pero una base "manejada a mano" no te da backups ni failover: esa responsabilidad vuelve a tu mesa.

Ejercicio

  1. Crea una DB Postgres db.t3.micro en el tier gratuito sin acceso público y conusuar fuera de la VPC para que te la bloquee.
  2. Conecta tu API en una EC2 de la misma VPC usando DATABASE_URL.
  3. Haz un backup manual con aws rds create-db-snapshot y restaura una copia.

Resumen

  • RDS = base gestionada: OS, parches y backups los hace AWS.
  • La DB sin acceso público + security group internos mantiene los datos fuera del internet.
  • Multi-AZ da alta disponibilidad; read replicas escalan lecturas.
  • Los snapshots permiten restaurar en minutos.
