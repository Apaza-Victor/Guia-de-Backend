IAM y seguridad

🔥 Avanzado 9 min Cloud para Backend Módulo 2 · AWS

Quién puede hacer qué

IAM (Identity and Access Management) es el sistema de permisos de AWS: quién (identidad) puede hacer qué (acción) sobre cuál recurso. La mayoría de los hackeos de cuentas AWS vienen de credenciales con demasiado poder. IAM te permite dormir tranquilo con el menor privilegio.

Las tres piezas: usuarios, grupos, políticas

  • Usuarios IAM: identidades para personas o máquinas, con una Access Key (ID + secret) para la CLI.
  • Grupos: agrupan usuarios (ej. devs, ops) y sus permisos se heredan.
  • Políticas: JSON que define acciones y recursos permitidos/denegados.

Regla inquebrantable: jamás operes con la cuenta raíz. Se crea un usuario con sus permisos y con MFA obligatorio.

Una política de menor privilegio

Solo lee/escribe en el bucket de la API y solo desde una IP. Esa es la mentalidad: acciones específicas, recursos específicos, condiciones.

Roles: permisos para servicios, no para personas

Los roles IAM otorgan permisos a un servicio (EC2, Lambda) de forma temporal y segura. Tu Lambda puede leer S3 sin que guardes ninguna Access Key en el código (pésima práctica): el rol lo hace.

Las credenciales temporales se renuevan solas: es más seguro que andar guardando secretos.

Checklist de seguridad mínimo

  • MFA activado en la cuenta raíz y en los usuarios con permisos altos.
  • Cero Access Keys en código o archivos de configuración del repo.
  • Políticas con el menor alcance posible (acciones + recursos + condiciones).
  • SSH y puertos de bases cerrados a internet con security groups.
  • Revisión periódica de qué permisos tienen los usuarios inactivos (delétalos).

Ejercicio

  1. Crea un usuario IAM con acceso solo a S3 de un bucket (y nada más).
  2. Genera sus Access Keys y comprueba en la CLI que ec2 describe-instances falla.
  3. Crea un rol para Lambda y pásalo a una de tus funciones que lee S3 sin usarse ninguna Key.

Resumen

  • IAM define quién puede hacer qué: usuarios, grupos, roles y políticas.
  • El menor privilegio es la norma: acciones y recursos mínimos.
  • Los roles dan permisos temporales a servicios sin exponer secretos.
  • MFA + cero roots en operación + claves fuera del código = cuenta sana.
