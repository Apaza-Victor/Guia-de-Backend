Lambda: funciones serverless

🔥 Avanzado 12 min Cloud para Backend Módulo 2 · AWS

Código sin servidores

AWS Lambda ejecuta tu código bajo demanda sin que veas una sola máquina. Escribes una función, la conectas a un evento (HTTP, archivo en S3, mensaje en SQS, cron) y AWS la corre, la escala y cobra solo por milisegundos de uso. Es el corazón del serverless de AWS.

La forma de una Lambda

Se empaqueta en un zip (o un contenedor) y se sube junto con sus dependencias. Los límites importan: hasta 15 min de ejecución, 10 GB de memoria, y el estado local (archivos temporales) no persiste entre invocaciones.

Eventos que te interesan como Backend

  • API Gateway: convierte HTTP en invocaciones. Tu "endpoint serverless".
  • S3: al subir un objeto, se dispara una función (thumbnail, AV de virus).
  • SQS: cada mensaje de la cola se procesa con una Lambda (consumidor de eventos).
  • EventBridge / cron: trabajos periódicos (limpieza, reportes).

API serverless con Lambda + API Gateway

El patrón dorado: Lambda firma y el cliente sube directo a S3. Tu función nunca maneja el archivo binario, y el tiempo de ejecución se dispara solo con metadatos.

Despliegue con la CLI

Cuándo sí y cuándo no

  • Sí: picos imprevisibles, funciones de evento, prototipos, procesos cortos y desacoplados.
  • No: conexiones persistentes, tareas > 15 min, tecnologías no soportadas, o cargas constantes que volverían más caro el "por invocación" que una VM estable.

Ejercicio

  1. Escribe una Lambda "hola" en Python, unzipala y sube con create-function.
  2. Conéctala a un API Gateway y llama tu endpoint con curl.
  3. Crea un trigger de S3 que imprima el nombre de cada objeto subido.

Resumen

  • Lambda ejecuta código por evento, escala solo y se paga por uso.
  • API Gateway, S3, SQS y EventBridge son sus disparadores típicos.
  • Límites: 15 min, memoria configurable, sin estado persistente.
  • Perfecta para eventos y picos; mala para cargas constantes o conexiones largas.
