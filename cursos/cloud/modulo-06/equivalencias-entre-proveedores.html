Equivalencias entre AWS, GCP y Azure

🔥 Avanzado 11 min Cloud para Backend Módulo 6 · Costos y Estrategia

Un mismo platillo, tres recetas

AWS, GCP y Azure compiten por resolver lo mismo. La buena noticia para el backender: si dominas los conceptos en uno, el siguiente es "cambiar los nombres". Esta lección es la tabla de traducción que convierte tu experiencia en portátil.

La tabla de equivalencias

Las diferencias que importan

  • Modelos de identidad: AWS usa IAM puro; Azure apuesta por Azure AD / Entra ID y está casado con el ecosistema Microsoft (mejor si tu empresa ya usa Office 365).
  • Déploys: GCP brilla con contenedores (Cloud Run despliega una imagen sin que armes orquestación manual). Azure se integra fuerte con CI/CD de Azure DevOps y GitHub.
  • Serverless: Lambda es de las más maduras; Cloud Functions es sencilla; Azure Functions permite varios lenguajes y binding con servicios de Microsoft.
  • Precios: difieren según servicio y región; los precios "por invocación" son por momentos distintos entre proveedores.

Cómo elegir proveedor

  • Familiaridad del equipo: la curva de aprendizaje real pesa más que la propaganda. Si el equipo ya conoce AWS, no migres "porque es más barato en papel".
  • Integración existente: empresa con Microsoft = Azure; móviles + analítica de Firebase = GCP; comunidad y servicios vastos = AWS.
  • Servicios gestionados específicos: algunos casos solo están en una nube (DynamoDB vs Firestore vs Cosmos: elige por modelo y no por marca).
  • Costo total: si no es un requisito legal, compara a 3 años incluyendo el esfuerzo de operar y de salida (“exit” es difícil en cualquier lado).

¿Y el multi-cloud?

Usar dos nubes a la vez añade complejidad (redes, IAM, y duplicar operación). Solo compensa cuando hay un requisito fuerte (disponibilidad entre proveedores, cumplimiento, o equipos separados). Para el 99% de los proyectos, una nube bien usada supera a dos a medias.

Ejercicio

  1. Traduce tu arquitectura mental (VM + S3 + Postgres + Lambda) a los nombres de GCP y Azure.
  2. Investiga un servicio exclusivo de cada nube y decide cuál usarías.
  3. Escribe 3 criterios que usarías para elegir proveedor en un proyecto nuevo.

Resumen

  • Los tres grandes resuelven lo mismo con nombres distintos: conoce los conceptos, los nombres viajan.
  • Cada nube tiene sesgo: Azure-Microsoft, GCP-contenedores, AWS-catálogo.
  • La elección se basa en equipo, integración existente y costo total, no en marca.
  • El multi-cloud es una excepción justificada, no una moda global.
