Introducción al despliegue continuo

🔥 Avanzado 9 min DevOps para Backend Módulo 5 · Despliegue Continuo

¿Qué es el despliegue continuo?

La integración continua (CI) verifica que el código funciona; el despliegue continuo (CD) lo lleva a los entornos automáticamente. Cada cambio que pasa las pruebas se publica en producción sin intervención humana, y la CD agrega además el cómo: servir las versiones sin interrumpir a los usuarios y poder volver atrás.

Entrega continua vs despliegue continuo

Suena parecido pero no es lo mismo:

  • Entrega continua: cada cambio verificado queda listo para desplegar, pero alguien pulsa el botón en producción.
  • Despliegue continuo: nadie pulsa el botón; el pipeline publica automáticamente, y luego se valida con monitoreo.

Para una API que escala, el despliegue continuo reduce el tiempo de ciclo (de "idea a producción") y elimina el error humano del despliegue manual.

El pipeline completo de una API

Cada etapa termina antes de que empiece la siguiente: si el test falla, jamás se llega al paso 4. Esta secuencia reproducible es la base de todo lo demás en este módulo.

El role de los entornos

En la práctica no vas de dev directo a prod. Los entornos habituales:

  • Development: auto-deploy en cada push, datos simulados.
  • Staging: réplica de producción con datos de prueba; aquí se ensaya el deploy.
  • Producción: público final; se alimenta de la rama main tras pasar staging.

Cada entorno es un deployment (un target en GitHub) con sus secrets independientes, lo que permite que los permisos de despliegue sean más estrictos en producción.

Ejercicio

  1. Dibuja el pipeline CI→CD de tu proyecto actual y señala dónde interviene un humano hoy.
  2. Identifica qué partes podrían automatizarse y qué riesgo correrías al automatizarlas.
  3. Escribe en dos líneas la diferencia entre entrega continua y despliegue continuo con tus palabras.

Resumen

  • CI valida; CD publica. El despliegue continuo automatiza hasta producción.
  • La entrega continua deja el código listo; el despliegue continuo no necesita botón.
  • El pipeline sigue una secuencia reproducible: construir, subir, publicar, validar.
  • Los entornos (dev → staging → prod) separan pruebas de riesgo real.
