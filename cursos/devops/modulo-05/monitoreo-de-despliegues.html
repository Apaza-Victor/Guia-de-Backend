Monitoreo de despliegues

🔥 Avanzado 12 min DevOps para Backend Módulo 5 · Despliegue Continuo

Ver para creer

Un despliegue no termina con parece que anda. Sin monitoreo no sabes si la nueva versión degrada la latencia, produce 500 ocultos o agota la memoria. El monitoreo convierte un "deploy exitoso" en una serie de señales observables.

Los cuatro pilares: métricas, logs, trazas, alertas

  • Métricas: números agregados en el tiempo: requests/s, latencia (p50/p95/p99), tasa de error, uso de CPU/RAM, threads.
  • Logs: eventos individuales con contexto, útiles para buscar el porqué de una anomalía.
  • Trazas: el recorrido de una petición a través de los servicios (conteo de saltos).
  • Alertas: reglas que disparan notificaciones cuando una métrica cruza un umbral.

El endpoint /health

Todo servicio debe exponer un /health (o /ready) que valide partes importantes y responda 200 u otro código:

El orquestador y Nginx lo consultan periódicamente. Es la primera línea de detección de un deploy roto.

Un stack mínimo viable

  • Prometheus: recopila métricas desde un endpoint /metrics de la API (p. ej. con prometheus-client): requests, latencias, errores, versiones desplegadas.
  • Grafana: dashboards visuales sobre Prometheus.
  • Logs con estructura: salida JSON con timestamp, nivel, request_id; journalctl o un agregador como Loki/ELK.
  • Alertas: umbrales como "tasa de 5xx > 5% durante 5 min" o "latencia p95 > 800 ms".

Detectar un deploy defectuoso

Compara las métricas antes y después del despliegue. Señales típicas de problema:

  • La tasa de errores 5xx sube abruptamente justo tras el cambio.
  • La latencia p99 se dispara (nueva query lenta, cache fría).
  • El uso de memoria crece sin freno (leak introducido).
  • El healthcheck responde 503 en algunas instancias.

Con la alerta en el canal correcto (Slack, email, Telegram), el equipo actúa minutos antes de que los usuarios lo noten.

Ejercicio

  1. Agrega un endpoint /health a tu API que valide la conexión a la base de datos.
  2. Añade métricas básicas de requests y errores (por ejemplo con prometheus-client).
  3. Define una alerta: tasa de 5xx > 5% durante 5 minutos. ¿Dónde la activarías?

Resumen

  • Métricas, logs, trazas y alertas forman la observabilidad del deploy.
  • El endpoint /health detecta instancias rotas de inmediato.
  • Prometheus + Grafana + logs estructurados es un stack sólido y gratis.
  • Comparar métricas antes/después del deploy revela regresiones.
