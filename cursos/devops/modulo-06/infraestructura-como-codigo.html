Infraestructura como código

🔥 Avanzado 14 min DevOps para Backend Módulo 6 · DevOps en el Backend

Manual vs reproducible

"Configuré esto a mano, no lo toques" es una frase que mata proyectos. La infraestructura como código (IaC) describe tu servidor (paquetes, servicios, configs) en archivos versionados; cualquier máquina se construye ejecutando esos archivos. Se acabaron los servidores mutantes e irrepetibles.

  • Versionas la infraestructura junto al código.
  • Reproduces un entorno idéntico en segundos.
  • Las mismas herramientas sirven para auditar qué hay instalado.

Comenzar simple: scripts idempotentes

Un script idempotente se puede ejecutar mil veces con el mismo resultado. La técnica mínima: solo actuar si falta el paquete o la config.

Con if por cada componente el script es seguro de repetir: el núcleo de toda herramienta IaC.

Contenedores: la imagen como código

Con Docker, la infraestructura se convierte en una imagen inmutable descrita por un Dockerfile. Nada de "parece que le cambió la config": la imagen es el estado exacto.

Levantar todo el entorno: docker compose up -d. Recién ahí notas el superpoder de IaC.

Herramientas dedicadas

  • Ansible: scripts YAML sin agente; perfecto para configurar VPS y desplegar apps.
  • Terraform: crea la infraestructura en la nube (instancias, DBs, redes) declarativamente.
  • Kubernetes/Helm: orquestación de contenedores con despliegues declarativos.

Basta dominar scripts idempotentes + Docker para un proyecto personal; Ansible y Terraform llegan cuando hay más servidores que manos.

Buenas prácticas

  • Todo lo que se configure ne servidor manualmente es deuda; anótalo y automatízalo.
  • Los archivos de config van en el repo; los secretos no.
  • Prueba en una máquina vacía: si el script funciona de cero, funciona en el desastre.
  • Solicita auditorías de qué versión corre hoy: IaC te da ese historial gratis.

Ejercicio

  1. Escribe un script idempotente que instale Nginx y copie un server block si falta.
  2. Empaqueta tu API en un Dockerfile y arrándala con docker compose junto a Postgres.
  3. Ejecuta tu script dos veces seguidas y demuestra que el resultado no cambia.

Resumen

  • IaC describe el servidor en archivos versionados, reproducibles.
  • Los scripts idempotentes son la puerta de entrada, sin herramientas extra.
  • Docker convierte el estado en imágenes inmutables y fáciles de replicar.
  • Ansible/Terraform/Kubernetes escalan cuando el entorno crece.
