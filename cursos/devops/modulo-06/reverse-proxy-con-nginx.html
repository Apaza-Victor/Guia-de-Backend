Reverse proxy con Nginx

🔥 Avanzado 13 min DevOps para Backend Módulo 6 · DevOps en el Backend

¿Qué es un reverse proxy?

Un reverse proxy es el portero de tu infraestructura: recibe todas las peticiones por fuera (puerto 80/443) y las entrega a los servicios internos. Tu API escucha en un puerto privado (p. ej. 8000) y jamás se expone directamente a internet.

  • Toda la seguridad por fuera se concentra en una sola entrada.
  • Puedes servir varias APIs en el mismo dominio con rutas distintas.
  • Nginx añade al pasito la compresión, TLS y balances.

Configuración mínima

Los proxy_set_header son clave: tu API necesita saber qué host, qué IP real y si la conexión era HTTP o HTTPS. Si no se reenvían, las apps no distinguen a los usuarios ni generan URLs correctas.

Servir varias apps en un dominio

Con proxy_pass .../api/ se reescribe la ruta: la petición /api/usuarios llega al Backend como /usuarios.

Límites y tiempo de espera

Por defecto Nginx deja subir 1 MB y espera 60 s. Para una API que recibe archivos o tarda más, ajusta:

Reducir client_max_body_size por defecto es una defensa barata contra requests gigantes.

Balanceo entre varias instancias

Esto es un load balancer hecho a mano: reparte el tráfico y, si una instancia cae, Nginx redirige a las sanas.

Ejercicio

  1. Levanta una API local en el puerto 8000 y configura Nginx para servirla en un dominio de prueba.
  2. Añade un /api/ que reescriba la ruta y verifica la reescritura con los logs de Nginx.
  3. Lanza dos instancias y crea un upstream con least_conn; verifica que reparta peticiones.

Resumen

  • El reverse proxy concentra el tráfico y protege a los servicios internos.
  • Los headers X-Forwarded-* llevan la IP y el protocolo reales al Backend.
  • Una ubicación /api/ permite servir frontend y Backend en el mismo dominio.
  • Con un upstream Nginx también balancea y reintenta.
