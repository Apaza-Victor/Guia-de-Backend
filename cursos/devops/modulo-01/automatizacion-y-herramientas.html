Automatización y herramientas

🔥 Avanzado 8 min DevOps para Backend Módulo 1 · Introducción a DevOps

Introducción

Existen cientos de herramientas DevOps. En lugar de memorizarlas, conviene organizarlas por categoría: cada categoría automatiza una parte del ciclo de vida. Elegir una herramienta por categoría y aprenderla bien rinde más que probar diez superficialmente.

Las categorías esenciales

  • Control de versiones: Git, la base de todo. Código, config y documentos versionados.
  • CI/CD: GitHub Actions, GitLab CI, Jenkins, CircleCI. Automatizan build, test y deploy.
  • Contenedores: Docker (empaquetar) y Kubernetes (orquestar). Reproducibilidad total.
  • Configuración e infraestructura: Ansible, Terraform. "Infraestructura como código".
  • Observabilidad: Prometheus + Grafana, ELK, Sentry. Métricas, logs y errores.
  • Mensajería y automatización: Slack/Teams, scripts de SSH, webhooks que disparan acciones.

La regla de oro: automatizar lo repetitivo

Un buen criterio para decidir qué automatizar es simple: si hiciste lo mismo dos veces, la tercera debe hacerlo una máquina. Se aplica a martillazos manuales como:

No todo se automatiza el primer día. La estrategia recomendada es automatizar por etapas: 1) build y tests, 2) despliegue a staging, 3) despliegue a producción con supervisión, 4) rollback automático. Cada etapa da confianza para la siguiente.

El idioma común: YAML

La mayoría de las herramientas de CI/CD se configuran con YAML, incluido GitHub Actions. No hace falta dominarlo todo, pero sí sus tres conceptos: clave: valor, listas (con guiones) y mapas anidados (con indentación).

El YAML es sensible a la indentación (espacios, no tabuladores). Un error de indentación rompe la sintaxis; lo verás con un marcador claro en la interfaz del pipeline.

Cómo elegir

  • Los problemas preliminares (dependencias, entornos) suelen resolverse con contenedores.
  • Los problemas de velocidad (mucho empaquetado o test lento) se resuelven con caché y paralelización en CI.
  • Los problemas de fiabilidad se resuelven con pruebas y despliegues en fases.
  • Empieza con la herramienta que ya usa tu equipo (ej. GitHub) antes de añadir más piezas.

Ejercicio

  1. Lista 5 tareas repetitivas de tu día a día y clasifica cuáles se pueden automatizar hoy.
  2. Escribe en YAML un mini-pipeline de 3 etapas para un proyecto tuyo.
  3. Elige una herramienta por categoría del ciclo de vida y, para cada una, anota qué problema te resuelve.

Resumen

  • Las herramientas DevOps se agrupan por categorías: git, CI/CD, contenedores, config y observabilidad.
  • La automatización debe dirigirse a lo repetitivo y aumentar en etapas.
  • YAML es el formato de configuración principal de la mayoría de los pipelines.
  • Empieza sencillo y amplía: automatizar el build primero, después el deploy.
