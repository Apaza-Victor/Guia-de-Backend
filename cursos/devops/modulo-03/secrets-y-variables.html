Secrets y variables

🔥 Avanzado 12 min DevOps para Backend Módulo 3 · GitHub Actions

Introducción

Los pipelines necesitan configuración: en qué rama correr, con qué credenciales conectarse al servidor, cuál es la URL de la base de datos. Meter contraseñas en el archivo YAML es un error grave porque el repositorio es compartido. Para eso existen dos mecanismos: variables (no secretas) y secrets (cifrados).

Variables vs secrets

  • Variables (vars): valores de configuración no sensibles que puedes leer en el YAML. Ejemplos: nombre del entorno, versión por defecto.
  • Secrets: valores sensibles cifrados (contraseñas, tokens, llaves SSH). Solo se escriben, nunca se muestran en logs. Se declaran en Settings → Secrets and variables → Actions.

Los secrets se definen a nivel de repositorio, de entorno o de organización. El nivel de entorno es el más seguro: permite exigir revisores antes de usarse (protections).

El token integrado: GITHUB_TOKEN

GitHub provee automáticamente un token con permisos limitados para actuar en el propio repositorio (crear issues, comentar en PR, descargar el código). Es un secreto especial:

Como en los logs no se imprime el valor, si usando el token de una API de terceros la respuesta falla, revisa primero si el secreto existe y si su permisos alcanzan.

Buenas prácticas

  • Jamás pongas credenciales en el YAML ni en código; siempre a través de secrets.
  • Rota las credenciales regularmente y al cambiar los integrantes del equipo.
  • Usa scopes mínimos: si solo se necesita publicar a Docker Hub, un token de solo escritura al paquete.
  • No imprimas secretos ni con purpose diagnóstico; GitHub los enmascara pero no los elimina del historial.
  • Usa env por entorno (staging/prod) para tener configs distintas y verificables.

Ejercicio

  1. Crea una variable ENTORNO y un secreto cualquiera de prueba en tu repositorio (Settings → Secrets and variables → Actions).
  2. Escribe un workflow que los use con ${{ vars.ENTORNO }} y ${{ secrets.NOMBRE }} y verifica que el secreto aparece enmascarado en los logs.
  3. Deja constancia por escrito de cómo evitarías filtrar un secreto en un log.

Resumen

  • Las variables son configuración visible; los secrets son credenciales cifradas.
  • Los secrets pueden vivir en repositorio, entorno u organización.
  • GITHUB_TOKEN permite actuar sobre el propio repositorio sin crear credenciales.
  • Menos permisos y rotación frecuente son las claves de la seguridad.
