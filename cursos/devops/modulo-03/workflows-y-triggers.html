Workflows y triggers

🔥 Avanzado 12 min DevOps para Backend Módulo 3 · GitHub Actions

Introducción

GitHub Actions es la plataforma de CI/CD integrada en GitHub. Todo el pipeline se describe con archivos YAML en una carpeta especial llamada .github/workflows. Cada archivo define un workflow (flujo de trabajo, la traducción de "pipeline"), y un trigger (evento) decide cuándo se ejecuta.

Estructura de un workflow

Un workflow mínimo tiene tres bloques: name (nombre visible), on (el trigger) y jobs (las tareas). Las lecciones siguientes exploran jobs y steps; aquí nos centramos en las dos primeras claves.

Archivo: .github/workflows/ci.yml. En cuanto hagas git push —o abras un pull request hacia main—, el workflow aparece en la pestaña Actions del repositorio.

Eventos (triggers) más usados

  • push: se ejecuta al hacer push a una rama o ruta.
  • pull_request: se ejecuta al abrir o actualizar una PR (ideal para CI).
  • schedule: programación estilo cron, por ejemplo revisiones nocturnas.
  • workflow_dispatch: botón manual para ejecutarlo cuando quieras.
  • release: al publicar una versión. Típico para deploy a producción.

Filtros y restricciones

Si quieres un pipeline que solo corra en pull requests y no en pushes directos, o viceversa, usa los filtros de cada evento. También puedes excluir rutas con paths-ignore para no ejecutar CI cuando cambia solo la documentación:

Contextos útiles

GitHub Actions expone contextos: objetos con información de la ejecución. Los más usados son github (repo, actor, ref), secrets (secretos) y vars (variables). Se acceden con la sintaxis ${{ ... }}.

Ejercicio

  1. Crea en tu repositorio la carpeta .github/workflows y un archivo ci.yml con dos triggers: push a main y pull_request.
  2. Haz push a una rama distinta y comprueba que el workflow NO se ejecuta por el trigger de push.
  3. Añade el trigger workflow_dispatch con un input entorno y lánzalo manualmente.

Resumen

  • Los workflows viven en .github/workflows y se escriben en YAML.
  • El trigger on define cuándo se ejecuta el pipeline.
  • Los filtros por rama y por ruta afinan cuándo corre.
  • Los contextos github, secrets y vars proveen datos a la ejecución.
