Tests y linting en CI

🔥 Avanzado 11 min DevOps para Backend Módulo 3 · GitHub Actions

Introducción

La integración continua (CI) es regla número uno de DevOps: en cada cambio, la máquina ejecuta las pruebas y verifica la calidad automáticamente. GitHub Actions la hace posible en minutos y, si falla algo, la PR no se puede fusionar: el propio GitHub puede aplicarlo con branch protection.

Workflow de CI completo

Un flujo típico para un Backend en Python: instalar dependencias, ejecutar tests, pasar el linter y reportar cobertura.

Caché: el secreto de la velocidad

Instalar dependencias cada vez hace lento el job. GitHub Actions permite cachear los paquetes según la huella del archivo de dependencias. En Python con pip se logra con cache: pip; en Node con actions/setup-node y cache: npm.

Protección de ramas

Para hacer cumplir la CI: en Settings → Branches → Add rule, exige status checks en main. Nadie podrá fusionar la PR si el job test o lint está en rojo. Ese candado es lo que separa una convención de una garantía.

  • Activando GitHub Actions sobre cambios no es suficiente: el branch protection es quien bloquea.
  • También puedes requerir revisiones de PR (p. ej. 2 aprobadores).

Salidas útiles del pipeline

  • Badges: el badge "status" de la CI se pega en el README para mostrar que el proyecto pasa verde.
  • Job summaries: con $GITHUB_STEP_SUMMARY puedes escribir un resumen visible en la página de la ejecución.
  • Notificaciones: un paso puede avisar a Slack/TM con el resultado de los tests.

Ejercicio

  1. Crea un workflow de CI que ejecute los tests de un proyecto tuyo al hacer pull_request.
  2. Añade un job de lint y activa caching de dependencias.
  3. Configura branch protection en main y verifica que una PR con un test rojo no se puede fusionar.

Resumen

  • La CI ejecuta tests y calidad en cada cambio, con problemas detectados al instante.
  • El caching de dependencias reduce drásticamente el tiempo del pipeline.
  • El branch protection convierte la CI en una garantía real.
  • Badges y resúmenes hacen visible el estado del proyecto.
