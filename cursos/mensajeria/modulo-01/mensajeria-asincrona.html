Mensajería asíncrona

🚀 Avanzado 9 min Mensajería Backend Módulo 1 · Fundamentos

Introducción

En una aplicación típica, cuando un usuario hace clic en «Comprar», el servidor debe validar el carrito, cobrar, actualizar inventario y enviar un correo. Si todo se hace dentro de la misma petición HTTP, el cliente espera cada operación, y el servicio de correo (lento, externo) convierte una operación de 50 ms en una de 3 segundos.

La mensajería asíncrona cambia ese modelo: en lugar de bloquearse llamando a otros servicios, el productor escribe un mensaje en una cola y responde inmediatamente. El trabajo de verdad lo hace después un consumidor, en el momento en que pueda. El resultado es un backend que no se detiene por la lentitud de sus dependencias.

Productores, colas y consumidores

Toda mensajería asíncrona se apoya en tres actores:

  • Productor: el servicio que crea el mensaje. No conoce quién lo va a procesar.
  • Cola: el búfer intermedio que guarda mensajes hasta que alguien los consuma. Es durable: sobrevive a reinicios.
  • Consumidor: el servicio que toma los mensajes uno a uno y ejecuta la tarea. Puede haber muchos consumidores compartiendo una cola.

Este trío produce dos beneficios enormes. Primero, desacople: productor y consumidor se comunican con un mensaje, no con una llamada directa, y pueden evolucionar (o fallar) de forma independiente. Segundo, resiliencia: si el consumidor está caído, los mensajes esperan en la cola sin perderse.

Comunicación síncrona vs asíncrona

La tabla rápida para decidir cuándo usar mensajería:

  • Síncrono (HTTP): necesitas la respuesta ya — leer un perfil, validar un token, consultar saldo. El cliente espera y recibe un resultado.
  • Asíncrono (cola): la operación puede completarse en segundo plano — enviar correo, generar imágenes, indexar datos, notificar eventos. El cliente recibe inmediatamente una confirmación y ya.

Regla práctica: si el cliente necesita el resultado de la operación para seguir, es síncrono. Si solo necesita saber que «se encargaron de ello», es asíncrono.

Ejemplo: enviar un correo sin bloquear

Observa la diferencia. Sin mensajería, el endpoint de registro llama a un servicio de correo dentro de la petición y el usuario espera:

app.post('/register', async (req, res) => {
  const usuario = await db.insert('usuarios', req.body);

  // Bloquea la respuesta mientras un servicio lento (SMTP) trabaja
  await emailService.enviarBienvenida(usuario.email, usuario.nombre);

  // El cliente solo recibe la respuesta 2-4 segundos después
  res.status(201).json(usuario);
});

Con una cola, el endpoint publica un mensaje y responde en milisegundos. El envío del correo ocurre después, en otro proceso:

app.post('/register', async (req, res) => {
  const usuario = await db.insert('usuarios', req.body);

  // Publicar en la cola 'emails' y responder al instante
  await cola.publish('emails', {
    tipo: 'bienvenida',
    destinatario: usuario.email,
    nombre: usuario.nombre
  });

  res.status(201).json(usuario);
});

// Otro proceso, a su propio ritmo, procesa la cola
cola.consume('emails', async (msg) => {
  await emailService.enviarBienvenida(msg.destinatario, msg.nombre);
});

Si el servicio de correo cae, los mensajes quedan encolados y se procesan cuando vuelve. El usuario no nota nada.

Trabajos en segundo plano: el caso más común

Las colas también sirven para mover trabajo pesado fuera de la petición web. Generar un PDF, transcodificar un vídeo o procesar archivos CSV son candidatas perfectas:

# Un CLI lanza un trabajo a la cola
curl -X POST http://api/productos/importar \
  -H "Content-Type: application/json" \
  -d '{"archivo": "catalogo_2026.csv"}'

# La API responde 202 Accepted al vuelo
# Un worker aparte consume el archivo línea por línea

python worker.py --queue importaciones
# Linea 1/12000: producto sku-001 insertado
# Linea 2/12000: producto sku-002 insertado
# ...

El cliente recibe un 202 Accepted (aceptado, procesando) y puede consultar el estado del trabajo si el sistema lo expone. El procesamiento pesado nunca toca el hilo de la petición.

Ejercicio

  1. Lista cinco operaciones de tu backend actual e identifica cuáles dependen de servicios lentos o externos (correo, SMS, pago, notificaciones, reportes).
  2. Para cada una, decide: ¿el cliente necesita el resultado síncrono o basta con una confirmación? Las segundas van a una cola.
  3. Amplía el ejemplo: ¿qué pasaría con los mensajes de «bienvenida» si el productor se cae justo después de publicar pero antes de responder? ¿Y si la cola no es durable?

Resumen

  • La mensajería asíncrona separa la producción del mensaje de su procesamiento.
  • Productor, cola y consumidor desacoplan servicios que, de otro modo, esperarían el uno al otro.
  • Es síncrono cuando necesitas la respuesta; asíncrono cuando basta con confirmar la recepción.
  • Las colas aguantan caídas del consumidor: los mensajes esperan y no se pierden.
  • Trabajo pesado en segundo plano (archivos, reportes, correos) es el cilindro típico de una cola.
