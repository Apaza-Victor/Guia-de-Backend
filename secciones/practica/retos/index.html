🏁 Un desafío por semana

🏁 Retos semanales

Ocho desafíos completos, pensados para resolver uno por semana. A diferencia de los ejercicios, aquí no hay pista ni solución de un solo párrafo: hay requisitos, criterios de aceptación y entregables que deberías poder sostener en una entrevista.

8 retos 1 por semana Requisitos y entregables Intermedio a experto

Semana 1 · CRUD REST completo

Reto 1 · API de tareas con CRUD

🚀 Nivel 1

Construye una API REST de tareas con persistencia en base de datos. Es el clásico punto de partida: simple, pero con todas las piezas de una API real.

Requisitos

  • Recursos GET /tareas, POST /tareas, GET /tareas/:id, PUT /tareas/:id, DELETE /tareas/:id.
  • Validación: título obligatorio, estado en pendiente | en_progreso | completada.
  • Respuestas con códigos HTTP correctos (200, 201, 400, 404).
  • Persistencia real: SQLite, MySQL o PostgreSQL.

Entregables

  • Repositorio en GitHub con README que explique cómo ejecutarlo.
  • Colección de peticiones de ejemplo (curl o similar) probando todos los endpoints.

Semana 2 · Autenticación JWT

Reto 2 · Login seguro con JWT

⚡ Nivel 2

Agrega registro e inicio de sesión a la API del Reto 1 y protege las rutas de creación y edición con un token JWT con caducidad.

Requisitos

  • POST /auth/registro y POST /auth/login.
  • Contraseñas guardadas con hash (bcrypt o argon2), nunca en texto plano.
  • Token firmado con secreto, con expiración y renovación (refresh token).
  • Cada tarea pertenece a su usuario: nadie puede editar tareas ajenas.

Entregables

  • Demostración de que una petición sin token recibe 401 y con token inválido 403.
  • Scripts de prueba automatizados para los dos flujos de autenticación.

Semana 3 · Caché con Redis

Reto 3 · Respuestas de milisegundos

⚡ Nivel 3

Acelera el endpoint más consultado de tu API guardando sus respuestas en Redis con una estrategia de expiración y de invalidación consciente.

Requisitos

  • Cachea la lista de tareas en Redis con TTL de 60 segundos.
  • Invalidación: al crear, editar o borrar una tarea, la caché se elimina.
  • Mide y documenta la latencia con y sin caché.
  • Manejo del caso en que Redis no está disponible (fallo controlado, sin romper la API).

Entregables

  • Comparativa de tiempos (ms) con y sin caché en el README.
  • Comandos Redis usados documentados.

Semana 4 · Dockeriza tu API

Reto 4 · Contenedores reproducibles

⚡ Nivel 4

Empaqueta tu API y su base de datos en contenedores para que cualquiera la levante con un solo comando.

Requisitos

  • Dockerfile multi-etapa para la API (construcción y runtime).
  • docker-compose.yml con API + base de datos + Redis.
  • Variables de entorno para configuración (puertos, credenciales, secretos).
  • La app arranca con docker compose up sin pasos manuales.

Entregables

  • Archivos de compose y Dockerfile versionados en el repo.
  • Captura o evidencia de la API funcionando dentro de contenedores.

Semana 5 · CI/CD con GitHub Actions

Reto 5 · Pipeline de integración continua

🔥 Nivel 5

Automatiza la calidad de tu código: cada vez que subas un cambio, el pipeline corre tests, análisis estático y construye la imagen.

Requisitos

  • Workflow de GitHub Actions que se dispara en push y pull request.
  • Pasos: instalación de dependencias, ejecución de tests y construcción de la imagen Docker.
  • Gate: si los tests fallan, el workflow falla.
  • Opcional: despliegue automático a un entorno de pruebas.

Entregables

  • Archivo YAML del workflow en .github/workflows/.
  • Badge de estado del pipeline en el README.

Semana 6 · Notificaciones en tiempo real

Reto 6 · WebSockets con salas

🔥 Nivel 6

Agrega un canal de tiempo real: cuando un usuario crea una tarea, todos los conectados a la misma sala la reciben al instante.

Requisitos

  • Servidor de WebSockets junto a la API (o servicio aparte).
  • Salas por usuario o por proyecto, con unión y salida controladas.
  • Evento tarea.creada con el payload de la tarea.
  • Manejo de reconexión y de desconexiones.

Entregables

  • Cliente de prueba (HTML o script) conectado que muestre los eventos en consola.
  • Documentación de los mensajes que intercambia el protocolo.

Semana 7 · Reporte con SQL avanzado

Reto 7 · Analítica con SQL

🔥 Nivel 7

Genera un reporte agregado de tu base de datos: estado de tareas por usuario, promedios de completado y ranking, usando solo SQL.

Requisitos

  • Consulta con JOIN entre al menos dos tablas.
  • Agregación con GROUP BY y filtro de grupos con HAVING.
  • Al menos una función de ventana (RANK o ROW_NUMBER).
  • Índice que acelere la consulta más usada y plan EXPLAIN documentado.

Entregables

  • Archivo .sql con todas las consultas comentadas.
  • Análisis del plan de ejecución antes y después del índice.

Semana 8 · Límites y endurecimiento

Reto 8 · Rate limiting y seguridad

🏆 Nivel 8

Protege tu API contra abuso: limita las peticiones por IP y por usuario, y endurece los headers HTTP básicos de seguridad.

Requisitos

  • Rate limiting por IP y por token (por ejemplo 100 peticiones/minuto, respondiendo 429 al exceder).
  • Headers de seguridad: X-Content-Type-Options, Cache-Control y CSP.
  • Validación de entrada en todos los endpoints (tipo, longitud, formato).
  • Ningún secreto en el código: todas las credenciales por variables de entorno.

Entregables

  • Demostración del 429 después del límite.
  • Lista de comprobación OWASP Top 10 aplicada al proyecto, marcada y comentada.
