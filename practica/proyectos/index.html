🏗️ De un CRUD a un sistema distribuido

🏗️ Ruta de proyectos

Seis proyectos progresivos. Cada uno suma herramientas y desafíos al anterior, así que el orden importa: termina el Nivel 1 antes de empezar el 2. Al llegar al Nivel 6 habrás construido el trayecto completo de un desarrollador Backend.

6 niveles Progresivo De CRUD a sistema distribuido Para tu portafolio

Nivel 1 · Fundamentos: API de tareas

API de tareas con CRUD

🌱 Nivel 1

El proyecto fundacional: una API REST que permite crear, listar, editar y borrar tareas, con la lógica clara y separada por capas.

Requisitos técnicos

  • Endpoints CRUD completos con códigos de estado correctos.
  • Modelo de datos con una tabla de tareas y validaciones de entrada.
  • Estructura por capas: rutas, controladores y acceso a datos.
  • Pruebas básicas de los endpoints principales.
Node + Express o Python + FastAPI SQLite

Nivel 2 · Usuarios: blog con sesiones

Blog con usuarios y sesiones

🚀 Nivel 2

Un blog donde los usuarios se registran, inician sesión y publican artículos y comentarios. Introducción real a relaciones entre tablas y a la autenticación.

Requisitos técnicos

  • Registro, login y logout con contraseñas hasheadas.
  • Tablas relacionadas: usuarios, artículos y comentarios con integridad referencial.
  • Los usuarios solo pueden editar o borrar sus propios artículos.
  • Paginación de artículos y búsqueda por título.
PHP + MySQL sesiones o Node + PostgreSQL

Nivel 3 · Transacciones: tienda online

Clon de tienda con transacciones

🚀 Nivel 3

Catálogo, carrito y pedidos donde el inventario nunca se corrompe: aquí aprendes por qué existen las transacciones y los bloqueos de base de datos.

Requisitos técnicos

  • Productos con stock, carrito asociado al usuario y procesamiento de pedidos.
  • Creación del pedido y descuento de stock dentro de una transacción atómica.
  • Manejo de concurrencia: dos compras simultáneas no pueden vender el último artículo dos veces.
  • Historial de pedidos por usuario.
Python + PostgreSQL transacciones SQL

Nivel 4 · Tiempo real: panel de equipo

Gestión de tareas de equipo en vivo

⚡ Nivel 4

Un Trello minimalista: tableros, listas y tarjetas compartidas por un equipo, con movimientos que se sincronizan en tiempo real para todos.

Requisitos técnicos

  • Autenticación JWT y permisos por proyecto (miembro o administrador).
  • Tableros, listas y tarjetas con movimiento entre listas.
  • WebSockets: los cambios se propagan a los conectados del mismo tablero.
  • Auditoría de acciones (quién movió qué y cuándo).
Node + Socket.IO JWT Redis

Nivel 5 · Servicios: microservicios de inventario

Microservicios de inventario y pedidos

🔥 Nivel 5

Divide el monstruo: un servicio de productos, otro de stock y otro de pedidos, que se comunican por colas y cada uno guarda sus propios datos.

Requisitos técnicos

  • Tres servicios independientes con su propia base de datos y API.
  • Comunicación asíncrona con un broker (RabbitMQ o Kafka).
  • Consistencia eventual: el pedido se confirma aunque el stock se actualice después.
  • Docker Compose para levantar todos los servicios.
Go o Node RabbitMQ Docker Compose

Nivel 6 · Escala: sistema de alto tráfico

Sistema distribuido de alto tráfico

🏆 Nivel 6

El proyecto final: un sistema diseñado para picos masivos, con balanceo, caché distribuida, replicación de datos y observabilidad completa.

Requisitos técnicos

  • Balanceador de carga con varias réplicas de la API.
  • Caché distribuida con Redis Cluster y estrategia de invalidación.
  • Base de datos con réplicas de lectura y backups.
  • Métricas, logs y trazas con Prometheus y Grafana.
  • Prueba de carga que demuestre la capacidad del sistema.
Kubernetes o compose swarm Redis Cluster Prometheus + Grafana

Consejos para la ruta

  • Sube todo a GitHub desde el Nivel 1: cada proyecto es una vitrina en sí mismo.
  • Termina antes de avanzar: cada nivel usa lo aprendido en el anterior.
  • Escribe el README al inicio, no al final: documentar el porqué de las decisiones es parte del ejercicio.
  • Complementa con los retos: los retos semanales refuerzan técnicas que estos proyectos requieren.
